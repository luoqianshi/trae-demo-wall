# 《更好的一天》网页版 MVP 实现计划

## 一、项目概述

一个纯前端的每日晨间陪伴网页，用户每天早上打开即可完成 2 分钟的唤醒体验（语音 + 呼吸 + 早安消息）。

## 二、技术选型

| 维度 | 选择 | 理由 |
|------|------|------|
| 前端框架 | 纯 HTML/CSS/JS | 零依赖、极简、无需构建工具 |
| 存储 | LocalStorage | 零后端，记录连续天数、消息池、投递内容 |
| 语音 | 预录唤醒音频（30条 MP3）+ 1条固定背景音乐 | 30条每日不同唤醒语音 + 1条通用BGM用于陌生人留言时段 |
| 动画 | CSS Animation + requestAnimationFrame | 无需第三方库 |
| 敏感词过滤 | 本地关键词列表 | 前端硬编码数组，无需 API |
| 部署 | GitHub Pages / Vercel / 任意静态托管 | 纯静态，上传即用 |

## 四、功能模块技术方案

### 4.1 每日内容呈现 (`content.js`)

- **数据结构**：一个包含 30 条内容的数组，每条包含 `day`（1-30）、`title`（短标题）、`morningMessage`（早安文案）、`audioFile`（音频文件名）
- **呈现策略（方案B，推荐）**：每日从 30 条内容中**随机抽取**一条展示，不按顺序推进。理由：
  - 用户首次使用日期不确定，按日期取模会让用户看到"第15天"的内容却显示"第1天"连续天数，产生困惑
  - 随机抽取让每次打开都是"盲盒"，体验更轻盈
  - 无需记录用户进度，开发最简单
- **替代方案（方案A）**：如需按顺序推进，用 LocalStorage 记录用户当前进度（`betterDay_contentIndex`），每次使用后 +1，重置后从第 1 天开始

### 4.2 音频播放 (`audio.js`)

**播放内容**：每日流程播放两段声音：
- **第一段**：当日唤醒语音（预录 MP3，30秒，每日从 30 条中随机选取）
- **第二段**：固定背景音乐/白噪音（预录 `bgm.mp3`，30秒，每日相同），同时屏幕上大字展示"陌生人留言"文字内容

**关键变更**：不使用 Web Speech API（TTS）播放陌生人留言文字。原因：移动端 Safari 支持差，合成语音机械感严重，与真人录制语音体验割裂。改为"文字展示 + 背景音乐"方案，只需 30 条唤醒语音 + 1 条 BGM。

**自动播放限制（重要 🔴）**：浏览器会阻止自动播放带声音的媒体。解决方案：
- 页面加载后显示全屏启动页，含"开始今天"按钮
- 用户点击按钮的**同步事件回调**中，执行以下步骤：
  1. 创建 AudioContext 并调用 `audioContext.resume()`（**必须在用户点击回调中同步执行，不能用 setTimeout 包裹**）
  2. 调用 `audio.play()` 开始播放
  3. 启动呼吸动画
- **播放控制**：使用 HTML5 `<audio>` 标签 + JavaScript API，第一段播放结束后触发 `ended` 事件，自动开始第二段（BGM）

### 4.3 呼吸引导动画 (`breathing.js`)

- **实现**：CSS 动画实现圆环持续缓慢缩放 + 透明度变化
- **设计原则**：引导性而非指令性。用户不需要"做对"，只需要"跟着感觉走"
- **视觉**：一个居中的圆形 SVG 或 div，伴随"吸气…""呼气…"文字提示交替显示
- **节奏**：每个完整缩放周期约 6-8 秒（缓慢放大 = 吸气，缓慢缩小 = 呼气）
- **持续时间**：与第一段唤醒语音同步，持续 30 秒。语音结束后动画停止
- **去掉"3次深呼吸"计数**，不强制用户同步节奏，不产生"做任务"的压力

### 4.4 连续天数记录 (`storage.js`)

- **LocalStorage 键**：
  - `betterDay_lastVisit`：上次访问日期字符串（YYYY-MM-DD）
  - `betterDay_streak`：连续天数
  - `betterDay_firstVisit`：是否首次访问
- **逻辑**：
  - 页面加载时检查 `lastVisit`
  - 如果 `lastVisit === today` → 今日已访问，不增加天数
  - 如果 `lastVisit === yesterday` → 连续天数 +1
  - 如果 `lastVisit` 早于昨天 → 连续天数重置为 1
  - 首次访问 → 连续天数设为 1，显示引导弹窗

### 4.5 留言存储与回放 (`message-pool.js`)

**重要设计决策**：纯前端 LocalStorage 方案下，用户投递的留言只存于自己设备，无法被其他用户看到。因此**这不是陌生人社交**，而是"自己写给自己的留言回放"。

- **定位调整**：文案从"给陌生人留一句早安"改为"给明天的自己留一句话" 或 "存一句话给未来的自己"
- **播放场景**：第二段音频（BGM）播放期间，屏幕上展示用户**自己之前投递**的留言，让用户感受到"过去的自己鼓励现在的自己"

- **LocalStorage 键**：
  - `betterDay_messages`：留言数组 `[{ text: "...", dateCreated: "2026-07-03" }]`
  - `betterDay_todayMessage`：今日展示的留言索引
- **留言投递流程**：
  1. 用户输入文字 → 敏感词过滤 → 通过后存入 `messages` 数组
  2. 每条留言记录创建日期
- **每日展示逻辑**：
  - 每次加载时，从 `messages` 数组中随机取一条展示
  - 如果 `messages` 为空（用户从未投递过），展示一条预设的默认文案，如"今天也要好好过"
- **BGM 播放方式**：使用 HTML5 `<audio>` 播放 `bgm.mp3`，同时在页面上居中大字展示留言文字

### 4.6 敏感词过滤 (`sensitive-words.js`)

- **实现**：一个硬编码的敏感词列表，包含常见不当词汇
- **过滤逻辑**：用户提交时遍历列表，如果包含敏感词则拒绝提交并提示"请调整您的文字"
- **列表来源**：开源敏感词库（如 `anti-spam` 词表的子集），约 50-100 个词

### 4.7 页面交互流程 (`index.html` + `app.js`)

```
页面加载
  ↓
检查是否首次访问 → 是 → 显示"设闹钟提醒"引导弹窗
  ↓
检查连续天数 → 更新显示 "第X天"
  ↓
显示全屏启动页（"更好的一天"标题 + "开始今天"按钮）
  ↓
用户点击"开始今天"（同步回调内执行 audioContext.resume() 解锁音频）
  ↓
┌────────────────────────────────────────────┐
│ 第一段：播放唤醒语音（30秒预录 MP3）      │
│ 同时：显示短标题 + 呼吸动画（持续缓慢缩放）│
│ 语音结束后自动触发 ended 事件              │
├────────────────────────────────────────────┤
│ 第二段：播放固定 BGM（30秒 bgm.mp3）       │
│ 同时：大字展示"自己过去的留言"文字          │
│ 如果无历史留言，展示默认文案                │
└────────────────────────────────────────────┘
  ↓
两段音频均结束 → 显示早安消息卡片
  ↓
显示"给明天的自己留一句话"输入框（限30字）
  ↓
用户提交 → 敏感词过滤 → 通过后存入 LocalStorage
  ↓
显示"今日已完成"结束页面
  ↓
（用户关闭页面，明日再来）
```

## 五、页面布局（移动端优先）

### 5.6 结束页
- 完成动画（勾选/星星）
- "明天见"文字
- 可选：再次引导设闹钟

## 八、验证方式

1. 打开页面 → 首次访问显示引导弹窗（设闹钟提醒）
2. 点击"开始今天" → 唤醒语音自动播放 + 呼吸动画同步
3. 唤醒语音结束后 → BGM 自动播放 + 展示"自己过去的留言"文字
4. BGM 结束后 → 显示早安消息 + 投递入口（"给明天的自己留一句话"）
5. 提交留言 → 敏感词过滤生效，通过后存入 LocalStorage
6. 次日刷新 → 连续天数 +1，内容随机切换
7. 多设备测试移动端适配（Chrome/Safari 手机浏览器）

## 九、不做事项（按用户文档约束）

- 不注册/登录
- 不语音录制投递
- 不后台播放
- 不推送提醒（改为引导设闹钟）
- 不做社交功能
- 不日历轨迹
- 不数据分析后台
- 不图标角标
- 不多语言
- 不离线使用
