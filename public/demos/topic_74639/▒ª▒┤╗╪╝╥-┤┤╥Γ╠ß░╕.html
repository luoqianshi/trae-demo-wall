一、创意介绍

想解决什么问题 · 为什么想到做这个 · 它是一款怎样的产品

❓

想解决什么问题

寻亲信息多以纯文字散布在社交平台，缺乏统一的可视化渠道；已团聚的正面案例常被淹没， 难以形成传播和线索反馈的闭环。

💡

为什么想到做它

真实的"宝贝回家"志愿者协会已帮助数以万计家庭团聚。希望用前端技术让寻亲信息在地图上直观分布、 让已团聚故事被更多人看到。

🌐

它是一款怎样的产品

纯前端 SPA 寻亲信息网站，8 个功能页面 + 2 个表单弹窗，数据存储在浏览器 localStorage， 无需后端，无需注册登录，双击即运行。

二、目标用户与痛点

三类核心用户 · 四种典型场景 · 四大痛点

👨‍👩‍👧 用户 1

寻找失踪亲人的家属

需要快速发布失踪信息、上传照片和描述、管理网友提供的线索，在找到后分享团聚喜悦。

👥 用户 2

愿意提供线索的网民

希望就近浏览身边的寻亲标记、方便留言提供信息、看到真正的反馈和结果，保持公益参与感。

🤝 用户 3

志愿者与公益组织

需要追踪寻亲进展、统计平台成果、管理数据并导出备份，为官方协作提供技术桥梁。

→ 使用场景

  • ①家属发布信息：上传照片、填写体貌特征、失踪地点、联系方式
  • ②网民浏览地图：红色标记（失踪中）、绿色标记（已团聚）
  • ③详情页留言：标记为"疑似线索"或"确认线索"，支持匿名
  • ④查阅已团聚故事：时间线 + 家庭留言 + 关键线索追溯，转发传播

! 当前痛点

  • ①纯文字信息，缺乏地图可视化，位置分布不直观
  • ②已团聚案例缺少独立展示，无法形成"希望感"和社会证明
  • ③评论线索无类型区分，真正帮助团聚的信息难以被追溯
  • ④联系方式直接暴露存在隐私风险

五、技术方案

纯前端 · 零依赖本地运行 · CDN + 本地双保险

技术栈

前端语言 原生 HTML5 + CSS3 + ES6+
样式框架 Tailwind CSS v3
地图服务 高德地图 JS SDK v2.0
图标 Font Awesome 6.5
数据存储 localStorage (JSON)
架构模式 SPA + hash 路由

关键实现

数字动画 requestAnimationFrame + cubic ease-out
SVG 统计图 stroke-dasharray 环形进度
图片处理 canvas 压缩至 800px 宽
搜索防抖 300ms setTimeout 模式
数据版本 DATA_VERSION = 1.1
代码规模 约 3,750 行原生代码
⚡

运行方式

方式一（推荐）：将项目文件夹部署到任意静态服务器，浏览器访问 index.html

方式二：本地开发：python -m http.server 8080 后访问 localhost:8080

方式三：直接双击 index.html 文件打开运行

六、未来规划

从创意提案到真实可用的公益工具

阶段 1 · 后端接入

真实数据与多设备同步

将 localStorage 升级为 Node.js + MongoDB 后端，实现多设备数据同步和官方机构对接通道。

阶段 2 · 用户体系

账号与审核机制

注册登录 · 发布者身份管理 · 信息真实性审核 · 防假信息举报机制。

阶段 3 · 移动端

微信小程序 / App

开发微信小程序降低传播门槛，让寻亲信息在熟人社交网络中更快扩散。

阶段 4 · AI 辅助

智能线索匹配

基于图像识别和自然语言处理，智能匹配失踪人员特征与网友评论线索，推送"疑似匹配"信息给发布者。

阶段 5 · 官方协作

与宝贝回家志愿者协会等官方机构对接

为真实的寻亲活动提供技术支持，让创意提案真正成为有用的公益工具。
