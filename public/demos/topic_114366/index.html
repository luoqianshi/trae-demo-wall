AI 代码审查系统 — Code Review

让 AI 替你守住代码质量，把 Leader 从繁琐 Review 中解放出来

💡 1. Demo 简介

一句话定位：这是一款借助 AI 实现 Git 代码 Diff 自动审查的系统，面向开发人员，在 MR/PR 与 Push 事件触发时自动拉取代码 Diff 并完成 AI 审查与评分。

是什么

一个借助 AI 实现 Git 代码 Diff 审查的系统。系统接入并维护多种 AI 模型，通过 Webhook 监听 Git 平台事件，自动拉取最新 Diff，对新提交或合并的代码进行 AI 审查，并按规则给出 0–100 分的评分。

面向谁

开发人员，以及需要把控代码质量的技术 Leader 与团队管理者。

主要功能

  • AI 接入维护：统一管理多个 AI 模型，支持加权随机选择策略，保证审查稳定性与多样性。
  • Webhook 接收：接收 Git 平台的 MR/PR 与 Push 事件 Webhook，异步触发审查流程。
  • Diff 拉取：对接 Git 平台拉取最新代码 Diff，作为 AI 审查输入。
  • AI 代码审查：对新增或合并代码进行 AI 审查，输出问题清单与评分结果并持久化保存。

🎯 2. Demo 创作思路

灵感来源

用于对开发人员提交的代码进行审核，并按照一定的规则进行分数评判。希望把"人工经验驱动的代码 Review"转化为"AI 规则驱动的标准化审查"，让质量评估更客观、可量化。

想解决的问题

解决开发人员及技术 Leader 对代码的人工 Review 问题。人工 Review 耗时长、容易遗漏细节，且严重依赖 Reviewer 的个人经验与精力，难以在团队规模扩大后保持一致的质量。

为什么做这个方向

借助 AI 的强大代码能力，能够快速、有效地发现开发人员提交代码中的潜在问题，节省大量代码 Review 时间，从而将 Leader 解放出来，投入到更有意义的创造性任务中，例如架构设计、技术演进与团队培养。

⚙️ 4. 核心功能与交互流程

1
Webhook 触发
GitLab/Gitee 的 MR/PR 与 Push 事件通过独立 Webhook 进入系统
2
异步分发
校验 Token 后异步分发审查任务，按平台适配对应代码托管客户端
3
拉取 Diff
调用 Git 平台 API 拉取最新代码 Diff 作为审查输入
4
AI 审查
按预设 Prompt 调用 AI 模型，输出问题清单与评分
5
结果持久化
审查结果写入数据库，并通过多渠道通知团队

🛠️ 5. 技术实现思路

  • 后端：Java 17 + Spring Boot 3.2.5，采用 controller-service-mapper-entity 分层架构，核心审查流程异步执行。
  • 前端：Vue 3.4 + Element Plus 2.6，按 views-router-api-store 组织，提供工作台、审查列表/详情、AI 模型管理、系统配置等页面。
  • 数据库：PostgreSQL 存储审查记录，Flyway 管理 schema 变更，MyBatis-Plus 统一逻辑删除策略。
  • 多平台支持：通过 CodeHostingClient 接口抽象，GitLabClientService 与 GiteeClientService 分别实现，Webhook 独立 Token 校验。
  • AI 能力：支持多模型接入与加权随机选择，预设 Prompt 保证审查输出一致性，结果以 ReviewResultDTO（0–100 分）统一返回。
  • 安全认证：基于 Sa-Token + BCrypt，API 请求携带 Token；CORS 显式暴露 Authorization 头。
  • 通知能力：NotifyDispatcher 策略模式实现钉钉、企业微信、飞书多渠道通知。
