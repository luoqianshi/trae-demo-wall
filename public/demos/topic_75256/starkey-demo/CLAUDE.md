# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

StarKey (`starkey-demo`) is a Next.js 15 (App Router) + React 19 + TypeScript app that generates personalized social-skills practice scenarios for autistic / Asperger's children, anchored on each child's special interest (subway, dinosaurs, Lego, etc.). UI is in Simplified Chinese. Styling is CSS Modules only (no framework). The app runs fully offline from a local scenario bank; an optional Volcano ARK LLM can generate scenarios live.

## Commands

```bash
npm run dev      # dev server (localhost:3000)
npm run build    # production build
npm run start    # serve the production build
npm run lint     # next lint
npm run pregen   # regenerate app/data/scenarios.json via ARK (requires ARK_API_KEY)
```

There is **no test framework** in this repo — don't assume `npm test` exists.

### Run modes (env-driven)

- **Demo mode** (default, competition-safe): set `DEMO_MODE=true` *or* simply leave `ARK_API_KEY` unset. The API serves only the local bank, no network. `isDemoMode()` in `route.ts` returns true if `DEMO_MODE==='true'` OR no `ARK_API_KEY`.
- **ARK mode**: set `ARK_API_KEY` (and optionally `ARK_MODEL`, default `doubao-seed-2-0-mini-260428`) in `.env.local`. The API tries the LLM first, then falls back to the local bank.

## Architecture

### The layered fallback chain (the core design)

Every scenario request flows through fallbacks so the user **never** sees an error or empty screen. Understanding this chain is essential before editing scenario logic:

1. Client `app/page.tsx` → `getScenario()` → POST `/api/generate`.
2. `app/api/generate/route.ts` `POST`:
   - **Demo mode** → `findMatchingScenarios()` over the local bank → `generateGenericFallback()` if nothing matches.
   - **ARK mode** → `callArk()` up to 2 attempts + `extractJSON()` → on failure falls back to the same local bank → generic fallback.
   - The outer `try/catch` *also* falls back to the bank, so the handler effectively cannot 500 for a valid request.
3. If the API itself is unreachable, the client falls back to its **own** copy of the bank (`pregenData`, imported directly into `page.tsx`).

The response `source` field tells you which layer answered: `ark` | `local` | `pregen` | `generic-fallback`. The `demo` boolean drives the client's demo banner and `demoHint` messaging.

### Two scenario data sources inside the API (don't confuse them)

`route.ts` draws scenarios from **both**:
- `app/data/scenarios.json` — the canonical bank (~73 items), loaded via `getScenariosFromJson()` / `convertFromScenariosJson()`. This file is generated by `npm run pregen`; **edit the generator or the JSON, not by hand-duplicating into code**.
- `EXTENDED_SCENARIOS` — a large hardcoded array literal also in `route.ts` (14 interests × 3 difficulties). Matching logic searches across both.

`app/page.tsx` *also* imports `app/data/scenarios.json` (as `pregenData`) for its client-side fallback, with format detection for v1 (flat array), v2, and v3 (nested `data[theme][skill][difficulty]`) shapes — see `isV3Data()`, `getFromPregen3D()`, `getFromPregenByTopic()`.

### Topic naming has two coexisting vocabularies

Training topics exist in an **old** and **new** naming scheme, bridged by `TOPIC_ALIASES` and `isTopicMatch()` in `route.ts`:
- new: 看懂心情 / 轮流说话 / 开始聊天 / 处理变化
- old: 看懂心情 / 轮流玩 / 看懂表情和动作 / 遇到不开心的时候

`types/index.ts` `TrainingTopic` uses the *old* set, while `page.tsx getSavedTopic()` validates against yet another set (控制情绪 / 学会合作). When touching topic logic, route everything through `isTopicMatch`/`TOPIC_ALIASES` rather than comparing strings directly, and check both `types/index.ts` and `page.tsx`.

### Interest matching & redirection

When a user's interest isn't in the bank, the app does **transparent** redirection (never silent mismatch): `pickClosestPregenTopic()` (keyword map → closest supported theme, default 地铁) and `verifyScenarioConsistency()` (rejects content whose scene/options don't mention the displayed theme, forcing a fallback + a `demoHint` telling the user which substitute theme is shown).

### Autism-friendly UX invariants (intentional — preserve these)

- **No "wrong answer" punishment.** Score depends only on difficulty (`SCORE_PER_DIFFICULTY` in `types/index.ts`), identical for every option. `isRecommended` is **never** sent to the child UI — it is mapped to `feedbackTone` (`gentle` vs `supportive`) so all feedback reads as constructive.
- **Option positions are randomized.** `shuffleAndAssignIds()` Fisher-Yates–shuffles options and reassigns A/B/C on every render, so position can't be gamed.
- **No-repeat rotation.** Per-`(theme, skill, difficulty)` shuffle queues (`shuffleQueueRef`, `queueKey()`, `initShuffleQueue()`) avoid showing the same scenario twice in a row.
- **Sensory levels** (`SensoryLevel`: quiet/gentle/lively): default `quiet`, lowest stimulation; `lively` must be chosen explicitly and is the only level where sound can play (`gentleSound` in `lib/gentleSound.ts`).

### Progression / gamification

`types/index.ts` owns scoring & the subway-line metaphor: `LEVEL_THRESHOLDS`, `STATION_THRESHOLDS` (per-difficulty station distances), `getLevel()`, `getStationIndex()`, `getNextThreshold()`. `SubwayMap.tsx` renders the line; progress, skin, sensory level, and last selections persist in `localStorage` under `starkey.*` keys.

### Screen flow

`page.tsx` is a single client component switching on `GameState` (`screen1` interest/topic/difficulty select → `loading` → `screen2` answer → `screen3` feedback), composing `Screen1Interest` / `Screen2Scenario` / `Screen3Feedback` plus persistent `SubwayMap`, `CornerCharacter`, `SensorySelector`.

## Conventions

- Path alias `@/*` maps to repo root (`tsconfig.json`).
- `strict` TypeScript; `route.ts` uses `export const dynamic = 'force-dynamic'`.
- Scenario shape: see `types/generation.ts` (`GeneratedScenario`, `GenerationRequest`, `ApiResponse`) and `types/index.ts` (`Scenario`, `Option`). `socialRule` and `parentTip` are author-facing/parent-facing and not shown to the child as the answer.
- Regenerating the bank: edit `scripts/pregenerate.mjs` (it defines `THEMES`, `SKILLS`, `DIFFICULTIES` and writes `app/data/scenarios.json`), then `npm run pregen` with an ARK key.
