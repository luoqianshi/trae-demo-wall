## 1. 项目概述

### 1.1 项目背景

随着居民健康意识提升，个人健康指标的持续监测与及时干预愈发重要。传统体检存在"周期长、不连续、发现晚"的问题，且指标异常后缺乏便捷的专业指导渠道。本项目旨在构建一套个人身体状况监控系统，帮助用户实时掌握自身健康指标，对异常指标进行醒目告警，并提供健康建议与在线医生问诊服务，形成"监测—告警—建议—问诊"的完整健康管理闭环。

### 1.2 产品目标

- **用户价值**：让用户随时查看健康指标，异常指标醒目提示，一键获取健康建议或咨询医生。
- **业务目标**：构建覆盖监测、告警、建议、问诊的健康管理平台，支持设备数据自动接入。
- **核心指标**：日活用户健康指标查看率 ≥ 60%，异常指标问诊转化率 ≥ 30%。

### 1.3 核心价值

- 实时监控：聚合多来源健康指标，统一展示。
- 智能告警：基于可配置规则对异常指标分级告警。
- 专业指导：自动健康建议 + 真人医生问诊双通道。

### 1.4 名词定义

| 名词 | 说明 |
|------|------|
| 指标大类 | 健康指标的一级分类，如心血管系统、血液指标等 |
| 指标项 | 大类下的具体指标，如收缩压、空腹血糖等 |
| 告警等级 | 分为正常、预警、危险三级 |
| 问诊 | 用户与医生围绕健康问题进行的在线交流 |

## 2. 用户角色与权限

### 2.1 角色定义

| 角色 | 说明 | 核心场景 |
|------|------|----------|
| 个人用户（患者） | 关注自身健康的普通用户 | 查看指标、接收告警、咨询医生、导出报告 |

| 设备/数据源 | 智能穿戴/检测设备的数据对接方 | 上报血压、血糖、心率等数据 |

## 3. 功能需求

### 3.1 用户管理模块

#### 3.1.1 注册与登录
- 支持手机号 + 验证码注册登录。
- 支持第三方账号（微信）授权登录。
- 登录态保持，Token 过期自动刷新。
- 医生账号需后台审核开通，上传执业资质。

#### 3.1.2 个人档案
- 基础信息：姓名、性别、出生日期、身高、体重。
- 健康背景：既往病史、过敏史、用药情况。
- 紧急联系人。
- 档案信息用于指标正常范围的个性化计算（如年龄、性别差异化标准）。

### 3.2 健康指标监控模块（核心）

#### 3.2.1 可配置动态指标体系
- 指标采用"大类 → 指标项"两级结构，由管理员后台配置。
- 每个指标项包含：名称、单位、正常范围、预警阈值、危险阈值、适用性别、适用年龄段。
- 系统根据用户档案（年龄、性别）自动推荐适用指标项。
- 支持指标的启用/停用、排序。

**指标项配置字段示例：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 指标唯一标识 |
| categoryId | string | 所属大类 ID |
| name | string | 指标名称 |
| unit | string | 计量单位 |
| normalRange | object | 正常范围 {min, max} |
| warningThreshold | object | 预警阈值 {min, max} |
| dangerThreshold | object | 危险阈值 {min, max} |
| applicableGender | enum | 适用性别 all/male/female |
| applicableAgeRange | object | 适用年龄段 {min, max} |

#### 3.2.2 指标数据采集
- **手动录入**：用户手动输入指标数值，支持批量录入。
- **设备自动上报**：对接血压计、血糖仪、智能手表等设备，自动同步数据。
- **体检报告导入**：支持上传体检报告，OCR 识别后入库。
- 每条数据记录采集时间、数据来源、设备 ID（若有）。

#### 3.2.3 指标展示与告警
- 按大类卡片式展示，每张卡片展示该类下所有指标。
- 顶部状态概览：统计正常、预警、危险指标数量。
- 指标值根据告警等级着色：
  - 正常：绿色
  - 预警：黄色 + 慢速脉冲动画
  - 危险：红色 + 快速脉冲动画 + 告警标签
- 异常指标行显示"健康建议"与"医生解答"操作按钮。
- 支持指标趋势图（近 7/30 天折线图）。

#### 3.2.4 告警规则引擎
- 数据入库时触发规则计算，输出告警等级。
- 支持单次阈值告警与连续异常告警（如连续 3 次超标）。
- 危险等级告警通过 App 推送 + 短信通知用户。
- 告警记录可追溯，支持用户标记"已知晓"。

### 3.3 健康建议模块

#### 3.3.1 自动健康建议
- 用户点击异常指标的"健康建议"按钮，弹出对应建议内容。
- 建议内容来源：
  - 预置知识库：针对常见异常指标（高血压、高血糖、超重等）的标准建议。
  - 规则匹配：根据指标类型与告警等级匹配建议模板。
- 建议内容结构：紧急注意事项、日常建议、运动/饮食指导、就医提醒。

#### 3.3.2 健康知识库管理
- 管理员后台维护建议知识库，按指标关联。
- 支持富文本编辑，可插入图片。
- 知识库版本管理，更新后自动生效。

### 3.4 医生问诊模块

#### 3.4.1 混合问诊模式
系统同时支持两种问诊方式，用户可自由选择：

- **实时在线聊天**：从在线医生列表选择，发起即时会话，支持文字、图片、语音消息。
- **异步图文问诊**：提交病情描述 + 图片，预约医生在约定时段内回复。

#### 3.4.2 实时聊天功能
- 在线医生列表：展示医生头像、姓名、职称、擅长领域、在线状态、评分。
- 会话窗口：消息气泡（用户右侧、医生左侧）、发送时间、已读状态。
- 支持发送文字、图片（检验报告、患处照片）、语音消息。
- 医生可查看该用户最近 30 天健康指标，辅助诊断。
- 会话结束后用户可评价（星级 + 文字），并生成问诊记录。

#### 3.4.3 异步问诊功能
- 用户填写问诊单：主诉、症状描述、持续时间、伴随症状、相关图片。
- 选择科室与医生（或由系统分诊）。
- 医生在约定时段（如 24 小时内）回复，用户收到通知。
- 支持追问（限 3 轮），超时自动关闭。

#### 3.4.4 问诊管理
- 医生端：待接诊列表、进行中会话、历史记录。
- 用户端：我的问诊列表（进行中/已完成）。
- 问诊记录归档，可作为健康档案的一部分。

### 3.5 设备数据对接模块

#### 3.5.1 设备接入
- 支持主流健康设备接入（蓝牙血压计、血糖仪、智能手表等）。
- 设备绑定流程：扫码/搜索 → 绑定授权 → 数据同步。
- 设备列表管理：查看已绑定设备、解绑、同步状态。

#### 3.5.2 数据同步
- 设备采集数据后，通过 App 蓝牙或云端 API 自动上报。
- 数据上报接口需鉴权（设备 Token），防止伪造。
- 同步频率：实时（蓝牙连接时）/定时（云端同步，默认每小时）。
- 数据冲突处理：以最新采集时间为准，保留历史记录。

### 3.6 健康报告模块（新增）

- 支持生成个人健康报告（周报/月报/自定义时段）。
- 报告内容：指标汇总、异常项分析、趋势变化、健康建议汇总。
- 支持导出 PDF，下载响应头同时包含 `filename` 与 `filename*`（RFC 5987），兼容中文文件名。
- 支持分享给家庭账号成员或医生。

### 3.7 家庭账号模块（新增）

- 用户可创建家庭组，邀请家人加入。
- 家庭组成员可互相查看健康指标（需被查看人授权）。
- 适用于老人健康监护场景：子女远程查看父母指标。
- 家庭组上限 6 人，角色分为创建者与成员。

### 3.8 健康计划与积分激励模块（新增）

#### 3.8.1 健康计划
- 系统根据异常指标推荐健康计划（如减重计划、控压计划）。
- 计划包含目标、每日任务（如步数、饮食记录）、周期。
- 用户可打卡记录完成情况，查看进度。

#### 3.8.2 积分激励
- 完成健康任务、坚持打卡、指标改善均可获得积分。
- 积分可兑换健康服务（如免费问诊券、健康礼包）。
- 积分排行榜（周/月），激励用户参与。

### 3.9 后台管理模块

#### 3.9.1 指标体系管理
- 大类与指标项的增删改查、启用/停用、排序。
- 阈值配置与生效预览。

#### 3.9.2 用户与医生管理
- 用户列表、详情、封禁/解封。
- 医生资质审核、上线/下线、擅长领域配置。
- 角色权限分配。

#### 3.9.3 数据统计
- 平台数据概览：用户数、活跃度、问诊量、告警量。
- 指标异常分布统计、问诊满意度统计。
- 数据导出（限制条数上限，防止无限制拉取）。

## 4. 关键业务流程

### 4.1 指标监测与告警流程

```
用户/设备上报数据 → 数据校验入库 → 告警规则引擎计算
  → 正常：更新展示
  → 预警：标记黄色 + 推送通知
  → 危险：标记红色 + 推送 + 短信 → 用户查看 → 点击健康建议/医生问诊
```

### 4.2 实时问诊流程

```
用户查看异常指标 → 点击"医生解答" → 选择在线医生 → 发起会话
  → 医生接诊 → 查看用户指标 → 实时交流（文字/图片/语音）
  → 会话结束 → 用户评价 → 生成问诊记录
```

### 4.3 异步问诊流程

```
用户提交问诊单（主诉+图片）→ 选择科室/医生 → 系统分诊
  → 医生接单 → 约定时段内回复 → 用户收到通知 → 查看回复
  → 可追问（限3轮）→ 超时或结束 → 归档
```

### 4.4 设备数据同步流程

```
设备采集数据 → 蓝牙/云端上报 → 接口鉴权 → 数据校验
  → 入库 + 触发告警规则 → 更新用户指标 → 推送同步结果
```

## 5. 非功能需求

### 5.1 性能需求
- 指标列表页加载时间 ≤ 2 秒（P95）。
- 问诊消息发送到对方收到延迟 ≤ 1 秒。
- 设备数据上报接口响应时间 ≤ 500ms。
- 支持并发在线用户 1 万、并发问诊会话 1000。

### 5.2 安全需求
- 用户身份严禁由前端传入，必须从 Token/Session 安全上下文获取。
- 接口需鉴权与越权校验（用户只能访问自身数据）。
- 健康数据传输全程 HTTPS，敏感字段加密存储。
- 设备上报接口使用设备 Token 鉴权，防伪造。
- 问诊记录、健康档案数据保留期限符合法规要求。

### 5.3 可用性需求
- 系统可用性 ≥ 99.9%。
- 核心服务支持故障降级（如问诊服务不可用时，健康建议仍可用）。
- 数据库主从容灾，定期备份。

### 5.4 兼容性需求
- 移动端：iOS 12+、Android 8.0+。
- 浏览器：Chrome、Safari、Edge 最新两个大版本。
- 设备协议：兼容蓝牙 BLE 4.0+、主流厂商云端 API。

## 6. 数据模型与接口设计

### 6.1 核心数据实体

```
User（用户）: id, phone, name, gender, birthDate, height, weight, role, createdAt
HealthCategory（指标大类）: id, name, icon, sortOrder, enabled
HealthMetric（指标项）: id, categoryId, name, unit, normalRange, warningThreshold,
                      dangerThreshold, applicableGender, applicableAgeRange
HealthRecord（指标记录）: id, userId, metricId, value, unit, source, device_id, recordedAt
AlertRecord（告警记录）: id, userId, metricId, level, value, status, createdAt
AdviceTemplate（建议模板）: id, metricId, level, content, version
Consultation（问诊会话）: id, userId, doctorId, type(realtime/async), status, createdAt
Message（消息）: id, consultationId, senderType, contentType, content, sentAt
Device（设备）: id, userId, deviceType, model, token, boundAt
HealthPlan（健康计划）: id, userId, type, goal, tasks, period, progress
FamilyGroup（家庭组）: id, ownerId, members[], createdAt
```

### 6.2 核心接口定义

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 获取指标大类 | GET | /api/health/categories | 返回用户适用的指标大类及最新值 |
| 上报指标数据 | POST | /api/health/records | 手动/设备上报，触发告警 |
| 获取指标趋势 | GET | /api/health/records/trend | 返回指定指标历史趋势 |
| 获取健康建议 | GET | /api/health/advice/{metricId} | 根据指标返回建议内容 |
| 在线医生列表 | GET | /api/doctors/online | 返回当前在线医生 |
| 发起问诊 | POST | /api/consultations | 创建问诊会话 |
| 发送消息 | POST | /api/consultations/{id}/messages | WebSocket/HTTP 发送 |
| 设备数据上报 | POST | /api/devices/{id}/data | 设备 Token 鉴权 |
| 生成健康报告 | POST | /api/reports/generate | 返回报告下载链接 |
| 指标体系配置 | PUT | /api/admin/metrics/{id} | 管理员配置指标项 |

### 6.3 数据查询规范
- 所有列表查询必须带 limit/maxResults 上限，禁止无限制拉取。
- 判断数据是否存在使用 exists 或 limit 1，禁止 count 全表。
- 数据库聚合计算优先下推，减少应用层处理。

| 页面 | 核心要素 |

- 弹窗点击遮罩可关闭，关键操作需二次确认。

## 8. 验收标准

### 8.1 功能验收
- 指标体系支持管理员动态配置大类与指标项，配置后用户端即时生效。
- 指标数据上报后，告警等级计算正确，展示颜色与标签符合规则。
- 危险指标点击"健康建议"可弹出对应建议内容，点击"医生解答"可进入问诊。
- 实时问诊消息收发正常，支持文字/图片/语音，医生可查看用户指标。
- 异步问诊单可提交，医生可在约定时段回复，支持有限追问。
- 设备绑定后数据可自动同步并触发告警。
- 健康报告可生成并导出 PDF，文件名含中文且兼容各端。

### 8.2 非功能验收
- 指标列表页 P95 加载时间 ≤ 2 秒。
- 问诊消息端到端延迟 ≤ 1 秒。
- 越权访问被正确拦截（用户无法访问他人数据）。
- 系统在 1 万并发用户下稳定运行。

| 大类 | 示例指标项 |
|------|-----------|
