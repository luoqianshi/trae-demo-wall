# Handdrawn Course Image

Refined Chinese handdrawn technical PPT-style image generation. Optimized for course materials, article illustrations, and educational content.

## Operating Rule

Default output is **complete raster page images (PNG)** generated by `image_generate`. **All pages are 16:9** (preferred final size 1920x1080), including cover images. Each page is a final visual deliverable with diagram and Chinese text baked in.

In this skill, "PPT", "slides", "page", "deck" mean **finished PPT-style visual page images**, not editable presentation files. Editable PPTX, image-based PPTX, PDF export, and document packaging are out of scope.

## 6-Step Mandatory Pipeline

You **MUST** execute all 6 steps in order. Do not skip any step. Each step has a dedicated reference document you **MUST read before executing that step**.

| Step | Name | Reference (must read first) | Output |
|------|------|------------------------------|--------|
| 1 | Intake & Gap Diagnosis | `references/intake.md` | `intake_report.json` |
| 2 | Narrative Planning | `references/narrative-planning.md` | `slide_spine.json` |
| 3 | Slide Archetype Mapping | `references/slide-archetypes.md` | `page_archetypes.json` |
| 4 | Visual DNA / Style Lock | `references/visual-dna-v6.md` + `assets/theme-tokens.json` | `style_lock.json` |
| 5 | Prompt Building | `references/prompt-patterns.md` | `prompts.json` (one per page) |
| 6 | Generation + QA | `references/output-quality.md` | final PNG pages + contact sheet |

## Mandatory Style Anchor

For ALL page generations, you **MUST** pass the style anchor image as `ref_images` to `image_generate`:

```
ref_images = ["assets/reference-handdrawn-course-style.png"]
```

This is non-negotiable. The model needs visual anchoring, not just text descriptions of the style.

## Defaults

- Language: Simplified Chinese.
- Audience: Chinese learners with moderate technical familiarity.
- Deck length: 8-12 slides for one article, 15-30 for a course module, 5-8 for a short idea.
- Output: final PNG page images plus contact sheet plus short slide blueprint summary.
- Canvas: **all pages 16:9 (1920x1080)**, including covers. No 21:9 or other ratios.
- Style: refined near-white Chinese handdrawn technical article/PPT illustration V6.

## Step 1: Intake & Gap Diagnosis

Read `references/intake.md` first. Extract topic, audience, scenario, target length, source sufficiency, and 1-3 critical missing inputs. Ask at most 1-3 concise questions when the answer changes the deck materially; otherwise use defaults and continue.

Output `intake_report.json` with: `topic`, `audience`, `scenario`, `target_length`, `source_sufficiency`, `core_claims`, `assumptions`, `missing_inputs`.

## Step 2: Narrative Planning

Read `references/narrative-planning.md` first. Choose deck type (teaching / persuasive / report / product-explanation / knowledge-card). Build a slide-by-slide spine where each slide has exactly one main point.

Output `slide_spine.json` with: `deck_type`, `slides[]` (each with `slide_number`, `title`, `main_point`).

## Step 3: Slide Archetype Mapping

Read `references/slide-archetypes.md` first. For each slide, choose an archetype by **semantic content** (cover-metaphor / single-concept / left-right-contrast / horizontal-process / circular-mechanism / branching-map / classification-map / matrix-table / main-metaphor / takeaway). Vary archetypes across the deck.

Output `page_archetypes.json` with: `slides[]` extended with `archetype`, `content_blocks`, `visual_brief`.

## Step 4: Visual DNA / Style Lock

Read `references/visual-dna-v6.md` AND `assets/theme-tokens.json` first. Lock these cross-page constants:
- Paper tone (#FBFAF5)
- Line weight and ink color
- Pastel palette (blue / sage / peach / lavender)
- Page number style (upper-left, e.g. `01 / 10`)
- Title treatment (centered, medium, hard-pen Chinese, one pale blue underline)
- Subtitle position
- Corner construction marks
- Character policy (0 or 1 tiny far-corner)
- Diagram scale (50-60% page width, 35-45% page height for body; 50-55% for cover)

Output `style_lock.json` containing the full compact style lock paragraph that will be reused verbatim in every page prompt. The right-top corner decoration is decided here at the deck level and reused across every page of the deck; do not let each page pick its own decoration.

## Step 5: Prompt Building

Read `references/prompt-patterns.md` first. For each page, assemble a complete image prompt using:
- Page role lock (cover / body / standard)
- Title and subtitle
- Archetype
- Main point
- Style lock (paste compact style_lock.json content)
- Reference match clause (paste reference match text)
- Composition specifics (object-based handdrawn diagram description, not generic boxes)
- Scale lock
- Required text only (exact short Chinese text list)
- Avoid list

Output `prompts.json` with one complete prompt per page.

## Step 6: Generation + QA

Read `references/output-quality.md` first. For each page in `prompts.json`:

1. Call `image_generate` with:
   - `prompt`: the complete prompt from prompts.json
   - `ref_images`: **MUST include** `"assets/reference-handdrawn-course-style.png"`
   - `count`: 1
   - `mode`: "生图" (if a ref_image is provided)
2. Run QA checks (content / layout / visual / dimension / image-text / contact-sheet gates).
3. If QA fails, regenerate up to 3 times with reduced text or fixed composition. If exact Chinese text remains wrong, use deterministic text overlay on the accepted base image.
4. Save accepted images to the workspace.
5. Build a contact sheet when there are multiple pages.

Output: final PNG page images, contact sheet (if multiple pages), short slide blueprint summary.

## Final Response

When finished, report:
- Output folder and contact sheet path.
- Page count and deck type.
- Important assumptions.
- Verification performed and any remaining risks.

For planning-only requests, provide the blueprint directly and identify the critical questions to answer before deck production.
