# 织梦机 DreamLoom · Demo 体验指南

> 本 Demo 为 Trae AI 创造力大赛参赛作品，基于 TRAE IDE 全程开发。

## 一、Demo 简介

**是什么**：织梦机是一个面向小说创作者的"AI 协同创作工作台"——用知识星图管理世界观与人物关系，用一致性守卫实时检测剧情矛盾，用叙事标本库积累写作素材，让长篇小说创作从"凭感觉"变为"有依据"。

**面向谁**：奇幻/武侠/科幻等长篇小说创作者，尤其是需要管理复杂世界观、多角色关系、多线情节的作者。

**核心功能**（3 个）：
1. **知识星图** — 3D 可视化呈现人物、情节、世界设定、势力的关系网络，支持集群/实体/层级三种视图，帮助作者把握全局结构
2. **一致性守卫** — 双阶段检测（关键词匹配 + AI 深度确认）实时发现人物性格前后矛盾、伏笔未回收、世界设定冲突等问题
3. **AI 协同写作** — TipTap 富文本编辑器 + AI 助手，支持角色/情节/世界观的智能生成与改写，所有 AI 操作可降级到 Mock 模式离线运行

## 二、创作思路

**灵感来源**：长篇小说创作中，作者常常在第 50 章忘了第 3 章埋的伏笔，或者让角色性格在不知不觉中"崩坏"。市面上的写作工具要么只管排版（Word/WPS），要么只管大纲（Scrivener），没有一个能真正理解"故事内容"并帮作者维护一致性。

**想解决的问题**：
- 长篇小说越写越长，作者记不住所有设定和伏笔
- 角色多了之后，性格和行为容易前后矛盾
- 世界观复杂后，设定之间会冲突（如"北方人不吃辣"却在后续写了"北方人嗜辣"）
- 现有工具都是"被动记录"，没有"主动检测"

**为什么做这个方向**：AI 不应只做"生成"，更应做"守护"。DreamLoom 的核心创新是让 AI 理解故事内容并维护一致性，而非单纯生成文字。这是现有写作工具都没有覆盖的真实痛点。

## 四、体验路径

打开 Demo 后，系统已预置奇幻题材示例项目**"星陨之诗"**，按以下路径体验核心功能：

### 1. 首页（/）
- 展示"星陨之诗"项目卡片
- 点击进入项目

### 2. 写作页（/write）
- 左侧章节列表（6 章，2 卷）
- 中间 TipTap 富文本编辑器，可直接编辑章节正文
- 右侧 AI 助手面板

### 3. 人物页（/characters）
- 6 个角色卡片：凌霜、陆云天、星岚、赫连烈、凤舞、玄夜
- 每个角色含性格、背景、动机、欲望、缺陷、关系网络
- 点击角色可查看详情和编辑

### 4. 情节页（/plot）
- 10 个情节点，3 幕结构
- 3 个伏笔标记（星岚身份、玄夜身份、陨星使命）
- 情节之间有因果关系链

### 5. 星图页（/knowledge）⭐ 核心亮点
- 3D 力导向图谱，展示人物/情节/世界设定的关系网络
- 支持集群/实体/层级三种视图切换
- 鼠标拖拽旋转、滚轮缩放、点击节点查看详情
- 15 条依赖关系可视化

### 6. 守卫页（/guard）⭐ 核心亮点
- 4 条核心规则（世界观/角色/情节/其他分类）
- 2 个一致性问题（1 个 error + 1 个 warning）
- 展示双阶段检测：关键词匹配 → AI 深度确认

### 7. 标本页（/specimens）
- 4 个叙事标本：章节标题、角色日记、角色书信、编年史
- 展示如何积累不同文体的写作素材

### 8. 工作台（/workbench）
- 依赖关系图谱
- 版本历史管理

## 五、TRAE 实践过程

本 Demo 的完整功能均通过 TRAE IDE 开发完成，以下是关键开发步骤：

### 开发流程

1. **需求拆解**：用 TRAE 的 Spec 模式将"独立 Demo"需求拆解为 8 个任务，生成 spec.md / tasks.md / checklist.md 三份规范文档
2. **数据层**：用 TRAE 生成 11 个 mock JSON 文件（奇幻题材"星陨之诗"完整数据集），含 UUID 外键引用
3. **架构改造**：用 TRAE 识别并改造 3 处绕过 dataService 的硬编码 remote 调用（星图集群、图数据、导入图书）
4. **认证旁路**：用 TRAE 实现方案 A（注入假 token），让评审无需登录即可体验
5. **数据预填充**：用 TRAE 创建 seedMockData.ts，实现幂等的 IndexedDB 数据导入
6. **字段映射**：用 TRAE 处理 mock JSON 与 TypeScript 类型的字段差异（foreshadowings/coreRules/consistencyIssues）
7. **验证测试**：用 TRAE 运行 tsc 类型检查，确保零错误

## 六、对应评分维度的亮点

### 创新性（30%）
- **需求创新**：挖掘到长篇小说创作的真实痛点——设定遗忘与一致性崩坏，现有产品未妥善解决
- **解决思路**：首创"双阶段一致性守卫"（关键词匹配 + AI 深度确认），而非单纯 AI 生成
- **技术创新**：用 TRAE 的 Spec 模式驱动开发，AI 理解代码架构并自动改造硬编码 remote 调用

### 实用性（30%）
- **场景洞察**：精准定位长篇小说创作者，管理复杂世界观和多角色关系
- **解决效果**：可视化星图 + 自动矛盾检测，作者不再需要手动翻阅前文核对设定
- **落地可行**：Demo 已完整运行，核心功能（写作/人物/情节/星图/守卫/标本）全部可用

### 完成度（20%）
- **核心链路**：从首页 → 项目 → 写作 → 人物 → 情节 → 星图 → 守卫 → 标本 → 工作台，全流程跑通
- **数据完整**：预置 1 项目 / 6 角色 / 10 情节 / 6 章节 / 15 依赖 / 4 标本 / 3 伏笔 / 4 规则 / 2 问题
- **零后端依赖**：IndexedDB + Mock AI，开箱即用

### 美观度（20%）
- **视觉设计**：18 世纪天文台星图美学（深色玻璃 + 古金箔线 + 上升粒子），与"知识星图"主题契合
- **交互友好**：3D 力导向图谱可拖拽缩放，TipTap 编辑器流畅响应，所有操作零学习门槛
