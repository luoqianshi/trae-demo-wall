## 1. Demo 简介

**是什么：** 一个纯前端的 Web 应用，覆盖导游证考试"规划 → 学习 → 刷题 → 分析 → 面试模拟"全链路，打开浏览器即可使用，无需安装、无需注册、无需联网。

**面向谁：**
- 在职导游备考人员（旅行社前台、景区讲解员、想转行做导游的人）
- 零基础跨考考生
- 旅游管理专业在校学生

**主要功能：**

**功能一：智能学习规划**
输入考试倒计时和每日可用时间，系统根据四科分值权重自动生成动态学习日历。每天打开就能看到"今天该学什么、学多少、做什么题"，不用再纠结从哪开始。

> 建议配图：学习规划页面截图，展示日历视图和每日任务清单

**功能二：智能刷题 + 错题诊断**
内置 221 道真题，覆盖四科全部考点，支持章节练习、模拟考试、错题重练三种模式。答错的题自动进入错题本，系统诊断出薄弱知识点并给出针对性提分建议。

> 建议配图：刷题答题界面 + 错题本诊断页面截图

**功能三：AI 面试模拟（核心差异化）**
这是市面导游证 App 几乎没有的功能。AI 扮演面试官，覆盖景点讲解、应变能力、服务规范三大模块。用户输入回答后，系统根据关键词匹配度、内容完整性进行评分，并给出反馈和改进建议。

> 建议配图：面试模拟页面截图，展示题目和评分反馈

## 2. Demo 创作思路

**灵感来源：**
导游证考试和其他职业考试最大的不同在于：它不仅有 4 科笔试，还有 1 科面试，其中"景点讲解"单项占 45 分（满分 100）。但搜遍应用商店，所有备考 App 都在做同一件事——把题目从大纲搬进 App。没有一个能帮你练面试。这就是我做这个产品的契机：用 TRAE 做一个真正的"AI 备考教练"，而不是另一个题库。

**想解决的问题：**
- 科目庞杂无从下手：4 科笔试 + 1 科面试，不知从哪开始复习
- 分值权重不清：不清楚哪些章节是重点，时间分配全靠感觉
- 在职考生时间碎片化：白天上班晚上带娃，需要科学规划碎片时间
- 面试训练完全缺失：现有 App 没有面试功能，考生到考场上第一次开口讲

**为什么做这个方向：**
选题时对比了 5 个方向（资讯管理、消费降级、职业考试、旅行规划、停车场监控），最终选导游证考试有三个原因：
1. 数据可得性强——考试大纲、历年真题都是公开数据，不需要对接封闭 API
2. 痛点足够真实——每年数十万考生，面试训练是硬伤
3. AI 能力展示充分——智能规划、错题诊断、面试模拟，每个环节都能体现 TRAE 的价值

## 4. TRAE 实践过程

### 开发流程概览

整个 Demo 使用 TRAE Work 开发，全程 AI 辅助编码，分为三个阶段：

**阶段一：知识图谱与题库数据搭建**

向 TRAE 描述了导游证考试的大纲结构，AI 生成了完整的知识图谱数据文件，包含四科 33 个章节、150+ 知识点、29 个高频考点，以及面试评分标准。随后用类似方式生成了 221 道真题题库，覆盖单选、多选、判断三种题型。

> 建议配图：TRAE Work 中生成知识图谱数据的对话截图

**阶段二：核心应用逻辑开发**

将产品拆分为 7 个模块（数据管理、学习规划、刷题引擎、错题分析、面试模拟、学习分析、工具函数），逐一让 TRAE 生成实现代码。AI 理解了上下文，生成的代码结构清晰、可直接运行。

> 建议配图：TRAE Work 中生成 app.js 核心逻辑的对话截图

**阶段三：界面开发与联调**

向 TRAE 描述了 6 个页面的设计需求（首页仪表盘、学习规划、刷题、错题本、面试模拟、学习分析），AI 生成了完整的 HTML + CSS + JS 单页应用。测试中发现外部 JS 文件未加载，通过一次对话修复了 script 标签引用问题。

> 建议配图：TRAE Work 中生成 HTML 界面 + 浏览器测试截图
