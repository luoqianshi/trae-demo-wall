Core Features

它能做什么

从语音到视觉，从硬件到桌面，把几个独立的东西串成一套能用的桌面宠物。

语音对话

对着 ESP32 设备说话，它在设备上收音和放音；语音识别 FunASR 和 Live2D 形象渲染在 PC 上跑；大模型对话和语音合成走云端 API。两边通过 WiFi 实时同步，整套流程跑下来延迟可控。

ESP32 麦克风 → PC FunASR 识别 → 云端 DeepSeek/GLM 回复 → 云端 Qwen TTS 合成 → ESP32 扬声器播放

看图说话

调用 GLM-4V 做图像理解，能识别桌上的物品、描述当前画面，也可以分析你截下来的屏幕内容。

截图或拍照 → GLM-4V 视觉理解 → 输出场景/物品描述

Live2D 形象

通过 VTube Studio 驱动 Live2D 模型。说话的时候嘴型会跟着动，表情也会根据内容自动切换，看起来不那么冷冰冰。

TTS 音频流 → 嘴型同步 → Live2D 渲染输出

ESP32 小屏幕

微雪 ESP32-S3-RLCD-4.2 单色屏，分辨率 400x300。用来显示时间、天气、当前说话的文字，也能同步 VTS 的画面。

RenderEngine → 显示预设 → 4.2 寸单色 LCD

QQ 机器人

通过 NapNeko 框架接入 QQ，支持文字和语音消息。人在外面也能发消息给桌宠，它会走同一套处理链路回复你。

QQ 消息 → NapNeko 框架 → AstrBot 处理 → 文字/语音回复

日常助手

定时提醒、长期记忆、天气查询、工作区 Agent 模式。目的不是堆功能，而是让它真有点用。

定时任务 → 记忆检索 → Agent 工作区 → 主动提醒

Development Journey

开发过程

用 TRAE IDE 辅助完成，从搭架子到调细节，分了六个阶段。

STEP 01

项目初始化与架构设计

先用 TRAE IDE 搭好项目结构，把 ESP32固件、AstrBot插件、VTS渲染 三层拆开，定下各自负责的边界。

STEP 02

ESP32 固件开发

基于 ESP-IDF v6.0.2 和 ESP-SR AFE 做全双工音频，接入 ES8311/ES7210 驱动，先把硬件上的声音通路跑通。

STEP 03

WebSocket 协议设计

自定义 7字节帧头 协议，加上优先级队列，让语音流、显示指令、控制信号能同时传且不互相堵住。

STEP 04

音频管道优化

用 Opus 编码 压带宽，批量打包再加后台定速推流，把端到端延迟降下来，让对话更顺畅。

STEP 05

VTS 窗口捕获

通过 Windows PrintWindow API 结合 DWM 合成捕获 VTube Studio 画面，再推送到 ESP32 的屏幕上同步显示。

STEP 06

显示系统完善

写了 RenderEngine 渲染引擎和预设系统，让天气、时间、TTS 文字、VTS 画面能按场景自动切换。
