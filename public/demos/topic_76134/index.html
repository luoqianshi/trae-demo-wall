数字遗产保险箱

让一个人的数字世界在身后不会变成黑箱，也不会变成隐私灾难

01 创意概述

创意名称

数字遗产保险箱（对外可称「家庭数字资产整理箱」，弱化"遗嘱"概念）

想解决什么问题

当一个人去世后，他的数字世界往往变成黑箱——子女不知道银行账号、保险在哪，找不到云盘里的家庭照片，解不开手机和电脑，甚至连微信、支付宝密码都是谜。中华遗嘱库2024年接收涉及虚拟财产的遗嘱458份，同比增长217%，数字遗产继承已成为真实且快速增长的社会需求。

灵感来源

身边有长辈突然离世，家人花了几个月才找回他的支付宝密码和退休金账户。数字时代，人走了，但数字资产不会自动消失——它们变成了家人无法触及的"黑箱"。

产品形态

一个面向家庭的 Web 端数字遗产管理平台，支持拍照识别录入资产、多角色授权、多重触发验证和分层执行。

02 目标用户及痛点

核心用户群体（按优先级排序）

  • 第一优先级：中老年家庭 — 解决"老人突然去世，子女不知道钱在哪、账号在哪"，实际操作者通常是子女，老人确认意愿。
  • 第二优先级：小企业主 / 自媒体主 — 域名、公众号、店铺一旦出事，业务直接停摆，需要业务连续性保障。
  • 第三优先级：高净值 / 加密资产人群 — 最怕密钥丢失、平台不认、继承人不会操作。

使用场景

  • 换手机、搬家时顺便把数字资产理一理
  • 配合纸质遗嘱，提前理清数字资产清单
  • 企业主做风险预案，确保意外时业务可交接

当前痛点

痛点 具体表现
找不着 子女不知道老人有哪些账号、密码是什么
解不开 手机、电脑、硬盘有重要数据，但没人知道解锁方式
办不了 平台注销/继承流程复杂，需要跑多个线下柜台
隐私泄露 去世后聊天记录、浏览历史等隐私被家人随意翻看
密钥丢失 加密钱包、域名管理密钥一旦丢失，资产永久无法找回

03 产品核心设计（四层架构）

第一层：资产清单

记录用户拥有的各类数字资产，默认不暴露密码，只记录"有什么、在哪、联系人是谁"。

支持资产类型：金融类（银行、保险、证券、支付宝）、账号类（云盘、邮箱、域名、公众号）、硬件类（手机、电脑、NAS）、其他（加密货币钱包等）。

录入方式：拍照识别 + AI自动提取关键信息（如拍一张保险单，AI自动识别保险公司、保单号、客服电话）。

第二层：生前授权

用户指定谁能看什么，实现精细化权限管理：

  • 儿子：只能查看财产类资产线索
  • 配偶：能查看医疗和保险信息
  • 指定联系人：某些聊天记录永不开放
  • 隐私设置：某些照片/视频去世后自动删除

意愿确认机制：子女代录后，老人需使用独立的「确认密码」进行确认，确保内容真实反映老人意愿。

第三层：多重触发机制

不依赖单一"长期不登录"，采用多重验证避免误触发：

验证层级 说明
定期确认 系统定期向用户发送确认提醒
紧急联系人确认 指定联系人发起触发申请
死亡证明 由指定联系人（如长子）上传死亡证明
多人联合确认 多位指定联系人共同确认
公证/遗嘱执行人 （预留）接入正式法律程序

流程：指定联系人上传证明 → 其他指定联系人逐一确认 → 达到确认人数后触发执行。

第四层：分层执行

触发后，系统按用户生前设定的规则执行：

资产类型 执行方式
财产类 给继承人"办理指引 + 资产线索 + 平台申请材料模板"，而非直接给密码
隐私类 按用户生前安排封存、删除或部分开放
密钥类 多人同时在线确认后才展示（比赛原型演示方案）
平台类 生成标准化申请材料，引导继承人走正规继承流程

04 价值与意义

社会价值

填补数字时代"遗产继承"的社会服务空白。目前法律和技术层面都几乎空白，这个产品不是教老人用手机，而是帮他们规划"用手机留下的一切"。未来很可能是"遗嘱 + 公证 + 保险 + 家庭数字管家"的交叉入口。

家庭价值

  • 减少子女在老人离世后的信息混乱和重复跑腿
  • 把"翻箱倒柜找密码"变成"一份清晰清单一键交接"
  • 避免因账号丢失造成的财产损失和家庭纠纷
  • 保护逝者隐私，避免聊天记录等敏感信息被随意翻看

最有价值的切口：不是"自动发密码"，而是让一个人死后，他的数字世界不会变成黑箱，也不会变成隐私灾难。

05 可行性验证结论

通过两轮产品策划问答，已验证以下核心问题：

触发安全

多人 + 死亡证明共同触发，系统不主动判断

密码安全

加密存储，原型简化为多人同时在线确认

平台认可

只做材料整理和指引，不承诺平台100%认可

用户心理

对外称"整理箱"而非"遗嘱"，降低心理门槛

录入体验

拍照识别 + AI自动提取，降低录入门槛

意愿真实性

老人独立确认密码，子女代录需老人确认

06 产品逻辑链

老人/子女拍照录入资产
↓
AI自动提取关键信息
↓
老人用「确认密码」确认内容
↓
生前：随时可修改资产清单和分配规则
↓
触发：指定联系人上传证明 + 多人同时确认
↓
执行：按生前规则展示内容
（财产给线索、隐私封存、需多人确认才展示）

结论：从录入 → 确认 → 触发 → 执行，逻辑自洽，没有明显死胡同。

07 原型演示方案（比赛建议）

核心演示流程（5-8分钟）

1
开场（1分钟） 讲述一个真实痛点故事（长辈离世后找不到账号）
2
资产录入（2分钟） 演示拍照识别保险单/银行卡，AI自动提取信息
3
权限设置（1分钟） 展示"谁能看什么"的授权界面
4
老人确认（1分钟） 演示老人输入确认密码，锁定意愿
5
触发执行（2分钟） 模拟"上传证明 → 多人确认 → 内容释放"的完整流程
6
结尾（1分钟） 强调社会价值——让数字世界不会变成黑箱

技术实现建议（基于TRAE）

  • 前端：React/Vue Web应用，大字体、简洁流程，适配手机端
  • AI能力：调用多模态模型API识别图片文字；自然语言处理辅助生成申请材料模板
  • 数据存储：本地加密存储 + 云端备份（比赛原型可用模拟数据）
  • 安全机制：原型阶段用"多人确认计数"模拟分片解锁逻辑

08 后续优化方向

  1. 冷静期机制：触发后增加48小时延时生效窗口，给用户留反悔/申诉时间
  2. 老人密码找回：为"确认密码"设置备用找回方式（如备用邮箱、子女协助重置）
  3. 硬件资产估值：结合装机背景，为旧电脑、手机等设备提供二手估值参考
  4. 公证处合作：预留接口，未来可对接遗嘱库、公证处等正式机构
