# 知识库重构架构设计

> 创建时间：2026-07-06
> 目标：基于 Neo4j 图数据库，重构知识入库流程，实现事件因果链、人物画像、案例关联

## 一、信息类型体系

### 1.1 六种信息类型

| 类型 | 定义 | 特点 | 存储方式 | 检索方式 |
|------|------|------|---------|---------|
| **事件** | 发生在特定时间的行动 | WHO+WHEN+WHAT+因果链 | Neo4j 节点 | 图遍历 |
| **实体** | 人/组织/产品/地点 | 可命名、可关联 | Neo4j 节点 | 图遍历 |
| **观点** | 某人的看法/判断 | WHO+观点内容+置信度 | PostgreSQL + Neo4j 关系 | 过滤+语义 |
| **案例** | 完整实践记录 | 场景+做法+结果+经验 | PostgreSQL + Neo4j 关系 | 过滤+语义 |
| **思维模型** | 思考框架（SWOT等） | 单次调用工具 | PostgreSQL（Function Calling） | 路由匹配 |
| **描述性知识** | 背景信息/定义 | 自然语言文本 | PostgreSQL + 向量 | 语义检索 |

## 二、Neo4j 图结构设计

### 2.1 节点类型

#### Entity（实体节点）

```cypher
CREATE (e:Entity {
    id: 'ent_001',
    name: '马斯克',
    type: '人物',              // 人物/组织/产品/地点/概念
    aliases: ['马斯克', 'Elon Musk', '马一龙'],
    description: '特斯拉CEO，出生于南非...',
    facts: [                   // 关于该实体的事实（JSON数组）
        {'fact': '出生于南非', 'source': '维基百科'},
        {'fact': '净资产超2000亿美元', 'as_of': '2024-01'}
    ],
    kb_id: 'kb_xxx',
    create_time: '2026-07-06'
})
```

#### Event（事件节点）

```cypher
CREATE (e:Event {
    id: 'evt_001',
    action: '收购',            // 动作类型
    result: '成为最大股东',
    event_time: '2022-04-25',
    assertion_time: '2022-04-25',
    event_type: '商业行为',     // 收购/发布/合作/因果/观点/数据
    
    // 附属物（用户强调的）
    artifacts: [
        {'type': '文件', 'name': '收购协议', 'url': '...'},
        {'type': '数据', 'name': '交易金额440亿美元'},
        {'type': '媒体', 'name': '发布会视频', 'url': '...'}
    ],
    
    // 证据/支撑
    evidence: [
        {'type': '原文', 'content': '据CNN报道...'},
        {'type': '数据', 'content': 'Twitter市值...'}
    ],
    
    kb_id: 'kb_xxx',
    doc_id: 'doc_xxx',
    source_text: '原文片段...',
    confidence: 0.95,
    create_time: '2026-07-06'
})
```

#### Concept（概念节点）

```cypher
CREATE (c:Concept {
    id: 'con_001',
    name: '私域打法',
    type: '方法论',
    description: '通过私域流量...',
    version: 'V2.0',
    kb_id: 'kb_xxx'
})
```

### 2.2 关系类型（深化版）

#### 2.2.1 实体-实体关系（Entity → Entity）

| 关系类型 | 含义 | 属性 | 示例 |
|---------|------|------|------|
| **RELATED_TO** | 通用关联 | relation_type, context | 马斯克 RELATED_TO 特斯拉（创始人） |
| **COLLABORATED_WITH** | 合作关系 | time_range, context | 马斯克 COLLABORATED_WITH 特斯拉工程师 |
| **COMPETES_WITH** | 竞争关系 | domain, intensity | 特斯拉 COMPETES_WITH 比亚迪（电动车领域） |
| **INVESTED_IN** | 投资关系 | amount, time | 马斯克 INVESTED_IN SpaceX |
| **ACQUIRED** | 收购关系 | amount, time | 马斯克 ACQUIRED Twitter |
| **EMPLOYED_BY** | 雇佣关系 | position, time_range | 马斯克 EMPLOYED_BY 特斯拉（CEO） |
| **FAMILY_OF** | 家庭关系 | relation_type | 马斯克 FAMILY_OF 某亲戚 |
| **MENTORED_BY** | 导师关系 | time_range | 某人 MENTORED_BY 马斯克 |
| **OPPOSES** | 对立关系 | domain, reason | 马斯克 OPPOSES 某观点持者 |
| **ENDORSES** | 支持/背书 | time, context | 某人 ENDORSES 马斯克的观点 |

#### 2.2.2 实体-事件关系（Entity → Event）

| 关系类型 | 角色 | 属性 | 示例 |
|---------|------|------|------|
| **INITIATED** | 发起者/主体 | context | 马斯克 INITIATED 收购事件 |
| **TARGETED** | 被影响对象 | context | Twitter TARGETED 收购事件 |
| **PARTICIPATED** | 参与者 | role, context | 投资银行 PARTICIPATED 收购事件 |
| **AFFECTED_BY** | 受影响者 | impact_type, degree | Twitter员工 AFFECTED_BY 裁员事件 |
| **WITNESSED** | 见证者 | context | 某记者 WITNESSED 收购事件 |
| **BENEFITED_FROM** | 受益者 | benefit_type | 股东 BENEFITED_FROM 股价上涨事件 |
| **OPPOSED_EVENT** | 反对者 | reason | 广告商 OPPOSED_EVENT 改名事件 |
| **REPORTED** | 报道者 | platform, time | 某媒体 REPORTED 收购事件 |

#### 2.2.3 事件-事件关系（Event → Event）

| 关系类型 | 含义 | 属性 | 示例 |
|---------|------|------|------|
| **CAUSED** | 直接因果 | confidence, mechanism | 收购 CAUSED 改名 |
| **ENABLED** | 条件/前提 | condition | 融资成功 ENABLED 产品发布 |
| **TRIGGERED** | 触发/诱发 | trigger_type | 某言论 TRIGGERED 争议事件 |
| **PREVENTED** | 阻止/阻碍 | reason | 监管 PREVENTED 某收购 |
| **RESPONSE_TO** | 回应/应对 | response_type | 裁员声明 RESPONSE_TO 裁员事件 |
| **CONCURRENT** | 同时发生 | time_overlap | 产品发布 CONCURRENT 融资事件 |
| **FOLLOWED** | 时间先后（非因果） | time_gap | 改名 FOLLOWED 收购 |
| **CONTRASTS** | 对比/反差 | contrast_type | 某成功案例 CONTRASTS 某失败案例 |
| **SIMILAR_TO** | 相似/类比 | similarity_type | 某收购 SIMILAR_TO 另一收购 |
| **PART_OF_SEQUENCE** | 属于序列 | sequence_name, position | 某事件 PART_OF_SEQUENCE 产品开发流程 |

#### 2.2.4 事件-附属物关系（Event → Artifact）

| 关系类型 | 含义 | 属性 | 示例 |
|---------|------|------|------|
| **PRODUCED** | 产出物 | artifact_type, importance | 收购事件 PRODUCED 收购协议文件 |
| **GENERATED_DATA** | 产生数据 | data_type, value | 裁员事件 GENERATED_DATA 剩余员工数 |
| **CREATED_MEDIA** | 产生媒体 | media_type, url | 发布会 CREATED_MEDIA 演讲视频 |
| **RESULTED_IN** | 结果 | result_type | 改名事件 RESULTED_IN 新品牌X |

#### 2.2.5 观点-实体/事件关系

| 关系类型 | 起点 | 终点 | 属性 | 示例 |
|---------|------|------|------|------|
| **EXPRESSED_BY** | Viewpoint | Entity | - | 某观点 EXPRESSED_BY 马斯克 |
| **SUPPORTS** | Viewpoint | Event/Entity | strength | 某观点 SUPPORTS 收购决策 |
| **OPPOSES** | Viewpoint | Event/Entity | reason | 某观点 OPPOSES 裁员事件 |
| **PREDICTS** | Viewpoint | Event（未来） | confidence | 某观点 PREDICTS 未来事件 |
| **ABOUT_TOPIC** | Viewpoint | Concept | - | 某观点 ABOUT_TOPIC 私域流量 |

#### 2.2.6 案例-事件/实体关系

| 关系类型 | 起点 | 终点 | 属性 | 示例 |
|---------|------|------|------|------|
| **INCLUDES_EVENT** | Case | Event | significance | 某案例 INCLUDES_EVENT 收购事件 |
| **INVOLVES_ENTITY** | Case | Entity | role_in_case | 某案例 INVOLVES_ENTITY 马斯克 |
| **BENCHMARKS** | Case | Case | benchmark_type | 某案例 BENCHMARKS 行业标杆案例 |
| **LEARNS_FROM** | Case | Case | lesson_type | 某案例 LEARNS_FROM 失败案例 |

### 2.3 关系创建示例

#### 2.3.1 完整的收购案例

```cypher
// ===== 创建实体节点 =====
CREATE (musk:Entity {
    id: 'ent_001',
    name: '马斯克',
    type: '人物',
    aliases: ['马斯克', 'Elon Musk', '马一龙']
})
CREATE (twitter:Entity {
    id: 'ent_002', 
    name: 'Twitter',
    type: '组织',
    aliases: ['Twitter', 'X', '推特']
})
CREATE (advertiser:Entity {
    id: 'ent_003',
    name: '广告商',
    type: '组织'
})
CREATE (employee:Entity {
    id: 'ent_004',
    name: 'Twitter员工',
    type: '群体'
})

// ===== 创建事件节点 =====
CREATE (evt_acquire:Event {
    id: 'evt_001',
    action: '收购',
    result: '成为最大股东',
    event_time: '2022-04-25',
    event_type: '商业行为',
    artifacts: [
        {'type': '数据', 'name': '交易金额', 'value': '440亿美元'},
        {'type': '文件', 'name': '收购协议'}
    ],
    confidence: 0.95
})
CREATE (evt_rename:Event {
    id: 'evt_002',
    action: '改名',
    result: '更名为X',
    event_time: '2023-07',
    event_type: '品牌行为'
})
CREATE (evt_layoff:Event {
    id: 'evt_003',
    action: '裁员',
    result: '裁掉50%员工',
    event_time: '2022-11',
    event_type: '人事变动'
})
CREATE (evt_exodus:Event {
    id: 'evt_004',
    action: '出走',
    result: '收入大幅下降',
    event_time: '2023-Q1',
    event_type: '商业影响'
})

// ===== 实体-事件关系（带角色） =====
// 收购事件
CREATE (musk)-[:INITIATED {context: '出资440亿美元'}]->(evt_acquire)
CREATE (twitter)-[:TARGETED]->(evt_acquire)
CREATE (bank:Entity {name: '投资银行'})-[:PARTICIPATED {role: '财务顾问'}]->(evt_acquire)

// 改名事件
CREATE (musk)-[:INITIATED]->(evt_rename)
CREATE (twitter)-[:TARGETED]->(evt_rename)

// 裁员事件
CREATE (musk)-[:INITIATED]->(evt_layoff)
CREATE (employee)-[:AFFECTED_BY {impact: '失业', degree: 'high'}]->(evt_layoff)

// 广告商出走事件
CREATE (advertiser)-[:INITIATED {reason: '不认同新政策'}]->(evt_exodus)
CREATE (twitter)-[:AFFECTED_BY {impact: '收入下降'}]->(evt_exodus)

// ===== 事件-事件关系（因果链） =====
CREATE (evt_acquire)-[:CAUSED {mechanism: '所有权变更触发品牌重塑'}]->(evt_rename)
CREATE (evt_acquire)-[:CAUSED {mechanism: '成本削减'}]->(evt_layoff)
CREATE (evt_layoff)-[:TRIGGERED {trigger_type: '服务能力下降'}]->(evt_exodus)
CREATE (evt_rename)-[:CONCURRENT]->(evt_layoff)

// ===== 实体-实体关系 =====
CREATE (musk)-[:ACQUIRED {amount: '440亿美元', time: '2022-04-25'}]->(twitter)
CREATE (musk)-[:EMPLOYED_BY {position: 'CEO', time_range: '2022-至今'}]->(twitter)
CREATE (advertiser)-[:OPPOSES_EVENT {reason: '不认同新政策'}]->(evt_rename)

// ===== 创建观点节点（关联到实体） =====
CREATE (vp_001:Viewpoint {
    id: 'vp_001',
    content: '马斯克裁员是对的，Twitter之前效率太低',
    claim_type: 'opinion',
    confidence: 0.8,
    assertion_time: '2024'
})
CREATE (vp_001)-[:EXPRESSED_BY]->(musk)
CREATE (vp_001)-[:SUPPORTS {strength: 'strong'}]->(evt_layoff)

CREATE (vp_002:Viewpoint {
    id: 'vp_002',
    content: '裁员导致广告商出走，得不偿失',
    claim_type: 'opinion',
    confidence: 0.75
})
CREATE (vp_002)-[:EXPRESSED_BY]->(advertiser)
CREATE (vp_002)-[:OPPOSES {reason: '损害商业利益'}]->(evt_layoff)

// ===== 创建案例节点 =====
CREATE (case_001:Case {
    id: 'case_001',
    name: 'Twitter收购案例',
    industry: '社交媒体',
    scenario: '企业收购',
    experience: '收购后要平衡效率和文化'
})
CREATE (evt_acquire)-[:PART_OF_SEQUENCE {position: 1}]->(case_001)
CREATE (evt_rename)-[:PART_OF_SEQUENCE {position: 2}]->(case_001)
CREATE (evt_layoff)-[:PART_OF_SEQUENCE {position: 3}]->(case_001)
CREATE (evt_exodus)-[:PART_OF_SEQUENCE {position: 4}]->(case_001)
```

#### 2.3.2 关系查询示例

```cypher
// ===== 查询1：马斯克发起的所有事件（含角色） =====
MATCH (e:Entity {name: '马斯克'})-[r:INITIATED|PARTICIPATED|AFFECTED_BY]->(evt:Event)
RETURN 
    type(r) as 关系类型,
    evt.action as 事件,
    evt.event_time as 时间,
    evt.result as 结果,
    r.context as 上下文
ORDER BY evt.event_time DESC

// ===== 查询2：完整因果链（递归） =====
MATCH path = (start:Event {action: '收购'})-[:CAUSED|TRIGGERED|ENABLED*1..5]->(end:Event)
RETURN 
    [node in nodes(path) | node.action] as 因果链,
    [rel in relationships(path) | rel.mechanism] as 机制,
    length(path) as 深度

// ===== 查询3：某事件的所有利益相关方（按影响程度） =====
MATCH (evt:Event {id: 'evt_003'})<-[r]-(e:Entity)
RETURN 
    e.name as 实体,
    type(r) as 关系类型,
    r.degree as 影响程度,
    r.impact as 影响类型
ORDER BY r.degree DESC

// ===== 查询4：围绕某事件的观点冲突（罗生门） =====
MATCH (vp1:Viewpoint)-[:SUPPORTS]->(evt:Event)<-[:OPPOSES]-(vp2:Viewpoint)
WHERE evt.id = 'evt_003'
RETURN 
    vp1.content as 支持观点,
    vp2.content as 反对观点,
    vp1.confidence as 支持置信度,
    vp2.confidence as 反对置信度

// ===== 查询5：两个实体之间的所有关系路径 =====
MATCH path = (e1:Entity {name: '马斯克'})-[*1..4]-(e2:Entity {name: '广告商'})
RETURN 
    [node in nodes(path) | labels(node)[0] + ':' + coalesce(node.name, node.action)] as 路径,
    [rel in relationships(path) | type(rel)] as 关系链

// ===== 查询6：某案例的完整事件序列 =====
MATCH (c:Case {id: 'case_001'})<-[r:PART_OF_SEQUENCE]-(evt:Event)
RETURN 
    evt.action as 事件,
    evt.event_time as 时间,
    r.position as 序号
ORDER BY r.position

// ===== 查询7：实体关系网络（社交网络分析） =====
MATCH (e1:Entity)-[r]-(e2:Entity)
WHERE e1.type = '人物' AND e2.type = '组织'
RETURN 
    e1.name as 人物,
    type(r) as 关系,
    e2.name as 组织,
    r.time_range as 时间范围

// ===== 查询8：某时间点前后的所有事件（时序分析） =====
MATCH (evt:Event)
WHERE evt.event_time >= '2023-01-01' AND evt.event_time <= '2023-12-31'
OPTIONAL MATCH (evt)-[:FOLLOWED]->(next:Event)
OPTIONAL MATCH (prev:Event)-[:FOLLOWED]->(evt)
RETURN 
    evt.action as 事件,
    evt.event_time as 时间,
    prev.action as 前置事件,
    next.action as 后续事件
ORDER BY evt.event_time
```

### 2.5 关系强度与置信度

每条关系都应携带置信度属性，用于表示该关系的可靠性：

```cypher
// 高置信度关系（事实）
CREATE (musk)-[:ACQUIRED {amount: '440亿美元', confidence: 0.95}]->(twitter)

// 中置信度关系（推断）
CREATE (evt1)-[:TRIGGERED {trigger_type: '推测', confidence: 0.7}]->(evt2)

// 低置信度关系（猜测）
CREATE (e1)-[:RELATED_TO {relation_type: '可能相关', confidence: 0.4}]->(e2)
```

检索时可以过滤低置信度关系：

```cypher
MATCH path = (start:Event)-[r*1..5]->(end:Event)
WHERE ALL(rel IN r WHERE rel.confidence >= 0.7)
RETURN path
```

### 4.2 信息类型分类器

```java
@Component
public class ContentTypeClassifier {
    
    private static final String CLASSIFY_PROMPT = """
        分析以下文档，判断其主要包含的信息类型。
        
        文档内容：
        {{DOCUMENT_CONTENT}}
        
        信息类型定义：
        1. 事件密集型：大量人物-动作-对象-时间的记录（如新闻、行业动态）
        2. 观点密集型：大量个人看法、判断、预测（如访谈、评论文章）
        3. 案例型：完整的实践记录，有背景-做法-结果-经验（如案例分析、复盘文章）
        4. 方法论型：可抽象为步骤的方法论（如教程、SOP）
        5. 描述型：背景介绍、概念定义（如百科、产品介绍）
        
        请输出 JSON：
        {
            "primary_type": "事件密集型/观点密集型/案例型/方法论型/描述型",
            "secondary_types": ["可能还包含的其他类型"],
            "confidence": 0.0-1.0,
            "reason": "判断依据"
        }
        """;
    
    public ContentClassification classify(String rawText, String modelConfigId) {
        // LLM 分类
        JSONObject result = llmClient.chat(CLASSIFY_PROMPT, rawText, modelConfigId);
        return new ContentClassification(
            result.getStr("primary_type"),
            result.getJSONArray("secondary_types"),
            result.getDouble("confidence")
        );
    }
}
```

### 5.1 案例：抖音视频入库（某博主分析马斯克）

```

裁员能让公司更精简。但是很多广告商不认同，纷纷出走，
导致Twitter收入大幅下降。这给我们一个启示：收购一家

```

```

├─ EntityExtractor.extract()

│   CREATE (musk:Entity {name: '马斯克', type: '人物'})

│   Event 1: 收购Twitter
```

### 5.2 查询示例

**查询：马斯克收购Twitter后发生了什么？**

```cypher
// Neo4j 查询因果链
MATCH path = (start:Event {action: '收购'})-[:CAUSED*1..5]->(end:Event)
WHERE (e:Entity {name: '马斯克'})-[:INVOLVED_IN {role: 'subject'}]->(start)
RETURN 
    start.action as 事件1,
    start.event_time as 时间,
    [node in nodes(path) | node.action] as 因果链,
    [node in nodes(path) | node.result] as 结果链
```

**结果：**
```
事件1: 收购
时间: 2022
因果链: ['收购', '改名', '裁员', '出走']
结果链: ['成为最大股东', '更名为X', '裁掉50%员工', '收入下降']
```

**查询：马斯克的完整画像**

```cypher
// Neo4j 获取事件
MATCH (musk:Entity {name: '马斯克'})-[r:INVOLVED_IN]->(evt:Event)
RETURN collect({action: evt.action, time: evt.event_time, role: r.role}) as events

FROM viewpoints
WHERE entity_id = '马斯克的ID';
```

