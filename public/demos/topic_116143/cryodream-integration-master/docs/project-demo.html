核心理念

为什么是「一人公司 OPC」？

传统 AI 应用平台（Dify / Coze / FastGPT）面向团队与外部用户，解决「规模化服务」问题； 本项目面向 单人长期运营，解决「专注、执行、目标沉淀」问题——它是一个操作系统，不是工具集合。

传统 SaaS 思路 工具视角

  • 以「应用 / Bot」为中心，发布给外部用户消费
  • 云端多租户，数据归属平台，迁移成本高
  • 知识库只是「分块 + 向量」，无结构化沉淀
  • 功能边界由平台定义，无法本地化深度定制
  • 无项目隔离，所有应用共享同一上下文
  • 面向「会话」，不面向「长期目标」

OPC 平台思路 操作系统视角

  • 以「项目 + 工作流」为中心，服务于个人长周期任务
  • 桌面端本地运行，数据落在自有 PostgreSQL / 文件系统
  • 知识库五维结构化（实体/事件/案例/观点/思维模型）
  • 节点式画布可自由编排，所有 AI 能力皆工作流化
  • FlowProject 实现项目级数据隔离与上下文切换
  • 面向「目标沉淀」，可追溯、可复用、可演化

总结

Cryodream 到底要解决什么

一句话：让一个人，也能像一家公司一样长期运营自己的能力与知识资产。 不是又一个 AI 工具，是个人操作系统。

★核心目的

市面上的 AI 平台都在抢「企业服务」赛道——帮团队把 LLM 包装成 App、卖 API、做 SaaS。 但有一群人被忽略了：独立开发者、一人公司创业者、长期主义的知识工作者。 他们不需要把 AI 卖给别人，他们需要 AI 帮自己把一个人活成一家公司。

Cryodream 就是给这群人做的。它解决三个问题：

  • 专注——FlowProject 让一个人也能像团队一样按项目切上下文，知识库、工作流、画布全部隔离。不再信息过载。
  • 执行——所有 AI 能力统一为节点式工作流，30+ 节点自由编排。新能力 = 新模板 + 新节点，无需改业务代码。
  • 目标——事件 / 案例 / 观点 / 思维模型四维结构化沉淀，让个人知识资产可追溯、可复用、可演化。目标不丢。

①架构核心思路

「工作流即能力」——所有 AI 功能不再以「应用」形态离散存在， 而是统一抽象为 FlowGraphExecutor 调度下的节点图。每一种 AI 能力 （歌词改写、知识入库、抖音解析、日记分析…）都对应一个 tpl-* 模板与一组节点链。

这种设计让平台具有「能力可演化」的特性：新能力 = 新模板 + 新节点执行器， 不需要改业务层代码，前端只需在 nodeTemplates.ts 注册 UI 元数据， 后端加一个 @Component 实现即可。

②双画布哲学

LLM 画布（features/flow/）处理文本/知识/结构化提取； ComfyUI 画布（features/comfyui/）处理图像/视频生成。 两者通过 ScilWorkflow 节点桥接，让 LLM 工作流的输出可触发 ComfyUI 执行。

这意味着平台可以编排「LLM 抽取案例 → 生成配图 → 输出知识卡片」这类跨模态工作流， 而不是把图像生成隔离成独立子系统。

③知识四维体系

知识库不再是「分块 + 向量」的扁平存储，而是按认知层级结构化为四类：

  • 实体：人/公司/产品/概念，跨模块聚合锚点
  • 事件：带时间维度 + 实体动作 + 影响推断
  • 案例：context → problem → solution → outcome 完整结构
  • 观点：含利益相关 + 逻辑严密性 + 失效触发条件

前 3 类采用「专属表 + 向量双写」，支持结构化查询 + 语义检索双通道；思维模型不入 RAG 分块，作为 Agent 可调用工具存在。

④图驱动 + 兜底硬编码

KnowledgeBaseIngestionService 优先加载 tpl-* 模板整图执行； 若图执行失败，自动回退到硬编码流水线兜底。

这种「双保险」设计让平台既保持工作流的可视化可编辑性， 又具备生产级别的健壮性——模板出问题不会阻断业务。

⑤与 Dify 的本质差异

Dify 解决的是「如何让团队把 LLM 包装成应用发布给用户」——它是 B2B / B2C 的工具平台， 核心度量是「应用 DAU、调用 token、API 收入」。

Cryodream 解决的是「如何让一个人像一家公司一样长期运营自己的能力与知识资产」—— 它是个人操作系统，核心度量是「专注度（项目隔离）、执行力（工作流化）、目标沉淀（四维知识）」。

因此本项目刻意不做多租户、不做应用市场、不做云端托管， 而是把资源投入到 桌面化、项目隔离、结构化知识、 版本管理、个人记录等 Dify 不会做的领域。 二者不是替代关系，而是「外部规模化」与「内部沉淀化」的互补。

⑥技术亮点速览

  • Electron sidecar 启动：自动注入 workspace.path 等工作区路径，避免静态资源加载失败
  • 三层节点数据查找（FlowNodeDataUtils.getTemplateValue）：运行时注入 > 节点静态配置 > 模板字段默认值
  • 入口节点自动推断：按 ObjectInput → ChatInput → 零入度节点优先级定位，无需用户指定起点
  • Kahn 拓扑排序 + 失败即停：节点失败时返回已执行步骤，精确定位失败点
  • 前后端节点注册对称：前端 nodeTemplates.ts + 后端 @Component + supports()，新增节点各加一处
  • 模板与用户工作流分离：workflow_template 表存系统模板，workflow 表存用户工作流，sourceTemplateId 溯源
  • 歌词双层级版本：大版本手动归档（V1.00），小版本自动生成于采纳候选（V1.01）
  • 网页提取三级降级：jsoup → Jina Reader → Scrapling 微服务
  • PGVector 复用：PostgreSQL 兼任业务库 + 向量库，无需独立向量数据库
  • Neo4j 知识图谱：原生图数据库支持实体关系可视化与时间线
