# 小说创作模块完整开发计划

> 编号：015　｜　状态：已完成（首版编码完成，待联调）　｜　创建日期：2026-07-08　｜　完成日期：2026-07-08

## 模块概述

**模块名称**：小说创作（Novel Studio）
**模块目标**：构建一个面向长篇小说作者的一体化创作工作台，覆盖「小说管理 → 大纲构建（卷/章/节三级） → 章节 Markdown 编辑 → 人物设定与关系图 → 世界观 wiki → AI 辅助（续写/润色/一致性检查）」的完整创作闭环。
**计划周期**：2026-07-08 - 2026-07-14（预估，7 天）

### 设计依据（来自需求确认）

| 决策项 | 结论 |
|--------|------|
| 模块定位 | 新增独立功能域「小说创作」，独立后端表 + 独立前端 feature |
| 存储方案 | **独立后端模块**：新建 `t_novel` / `t_novel_outline` / `t_novel_character` / `t_novel_relation` / `t_novel_setting` 五张表 |
| 首版范围 | ① 小说列表 + 章节编辑器；② 三级大纲（卷/章/节）；③ 人物设定 + 人物关系图；④ AI 辅助（续写/润色/一致性检查）；⑤ 世界观 wiki |
| 编辑器 | 复用 **Milkdown**（项目已集成，见 `features/documents/editor/milkdown-editor.tsx`） |
| 关系图形态 | **React Flow 可拖拽画布**（复用 `@xyflow/react`，节点位置可持久化） |
| 大纲交互 | 树形三级结构，支持拖拽排序，节点点击直接跳到章节编辑 |
| AI 能力 | 复用现有 `model-config` + LLM 调用链路，不新引入模型层 |
| 标签体系 | 复用通用 `features/tags` 打标（流派、情绪、角色 tag） |

```
以便写作时不用来回切换工具。
```

```
作为一名系列小说作者，
```

## 业务流程设计

### 1. 小说创建与打开

1. 进入 `/novels` 页面 → 卡片式小说列表（封面、标题、字数、更新时间）
2. 点击「新建小说」→ 弹窗填写标题、简介、流派 tag → 建 `t_novel` 记录
3. 点击卡片 → 进入 `/novels/$novelId`，默认打开「大纲」标签

### 2. 大纲构建流程（卷/章/节）

1. 大纲区域左侧显示可折叠三级树：📚 卷 → 📖 章 → 📄 节
2. 每个节点可右键：新增子级、重命名、删除、上移/下移
3. 拖拽调整顺序（更新 `sort_order`）
4. 点击叶子节点（节）→ 右侧切换为章节编辑器
5. 每个节点存字段：`title`、`summary`（一句话概要）、`level`（1/2/3）、`sort_order`、`parent_id`

### 3. 章节编辑流程

1. 复用 Milkdown 编辑器（同 documents 模块）
2. 顶部信息栏：字数统计、上次保存时间、当前节点面包屑（卷 › 章 › 节）
3. 底部操作栏：AI 续写、AI 润色、一致性检查
4. 自动保存（防抖 2s）+ 手动保存
5. 章节正文存 `t_novel_outline.content`（大纲节点即章节）

### 4. 人物设定流程

1. 进入「人物」标签 → 人物卡网格（头像/姓名/身份/标签）
2. 新建人物 → 弹窗表单：姓名、别名、身份、性格、背景、口头禅、外貌、备注
3. 人物卡可关联：出场章节（多选大纲节点）、所属组织（世界观条目）

### 5. 人物关系图流程

1. 「关系图」标签 → React Flow 画布
2. 左侧栏：未上图的人物列表，拖拽到画布形成节点
3. 节点显示头像 + 姓名 + 身份 badge
4. 连线创建关系 → 弹窗选择关系类型（父子/夫妻/师徒/敌对/挚友/上下级/自定义）
5. 节点位置、连线、关系类型持久化到 `t_novel_character.canvas_pos` 和 `t_novel_relation`
6. 支持导出为图片（后续迭代）

### 6. 世界观 wiki 流程

1. 「设定」标签 → 分类树（地点 / 组织 / 物品 / 势力 / 自定义分类）
2. 条目详情用 Milkdown 编辑，字段：名称、分类、简述、正文
3. 支持在章节编辑器中通过 `@` 引用条目（后续迭代）

### 7. AI 辅助流程

- **AI 续写**：选中段落末尾 → 弹窗填写「续写风格提示」→ 调 LLM → 插入光标处
- **AI 润色**：选中文本 → 弹窗选择润色方向（更简洁/更生动/更书面）→ 返回候选替换
- **一致性检查**：单独按钮 → 分析当前章节中的人物言行 vs 人物卡设定，输出偏差报告
- 所有 AI 调用统一通过 `/api/agent/chat` 或 `/api/llm/complete`（复用现有能力）

## 技术方案设计

### 一、后端方案（Spring Boot）

#### 1. 数据库 Schema

新建 `NovelSchemaMigration` 类，参照 [DocumentSchemaMigration.java](file:///g:/ice-project/comfyUI-draw-flow/service/src/main/java/com/ice/template/config/DocumentSchemaMigration.java)：

```sql
-- 小说主表
CREATE TABLE IF NOT EXISTS t_novel (
  id VARCHAR(64) PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  summary TEXT,
  cover_url VARCHAR(500),
  genre VARCHAR(100),          -- 流派：都市/玄幻/科幻…
  tags VARCHAR(500),           -- 逗号分隔的标签
  word_count INT DEFAULT 0,    -- 冗余：全书字数（异步刷新）
  status VARCHAR(20) DEFAULT 'writing', -- writing/paused/finished
  is_delete INT DEFAULT 0,
  create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  update_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 大纲/章节统一表（三级：卷=1 / 章=2 / 节=3）
CREATE TABLE IF NOT EXISTS t_novel_outline (
  id VARCHAR(64) PRIMARY KEY,
  novel_id VARCHAR(64) NOT NULL,
  parent_id VARCHAR(64),                -- 顶级卷为 NULL
  level TINYINT NOT NULL,               -- 1/2/3
  title VARCHAR(200) NOT NULL,
  summary VARCHAR(1000),                -- 一句话概要
  content TEXT,                         -- 正文（只有 level=3 使用）
  sort_order INT DEFAULT 0,
  word_count INT DEFAULT 0,
  is_delete INT DEFAULT 0,
  create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  update_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_novel_parent (novel_id, parent_id, sort_order)
);

-- 人物表
CREATE TABLE IF NOT EXISTS t_novel_character (
  id VARCHAR(64) PRIMARY KEY,
  novel_id VARCHAR(64) NOT NULL,
  name VARCHAR(100) NOT NULL,
  alias VARCHAR(200),
  avatar_url VARCHAR(500),
  identity VARCHAR(200),                -- 身份/职业
  personality TEXT,                     -- 性格
  background TEXT,                      -- 背景
  appearance TEXT,                      -- 外貌
  catchphrase VARCHAR(500),             -- 口头禅
  remark TEXT,
  canvas_pos VARCHAR(50),               -- 关系图位置 "x,y"
  is_delete INT DEFAULT 0,
  create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  update_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_novel (novel_id)
);

-- 人物关系表
CREATE TABLE IF NOT EXISTS t_novel_relation (
  id VARCHAR(64) PRIMARY KEY,
  novel_id VARCHAR(64) NOT NULL,
  source_id VARCHAR(64) NOT NULL,       -- 人物 A
  target_id VARCHAR(64) NOT NULL,       -- 人物 B
  relation_type VARCHAR(50) NOT NULL,   -- 父子/夫妻/师徒/敌对…
  description VARCHAR(500),
  is_delete INT DEFAULT 0,
  create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_novel_source (novel_id, source_id)
);

-- 世界观设定表
CREATE TABLE IF NOT EXISTS t_novel_setting (
  id VARCHAR(64) PRIMARY KEY,
  novel_id VARCHAR(64) NOT NULL,
  category VARCHAR(50) NOT NULL,        -- location/organization/item/faction/custom
  name VARCHAR(200) NOT NULL,
  brief VARCHAR(500),
  content TEXT,                         -- Markdown 正文
  is_delete INT DEFAULT 0,
  create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  update_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_novel_category (novel_id, category)
);
```

## 风险与决策项

| 风险 | 应对 |
|------|------|
| 长篇小说 100 章以上，前端一次拉取大纲树可能大 | 首版一次性拉取；后续按需懒加载 level=3 内容 |
| Milkdown 大文本性能（单章 3 万字+） | 单章限制 3 万字提示；超长则拆节 |
| 三级树拖拽库选型 | 优先 `@dnd-kit/core`（生态最活跃），需 review 通过后再引入 |
| AI 续写费用与延迟 | 复用现有模型配置，用户自选模型；显示 loading |
| 人物一致性检查准确率 | 首版做「有偏差就列出，交给作者判断」，不做强判定 |
