# RAG 模块一：知识入库流水线

## 模块目标

实现 V6.0 认知级 RAG 架构的「阶段一：入库流水线 (Ingestion)」，完成从原始文档到父子 Chunk 与新版 metadata jsonb 的完整入库流程。

核心特性：
- **默认工作流驱动**：知识库入库按钮默认触发系统 RAG 工作流，入库策略优先通过工作流节点、提示词和模型配置微调
- **全局元数据提取**：LLM 先阅读全文，提取 Domain/Theme/Entities/Concepts/Events
- **语义分块**：按段落逻辑切分，而非机械字数切分
- **元数据挂载**：每个 Chunk 携带新版 `metadata jsonb`，包含领域范围、本体路由、认识论标签、父子块关系和 SPO 事件
- **向量化入库**：Name+Desc 拼接后 Embedding，存入 PGVector

## 最新架构思路：工作流即入库策略

知识入库流水线不再只是一段固定后端编排代码，而是由系统默认工作流驱动的可调流水线。知识库页面的入库按钮负责提交运行时上下文，后端负责选择默认工作流模板并执行节点图。

```text
知识库入库按钮
  → 入库模式 standard / deep / auto
  → 默认工作流模板
  → 节点执行器
  → knowledge_document / knowledge_chunk / PGVector
```

这种思路下，入库质量优化的第一入口是默认工作流：

- 想换模型：调整工作流节点模型或运行时模型选择策略。
- 想改元数据质量：调整 GlobalMetadataExtractor 提示词。
- 想改分块质量：调整 IntelligentSemanticChunker 提示词、chunk_size、overlap_size。
- 想加质量检查：在工作流中插入校验节点或过滤节点。
- 想做灰度实验：复制默认工作流模板，改为实验版模板。

后端代码主要负责：

- 工作流模板解析和执行。
- 运行时上下文注入。
- 模型选择优先级。
- 任务状态回写。
- 数据落库一致性。
- LLM 失败后的结构化 JSON 修复重试、RAG 节点显式输出预算控制与规则兜底。

### 新版 metadata jsonb 结构

新版 metadata 不是旧的“简单三维背包”，而是与父子 Chunk、轻量 GraphRAG 兼容的结构。核心变化：

- `event_id` 废弃，事件改为 `events` 数组。
- `2_Ontology_Routing` 内增加 `chunk_level` 和 `parent_local_id`，用于表达 parent / child 关系。
- `entities`、`concepts`、`events` 均为当前 Chunk 级字段，优先由 LLM 对每个 child 独立抽取；fallback 时只从全局元数据中筛选能被当前 chunk_text 支撑的项，不再全量继承全文级事件。
- `knowledge_chunk.parent_id` 是落库后的真实父块 ID；`metadata.2_Ontology_Routing.parent_local_id` 是同一次 LLM 输出中的本地父块标识。

```json
{
  "1_Domain_Scope": {
    "domain": "个人成长/思维模型",
    "theme": "第一性原理思维解析与应用"
  },
  "2_Ontology_Routing": {
    "chunk_level": "child",
    "parent_local_id": "parent_0",
    "entities": [
      {"name": "埃隆·马斯克", "description": "第一性原理思维的实践者"}
    ],
    "concepts": [
      {"name": "第一性原理", "description": "从基本事实出发推导解决方案的思维方式"}
    ],
    "events": [
      {"subject": "埃隆·马斯克", "action": "应用", "object": "第一性原理", "result": "重构火箭制造成本", "event_time": "", "assertion_time": "", "event_type": "观点论证", "causal_role": "evidence", "evidence": "马斯克用第一性原理重构制造成本"}
    ]
  },
  "3_Epistemology_Tag": {
    "time_stamp": "2026-06-26",
    "claim_type": "案例分析",
    "source": "document",
    "confidence": 0.8,
    "chunk_summary": "马斯克用第一性原理重构制造成本"
  }
}
```

### 父子 Chunk 落库约定

```text
parent chunk：
  chunk_level = parent
  parent_id = null
  chunk_text = 父块摘要或父块聚合文本

child chunk：
  chunk_level = child
  parent_id = 对应 parent chunk 的真实 ID
  chunk_text = 子块原文
```

当前实现支持父子结构字段，但当 LLM 分块失败进入规则兜底时，系统可能只落 `child` 级 Chunk，此时 `parent_id` 为空；这是兜底路径的降级表现，不代表新版结构废弃。

## 技术选型

### 向量库
- **PGVector**：复用现有 PostgreSQL，零额外部署
- 需启用 pgvector 扩展：`CREATE EXTENSION IF NOT EXISTS vector;`
- HNSW 索引：`CREATE INDEX ON knowledge_chunk USING hnsw (embedding vector_cosine_ops);`

### 文档解析
- **第一阶段**：.txt / .md（纯文本，直接读取）
- **预留扩展**：pdf（Apache PDFBox 或 Tika）

### 嵌入模型
- 复用现有 `EmbeddingModelNodeExecutor`
- OpenAI 兼容协议（火山引擎、DeepSeek、Ollama 等）
- 向量维度：1536（text-embedding-ada-002）或 768（其他模型）

### LLM 元数据提取
- 复用现有 `LanguageModelNodeExecutor`
- Prompt 模板：定义「全局元数据提取」专用提示词

## 风险防御

| 风险 | 防御机制 |
| --- | --- |
| 层次爆炸 | 物理扁平化：用元数据 Tag 代替物理层级 |
| 语义坍塌 | 微型注释：实体和概念以 Name+Desc 拼接后向量化 |
| 边界毒化 | 文档级继承：先全局提取元数据，再下发给语义分块；规则兜底也必须继承全局元数据 |
| 幻觉复利 | 原始快照+溯源锚点：保留不被篡改的原文 |
| 默认模型错配 | RAG 入库运行时模型优先，自动模型选择同时支持 chat / llm 类型 |
| 提示词超载 | 普通 RAG 走轻量分块，认知级 RAG 分阶段抽取，优先通过默认工作流微调提示词 |
| 工作流配置漂移 | 入库任务应记录模板 ID、模型 ID、chunk_method，便于追踪实际执行路径 |
| 空元数据结构 | 分块器兼容新版 metadata jsonb；fallback 继承 domain/theme，并按 chunk_text 筛选 entities/concepts |
| events 全为空 | 全局元数据、Chunk metadata 和 knowledge_chunk.events 均使用事理图谱事件结构；Chunk 缺失 events 时先筛选全文事件，再按当前 chunk_text 推断，仍无证据则保持空数组 |
| Event Time 与 Assertion Time 混淆 | 事件发生时间和信息断言时间混用会污染时序图谱 | 每个 event 自带 `event_time`；`assertion_time` 仅在文本明确发布/记录/断言时间时填写；`3_Epistemology_Tag.time_stamp` 表示入库/元数据生成时间，不替代事件发生时间 |
| 旧 event_id 残留 | 代码、默认工作流模板和数据库模板均移除 event_id，占位字段改为 events 数组 |
