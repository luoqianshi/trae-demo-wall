# AI音乐模块完整开发计划

> 编号：014　｜　状态：待评审（计划阶段，尚未编码）　｜　创建日期：2026-06-26

## 模块概述

**模块名称**：AI音乐（AI Music）
**模块目标**：构建围绕「歌词创作 → 歌词版本归档 → 音乐生成」的完整 AI 音乐生产模块。歌词由工作流触发 AI 生成并展示在页面上，歌词需要独立存储；用户可划线选中歌词片段触发 AI 修改；修改后的歌词支持用户手动归档形成 V1、V2 等版本，并提供版本差异对比、不同版本颜色标识和总览视图。音乐生成阶段通过工作流阶段触发，本质上封装 ComfyUI 节点与项目现有工作流执行能力。
**计划周期**：2026-06-26 - 2026-06-30（预估）

### 设计依据（来自需求确认）

| 决策项 | 结论 |
|--------|------|
| 模块定位 | 新增独立功能域「AI音乐」，覆盖歌词生成、歌词迭代、音乐生成 |
| 歌词生成 | 通过工作流触发 AI 生成，结果展示在页面并进入独立歌词存储 |
| 歌词修改 | 支持划线选中歌词片段，基于选区触发 AI 修改歌词 |
| 版本迭代 | 用户手动点击归档触发版本升级，如 V1 → V2 |
| 版本差异 | 按行对比优先，支持查看版本区别，不同版本使用不同颜色，并提供总览 |
| 歌词编辑器 | 采用纯文本编辑，前端展示可做视觉美化与分段排版 |
| 输入参数 | 歌词生成输入参数固定为主题、曲风、情绪、语言 |
| 音乐结果 | 当前阶段只保存音频文件地址；封面、波形图、歌词时间轴后续迭代 |
| AI 修改候选 | 支持多候选方案，用户选择其中一个候选后再采纳应用 |
| 音乐生成 | 由工作流阶段触发，本质是封装 ComfyUI 节点；具体工作流由用户后续编排 |
| 代码实现 | 本计划只创建模块开发计划，不进入编码实现 |

## 用户故事

```
作为一名音乐内容创作者，
我希望输入主题、风格或提示词后，通过工作流生成歌词，
以便快速获得可继续编辑的歌词初稿。
```

```
作为一名歌词编辑者，
我希望可以划线选中某几句歌词并让 AI 定向修改，
以便只调整不满意的片段，而不是重写整首歌词。
```

```
作为一名创作负责人，
我希望在关键修改后手动归档歌词版本，
以便把 AI 修改后的多个阶段沉淀为 V1、V2、V3，并能回看每次变化。
```

```
作为一名工作流编排者，
我希望音乐生成由工作流阶段触发，
以便复用 ComfyUI 节点能力，把歌词、风格、音色等参数传入音乐生成流程。
```

## 业务流程设计

### 1. 歌词创作流程

1. 用户进入 AI音乐页面，新建音乐项目或歌词草稿
2. 用户填写固定创作输入：主题、曲风、情绪、语言
3. 前端调用工作流执行接口，将输入作为工作流参数传递
4. 后端执行歌词生成工作流，返回歌词正文与结构化元数据
5. 前端展示生成结果，并写入独立歌词存储
6. 初次保存可形成草稿态，不强制生成版本；用户点击归档后形成 V1

### 2. 划线 AI 修改流程

1. 用户在歌词编辑器中选中一段或多段歌词
2. 页面记录选区位置、原文、上下文范围和用户修改指令
3. 前端触发「歌词局部修改」工作流
4. 工作流返回多个建议替换内容，展示为候选修改列表
5. 用户选择一个候选并确认后替换选区内容，进入未归档修改态
6. 用户可继续修改多处歌词，直到手动点击归档

### 3. 版本归档流程

1. 当前歌词存在未归档修改时，页面显示「归档为新版本」
2. 用户点击归档，系统比较当前歌词与上一归档版本
3. 创建新版本号，如 V1 → V2
4. 保存版本快照、差异块、修改来源和归档说明
5. 版本总览刷新，支持查看不同版本之间的变化

### 4. 音乐生成流程

1. 用户选择歌词版本或当前草稿作为音乐生成输入
2. 用户选择音乐生成工作流与阶段参数
3. 前端将歌词、版本号、风格参数传入音乐生成工作流
4. 后端封装 ComfyUI 节点并执行阶段任务
5. 生成结果回写到音乐任务记录，包括音频地址、状态、参数、日志与错误信息
6. 页面展示生成状态、音频预览和历史记录；封面、波形图、歌词时间轴留到后续迭代

## 后端设计（service/）

### 分层结构

| 层 | 建议文件 | 说明 |
|----|----------|------|
| Controller | `AiMusicController` | 项目、歌词、版本、生成任务聚合入口 |
| Controller | `AiMusicLyricController` | 歌词生成、保存、局部修改、归档 |
| Controller | `AiMusicGenerationController` | 音乐生成任务触发与查询 |
| Service | `AiMusicProjectService` | AI音乐项目管理 |
| Service | `AiMusicLyricService` | 歌词生成、编辑、版本归档 |

### 核心接口设计

**AI音乐项目 `/ai-music/project`**
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/create` | 创建 AI音乐项目 |
| POST | `/update` | 更新项目标题、风格、说明 |
| GET | `/detail/{id}` | 项目详情，包含当前歌词与生成任务概览 |
| POST | `/list/page` | 分页查询项目列表 |
| POST | `/delete` | 删除项目 |

**歌词 `/ai-music/lyric`**
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/generate` | 通过工作流生成歌词 |
| POST | `/save` | 保存当前歌词草稿 |
| POST | `/rewrite-selection` | 对划线选区触发 AI 局部修改 |
| POST | `/apply-edit` | 采纳 AI 修改建议并更新当前歌词 |
| POST | `/archive` | 手动归档当前歌词为新版本 |
| GET | `/versions/{lyricId}` | 查询歌词版本列表 |
| POST | `/diff` | 查询两个版本的差异 |

**音乐生成 `/ai-music/generation`**
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/start` | 基于歌词版本和工作流阶段启动音乐生成 |
| GET | `/task/{taskId}` | 查询生成任务详情 |
| POST | `/tasks` | 查询项目下的生成任务历史 |
| POST | `/cancel` | 取消未完成任务（如现有工作流支持） |

### 工作流集成策略

- 歌词生成与歌词局部修改复用项目现有工作流执行链路，前端只传递工作流 ID、节点参数和上下文
- 音乐生成通过「阶段」概念封装 ComfyUI 节点，允许后续用户自行编写具体工作流
- 后端不把歌词生成逻辑写死在业务代码中，只负责参数标准化、执行调度、结果解析与落库
- 工作流返回内容需要统一解析为 `text`、`structuredJson`、`assets`、`logs` 四类结果，便于页面展示

### 4. 歌词编辑器能力

| 能力 | 说明 |
|------|------|
| 纯文本编辑 | 歌词编辑器采用纯文本编辑，保证输入和工作流参数简单稳定 |
| 美化展示 | 前端可按段落、歌词行、版本色块做视觉美化，但不改变底层纯文本存储 |
| 划线选区 | 监听用户选中的歌词范围，展示浮动工具条 |
| AI 修改 | 选区 + 修改指令触发工作流，返回多个候选替换文本 |
| 修改采纳 | 用户选择一个候选并确认后应用到当前歌词，标记为未归档 |
| 草稿保存 | 保存当前内容但不生成新版本 |
| 手动归档 | 用户点击后形成 V1 / V2 / V3 等版本 |

### 5. 版本总览与差异展示

- 版本列表按时间倒序展示 V1、V2、V3
- 每个版本分配稳定颜色，用于总览和差异块标识
- 差异视图优先按行对比，支持新增、删除、修改三类变化
- 总览视图展示每个版本的核心变化摘要、归档说明、修改来源
- 支持选择任意两个版本进行 diff，不只比较相邻版本

### 6. 音乐生成面板

- 选择歌词来源：当前草稿 / 指定版本
- 选择音乐生成工作流
- 配置固定输入参数：主题、曲风、情绪、语言
- 启动工作流执行，展示 pending / running / success / failed 状态
- 成功后展示音频预览、下载入口、生成参数快照
- 当前阶段只保存音频文件地址，封面、波形图、歌词时间轴后续迭代

## 功能边界

### 包含范围

- AI音乐项目基础管理
- 歌词独立存储
- 工作流触发 AI 歌词生成
- 歌词划线选区触发 AI 局部修改
- 修改采纳与草稿保存
- 用户手动归档形成 V1、V2 等歌词版本
- 版本差异查看、版本颜色标识、版本总览
- 音乐生成任务的工作流阶段触发与结果展示

### 不包含范围（后续迭代）

- 专业音频编辑器，如多轨混音、裁剪、母带处理
- 音频版权检测与相似度检测
- 多人协作编辑与评论批注
- 歌词自动押韵评分、旋律适配评分
- 音乐作品发布、分发、商业化授权流程

## 验收标准

1. 能创建 AI音乐项目并保存基础信息
2. 能通过工作流生成歌词，并在页面展示与落库
3. 歌词有独立存储，不依赖音乐生成任务存储
4. 用户能选中歌词片段并触发 AI 修改
5. AI 修改返回多候选方案，用户能选择其中一个候选预览、采纳，采纳后当前歌词进入未归档状态
6. 用户点击归档后能形成 V1、V2 等版本
7. 能查看任意两个版本的差异，不同版本具备不同颜色标识
8. 版本总览能展示版本列表、归档说明、变化摘要和当前版本
9. 音乐生成能选择歌词版本并通过工作流阶段触发
10. 音乐生成任务能展示状态、结果、错误信息和参数快照
11. 前端通过 lint/build，后端通过编译与关键接口测试

## 风险与注意事项

- 歌词版本不能只保存 diff，必须保存完整快照，避免历史版本因 diff 计算错误无法还原
- 划线选区需要保存字符位置与原文快照，防止 AI 返回后用户已继续编辑导致错位
- AI 修改结果建议先进入候选态，由用户确认采纳，避免自动覆盖用户内容
- 版本升级必须由用户手动归档触发，AI 修改 3 处不应自动生成 V2
