# 003-模型设置管理模块

## 模块目标

将模型配置从前端本地存储升级为前后端完整模块：模型设置页面独立存在，不挂在主侧边栏；后端提供模型配置新增、查询、修改、删除能力；工作流中的“模型”和“智能体”节点继续通过“模型配置”下拉框选择已启用模型。

## 用户要求

1. 模型设置单独写一个页面。
2. 模型设置不放在前端主侧边栏上。
3. 支持自定义模型。
4. 后端写完整新增、查询、修改、删除。
5. 使用 `dev-plan-assistant` 创建模块计划，再按计划开发。
6. 工作流 UI 仍保持中文标题、中文描述和中文字段。

## 功能边界

### 前端

- 新增独立模型设置页面：`/model-settings`。
- 移除主侧边栏中的“模型配置”入口。
- 移除设置页内部侧边栏中的“模型配置”入口。
- 模型设置页面负责：
  - 查看模型配置列表
  - 新增模型配置
  - 编辑模型配置
  - 删除模型配置
  - 启用/停用模型配置
  - 支持自定义厂商与自定义模型
- 工作流节点继续读取模型配置作为下拉选项。

### 后端

- 新增 `model_config` 表。
- 新增实体、DTO、VO、Mapper、Service、Controller。
- 接口路径统一为 `/modelConfig`。
- 支持接口：
  - `POST /modelConfig/add`：新增模型配置
  - `POST /modelConfig/delete`：删除模型配置
  - `POST /modelConfig/update`：修改模型配置
  - `GET /modelConfig/get?id=`：根据 ID 查询
  - `POST /modelConfig/list/page`：分页查询
  - `GET /modelConfig/list/enabled`：查询启用模型配置

## 数据结构

### model_config

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| name | varchar | 配置名称 |
| provider | varchar | 厂商标识，如 openai、anthropic、ollama、custom |
| provider_name | varchar | 自定义厂商显示名 |
| model_name | varchar | 模型名称 |
| base_url | varchar | 接口地址 |
| api_key | varchar | API 密钥 |
| temperature | double | 默认温度 |
| max_tokens | int | 默认最大令牌数 |
| enabled | tinyint | 是否启用 |
| description | varchar | 描述 |
| create_time | datetime | 创建时间 |
| update_time | datetime | 更新时间 |
| is_delete | tinyint | 逻辑删除 |
