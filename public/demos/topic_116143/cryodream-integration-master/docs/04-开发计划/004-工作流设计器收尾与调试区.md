# 004-工作流设计器收尾与调试区

## 模块目标

完成工作流设计器主线收尾，参考旧项目 Playground 调试方式，将当前 `/flow` 页面拆成编辑器区域和调试区：编辑器负责拖拽、连线、配置节点；调试区负责输入对话、运行流程、查看过程和输出结果。第一阶段先走通前端本地模拟流程，后续再替换为真实后端执行接口。

## 旧项目参考结论

旧项目调试方式主要有两类：

1. 编辑页右侧 Playground
   - 编辑器保持在主区域。
   - 右侧滑出调试区。
   - 调试区包含会话、消息列表、输入框、运行中状态、输出消息。
   - 顶部工具栏的“游乐场”按钮控制调试区开关。

2. 独立 Playground 页面
   - 通过 `/playground/:id` 打开公开运行页。
   - 使用全屏输入输出 Modal。

当前项目优先采用第一种方式：编辑器 + 右侧调试区。这样对现有画布侵入最小，也能先把流程跑通。

## 功能范围

### 编辑器区域

- 保留当前结构：节点侧边栏、画布、属性面板。
- 当调试区打开时，右侧属性面板暂时切换为调试区。
- 画布节点、连线、节点参数继续使用现有 store。

### 调试区

- 顶部显示“调试区”、运行状态、关闭按钮、清空按钮。
- 中间显示调试消息：用户输入、系统提示、模拟执行结果、错误信息。
- 底部提供对话输入框。
- 支持 Enter 发送，Shift + Enter 换行。
- 点击“调试运行”打开调试区。
- 支持输入 → 执行 → 输出的前端本地模拟流程。

### 流程执行

第一阶段使用本地模拟执行：

1. 读取当前工作流节点和连线。
2. 检查是否有节点。
3. 识别聊天输入、聊天输出、语言模型、智能体、提示模板等关键节点。
4. 将用户输入写入消息列表。
5. 输出流程概览、执行步骤和最终结果。
6. 显示运行成功或错误。

后续接入真实接口时，将本地模拟执行替换为 `runFlow` 或后端工作流执行接口。
