# RAG 模块二：动态检索引擎

## 模块目标

实现 V6.0 认知级 RAG 架构的「阶段二：动态检索流水线 (Retrieval)」，完成从用户模糊提问到精准 Chunk 召回的完整检索流程。

核心特性：
- **意图重构**（Query Rewriter）：LLM 将模糊提问翻译为标准 JSON 查询条件
- **隐式补全**：后台自动补全缺失条件，仅在致命缺失时触发单点反问
- **混合检索**（Hybrid Search）：元数据硬过滤 + 向量精准召回
- **时间感知**：默认限制时间窗口，防御概念漂移

## 技术选型

### 意图重构
- 复用现有 `LanguageModelNodeExecutor`
- Prompt 模板：定义「意图重构」专用提示词（将模糊提问翻译为 JSON）

### 元数据过滤
- PostgreSQL JSONB 查询：
  ```sql
  SELECT * FROM chunk
  WHERE knowledge_base_id = :kbId
    AND metadata->'1_Domain_Scope'->>'domain' IN (:domains)
    AND metadata->'3_Epistemology_Tag'->>'time_stamp' >= :startTime
    AND metadata->'3_Epistemology_Tag'->>'confidence' >= :minConfidence
  ```

### 向量召回
- PGVector cosine similarity：
  ```sql
  SELECT *, 1 - (embedding <=> :queryVector) AS score
  FROM chunk
  WHERE knowledge_base_id = :kbId
  ORDER BY embedding <=> :queryVector
  LIMIT :topK;
  ```

### 混合检索策略
1. **预过滤阶段**：元数据硬过滤（缩小候选集）
2. **向量召回阶段**：在候选集中进行向量相似度排序
3. **融合排序阶段**：置信度权重 × 相似度分数

## 验收标准

1. **意图重构**
   - 模糊提问正确翻译为 JSON 查询条件
   - 缺失条件自动补全（如时间范围默认 last_3_months）
   - 致命缺失时返回反问提示

2. **元数据过滤**
   - 按 Domain/Entity/Concept 正确过滤
   - 时间窗口正确计算
   - 置信度阈值正确应用

3. **向量召回**
   - 相似度分数正确计算（cosine similarity）
   - topK 结果正确返回

4. **混合检索**
   - 预过滤 + 向量召回正确编排
   - 置信度权重正确应用
   - 结果按综合分数排序

5. **工作流节点**
   - 4 个节点可正常串联执行
   - 输入输出符合节点模板定义

## 风险防御

| 风险 | 防御机制 |
| --- | --- |
| 交互摩擦 | 隐式重构：LLM 后台自动补全条件，仅在致命缺失时触发单点反问 |
| 概念漂移 | 时间感知：元数据强制带时间戳，检索时默认限制时间窗口 |
| 罗生门冲突 | 置信度权重：高置信度 Chunk 优先召回 |
| 语义坍塌 | 微型注释匹配：Entity/Concept 以 Name+Desc 拼接后匹配 |
