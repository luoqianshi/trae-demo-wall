## 模块概述

**模块名称**：通用标签系统（Tag System）
**模块目标**：构建一个**独立、通用、可复用**的标签能力，支持「分组（category）+ 组内配色」的标签体系，可被知识库文档、工作流/项目等多种业务对象绑定。提供独立的标签管理页面，并为后续开发模板的「标签绑定」预留通用接口。
**计划周期**：2026-06-23 - 2026-06-25（预估）

### 设计依据（来自需求确认）

| 决策项 | 结论 |
|--------|------|
| 作用对象 | 知识库文档（knowledge_document）、工作流/项目（workflow / project） |
| 分组维度 | **需要分组（category）+ 组配色**：标签归属分类，每个分类一个主色，组内标签同色系 |
| 配色方式 | **预设色板选择**：提供一组大厂风格柔和色板，创建时选择 |
| 管理入口 | **独立标签管理页**（/tags），全局集中管理 |
| 核心诉求 | **标签系统独立通用**，方便后续开发模板直接绑定（解耦业务） |

### 用户故事

```
作为一名知识管理员，
我希望给文档打上「领域」「功能」等不同分类的标签，
以便快速筛选和归类海量文档。
```

```
作为一名管理员，
我希望在独立的标签管理页统一维护标签和分类，
以便集中管理标签体系、设定分类配色。
```

```
作为一名开发者（后续模块），
我希望标签系统提供通用的「绑定/解绑/按标签查询」接口，
以便把任意业务对象（工作流、项目等）接入标签能力，而不必重写。
```

## 大厂设计参考

调研了主流产品的标签设计范式，提炼出本模块采用的方案：

| 产品 | 借鉴点 |
|------|--------|
| **Notion** | 多选标签、柔和色板（预设有限色）、标签即筛选 |
| **Linear** | Label 分组（Group）、组内统一色系、键盘可达 |
| **GitHub Labels** | 标签 = 颜色 + 名称 + 描述，按标签过滤 |
| **飞书多维表格** | 单选/多选字段、预设颜色、彩色 Pill 样式 |

**最终设计语言**：
- 标签呈现为 **彩色 Pill（圆角胶囊）**，浅色背景 + 同色系深色文字（保证对比度与柔和感）
- **分类（category）** 决定主色调（hue），同分类下标签使用该色系的不同明度/同一色值
- 预设 **12 色柔和色板**（参考 Notion/Linear），避免用户自由取色导致的视觉混乱
- 标签管理页采用项目现有 **标准列表布局（standard-list-layout）**

## 数据库设计

遵循项目规范：小写下划线表名、必备字段（id / create_time / update_time / is_delete 逻辑删除）、`ASSIGN_UUID` 主键、PostgreSQL。

### 1. 标签分类表 `tag_category`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | varchar(主键, UUID) | 分类 ID |
| name | varchar | 分类名称（如「领域」「功能」） |
| color | varchar | 分类主色（预设色板 key，如 `blue` / `green`） |
| sort | int | 排序 |
| description | varchar | 分类描述（可选） |
| create_time / update_time / is_delete | - | 通用字段 |

### 2. 标签表 `tag`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | varchar(主键, UUID) | 标签 ID |
| category_id | varchar | 所属分类 ID（外键逻辑关联，可空=未分类） |
| name | varchar | 标签名称 |
| color | varchar | 标签颜色（默认继承分类主色，可覆盖为同色板其它色） |
| sort | int | 排序 |
| create_time / update_time / is_delete | - | 通用字段 |

> 约束：同一分类下 `name` 唯一（应用层校验）。

### 3. 标签关联表 `tag_relation`（通用多态关联）

> **这是「独立通用」的关键**：用 `target_type + target_id` 多态关联任意业务对象，新接入对象无需改表结构。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | varchar(主键, UUID) | 关联 ID |
| tag_id | varchar | 标签 ID |
| target_type | varchar | 业务对象类型（`document` / `workflow` / `project` …） |
| target_id | varchar | 业务对象 ID |
| create_time / is_delete | - | 通用字段 |

> 索引建议：`(target_type, target_id)` 联合索引（按对象查标签）、`(tag_id)` 索引（按标签查对象）。
> 采用 SchemaMigration 方式自动建表（与项目现有 `DocumentSchemaMigration` 等一致）。

## 后端设计（service/）

参照现有 `KnowledgeDocument` 模块分层（Controller → Service → Mapper + Entity/DTO/VO）。

### 实体 / DTO / VO

| 类型 | 类名 | 说明 |
|------|------|------|
| Entity | `TagCategory` / `Tag` / `TagRelation` | 三张表映射 |
| DTO | `TagCategoryAddRequest` / `TagCategoryUpdateRequest` | 分类增改 |
| DTO | `TagAddRequest` / `TagUpdateRequest` / `TagQueryRequest` | 标签增改查 |
| DTO | `TagBindRequest`（tagIds + targetType + targetId） | 绑定/解绑 |
| VO | `TagVO`（含 category 信息与颜色）/ `TagCategoryVO`（含其下标签列表） | 视图对象 |

### 接口设计（RESTful，统一 `BaseResponse`）

**分类管理 `/tag-category`**
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/add` | 新增分类 |
| POST | `/update` | 更新分类（名称/颜色/排序） |
| POST | `/delete` | 删除分类（校验下属标签处理策略） |
| GET | `/list` | 分类列表（含色板信息） |

**标签管理 `/tag`**
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/add` | 新增标签 |
| POST | `/update` | 更新标签 |
| POST | `/delete` | 删除标签（级联清理关联） |
| POST | `/list/page` | 分页查询（按分类/名称筛选） |
| GET | `/list/all` | 全部标签（按分类分组返回，供下拉选择） |

**标签绑定 `/tag-relation`（通用能力）**
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/bind` | 给目标对象绑定一组标签（全量覆盖式） |
| POST | `/listByTarget` | 查询某对象的标签（targetType + targetId） |
| POST | `/listTargets` | 按标签反查对象 ID 列表（供筛选用） |

### 预设色板（后端常量 + 前端共享）

12 色柔和色板（参考 Notion）：`gray / red / orange / amber / yellow / green / teal / blue / indigo / purple / pink / brown`，每色定义 `bg`（浅背景）、`text`（深文字）、`border` 三个值，前后端共用 key。

- `features/tags/api/tag-api.ts`：封装上述全部接口，类型定义（`Tag` / `TagCategory` / `TagRelation` / `TagColorKey`）

### 5. 业务接入（验证通用性）

- **知识库文档**：在文档详情页/列表项接入 `TagSelector`，调用 `/tag-relation/bind`，列表支持按标签筛选
- **工作流/项目**：预留接入点（本计划先打通文档场景，工作流/项目接入作为后续小迭代）

## 功能边界

**包含范围**：
- 标签分类与标签的完整 CRUD
- 预设色板 + 分组配色
- 通用多态绑定关联（tag_relation）
- 独立标签管理页 + 通用前端组件
- 知识库文档场景接入（打标签 + 按标签筛选）

**不包含范围**（后续迭代）：
- 工作流/项目场景的 UI 接入（仅预留接口）
- 标签权限控制（谁能创建/删除）
- 标签使用统计与热度排序
- 标签的批量导入导出

## 验收标准

1. 能在 /tags 页面创建分类并指定主色，创建标签并归类
2. 标签以柔和彩色 Pill 呈现，同分类同色系
3. 在知识库文档上能绑定/解绑标签，刷新后保持
4. 知识库文档列表能按标签筛选
5. `/tag-relation/bind` 与 `/listByTarget` 对任意 targetType 通用（用 document 验证）
6. 前后端类型与色板 key 对齐，无 TS / 编译错误

## 风险与注意事项

- **通用性优先**：关联表必须用 `target_type + target_id` 多态设计，禁止给每种对象单独建关联表，否则违背「独立通用」目标
- **配色对比度**：浅背景 + 深文字需在亮/暗主题下都达标（参照项目 oklch 变量体系，避免 hsl 包裹问题）
- **删除策略**：删除分类时其下标签的处理（置为未分类 or 一并删除）需在实现时确认
- **色板单一来源**：前后端色板 key 必须同源，建议后端为权威、前端镜像常量
