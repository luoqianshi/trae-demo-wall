# 日记模块完整开发计划

> 编号：017　｜　状态：✅ 已完成（首版编码完成，前后端均已编译通过）　｜　创建日期：2026-07-12　｜　完成日期：2026-07-12

## 模块概述

**模块名称**：日记（Diary Studio）
**模块目标**：构建一个「说完就记」的智能日记系统，覆盖「语音/文字快速录入 → AI 自动摘要与分类 → 自动抽取标签 → 情绪打标 → 时间线可视化回顾」的完整闭环。让用户从「懒得写日记」变成「按住说话就行」。
**计划周期**：2026-07-12 - 2026-07-16（预估，5 天）

### 设计依据（前置调研结论）

在制定本计划前，先扫描了当前 workspace 的既有能力，得出「几乎不需要引入新库」的结论——所有基础设施都可复用现有模块：

| 需求点 | 复用来源 | 说明 |
|--------|----------|------|
| 语音转文字 | `service/executor/node/VideoAudioTranscriberNodeExecutor.java` | 项目已集成 FFmpeg 8.x + whisper 滤镜 + `models/ggml-medium.bin`，支持从音视频转录成 SRT / Markdown，中文默认繁转简 |
| AI 摘要/分类/抽标签 | `service/service/NovelAiService` + `integration/llm/OpenAiCompatibleClient` + `service/ModelConfigService` | 已打通模型配置 → LLM 调用链路，直接复用即可 |
| 通用标签系统 | `service/service/TagService` + `TagRelation` 多态关联表；前端 `client/src/features/tags/api/tag-api.ts` | 已支持 `bizType` 多态挂载，接入日记只需 `bizType='diary'` |
| 时间线设计 | `features/novels/components/TimelinePanel.tsx` + `NovelTimelineEvent` | 可借鉴的时间轴 UI + 表结构范式 |
| Markdown 编辑器 | `features/documents/editor/milkdown-editor.tsx` | 已封装，可直接嵌入 |
| 前端框架 | React 19 + tanstack-router + shadcn + zustand + i18n | 项目主栈 |
| 后端框架 | Spring Boot + MyBatis Plus + PostgreSQL + `XxxSchemaMigration` 自动建表 | 与 `NovelSchemaMigration` 同模式 |

### 关键决策项（采用推荐默认方案）

| 决策项 | 结论 | 理由 |
|--------|------|------|
| 语音输入 | **录音上传 + Whisper 后端转写** | 复用现有 FFmpeg+whisper，中文精度高、可离线、无浏览器兼容问题 |
| 分类体系 | **预设 7 类目 + 用户可扩展** | 工作/学习/生活/情感/健康/灵感/复盘；LLM 从当前类目池挑，稳定可控又可扩 |
| 标签抽取 | AI 从正文抽 3-5 个关键词标签 + 落入通用 `tag` 表 + `TagRelation(bizType=diary)` | 与项目标签体系无缝互通 |
| 情绪维度 | **AI 自动打情绪标签 + 手动可改**（喜悦/平静/焦虑/低落/愤怒/困惑 6 档） | 情绪时间线是日记的高价值可视化 |
| 编辑器形态 | Milkdown 富文本 | 与文档/小说模块一致 |
| 时间线交互 | 卡片流 + 时间轴双视图切换 | 日常速览用卡片流，深度回顾用时间轴 |
| 数据独立性 | 独立后端表 + 独立前端 feature | 与其他业务解耦，便于将来单独离线包 |

## 用户故事

```
作为一个想记录生活但懒得打字的用户，
我希望按住麦克风说话，松开后 AI 自动把语音转成文字，
以便随时随地一句话记一条日记。
```

```
作为一个不擅长整理内容的用户，
我希望 AI 帮我自动分类（这是工作/生活/情感）、抽标签，
以便日后按类目和标签检索，而不需要自己费心归类。
```

```
作为一个想回顾成长轨迹的用户，
我希望有一个时间线视图，展示我一年来的日记摘要、情绪起伏、高频标签，
以便一眼看到自己经历过什么、心情如何变化。
```

```
作为一个注重隐私的用户，
我希望所有日记数据都在本地/自建后端，不上第三方 SaaS，
以便安心记录私密内容。
```

## 业务流程设计

### 1. 语音速记流程（核心场景）

```
用户点击麦克风按钮
  ↓
（前端）MediaRecorder 开始录音，UI 显示波形与秒表
  ↓
用户松手 / 点击停止
  ↓
（前端）将 webm/wav Blob 打包成 FormData POST 到 /api/diary/transcribe
  ↓
（后端）DiaryTranscribeService：
  ① 保存录音到 media/diary/audio/{yyyyMMdd}/{uuid}.wav
  ② 调 FFmpeg → 16kHz 单声道
  ③ 调 whisper 滤镜 → SRT
  ④ SRT → 纯文本
  ↓
返回 { audioUrl, plainText, durationSec }
  ↓
（前端）自动把 plainText 塞进 Milkdown 编辑器 + 显示"重新录制/继续录制"
  ↓
用户点击"保存"
  ↓
（后端）POST /api/diary/save：
  ① 写 t_diary 主记录（含 audio_url、content、mood、category、summary）
  ② 异步触发 AI 分析（分类 + 摘要 + 标签 + 情绪）
  ③ 更新完成后写标签关联 t_tag_relation
  ↓
（前端）成功 toast + 返回日记列表 / 时间线
```

### 2. AI 自动分析流程

```
save 完成后，后端异步链路（DiaryAiService）：
  ↓
Prompt 组装（正文 + 当前分类池 + 情绪枚举 + 已有热门标签）
  ↓
调 OpenAiCompatibleClient（使用 model-config 里配置的默认 LLM）
  ↓
LLM 返回结构化 JSON：
{
  "category": "工作",
  "mood": "焦虑",
  "summary": "……不超过 60 字",
  "tags": ["需求评审", "跨部门协作", "OKR"],
  "highlights": ["……可选，摘出的金句"]
}
  ↓
后端解析 + 落库：
  ① 更新 t_diary.summary / mood / category
  ② 循环 tags：如果 t_tag 存在则复用，否则新建（挂到"日记标签"分类下）
  ③ 写 t_tag_relation（biz_type='diary', biz_id=diaryId, tag_id）
  ↓
SSE 或轮询推送到前端，UI 局部刷新显示 AI 分析结果
```

### 3. 时间线回顾流程

```
用户进入 /diary/timeline
  ↓
默认视图：本月 —— 按日聚合卡片流
  ↓
可切换：
  - 视图：卡片流 / 时间轴 / 情绪热力图
  - 粒度：日 / 周 / 月 / 年
  - 筛选：分类 / 标签 / 情绪
  ↓
悬浮统计条：本周共 X 条日记 · 平均情绪 X · 最高频标签 X
  ↓
点击卡片跳转 /diary/$diaryId 详情/编辑
```

### 4. 日记列表流程

```
/diary（默认页）
  ↓
顶部：搜索框 + 快速录入按钮（麦克风 + 文字）
  ↓
左侧：类目树（含系统预设 + 用户自建）+ 全部/未分类
  ↓
主区：日记卡片流
  - 每卡：日期头 · 情绪 emoji · 摘要 · 标签 Pill · 音频波形 icon
  - 支持行内快捷情绪修改
  - 点击进入详情/编辑
```

### 5. 手动编辑流程

```
详情页 /diary/$diaryId
  ↓
顶部：日期时间 · 分类下拉 · 情绪 chip · 标签 Pills · 音频播放器（如有）
  ↓
中区：Milkdown 编辑器
  ↓
右侧抽屉：AI 结果面板（摘要 / 建议标签 / 情绪判断依据 / 重新分析按钮）
  ↓
底部：删除 · 导出 Markdown · 保存
```

## 数据库设计

遵循项目规范：小写下划线表名、`ASSIGN_UUID` 主键、`create_time / update_time / is_delete` 通用字段、PostgreSQL、Schema 用 `DiarySchemaMigration.java` 自动建表。

### 1. 日记主表 `diary`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | varchar(主键, UUID) | 日记 ID |
| user_id | varchar | 所属用户 |
| title | varchar(200) | 标题（可为空，默认取摘要首句） |
| content | text | Markdown 正文 |
| summary | varchar(500) | AI 摘要 |
| category | varchar(50) | 分类（工作/学习/生活/情感/健康/灵感/复盘/自定义） |
| mood | varchar(20) | 情绪：joy/calm/anxious/sad/angry/confused |
| mood_score | int | 情绪打分 -2 ~ +2，用于时间线情绪曲线 |
| audio_url | varchar | 原始录音相对路径（可为空） |
| audio_duration_sec | int | 录音时长 |
| word_count | int | 字数 |
| ai_analysis_status | varchar(20) | pending / running / done / failed |
| ai_raw_response | jsonb | LLM 原始返回，便于回溯 |
| diary_date | date | 日记归属日期（用户可与 create_time 不同） |
| create_time / update_time / is_delete | - | 通用字段 |

**索引**：`(user_id, diary_date DESC)`、`(user_id, category)`、`(user_id, mood)`

### 2. 日记分类表 `diary_category`

预设与用户自定义合流；预设行 `is_preset=1` 不允许删除，只能重命名。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | varchar | 主键 UUID |
| user_id | varchar | 用户（预设为 `SYSTEM`） |
| name | varchar(30) | 类目名 |
| color | varchar(20) | 预设色板 key，与 tag 系统一致 |
| icon | varchar(30) | lucide 图标名 |
| sort | int | 排序 |
| is_preset | int | 是否系统预设 |
| create_time / update_time / is_delete | - | 通用字段 |

**初始化插入 7 行预设**：工作(work/blue)、学习(study/indigo)、生活(life/green)、情感(emotion/pink)、健康(health/teal)、灵感(inspiration/amber)、复盘(review/purple)

### 3. 标签关联（复用现有 `tag_relation`）

不新建表。写入时：
```
tag_relation:
  biz_type = 'diary'
  biz_id   = diary.id
  tag_id   = tag.id
```
AI 抽到的新标签落到"日记标签"这个 `tag_category`（首次运行时自动创建）。

### DiaryTranscribeService 关键实现

复用 `VideoAudioTranscriberNodeExecutor` 里 whisper 的 FFmpeg 参数模板；但独立抽一个纯服务（不走工作流节点），因为日记是同步业务调用而不是节点编排：

```
Path audioFile = mediaStorageService.save(audioBlob, "diary/audio", ".wav");
Path wavFile = ffmpegExtractWav16k(audioFile);      // 复用 FFmpeg 抽 16k
Path srtFile = ffmpegWhisperTranscribe(wavFile, "zh"); // 复用 whisper 滤镜
String plain = srtToPlainText(srtFile);
return new TranscribeResult(audioFile.toUrl(), plain, durationSec);
```

**复用点**：抽取 `VideoAudioTranscriberNodeExecutor` 中的 FFmpeg 命令拼接方法为公共方法（可下沉到 `service/impl/FfmpegWhisperHelper.java`），日记与工作流节点共用。

### DiaryAiService Prompt 模板

```
你是一位日记助手，请对以下日记正文做结构化分析。

分类池：{{categories}}   # 从 diary_category 表拉当前用户的类目名 CSV
情绪枚举：joy(喜悦) / calm(平静) / anxious(焦虑) / sad(低落) / angry(愤怒) / confused(困惑)
情绪打分：-2(极负) ~ +2(极正)

日记正文：
"""{{content}}"""

请仅返回 JSON（不要 Markdown 代码块）：
{
  "category": "从分类池中选一个",
  "mood": "情绪枚举之一",
  "moodScore": -2到2的整数,
  "summary": "60字以内摘要",
  "tags": ["3-5个关键词标签"]
}
```

用 `StructuredJsonOutputRepairer`（项目已有）兜底解析。

## 风险与预案

| 风险 | 预案 |
|------|------|
| Electron 麦克风权限被拒 | main.ts 里配 `setPermissionRequestHandler(['media'] => true)`；权限请求前给出引导 |
| Whisper 中文长句幻听/漏字 | 已有 `ggml-medium.bin` 精度足够；提供"人工纠错"入口，把转写文本先塞编辑器供用户改 |
| LLM 返回非 JSON | 复用 `StructuredJsonOutputRepairer`；失败降级为 category=未分类、mood=calm、tags=[] |
| 情绪判断过度自信/误判 | 情绪 chip 允许一键手改；ai_raw_response 存原始，便于用户查看依据 |
| 音频文件占空间 | 录音默认 16kHz 单声道 wav 或 opus；可在设置里配"7 天后删除原始录音，只留文本" |
| 私密性 | 全链路走本地/自建后端；LLM 建议默认用 model-config 中标注为 local 的模型 |
