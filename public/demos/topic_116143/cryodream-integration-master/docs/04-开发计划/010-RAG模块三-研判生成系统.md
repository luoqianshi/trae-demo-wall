# RAG 模块三：研判生成系统

## 模块目标

实现 V6.0 认知级 RAG 架构的「阶段三：研判生成 (Generation)」，完成从召回 Chunk 到情报分析报告的完整生成流程。

核心特性：
- **情报分析师 LLM**：以「理论为基、数据为核」输出研判简报
- **置信度分层展示**：高置信度数据与低置信度叙事分块呈现
- **溯源锚点**：每个结论必须带引用链接（Chunk ID）
- **行动建议**：基于研判结果给出可执行建议

### 本次已完成（后端研判闭环 + 前端页面）

- `IntelligenceAnalyzerController`：`POST /generation/analyze`（溯源详情复用既有 `/chunk/get?id=`）。
- `IntelligenceAnalyzerNodeExecutor`：一体化研判工作流节点（`@Component` 自动注册），输出研判简报 + 溯源锚点 + 调试明细。
- 前端：`generation-api.ts` + 研判生成页面（知识库选择、分层简报卡片按区块着色、`[引用: 资料N]` 高亮、右侧溯源锚点面板含置信度配色、导出 Markdown）+ 路由 `/intelligence-analysis` + 侧边栏「情报研判」入口。

### 本次收尾完成（研判历史 + 溯源跳转）

- 研判历史表 `analysis_history`：通过 `GenerationSchemaMigration`（ApplicationRunner）启动时幂等自动建表，免手动执行 SQL。
- `AnalysisHistory` 实体 + Mapper + Service + ServiceImpl（MyBatis-Plus，UUID 主键，JSONB 存 rewritten_query/citations，逻辑删除）。

## 数据结构

### 研判简报结构

```markdown
## 💡 一句话核心研判
张三近期的私域盈利宣传不靠谱，实际处于亏损状态。

## 🏗️ 底层逻辑与概念
涉及概念【私域打法】：基于微信生态的转化策略。目前该打法的核心瓶颈在于前端投流成本的急剧上升。

## 📊 核心数据与事实（高置信度）
* [前员工爆料 | 置信度 0.8]：张三实际亏损 50 万，投流成本极高，资金链紧张。 [引用: Chunk_2]

## 📢 市场叙事与情绪（低置信度）
* [张三朋友圈 | 置信度 0.3]：张三对外宣称赚了 100 万。这种高调的营销主张，通常是为了掩盖现金流危机。 [引用: Chunk_1]

## 🎯 综合行动建议
警惕近期张三可能推出的高价课程，其底层商业模型已无法跑通，切勿盲目入场。
```

### 溯源锚点结构

```json
{
  "citation_id": "cite_chunk_2",
  "chunk_id": "doc123_chunk2",
  "source": "前员工爆料",
  "confidence": 0.8,
  "claim_type": "事实陈述",
  "time_stamp": "2026-05",
  "snippet": "张三实际亏损 50 万..."
}
```

### 研判历史记录表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| knowledge_base_id | bigint | 知识库 ID |
| user_query | text | 用户原始提问 |
| rewritten_query | jsonb | 重构后的 JSON 查询 |
| retrieved_chunks | jsonb | 召回的 Chunk ID 列表 |
| analysis_result | text | 研判简报（Markdown） |
| citations | jsonb | 溯源锚点列表 |
| elapsed_ms | int | 总耗时 |
| create_time | datetime | 创建时间 |

## 技术选型

### 研判生成 Prompt
- 复用现有 `LanguageModelNodeExecutor`
- Prompt 模板：定义「情报分析师」专用提示词
  - 输入：召回 Chunk 列表（含置信度标签）
  - 输出：分层研判简报（Markdown 格式）
  - 约束：每个结论必须带 [引用: Chunk_X]

### 溯源锚点生成
- 从 Chunk 元数据提取 Source/Confidence/ClaimType/TimeStamp
- 生成可点击的引用链接（Chunk ID → Chunk 详情页）

### 行动建议生成
- 基于研判简报，LLM 生成可执行建议
- 约束：建议必须基于数据事实，而非主观臆断

## 验收标准

1. **研判生成**
   - 研判简报包含 5 个标准区块（核心研判、底层逻辑、数据事实、市场叙事、行动建议）
   - 每个结论带 [引用: Chunk_X] 溯源锚点
   - 高/低置信度数据分层展示

2. **溯源锚点**
   - 点击引用链接可跳转到 Chunk 详情页
   - Chunk 详情页显示完整元数据背包
   - 溯源信息包含 Source/Confidence/ClaimType/TimeStamp

3. **行动建议**
   - 建议基于数据事实，而非主观臆断
   - 建议可执行、可验证

4. **研判历史**
   - 历史记录正确保存
   - 可查询历史研判结果
   - 可导出为 Markdown

5. **工作流节点**
   - 3 个节点可正常串联执行
   - 输入输出符合节点模板定义

## 风险防御

| 风险 | 防御机制 |
| --- | --- |
| 幻觉复利 | 溯源锚点强制：每个结论必须带引用链接，无引用则拒绝输出 |
| 罗生门冲突 | 置信度分层：高置信度数据与低置信度叙事分块呈现 |
| 概念漂移 | 时间戳标注：每个溯源锚点显示时间戳，提醒用户时效性 |
| 边界毒化 | 原文快照：Chunk 详情页显示不可篡改的原始文本 |
