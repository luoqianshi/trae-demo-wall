# 1. 文档范围与关键假设

## 1.1 项目背景

公司为壁炉源头制造商，计划建设一个面向全球销售的品牌独立站。网站既要承载品牌定位和产品展示，也要支持标准化商品交易、工程项目询价、经销商与安装服务导流，并为建筑师、室内设计师和经销商提供技术资料。

## 1.2 本 PRD 的目标

- 明确高端壁炉独立站的业务模式、核心用户、页面架构、功能范围和验收标准。

- 完成主流国际品牌网站的产品形态调研，提炼可复用的设计与交易模式。

- 确定适合沉浸式滚动动画、全球电商、SEO 和后续扩展的技术架构。

- 将“滚动鼠标驱动定格帧动画”拆解为可生产、可开发、可验收的专项方案。

## 1.3 当前未知项与处理原则

| 未知项 | 待业务提供 | PRD 处理方式 |
| --- | --- | --- |
| 品牌与视觉资产 | 品牌中英文名、Logo、字体许可、品牌色、品牌故事 | PRD 使用高端极简方向，UI 阶段替换为正式资产 |
| 产品与认证 | 燃料类型、型号、国家认证、安装限制、保修政策 | 按 SKU 与销售国家建立可售规则，不默认全球通售 |
| 交易与履约 | 仓库、物流商、关税、安装服务、退换货 | MVP 采用区域可售 + 询价分流，避免错误承诺 |
| 语言与市场 | 首发语言、首发国家、区域定价 | 建议英文优先，分阶段增加德/法/西/意/中文 |
| B2B 模式 | 经销价、MOQ、区域保护、样品政策 | MVP 提供申请与线索管理，价格门户后置 |

# 2. 国际竞品与行业网站调研

## 2.1 调研样本

本轮选取 Planika、EcoSmart Fire、Focus、Stovax & Gazco、Napoleon 五类代表性品牌，覆盖技术创新型、设计艺术型、成熟零售网络型与综合家居设备型网站。重点观察导航、品牌叙事、产品发现、交易、专业客户、售后与国际化。

| 品牌 | 网站定位 | 观察到的核心能力 | 对本项目的启示 |
| --- | --- | --- | --- |
| Planika | 技术创新 + 现代极简 | 多语言/国家/货币；按燃料、形态、安装方式分类；独立 Shop、Dealer Map、Professional、技术故事 | 以技术建立溢价；品牌站与交易站可解耦 |
| EcoSmart Fire | 编辑式大图 + 视频 + 生活方式 | Collection、Technology、Inspiration、Support、Quotes、Trade/B2B；首页视频与场景模块；部分商品直接购物 | B2C 与 B2B 同站并行；“案例 + 技术 + 报价”是重要转化链 |
| Focus | 设计艺术品 + 品牌遗产 | 多语言、约 20 款经典设计、燃料类型、设计奖项、建筑师/酒店/经销商入口、销售点 | 高端品牌不必堆 SKU；单品历史、设计理念与标志性视觉更重要 |
| Stovax & Gazco | 产品发现 + 教育 + 零售网络 | Product Finder、选择指南、烟道/现场勘察知识、Brochures、Support、Retailer | 复杂产品要用筛选器和教育内容降低决策门槛 |
| Napoleon | 综合型高级消费品牌 | 地区/语言、Product Finder、Dealer Locator、Online Shop、Design Studio、App、手册/规格/注册/保修 | 线上购买、配置工具、本地专家与售后体系可并存 |

## 2.2 共同规律

- 视觉不是单独的装饰层：高端壁炉网站普遍用全屏场景、视频、设计故事和技术叙述支撑高价定位。

- 产品决策不是“看价格立即购买”：用户必须判断燃料、安装形式、尺寸、空间、烟道/供电/燃气条件、国家可售性和服务能力。

- 交易路径呈混合模式：标准 SKU 可在线购买；高配置、安装依赖或地区限制产品进入询价、咨询或经销商路径。

- 专业客户是独立增长渠道：建筑师、设计师、酒店、开发商和经销商需要 CAD/BIM、规格书、安装手册、项目支持和批量询价。

- 售后内容是销售能力的一部分：交付、安装、安全、维护、保修、注册与配件应在购买前即可访问。

## 2.3 设计风格基线

| 维度 | 建议基线 |
| --- | --- |
| 画面 | 大面积留白或深色空间、真实火焰、高级材质、建筑摄影；避免廉价促销感 |
| 排版 | 大标题 + 短句叙事；正文克制；规格区高密度但结构化 |
| 动效 | 慢节奏、物理感、镜头感；动效服务产品理解，不做无意义炫技 |
| 色彩 | 炭黑、暖灰、米白为主体；火焰橙/铜色作为高亮；每屏控制强调色数量 |
| 交互 | 整屏叙事与清晰 CTA 并存；不能因为沉浸动画隐藏导航、价格、参数和购买路径 |
| 摄影/渲染 | 产品必须有统一光照、镜头、材质与比例；场景图、细节图、结构图、安装图形成完整证据链 |

## 2.4 差异化机会

| 建议的品牌体验主线<br>“从一束火，到一个空间的核心。”首页用滚动定格帧展示产品由黑暗中显现、点火、火焰稳定、材质细节、结构与空间落地；中段用工程能力、认证、安全与定制支撑信任；下段将用户分流至购买、配置、项目咨询或经销商。 |
| --- |

- 以“源头制造 + 高端设计 + 工程交付”形成区别于纯经销品牌的可信定位。

- 用可视化配置和技术资料把工厂能力翻译成客户可理解的价值，而非只展示生产车间。

- 建立统一的全球品牌体验，但商品、价格、认证、物流与服务按市场动态切换。

# 3. 产品战略与定位

## 3.1 产品定义

一个兼具品牌官网、产品目录、国际电商、项目询价、专业资料库和售后支持能力的全球高端壁炉独立站。前台采用内容驱动的 Headless 架构，后台由成熟商业平台管理商品、库存、订单、支付和地区市场。

## 3.2 价值主张

| 对象 | 核心价值 |
| --- | --- |
| 消费者 | 用沉浸式体验理解产品，用明确的适配信息判断能否安装，并获得可信的购买与售后路径 |
| 建筑师/设计师 | 快速筛选产品，下载规格、CAD/BIM 与材质资料，提交项目参数并获得技术支持 |
| 经销商/安装商 | 申请合作、获取资料、提交线索/订单、查看区域政策与售后入口 |
| 公司运营 | 统一全球品牌、商品与内容；按国家管理可售性、价格、线索、订单与营销数据 |

## 3.3 业务模式

- Direct-to-Consumer：对标准化、易运输、安装边界清晰的 SKU 开放在线支付。

- Consultative Commerce：对高客单、可定制、需要现场条件确认的产品提供“起售价 + 配置 + 询价/预约”。

- Dealer-assisted Commerce：按国家或邮编将用户导向授权经销商/安装商，并保留总部线索归因。

- Trade / Project Sales：面向建筑、设计、酒店与地产项目提供技术选型、批量报价和项目跟进。

## 3.4 产品目标与非目标

| 类型 | 说明 |
| --- | --- |
| P0 目标 | 建立全球统一高端品牌形象；让用户在 3 次点击内进入合适产品；生成可跟进的高质量线索；在允许市场完成在线交易；达到良好 Core Web Vitals。 |
| P1 目标 | 配置器、经销商地图、专业资料中心、案例内容体系、产品注册与售后工单。 |
| 非目标 | 首期不自研支付、税务、订单、仓储系统；不承诺所有国家均可购买；不以复杂社区、论坛或全功能 ERP 为范围。 |

# 4. 用户角色与核心任务

| 角色 | 核心任务 | 关键触点 |
| --- | --- | --- |
| 高端住宅业主 | 寻找与空间风格匹配的壁炉；确认尺寸、能源、安装和预算；购买或预约顾问 | 场景灵感、筛选器、PDP、配置、报价/购买 |
| 建筑师/室内设计师 | 按项目尺寸与规范选型；获取 CAD/BIM、材质、规格和认证；沟通定制 | 专业筛选、下载中心、项目表单、案例 |
| 酒店/地产/商业项目方 | 批量选型、交期、定制、合规、报价、项目支持 | 行业案例、工程能力、批量询价、客户经理 |
| 经销商/安装商 | 合作申请、区域政策、资料、培训、线索和售后 | Trade 入口、B2B 申请、资料、工单 |
| 已有客户 | 安装、操作、维护、保修、配件和问题处理 | 序列号注册、手册、FAQ、售后工单 |

## 4.2 用户决策变量

- 燃料/能源：电、燃气、生物乙醇、木燃等（以公司真实产品线为准）。

- 安装形态：嵌入式、壁挂式、独立式、吊装式、双面/三面/岛式、户外。

- 空间条件：房间大小、墙体结构、开孔、烟道、供电、燃气、通风、热管理、电视共墙。

- 设计变量：尺寸、可视面、框体、材质、颜色、燃烧介质、控制方式。

- 商业变量：价格、运输、关税、安装服务、交期、认证、保修与售后。

# 6. 核心用户旅程

## 6.1 消费者：灵感到购买/咨询

1. 进入首页，自动获得合适的语言与市场建议，但由用户确认国家/货币。

1. 观看滚动叙事或跳过动画，进入“选择你的火焰/空间”入口。

1. 通过产品筛选器选择能源、安装方式、空间和预算。

1. 在 PDP 查看场景、尺寸、适配条件、价格、交期、认证与安装要求。

1. 若符合在线销售规则：加入购物车并结账；否则：保存配置并提交咨询/项目询价。

1. 购买后进入订单、安装资料、注册与售后路径。

## 6.2 设计师：项目选型到技术确认

1. 进入 Professionals，选择 Architect/Designer。

1. 按尺寸、形态、燃料、可视面、热输出与认证筛选。

1. 对比 2–4 个产品，下载规格书、CAD/BIM、材质与安装文件。

1. 填写项目国家、建筑类型、数量、时间、图纸和定制需求。

1. 系统将线索分配给对应销售/技术人员，并记录来源和资料下载。

## 6.3 经销商：合作申请

1. 查看品牌优势、产品线、支持政策与基本准入要求。

1. 提交公司、区域、渠道、团队、展厅与安装能力资料。

1. CRM 建立合作线索并触发审核；通过后进入 B2B 门户或人工对接。

## 8.3 动画资产规格

| 项目 | 规格 |
| --- | --- |
| 母版 | 3D 渲染优先；EXR/PNG 无损母版；固定镜头、曝光、色彩空间和产品比例 |
| 帧数 | 桌面建议 180–240 帧；移动端 100–160 帧；根据滚动距离和动作复杂度实测 |
| 尺寸 | 桌面 1920 或 1600 宽；平板 1280；移动端 828/960；按构图做独立裁切而非简单缩小 |
| 格式 | 首选 AVIF，WebP 回退；首帧另存高质量静态图并设 preload/fetchpriority |
| 体积预算 | 完整序列桌面建议控制在约 8–12 MB；移动端约 4–7 MB；关键首屏初始传输不等待全序列 |
| 命名 | scene-name/{breakpoint}/frame-0001.avif；manifest 记录帧数、尺寸、格式、校验与版本 |
| 内容安全 | 避免火焰遮挡文字；正文与 CTA 不烧录在帧内；文本保持真实 DOM |

## 8.4 运行时策略

- 首帧 SSR 输出为真实图片，确保无 JavaScript 时仍有主视觉、标题和 CTA。

- 仅预加载首帧及邻近 8–16 帧；用户接近 Hero 后分批加载其余帧，控制并发并缓存。

- scroll progress 仅更新目标帧；实际绘制由 requestAnimationFrame 节流，避免每个 scroll 事件直接绘制。

- Canvas 分辨率依据容器和 devicePixelRatio 设置，但 DPR 建议封顶 1.5–2，避免 4K 屏显存和解码失控。

- 使用 createImageBitmap/可用时的后台解码；离开页面或切换场景后主动释放位图与监听器。

- 网络慢、内存低、设备性能不足时减少帧数或切换轻量视频/静态图。

- 文本淡入、位移等简单效果可使用 CSS；核心帧序列由 JS 统一控制。原生 CSS Scroll-driven Animations 可渐进增强，但不作为唯一实现。

## 8.5 可访问性与降级

- 尊重 prefers-reduced-motion：默认禁用长距离镜头、缩放和快速视差，展示静态主视觉或短淡入。

- 提供可见的暂停/播放或“跳过动画”控制；键盘和屏幕阅读器可直接访问标题、CTA 和后续内容。

- Canvas 设置可理解的替代文本；关键信息不能仅存在于动画帧。

- 页面滚动必须保持浏览器原生行为，不得锁死滚轮、反向滚动或强制吸附造成操作障碍。

## 8.6 动画验收标准

| 维度 | 验收 |
| --- | --- |
| 视觉 | 滚动前进/后退均可逐帧响应；无闪白、拉伸、明显跳帧、错误裁切或火焰颜色漂移 |
| 性能 | 目标设备连续滚动主观流畅；主线程不因预加载长期阻塞；内存峰值可控；离开场景后可释放 |
| 加载 | 首帧优先呈现；动画未加载完时页面仍可滚动和点击；失败时自动回退 |
| 适配 | 桌面、平板、手机使用独立构图；横竖屏切换重算 Canvas；不依赖固定高度设备 |
| 可访问 | 减少动态效果、键盘、读屏、无 JS 场景均有可用替代 |
| 数据 | 记录动画开始、25/50/75/100%、跳过、CTA 点击和性能异常 |

## 11.3 架构原则

- 商业核心买成熟平台，品牌体验与内容在前端自主构建。

- 商品、内容、媒体、市场与资料分离建模，通过稳定 ID 关联。

- 页面可预渲染的尽量预渲染，价格/库存等时效数据按需刷新。

- 动画资产走独立 CDN 与版本清单，发布可回滚，不与应用包绑定。

- 任何第三方脚本都经过性能、隐私和故障隔离评审。

# 12. 非功能需求：性能、SEO、无障碍、安全

## 12.1 性能预算

| 指标 | 目标 | 备注 |
| --- | --- | --- |
| Core Web Vitals | P75：LCP ≤ 2.5s；INP ≤ 200ms；CLS ≤ 0.1 | 按移动/桌面、国家、模板持续监控 |
| 首屏关键资源 | 移动端目标 ≤ 2.0 MB（需实测调整） | 不包含后续渐进加载的完整帧序列 |
| JavaScript | 首屏业务 JS 尽量 ≤ 180 KB gzip | 第三方脚本延迟加载；动画模块按路由拆分 |
| 图片 | 响应式尺寸；AVIF/WebP；明确宽高；非首屏懒加载 | 首帧和 LCP 图不能懒加载 |
| 动画 | 目标设备滚动流畅；不在主线程做大批同步解码 | 真实设备 + 低端机 + 节流网络测试 |
| 缓存 | 静态媒体长缓存 + 内容哈希；HTML/数据按业务时效控制 | 商品价格/库存避免陈旧错误 |

## 12.2 SEO

- 产品、系列、案例、技术与文章均有可索引 HTML；Canvas 和视频不能替代正文。

- 结构化数据：Product、Offer（适用时）、Breadcrumb、Organization、Article、VideoObject、FAQ（符合搜索平台政策时）。

- 多语言/多市场正确配置 hreflang、canonical、站点地图和重定向。

- 产品图使用描述性文件名和 alt；规格以 HTML 表格/定义列表呈现。

- 下架产品保留合理替代与 301/410 策略，避免大量软 404。

## 12.3 无障碍

目标：关键消费者路径达到 WCAG 2.2 AA。

- 键盘可操作、焦点可见、跳至主要内容、表单错误可理解、对比度达标。

- 视频有字幕/文字说明；自动播放默认静音且可暂停。

- 尊重减少动态效果；避免滚动劫持、快速闪烁和大幅视差。

- 产品配置、筛选、对比与文件下载均可通过辅助技术完成。

## 12.4 安全与隐私

| 领域 | 要求 |
| --- | --- |
| 支付 | 使用托管结账；前台不存储卡号；最小化 PCI 范围 |
| 应用安全 | HTTPS/HSTS、CSP、输入校验、CSRF/XSS 防护、依赖扫描、Secrets 管理 |
| 边缘安全 | WAF、Bot/Rate Limit、DDoS 防护、上传文件扫描 |
| 权限 | CMS、Shopify、CRM 使用最小权限、MFA、审计日志、离职回收 |
| 隐私 | 按市场提供隐私与 Cookie 管理；非必要追踪在同意前不加载；支持数据请求流程 |
| 数据 | 定义保留期、备份、恢复、跨境传输和供应商处理协议 |
| 发布 | 预览环境、自动测试、审批、回滚、状态监控与事故响应 |

## 15.4 MVP Definition of Done

- 用户可在任何首发市场明确知道：产品是否可购买、需要询价、需要顾问、仅经销商销售或不可售。

- 用户可在产品详情获得完成决策所需的场景、规格、安装、安全、资料与服务信息。

- 首页滚动序列不阻塞基础内容与 CTA，在性能不足和减少动态效果场景可靠降级。

- 所有线索和交易均带来源、产品、配置、市场和语言上下文进入后台。

- 运营团队无需改代码即可管理产品关联内容、案例、技术、资料和关键首页模块。

# 16. 风险、待确认事项与参考资料

## 16.1 主要风险与缓解

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 动画体积导致首屏慢 | 高 | 分端帧集、首帧优先、渐进加载、体积预算、真实设备 PoC |
| 全球可售承诺错误 | 高 | SKU×Market 规则、结账前二次校验、不可售分流、法务/认证审批 |
| 产品资料不完整 | 高 | 上线清单、结构化字段、责任人、缺失阻断发布 |
| 高端视觉与转化冲突 | 中高 | 固定导航、清晰 CTA、跳过动画、可用性测试、分屏埋点 |
| Headless 复杂度 | 中高 | 减少自研、定义系统边界、契约测试、监控、升级策略 |
| 3D/配置组合爆炸 | 中 | 先轻配置；限制可视组合；预渲染与实时 3D 分层 |
| 多语言内容失控 | 中 | 翻译状态、市场 Owner、版本审批、内容回退 |
| 经销商与直营渠道冲突 | 中高 | 按区域定义归属、线索分配、价格策略和渠道政策 |

## 16.2 UI 与开发前必须确认

- 首发国家、语言、货币和各市场负责人是什么？

- 产品线、SKU、选项、尺寸、燃料、认证和安装限制是否已结构化？

- 哪些产品可以直接在线购买，哪些必须询价/经销商？

- 是否有海外仓、DDP/DAP 策略、安装服务和退换货能力？

- 品牌正式名称、Logo、字体、视觉资产和摄影/3D 预算是多少？

- 现有 ERP、CRM、PIM、Shopify、物流、客服与邮件系统有哪些？

- 经销商渠道政策、区域保护、线索归属与 B2B 价格规则是什么？

- 首期要做几个定格帧场景？是否有 3D 模型、材质、工程图和可用于渲染的源文件？
