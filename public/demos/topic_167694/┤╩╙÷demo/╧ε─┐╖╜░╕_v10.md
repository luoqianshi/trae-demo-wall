## 五、Demo 展示方案

### 核心思路

Demo 的目标不是做一个完整产品，而是**讲清楚"词遇是什么"**——让评审者在几分钟内理解核心概念和交互方式。

分两层展示：
1. **组件层**：逐个展示系统的核心视觉单元，每个组件独立一块区域，说明它是什么、长什么样
2. **场景层**：把组件拼成几个典型使用场景，展示它们如何组合在一起

### 三个核心交互原则

以下原则贯穿整个 Demo：

#### 原则 1：全局划词

**划词是词遇最核心的交互方式。Demo 中必须充分体现"哪里都可以划"。**

用户可以在页面上的任何位置选中任何文本——不管是阅读区的一个单词、关联网络里的一个节点名称、测试题里的一个选项文本、甚至场景标题上的文字。只要选中了，系统就应该对选中的内容进行解析：

- **识别成分**：AI 判断选中的文本包含哪些基本单元（可能是单个词，也可能是短语里的多个词），并拆分展示
- **展示解析**：弹出划词浮窗，列出识别到的每个单元，每个单元可独立查看释义、发音
- **快捷操作**：每个识别出的单元旁边有"查看详情"按钮，可以直接跳转到该单元的详情面板
- **跨区域选中**：即使选中的文本跨越了多个组件区域（例如选中了半句阅读文本 + 半句系统标题），也能工作——AI 会对选中的整段文本做统一解析

**Demo 中的实现**：浏览器原生的 text selection 事件可以获取选中的文本。Demo 监听全局 `mouseup` 事件，当检测到有选中文本时，显示划词浮窗。浮窗的位置根据选区的 getBoundingClientRect 计算。

#### 原则 2：随处可达单元详情

**从任何涉及"词"的地方，都可以跳转到单元详情面板。**

- 关联网络中的节点 → 点击跳转
- 划词浮窗中识别出的单元 → "查看详情"跳转
- 历史记录中的涉及单元标签 → 点击跳转
- 阅读解析中的内联单元卡片 → 点击跳转
- 测试题中的词 → 可以跳转

**导航机制**：跳转到单元详情面板时，当前场景被推入导航栈。详情面板顶部有"返回"按钮，点击后回到之前的场景和位置。Demo 中用 `store.navStack` 数组管理导航历史。

#### 原则 3：减少操作、信息前置

**能直接展示的信息不要让用户多点一下。**

核心体现：阅读场景中，不是"画下划线 → 点击 → 弹出详情"的三步操作，而是根据用户的熟悉度，直接在文本下方内联展示关键信息。不熟悉的词，解释直接显示在旁边；熟悉的词，不展示或极简展示。用户不需要主动点击就能看到解析。

### 展示策略

**展示什么：**
- 以日语学习为例，统一使用一套 mock 数据
- 覆盖创意概述的核心流程：输入 → 拆分 → 记录 → 联想 → 评估
- 每个组件和场景旁边标注"此处为 AI 生成内容（示意）"

**不展示什么：**
- 系统维护分组的模块（行为日志、调用日志、缓存管理、数据管理、系统诊断）
- 真实的 AI 调用——全部用 mock 数据

**Mock 数据设定：**
- 用户正在学日语，目标 N4，入门水平，已使用一周
- 预设约 20 个基本单元（单词和语法点），每个有不同熟悉度
- 预设一篇日语短文、几条历史记录、一套测试题

### 第一层：组件展示

每个组件占一行，左侧是组件本身，右侧是文字说明。

#### 组件 1：基本单元卡片

**对应模块**：基本单元体系

**展示内容**：一张单词卡片——
- 单词（日语汉字 + 假名注音）
- 发音按钮
- 中文释义
- 词性标签
- 熟悉度指示
- 快捷操作按钮（标记认识 / 查看详情 / 查关联）

**Mock 数据**：

| 单词 | 假名 | 释义 | 词性 | 熟悉度 |
|------|------|------|------|--------|
| 食べる | たべる | 吃 | 動詞 | 见过 3 次，中等 |
| 勉強 | べんきょう | 学习 | 名詞 | 见过 5 次，较高 |
| 天気 | てんき | 天气 | 名詞 | 见过 1 次，较低 |

**可交互**：发音按钮、标记认识、点击"查看详情"跳转详情面板
**示意效果**：熟悉度由 mock 驱动

#### 组件 2：单元详情面板

**对应模块**：基本单元体系 + 学习轨迹留痕 + 关联网络

**展示内容**：从任何入口跳转后出现的面板——
- 顶部：返回按钮 + 单词 + 发音 + 释义
- 释义区：多义项列表，每个义项带例句（发音按钮）
- 关联区：相关单词、相关语法、近义表达（AI 生成，示意），每个关联词可点击跳转到对应详情（形成链式导航）
- 轨迹区：学习时间线
- 底部：熟悉度手动调节

**导航说明**：面板顶部有返回按钮。如果是从关联网络跳来的，返回到关联网络；如果是从划词跳来的，返回到之前的场景。导航栈记录完整路径。

**Mock 数据**：以「食べる」为例，预设 3 条义项、3 条例句、5 条关联、4 条轨迹记录

**可交互**：返回按钮、发音、标记熟悉度、点击关联词跳转（链式导航）
**示意效果**：关联内容标注"AI 生成"

#### 组件 3：关联网络展示

**对应模块**：关联网络

**展示内容**：以某个单词为中心，辐射状展示 AI 关联出的内容——
- 中心：当前单词
- 外层节点：按类别分组（近义表达 / 相关语法 / 常用搭配 / 场景差异）
- 每个节点可点击，**点击后跳转到该单元的详情面板**（而非就地展开）
- 节点之间的连线表示关联类型

**Mock 数据**：以「食べる」为中心，关联出近义表达、相关语法、常用搭配、场景差异各 2 项

**可交互**：点击节点跳转到单元详情面板
**示意效果**：标注"AI 动态生成，非预置知识库"

#### 组件 4：AI 对话浮窗

**对应模块**：全局查询

**展示内容**：固定在页面角落（右下角）的对话式交互入口——
- 默认收起状态：一个小图标按钮，悬浮在右下角，不干扰阅读
- 展开状态：一个较小的对话面板，从右下角向上展开
  - 用户输入区（底部）
  - AI 回复区（上方，消息气泡形式）
  - 回复内容不是干瘪的文字，而是**结构化的语言学习内容**：
    - 涉及的单词用高亮标注，可点击跳转到单元详情
    - 语法解释用格式化排版（缩进、标注）
    - 可以给出"意图猜测"：比如用户问了一句模棱两可的话，AI 先说"你可能是想问 XX，对吗？"
    - 相关的单元词语以标签形式展示在回复中，点击即可跳转
  - 追问在同一个对话流中，但每次追问会触发新的上下文分析
- **不挡阅读**：永远在角落，不影响页面主内容浏览
- **任何地方都可唤起**：划词浮窗中的"问问 AI"、场景中的"问问 AI 更多"、或者直接点击右下角图标

**Mock 数据**：预设几组查询——
- "这句话的语法结构是什么？"→ AI 返回句子拆解 + 语法标注（涉及词高亮、可点击）
- "我现在日语什么水平？"→ AI 返回基于学习数据的评估（场景化描述 + 涉及单元标签）
- 用户从划词浮窗触发"问问 AI"→ AI 结合选中的内容直接给出分析

**可交互**：输入问题、点击回复中的词/单元标签跳转
**示意效果**：AI 回复为 mock，标注"实际内容由 AI 动态生成"

#### 组件 5：划词浮窗（全局）

**对应模块**：划词即学

**展示内容**：在任何位置选中文本后弹出的浮窗——
- 选中的原文（带假名标注）
- **AI 解析结果**：识别出选中文本中的基本单元，每个单元独立展示：
  - 单词 + 假名 + 释义 + 发音按钮
  - "查看详情"按钮 → 跳转到单元详情面板
  - "加入学习"按钮
- "问问 AI"按钮 → 打开右下角 AI 对话浮窗，并将选中文本作为上下文
- 浮窗位置：根据选区位置计算，不遮挡选中文本

**核心特点**：不限于特定阅读区。在 Demo 中，用户可以选中关联网络里的词、测试题里的选项文本、组件说明中的日文示例等——任何位置都能触发划词。

**Mock 数据**：预设一个简单的映射表（选中某些词时返回对应的解析），对于未预置的文本返回通用的 AI 解析示意。

**可交互**：选中任意文本触发、发音、点击"查看详情"跳转、点击"问问 AI"
**示意效果**：浮窗解析用 mock 数据

#### 组件 6：测试题目卡片

**对应模块**：测试模块

**展示内容**：一道测试题——
- 题目类型标签（选择题 / 听力 / 填空）
- 题目内容（看词选义、看义选词、听选等），**题目中的词可选中划词**
- 选项列表，**选项中的词也可选中划词**
- 选择后的反馈：正确/错误 + 解析，**解析中涉及的词可点击跳转详情**
- 发音按钮

**Mock 数据**：预设 3 道不同类型的题

**可交互**：选择答案、查看反馈、播放发音、划词（题目和选项中的词）、点击解析中的词跳转
**示意效果**：标注"实际出题由 AI 动态生成"

#### 组件 7：能力评估卡片

**对应模块**：学习评估与复习

（与 v9 相同）
- 场景化描述、考试参考、五维度雷达、关键数据

#### 组件 8：历史记录条目

**对应模块**：学习轨迹留痕

（与 v9 相同）
- 时间戳、行为图标、内容摘要、涉及单元（可点击跳转）、来源标签
- 记录拆分机制说明

### 第二层：场景展示

每个场景是一个完整的页面布局，展示多个组件如何组合在一起。场景之间通过顶部导航栏切换，支持后退。

#### 导航机制

- 顶部有一个简单的导航栏，显示当前场景名称和"返回"按钮
- 跳转到单元详情面板时，导航栏显示单元名称 + 返回按钮
- 从详情面板返回时，恢复到之前的场景和位置
- 导航栈 `store.navStack` 记录完整路径

#### 场景 1：首页「今天学点啥」

**对应模块**：学习评估与复习（推荐机制）、内容入口、数据核心

**页面布局**：
- **顶部栏**：能力评估速览——场景化描述 + 雷达图入口
- **中部 · 今日推荐**：
  - "该复习了"区域：2-3 张基本单元卡片
  - "新材料"区域：1-2 篇推荐阅读的卡片
  - "快速测试"入口卡片
- **底部 · 最近历史**：最近 3 条历史记录条目

**组件组合**：基本单元卡片 × 3 + 能力评估卡片 + 历史记录条目 × 3

**可交互**：点击卡片跳转详情面板（有返回）、点击推荐阅读进入场景 2、点击快速测试进入场景 4
**特色**：全局划词在任何文本上可用

#### 场景 2：阅读与解析（内联模式）

**对应模块**：沉浸式阅读、查词与改写、关联网络、划词即学

**页面布局**：
- **文章区（全宽）**：一篇日语短文，直接展示
  - 每个句子下方，根据词的熟悉度**内联展示解析**：
    - **生词（熟悉度低）**：在词下方直接展示假名标注 + 中文释义 + 简短语法说明，排版紧凑但清晰
    - **半熟词（见过几次）**：只展示假名标注和简短提示，不展开完整释义
    - **熟词（掌握较好）**：不展示任何标注，不干扰阅读
  - 解析内容以缩进、小字号、次要颜色呈现，不影响原文阅读流畅度
  - 任何文本仍然可以划词，划词浮窗会给出更详细的分析
- **底部**：全文翻译（可折叠）

**Mock 数据**：同一篇日语短文——

```
今日は天気がいいですね。散歩しましょうか。
公園でお弁当を食べませんか。
いいですね。そうしましょう。
```

其中「天気」熟悉 → 只标假名；「散歩」半熟 → 假名 + 简短提示；「お弁当」生词 → 假名 + 释义 + 语法说明

**交互流程**：
1. 用户看到文章，生词下方已经展示了解析，无需点击
2. 用户想了解更多 → 直接选中某个词 → 划词浮窗弹出，提供更详细的分析
3. 用户点击内联解析中的某个词 → 跳转到该词的单元详情面板

**组件组合**：内联解析（自定义组件）+ 划词浮窗

**可交互**：划词（任何文本）、点击内联词跳转、折叠全文翻译
**示意效果**：解析内容标注"AI 根据用户熟悉度动态生成"

#### 场景 3：单元探索

**对应模块**：关联网络 + 基本单元体系 + 学习轨迹留痕

**页面布局**：
- **关联网络可视化**：以某个词为中心辐射展示
- **注意**：点击节点后**跳转到单元详情面板**（场景切换），而非就地展开
- **导航**：从详情面板返回时回到此场景，之前选中的节点高亮

**Mock 数据**：以「食べる」为入口

**交互流程**：
1. 用户看到关联网络
2. 点击「召し上がる」节点 → 跳转到「召し上がる」的详情面板
3. 在详情面板中点击关联词「食う」→ 继续跳转到「食う」的详情面板
4. 点返回 → 回到「召し上がる」详情 → 再返回 → 回到关联网络

**组件组合**：关联网络展示（节点点击触发跳转）+ 单元详情面板（带返回）

#### 场景 4：快速测试

**对应模块**：测试模块

（与 v9 基本相同）
- 进度条、题目卡片、选项、即时反馈、结果页
- **新增**：题目和选项中的词可划词、解析中的词可点击跳转

#### 场景 5：设置与配置

**对应模块**：模型接入中心 + 学习目标设置

（与 v9 相同）
- 左侧导航 + 右侧表单

### 技术实现

- **Vue 3**（通过 CDN 引入，不需要构建工具）
- 组件化开发，每个功能是一个 Vue 组件，场景页是组件的组合
- 使用 Vue 的 `reactive()` 作为全局状态管理
- **全局划词**：在 `#app` 容器上监听 `mouseup` 事件，通过 `window.getSelection()` 获取选中文本
- **导航栈**：`store.navStack` 数组 + `store.currentView` 字符串控制当前显示
- **AI 对话浮窗**：右下角固定定位，`store.aiChatOpen` 控制展开/收起

### Demo 结构

```
ciyu_proposal.html
├── 创意介绍区（静态文本）
├── 导航栏（场景切换 + 返回按钮）
├── 视图区（根据 currentView 切换）
│   ├── 组件展示页（8 个组件）
│   ├── 场景展示页（5 个场景）
│   └── 单元详情面板（从任何地方跳转进入）
├── 划词浮窗（全局，任何位置可触发）
├── AI 对话浮窗（右下角，任何位置可唤起）
└── 说明标注
```

## 六、视觉风格

- **风格定位**：干净简洁的学习工具风
- **具体色彩、字号等细节由实现时自由决定**，不做硬性规定
- **整体感觉**：像一本干净的学习笔记
- **AI 感藏在幕后**：不突出科技感，界面简洁自然
- 不用打卡天数、连续学习、纯数字统计
- 用能力评估的可视化替代（雷达图、场景化描述）
