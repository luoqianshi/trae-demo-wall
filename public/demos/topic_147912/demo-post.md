## 1. Demo 简介

EduRAG 是一个基于 RAG（检索增强生成）技术的 K12 智慧教育问答 Web 平台，面向中小学生、教师/教育机构、家长使用。

主要功能：

(1) 智能问答，三层路由精准匹配最佳策略

系统将用户提问自动分流为 FAQ 快速匹配、知识点问答、作业批改三类场景。高频问题（如"怎么退费？""什么时候考试？"）毫秒级直接返回，跳过 Agent 推理链，响应速度提升 87%。复杂知识点问题则通过 ReAct Agent 检索真实教材后生成可溯源回答。

> 📸 **此处插入截图 2**：Vue 前端智能问答界面截图，展示学生提问与 AI 流式回答

(2) 作业批改，多题批量自动评分

支持单题/多题批量批改，自动识别对错并给出解析。StateGraph 批改流程可处理数学计算题、语文阅读理解、英语语法题等多种题型，批改结果包含得分、错误定位、知识点分析。

(3) 拍照搜题 + 错题集，学习闭环

支持拍照上传题目图片，OCR 识别后自动检索答案。错题集基于艾宾浩斯遗忘曲线智能推送复习，帮助学生巩固薄弱知识点。

独创 4 层 × 4 变体 = 16 组独立消融实验，覆盖路由层、策略层、检索层、FAQ 层，使用 6 项指标（BLEU-1/2、ROUGE-L、F1、MRR、NDCG、Hit Rate）量化每个组件的独立贡献，用数据证明了架构设计的合理性。

## 2. Demo 创作思路

灵感来源：源于教育信息差与 AI 自学的交汇

作为一名 AI 技术自学者，我在学习 RAG 技术时发现，大模型虽然强大，但"幻觉"问题在教育场景中不可接受——一个数学题的错误答案可能误导学生整节课。同时，我身边有 K12 学龄的亲属，亲眼看到他们课后遇到难题时，家长无力辅导、搜索引擎答案质量参差不齐、付费答疑成本高昂的困境。这让我萌生了用 RAG 技术做教育问答的想法：让 AI 回答"有据可查"，而非凭空编造。

想解决的问题：补齐通用 AI 在教育场景的三大短板

第一，幻觉不可控。通用大模型在教育问答中可能"一本正经地胡说八道"，RAG 通过检索真实教材文档来约束回答，确保答案可溯源。

第二，策略一刀切。不同复杂度的教育问题需要不同的处理路径——"什么是勾股定理"和"这道压轴题怎么解"不应该用同一套流程。我们独创了三层递进路由 + 四种检索策略，让系统自动选择最优解答路径。

第三，缺乏系统验证。大多数 AI 教育产品只展示功能，不展示数据。我们通过 16 组消融实验量化了每个组件的贡献，用 BLEU-1、ROUGE-L、F1 等 6 项指标客观评估系统性能，让技术决策有据可依。

为什么做这个方向：将前沿 RAG 技术平民化、可验证

作为自学者，我深知 RAG 技术的学习门槛极高——LangChain、LangGraph、Milvus、向量嵌入、重排序——每个概念都需要大量时间消化。但正是自学经历让我相信，只要降低工具门槛，更多人能参与到 AI 应用开发中来。TRAE 正是这样的工具，它让我一个自学者在短时间内完成了从架构设计到实验验证的完整闭环，将前沿技术落地为可体验的教育产品。

## 4. TRAE 实践过程

**阶段一：系统架构搭建，从概念到可运行框架**

作为 AI 自学者，我对 RAG 的理解停留在文档阅读层面，不清楚如何将 LangChain、Milvus、FastAPI 等组件串联成可运行系统。TRAE 将开发工作拆解为标准化落地流程，覆盖项目骨架、数据层设计、API 接口、Agent 编排全链路。

初期我打算用单一路由策略处理所有用户提问，TRAE 结合教育场景的多样性，提出三层递进路由方案——规则匹配（0ms）→ 相似度匹配（~50ms）→ LLM 分类（~300ms），FAQ 高频问题走快速通道，复杂知识点走深度推理。后续陆续新增知识图谱增强、Reranker 重排序等模块，整套架构无需大幅改动就能兼容。

同时，TRAE 批量生成标准化 CRUD 代码，快速完成 FastAPI 路由、Vue 3 前端页面、JWT 鉴权等通用逻辑，高效搭建学生端 6 页 + 管理端 6 页基础框架，节省大量重复开发时间，让我可以专注核心 RAG 管道研发。

**阶段二：消融实验设计，用数据验证架构决策**

消融实验（Ablation Study）是我此前完全没接触过的领域。TRAE 帮我从零搭建了完整的实验框架——4 层（FAQ 层、路由层、策略层、检索层）× 4 变体 = 16 组独立实验，使用真实 LangGraph ReAct Agent 流水线评估每个组件的独立贡献。

实验框架覆盖 6 项指标：BLEU-1/2（生成质量）、ROUGE-L（召回率）、F1（检索精度）、MRR（排序质量）、NDCG（归一化折损累计增益）、Hit Rate（命中率）。TRAE 还辅助实现了统一评测器，集成了检索指标、生成指标和 LLM Judge 三重评估。

最终产出完整的消融评估报告，量化了每个组件的贡献——BM25 关键词检索对 F1 贡献最大（+0.064 vs 基线），HyDE 策略在 BLEU-1 上表现最佳（0.321），用数据证明了不同场景需要不同策略组合的架构设计合理性。

**阶段三：Bug 修复与性能优化，让系统从"能跑"到"可靠"**

消融实验不仅验证了架构设计，还暴露了两个关键性能问题。TRAE 辅助完成了系统性诊断与精准修复：

问题一：Reranker 导致 BLEU-1 退化 20.9%。TRAE 辅助定位根因——文档截断 500 字符丢失了 60-70% 的教育内容、top_n=3 丢弃了 40% 的相关文档、instruct prompt 使用通用 web 搜索描述而非教育领域。精准修复 3 处代码后，Reranker 对 F1 贡献从 -0.0035 转为 +0.0197。

问题二：向量检索静默失效。所有变体检索结果 score 全为 0.0，但系统不崩溃不报错。TRAE 辅助追踪根因链——Milvus 不返回 embedding → np.array(None) 产生 0 维 nan → cosine_similarity 静默返回 0.0 → 向量检索完全失效。精准修复 5 处代码（覆盖 vectorizer、vector_retriever、hybrid_retriever、milvus_db、ablation 共 5 个文件），修复后向量检索恢复正常。

倘若仅靠我单人摸索，光是定位这些深层 Bug 的根因就要耗费数天，TRAE 将调试周期从小时级缩短到分钟级。
