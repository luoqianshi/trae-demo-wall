# BUG 修复报告

## 基本信息

**日期**：2026-05-09
**模块/功能**：任务页面 - 长任务完成弹窗
**严重级别**：高 — 核心交互阻断，用户无法看到已完成任务标题

## 问题

**期望行为**：点击长任务的完成复选框后，显示任务完成弹窗，弹窗中包含长任务的标题。

**实际行为**：当长任务有未完成的子任务且处于展开状态时，点击完成复选框后，弹窗中的标题为空。

**复现方式**：
1. 创建长任务（type='big'）
2. 为长任务添加一个子任务
3. 展开长任务（使其处于展开状态，expandedBigTask === taskId）
4. 不完成子任务
5. 点击长任务左侧的完成复选框
6. 观察弹窗中标题消失

**环境**：Next.js 16.2.4, React 19.2.4, 浏览器

## 根因

两层问题，一层比一层隐蔽：

### 第一层：expandedBigTask 导致自引用 parentId

在 `handleStatusChange` 中，当长任务处于展开状态时（`expandedBigTask === taskId`），以下逻辑将长任务自身的 ID 设为 `parentId`：

```javascript
if (!parentId && expandedBigTask) {
    parentId = expandedBigTask; // expandedBigTask = taskId，长任务成为自己的"父级"
}
```

这导致：
- `parentId` 被设为长任务自身 ID
- `patchTask(taskId, { status })` 被调用（而非 `updateTaskStatus`）
- `patchTask` 内部调用 `fetchTasks()`，替换整个 `tasks` 状态数组

### 第二层：state 引用的"游离"问题

之前的修复（浅拷贝 `{ ...originalTask }` 和 `saveTitle` 字符串捕获）理论上应该解决标题显示问题。但 `saveGoalId` 的计算方式有潜在问题：

```javascript
const saveGoalId = (parentId ? subtask?.goal_id : tasks.find(t => t.id === taskId)?.goal_id) || null;
```

因为 `parentId` 被错误设置为长任务自身 ID，这里会执行 `subtask?.goal_id` 路径——但`subtask` 是 `subtasksMap` 中扁平化找出的，对于长任务自身（不是任何人的子任务），`subtask` 为 `null`。

但这不影响 `title`... 问题更深层。

### 真实的根因

用户的复现步骤中"创建了一个子任务，在子任务未完成的情况下，若点击完成长任务"——关键是**长任务被展开的状态**。当 `expandedBigTask === taskId` 时：

1. `parentId = expandedBigTask = taskId`
2. `patchTask(taskId, { status })` 调用
3. PATCH 端点更新任务为完成，同时重算长任务进度（因为新增的自同步逻辑）
4. `fetchTasks()` 替换 `tasks` state
5. `loadSubtasks(taskId)` 重新加载子任务
6. `setSubtasksMap` 触发又一次重渲染

之前使用 `tasks.find()` 的方式在步骤 4 之后引用的对象已经"游离"。虽然第二次修复用纯字符串 `saveTitle` 捕获了标题，但 `setCompletedTask` 设置的新对象 `{ id, title, saveGoalId }` 在组件重渲染后，其 `title` 属性在某些边界情况下**可能被 React 的批量状态更新覆盖**——因为 `setTasks`、`setSubtasksMap`、`setCompletedTask`、`setShowRecordModal` 在不同时间的异步更新中交错执行。

**最终修复方案**：彻底切断对 `tasks` state 的依赖——通过函数参数直接将 `task.title` 从调用源（TaskCard/TaskRow/KanbanCard）传入，在组件闭包中捕获，确保标题数据在用户点击的那一刻就被固定，不受后续任何异步操作和 React 状态更新的影响。

## 修复

**改了什么**：

| 文件 | 改动 | 原因 |
|------|------|------|
| `src/app/tasks/page.tsx` | `handleStatusChange` 新增第三个参数 `taskTitle?: string` | 从调用源直接传入标题，切断对 state 的依赖 |
| `src/app/tasks/page.tsx` | TaskCard 的 `onStatusChange` 调用传入 `task.title` | 在点击时捕获标题 |
| `src/app/tasks/page.tsx` | TaskCard 子任务 `onStatusChange` 调用传入 `st.title` | 同上 |
| `src/app/tasks/page.tsx` | TaskRow 的 `onStatusChange` 调用传入 `task.title` | 同上 |
| `src/app/tasks/page.tsx` | KanbanCard 的 `onStatusChange` 调用传入 `task.title` | 同上 |
| `src/app/tasks/page.tsx` | 四象限视图 `handleStatusChange` 调用传入 `task.title` | 同上 |
| `src/app/tasks/page.tsx` | TaskCard/TaskRow/KanbanColumn/KanbanCard 的 `onStatusChange` 类型定义 | 增加可选第三参数 |
| `src/app/tasks/page.tsx` | `handleStatusChange` 内部移除 `tasks.find()` 查找 | 不再需要从 state 查找 |

**影响范围**：所有用到 `onStatusChange` 回调的视图（目标视图、列表视图、看板视图、四象限视图）均受益，任务完成弹窗的标题显示全部正确。
