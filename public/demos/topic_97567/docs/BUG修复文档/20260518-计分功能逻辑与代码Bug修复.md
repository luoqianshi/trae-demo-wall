# 计分功能逻辑与代码Bug修复

> 修复日期：2026-05-18

## 问题描述

项目计分功能存在以下bug：
1. 长任务(big)在UI上显示的分数与实际计算分数不一致
2. todayStreak计算逻辑与calculateStreakDays函数不一致，导致连续天数显示错误

## 根因分析

### Bug 1: 长任务分数显示错误

**问题**：`SCORE_TEXT_MAP` 中长任务显示 `+5分`，但 `SCORE_VALUES.BIG_TASK_COMPLETED = 8`，实际应显示 `+8分`。

**位置**：`src/app/tasks/page.tsx:41`

**影响**：
- 用户在任务列表中看到长任务显示 `+5分 🎯`
- 实际完成长任务后获得8分
- 造成用户困惑，分数预期与实际不符

**修复**：将 `SCORE_TEXT_MAP.big` 从 `'+5分 🎯'` 改为 `'+8分 🎯'`

### Bug 2: todayStreak计算逻辑不一致

**问题**：`calculateTotalStats` 中 `todayStreak` 使用 `streakScore / SCORE_VALUES.STREAK_DAY + 1` 计算，但这与 `calculateStreakDays` 函数的逻辑不一致。

**位置**：`src/lib/snowball-score-calculator.ts:209`

**影响链**：
- `calculateStreakScore` 设计：今天有记录时不给今天加分，只有连续时才加分
- `calculateStreakDays` 设计：今天有记录时返回1，连续时返回总天数
- 旧计算方式：`streakScore > 0 ? Math.floor(streakScore / SCORE_VALUES.STREAK_DAY) + 1 : 0`
- 问题场景：当只有今天有记录时，`streakScore = 0`，导致 `todayStreak = 0`，但 `calculateStreakDays` 应返回1

**修复**：直接调用 `calculateStreakDays(records)` 获取连续天数，确保逻辑一致性
