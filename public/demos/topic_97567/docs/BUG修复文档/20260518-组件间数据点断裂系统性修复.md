# 组件间数据点断裂系统性修复

> 修复日期：2026-05-18

## 问题描述

项目中多个组件间存在数据流转断裂，导致以下功能异常：
1. 首页挑战功能完全失效，预设挑战任务全部丢失
2. 雪球问答交互后未生成提示卡片且未记录任务
3. 小成功记录在首页完全失败，仅有记录界面才能记录
4. 任务界面创建的任务无法在目标及四象限视图中显示

## 根因分析

### 1. 挑战系统字段不匹配（核心根因）

**问题**：API 存储和返回 `challenge_type` 字段，但前端 `useChallenges` hook 的 `Challenge` 接口使用 `type` 字段。

**影响链**：
- `useChallenges.ts` 中 `challenges.filter(c => c.type === 'bronze')` 始终返回空数组
- `ChallengeCard.tsx` 中 `challenge.type` 为 `undefined`，导致 `DIFFICULTY_CONFIG[challenge.type]` 回退到 bronze
- `isBronze` 和 `isSilverOrGold` 判断全部失败，挑战卡片显示异常
- `dailyChallenge` 始终为 `null`，首页显示"今日挑战已结束"

**修复**：在 API 响应中添加 `type: challenge.challenge_type` 字段映射，确保前端能正确读取。

### 2. 任务系统字段不匹配（核心根因）

**问题**：API 存储和返回 `task_type` 字段，但前端 `useTasks` hook 的 `Task` 接口使用 `type` 字段。

**影响链**：
- 首页 `bigTasks` 过滤 `t.type === 'big'` 始终返回空数组
- 任务页 `groupedTasks` 中 `t.type === 'big'/'quick'/'habit'/'normal'` 全部返回空
- 任务在目标视图和四象限视图中不可见

**修复**：在所有任务 API 响应中添加 `type: task.task_type` 字段映射。

### 3. 任务创建 goal_id 始终为 null

**问题**：`handleCreateTask` 中硬编码 `goal_id: null`，且 `CreateTaskModal` 无目标选择功能。

**影响**：创建的任务无法关联目标，在目标视图中不可见。

**修复**：
- 在 `CreateTaskFormData` 接口中添加 `goal_id` 字段
- 在 `CreateTaskModal` 中添加目标选择下拉框
- 在任务页传递 `goals` prop 并使用 `data.goal_id`

### 4. 四象限视图排除 quick/habit 类型任务

**问题**：四象限 API 仅过滤 `task_type === 'normal' || task_type === 'big'`，排除 quick 和 habit 类型。

**修复**：改为 `!t.parent_id` 过滤（显示所有顶层任务），并添加 `type` 字段映射。

### 5. 雪球问答后缺少任务创建机制

**问题**：`onRecordFromAnswer` 回调仅创建记录，不创建关联任务。

**修复**：
- 修改 `DailyQuestion` 组件传递 `questionText` 参数
- 在首页回调中，回答后自动创建 quick 类型任务
- 将 `createTask` 通过 prop 传递到 `MainContent` 组件

### 6. 小成功记录类型不匹配

**问题**：`handleQuickRecordSubmit` 参数类型使用 `related_goal_id`，但 `QuickRecord` 组件发送 `related_task_id`。

**修复**：统一为 `related_task_id`，并添加 try-catch 错误处理。

## 组件交互规范

### API 响应字段映射原则

所有 API 响应必须同时包含数据库原始字段和前端期望的字段名：
- 挑战：`challenge_type`（数据库）→ `type`（前端）
- 任务：`task_type`（数据库）→ `type`（前端）

### 组件通信规范

1. **回调函数签名必须与子组件 prop 类型一致**
   - `QuickRecord.onSubmit` 期望 `related_task_id`，回调必须使用相同字段名
   - `DailyQuestion.onRecordFromAnswer` 现在传递 `(content, questionText?)`

2. **跨组件状态传递**
   - 需要跨组件使用的函数（如 `createTask`）必须通过 props 显式传递
   - 不依赖闭包捕获外部作用域变量

3. **目标关联**
   - 任务创建时必须支持 `goal_id` 关联
   - `CreateTaskModal` 接受 `goals` prop 用于目标选择

4. **四象限视图**
   - 显示所有顶层任务（非子任务），不按 `task_type` 排除
