Hidble：跨网络 HID 蓝牙远程遥控系统

用一部手机作"中继桥"，借助 DKM-10 蓝牙 HID 模块，把控制端的虚拟键鼠指令跨网络送到任意一台电脑——电脑无需安装任何 Agent，插上蓝牙适配器即可被远程操控，并以内置摄像头拍屏 + WebRTC 视频回传形成完整视觉闭环。

赛道：硬件交互 形态：Android App + 云服务器 + DKM-10 HID 桥 创作工具：TRAE IDE 核心模块：DKM-10 / WebRTC / WebSocket
1创意介绍：想解决什么问题

痛点 · 电脑端"无 Agent 远控"几乎不存在

主流远程桌面（向日葵 / ToDesk / RDP）都要求在被控电脑上安装客户端/服务程序。一旦遇到公司禁装软件、公共机房、固障电脑、KVM 受限环境、甚至锁屏蓝屏，传统方案全部失效——你"够不着"那台机器。

方案 · 把电脑当成"蓝牙键鼠"操作

Hidble 利用 DKM-10 蓝牙 HID 桥接模块，让电脑把它识别成一台普通蓝牙键盘鼠标。所有控制指令在电脑看来就是真实的键鼠输入，无需任何 Agent、无需提权、绕过软件策略。受控端手机只负责"中转指令 + 拍屏回传"。

为什么会想到做这个

做远程协助时反复遇到"对方电脑不让装软件"的尴尬；又看到 DKM-10 这类蓝牙 HID 桥模块能被系统原生识别为键鼠，于是想把"硬件级键鼠注入 + 手机摄像头拍屏 + WebRTC 低延迟回传"三者串起来，做成一个真正"零侵入"的跨网络远控工具。

2目标用户与使用场景

远程办公 / 运维

出差时远程操作公司工位机；处理被防火墙隔离的内网设备；夜间响应服务器排障但无法 RDP 时。

IT 技术支持

帮长辈/客户修电脑但对方不会装软件；公共机房、培训机等"禁止装客户端"环境的临时接管。

硬件 / 展示场景

展会现场远距操作演示机；KVM 切换不便时跨房间控制；无障碍辅助——行动不便者用手机当作键鼠操作电脑。

当前痛点（没有 Hidble 时）

① 必须在被控端装 Agent，遇禁装环境直接失败；② 锁屏 / 蓝屏 / BIOS 阶段传统远控全部失效；③ 跨网络 NAT 穿透复杂，个人难部署；④ 硬件 KVM 又贵又只能本地用。Hidble 用一个几十元的蓝牙模块 + 一部旧手机就把这些痛点一次性解决。

3产品形态与核心功能
⌨️

五层叠加遥控界面

视频背景 + 浮动虚拟键鼠叠加层，支持触控板（相对位移）与点击（四点校准绝对坐标）双模式，像用 ToDesk 一样顺手。

🎯

DKM-10 协议对齐

实现四种帧：键盘 HID 报告 / 鼠标相对位移 / ASCII 字符串快发 / 多媒体键；即插即用，连接成功即可发送指令。

📡

云中继 + WebSocket

阿里云 ECS 中转指令，受控端手机收到后通过蓝牙 SPP 转给 DKM-10→电脑；控制端与受控端可在不同网络。

🎥

WebRTC 视觉反馈

受控端后置摄像头拍电脑屏幕 → WebRTC 实时回传控制端作视频背景，形成"看到 = 操作到"闭环，端到端延迟目标 ≤ 600ms。
