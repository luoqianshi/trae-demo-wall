01Demo 简介

hongbaoGE 是一个面向鸿蒙原生 3D 游戏开发的专用引擎。不是跨平台引擎的适配版本，而是从 API 设计、数据格式、工作流三个层面为 AI 协作深度定制的开发工具。同一套 C++20 代码可直接编译成 Windows 桌面游戏和鸿蒙原生应用，开发期在桌面大屏调试，确认无误后上真机验证。

02Demo 创作思路

灵感来源：一直想自己做游戏，但一个人做引擎、做渲染、做工具链，想想就头大。直到 AI 能力爆发，突然意识到可以换个思路 —— 不是我去适配引擎，而是让引擎从设计之初就为 AI 协作而生。

想解决的问题

1

鸿蒙原生工具稀缺

现有方案多为跨平台引擎适配，无法充分利用鸿蒙系统特性（XEngine 光线追踪、FFRT QoS 调度、GPU 内存管控等）。需要一个专门为鸿蒙而生的引擎。

2

AI 参与方式模糊

传统引擎 API 设计未考虑 AI 如何理解，AI 辅助往往停留在代码补全层面。需要让 AI 深度参与场景构建、逻辑编写和渲染管线设计。

3

真机调试成本高

手机屏幕小、迭代慢。Windows 桌面预览让开发效率提升数倍 —— 同一套代码直接编译成桌面游戏，大屏上调场景、调模型、调粒子。

为什么做这个方向：AI 不是后期插件，而是从架构层面预留接口。让 AI 能写代码、能验证、能修正，形成完整的开发闭环。这个理念贯穿了整个引擎的 API 设计、数据格式和工作流设计。

04TRAE 实践过程

开发关键步骤

引擎架构设计

使用 TRAE 完成 ECS 三定律设计、四层分层架构、类型原语统一（SlotHandle / Entity / Guid128 / TypeIndex）。AI 辅助生成了完整的类型系统和内存管理框架。

Vulkan 渲染管线搭建

使用 TRAE 搭建 RenderGraph V3 声明式 pass 编排系统、Forward+/Cluster 渲染路径、PBR 材质管线。AI 辅助编写了完整的 shader 代码和屏障管理逻辑。

鸿蒙平台适配与 XEngine 集成

使用 TRAE 完成鸿蒙 ArkTS/ETS 入口、napi 桥接、FFRT 调度器适配、XEngine 6 项能力接入（空域超分、RTGI、RT 阴影、RT 反射等）。

渲染系统现代化重构

使用 TRAE 推进 5 Stage 渲染系统现代化重构：RenderBackend 统一接管、Vulkan 边界隔离、错误传播链、资源句柄化、删除式迁移。

AI 辅助调试与工程治理

使用 TRAE 排查黑球渲染缺陷、修复纹理摩尔纹、优化 GPU 内存。AI 辅助编写了 AES Guard 23 条规则（16 阻断 + 7 警告）的 pre-commit hook 系统。

四层分层架构

平台壳 (Platform Shell) platforms/desktop/ platforms/ohos/
Windows 桌面入口 + 鸿蒙 ArkTS/ETS 入口 + napi 桥接。通过 IPlatformHost 接口与核心层通信，不包含引擎逻辑。
引导层 (Bootstrap) engine/core/app/
GameMain(App&) 是唯一合法触摸 App 的场所。负责引擎自动装配、game.json 加载、内置插件/资源注册。
服务层 (Service) engine/ 各功能模块
30+ 功能模块：render / scene / physics / animation / audio / input / scripting / particles / navmesh / network 等。每个模块通过 Plugin 注册。
核心层 (Core) engine/core/ engine/render/ engine/resource/
ECS 核心、类型系统、内存管理、作业调度、反射、Vulkan 渲染、资源管理。核心层禁止 include 服务层头文件，无平台条件编译。
