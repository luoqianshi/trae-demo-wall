# Phase 1 — 需求文档（唯一对话阶段）

> Phase 1 是唯一通过对话收集信息的阶段。对话结束后，信息被整理为 `docs/需求/需求输入.md`，后续所有 Phase 均通过读取文件获取输入，不再使用上下文。

## 对话收集点
- 产品名称 / 项目背景
- 核心用户与使用场景
- 业务目标与成功指标
- 功能范围（MVP vs 后续版本）
- 非功能需求（性能、安全、合规等）
- 推进模式选择
- **技术栈选择**：
  - 前端框架（Vue 3 / React / Angular / 其他）
  - 后端语言（Python / Java / Node.js / Go / 其他）
  - 数据库（MySQL / PostgreSQL / MongoDB / SQLite / 其他）
  - 其他技术偏好

## 执行流程
1. **写 Prompt 文件**：根据业务需求动态生成 Prompt 内容，写入 `docs/prompts/phase_1_需求_prompt.md`
2. **读 Prompt 文件**：读取 `docs/prompts/phase_1_需求_prompt.md`
3. **执行作业**：根据 Prompt 文件的指令执行

## Prompt 模板（必要条件）

```markdown
任务：生成项目需求文档与可追溯性报告。

必填结构：
1) 输入：与用户对话收集的业务信息（动态内容）
2) 输出：
   - docs/需求/需求输入.md（结构化 YAML/JSON，必须包含技术栈字段）
   - docs/需求/需求规格说明书.md
   - docs/需求/需求可追溯性报告.md

需求规格说明书.md 结构要求：
- 项目概述（背景、目标、术语表）
- 用户画像与核心场景
- 功能性需求（分模块，REQ-xxx 编号、描述、验收标准）
- 非功能需求
- 范围边界（In Scope / Out of Scope）
- 风险与假设
- MVP 里程碑
- 技术栈确认（前端框架、后端语言、数据库等）

需求可追溯性报告.md 结构要求：
- 输入引用清单
- 输出 → 输入映射表（REQ 编号 → 对话字段）
- 符合项核对清单
- 差异与风险

动态内容补充（根据业务需求）：
- 用户的具体业务场景描述
- 核心功能的详细说明
- 特殊业务规则和约束
```

## 产出
- `docs/prompts/phase_1_需求_prompt.md`（动态生成的 Prompt 文件）
- `docs/需求/需求输入.md`（对话落盘，后续阶段唯一输入源，包含技术栈信息）
- `docs/需求/需求规格说明书.md`
- `docs/需求/需求可追溯性报告.md`
