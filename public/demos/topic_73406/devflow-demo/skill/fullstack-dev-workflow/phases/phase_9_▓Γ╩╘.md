# Phase 9 — 测试计划与测试代码

## 执行流程
1. **写 Prompt 文件**：根据开发产出和技术栈，动态生成 Prompt 内容，写入 `docs/prompts/phase_9_测试_prompt.md`
2. **读 Prompt 文件**：读取 `docs/prompts/phase_9_测试_prompt.md`
3. **执行作业**：根据 Prompt 文件的指令执行

## Prompt 模板（必要条件）

```markdown
任务：基于需求与设计产出测试计划、测试报告与可追溯性报告。

必填结构：
1) 输入：
   - docs/需求/需求规格说明书.md
   - docs/详细需求/模块/*.md
   - docs/API设计/API设计文档.md
   - docs/模块开发/*_前端详细设计.md
   - docs/模块开发/*_前端开发索引.md
   - docs/模块开发/*_后端详细设计.md
   - docs/模块开发/*_后端开发索引.md
   - docs/代码审查/代码审查报告.md
   - src/frontend/ 下所有代码
   - src/backend/ 下所有代码
2) 输出：
   - docs/测试/测试计划.md
   - docs/测试/测试报告.md
   - docs/测试/测试可追溯性报告.md
   - 测试代码（单元/集成/E2E/性能，生成到 src/ 对应位置）

测试计划.md 结构要求：
- 测试范围与目标
- 测试策略（单元/集成/E2E/性能，区分前端/后端）
- 测试环境与数据
- 测试用例清单（每条关联 REQ → API → 数据表 → 开发端）
- 准入 / 准出标准
- 风险与缓解措施

测试报告.md 结构要求：
- 覆盖率统计（前端/后端分别统计）
- 已通过 / 失败用例清单
- 已知缺陷与建议
- 发布建议

测试可追溯性报告.md 必须包含：
- 输入引用清单
- 输出 → 输入映射表（测试用例 → REQ → API → 数据表 → 代码文件 → 开发端）
- 符合项核对清单：
  ✅ 是否符合项目需求
  ✅ 是否符合 API 设计
  ✅ 是否符合数据库设计
  ✅ 是否覆盖审查报告风险点
- 差异与风险

动态内容补充（根据业务需求）：
- 针对所选技术栈的测试框架和工具
- 前端和后端的测试策略差异
- 性能测试和安全测试的具体要求
```

## 产出
- `docs/prompts/phase_9_测试_prompt.md`（动态生成的 Prompt 文件）
- `docs/测试/测试计划.md`
- `docs/测试/测试报告.md`
- `docs/测试/测试可追溯性报告.md`
- 测试代码（生成到 `src/frontend/` 和 `src/backend/` 对应位置）
