# Phase 3 — 详细需求（总览 + 子模块）

## 执行流程
1. **写 Prompt 文件**：根据架构设计和业务需求，动态生成 Prompt 内容，写入 `docs/prompts/phase_3_详细需求_prompt.md`
2. **读 Prompt 文件**：读取 `docs/prompts/phase_3_详细需求_prompt.md`
3. **执行作业**：根据 Prompt 文件的指令执行

## Prompt 模板（必要条件）

```markdown
任务：生成详细需求文档与可追溯性报告。

必填结构：
1) 输入：
   - docs/需求/需求规格说明书.md
   - docs/架构设计/架构设计文档.md
   - docs/架构设计/架构可追溯性报告.md
2) 输出：
   - docs/详细需求/需求总览.md
   - docs/详细需求/需求总览可追溯性报告.md
   - docs/详细需求/模块/<模块名>.md（按模块数量生成）
   - docs/详细需求/模块/<模块名>_可追溯性报告.md

<模块名>.md 结构要求：
- 功能清单（REQ-xxx 编号、优先级）
- 页面 / 交互流程
- 业务规则
- 数据字段（预先列出，与未来 DB / API 对齐）
- 边界条件与异常
- 验收标准

每个 *_可追溯性报告.md 必须包含：
- 输入引用清单
- 输出 → 输入映射表（模块功能 → REQ 编号 → 架构模块）
- 符合项核对清单：
  ✅ 是否符合项目需求
  ✅ 是否依据需求点
  ✅ 是否符合架构设计
- 差异与风险

动态内容补充（根据业务需求）：
- 各模块的具体业务逻辑
- 用户交互的详细流程
- 特殊业务规则和校验条件
```

## 产出
- `docs/prompts/phase_3_详细需求_prompt.md`（动态生成的 Prompt 文件）
- `docs/详细需求/需求总览.md` + `需求总览可追溯性报告.md`
- `docs/详细需求/模块/*.md` + `*_可追溯性报告.md`
