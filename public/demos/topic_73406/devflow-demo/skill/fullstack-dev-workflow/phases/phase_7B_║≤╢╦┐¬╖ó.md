# Phase 7B — 后端分模块开发（优先执行）

> **执行顺序说明**：后端开发应优先于前端开发启动，因为前端依赖 API 接口定义。后端 API 接口开发完成后，前端可并行进行对接开发。

## 执行流程
1. **写 Prompt 文件**：根据开发计划和后端技术栈，动态生成 Prompt 内容，写入 `docs/prompts/phase_7B_后端开发_prompt.md`
2. **读 Prompt 文件**：读取 `docs/prompts/phase_7B_后端开发_prompt.md`
3. **执行作业**：根据 Prompt 文件的指令执行

## Prompt 模板（必要条件）

```markdown
任务：完成所有模块的后端开发，生成后端详细设计、开发索引、可追溯性报告，并更新开发进度矩阵。

必填结构：
1) 输入：
   - docs/需求/需求输入.md（读取技术栈信息）
   - docs/架构设计/架构设计文档.md
   - docs/详细需求/模块/*.md
   - docs/数据库设计/数据库设计文档.md
   - docs/API设计/API设计文档.md
   - docs/开发计划/开发计划文档.md
   - docs/开发计划/开发进度矩阵.md
2) 输出：
   - docs/模块开发/<模块名>_后端详细设计.md
   - docs/模块开发/<模块名>_后端开发索引.md
   - docs/模块开发/<模块名>_后端可追溯性报告.md
   - src/backend/ 下的实际代码

开发流程：
1) 读取 开发进度矩阵.md，筛选出"开发端=后端"或"开发端=全栈"的最小功能单元；
2) 按照矩阵中的依赖关系和优先级确定开发顺序；
3) 按模块依次生成后端代码和文档；
4) **每个模块开发完成后，必须更新 docs/开发计划/开发进度矩阵.md：**
   - 将该模块下所有"开发中"状态的后端功能单元更新为"已完成"
   - 更新"完成日期"字段为实际完成日期
   - 如果有前端功能单元依赖本后端模块且本模块已完成，将前端功能单元的状态从"待开发"更新为"开发中"

<模块名>_后端详细设计.md 结构要求：
- 模块概述
- 目录结构（后端特定）
- 关键类/服务职责
- 数据访问层设计
- API 控制器设计
- 业务逻辑流程
- 中间件与拦截器
- 测试用例清单
- TODO 清单

<模块名>_后端开发索引.md（强制输出）结构要求：
- 代码文件清单（后端）
- 每个文件 ↔ API 接口 ↔ 数据表 ↔ REQ 编号 的映射表
- 依赖的第三方库清单（必须与 架构设计文档.md 保持一致）
- 配置项清单
- 启动 / 构建 / 测试命令
- **开发进度矩阵引用**：列出本模块涉及的所有后端功能单元及其在矩阵中的状态更新情况

<模块名>_后端可追溯性报告.md 必须包含：
- 输入引用清单
- 输出 → 输入映射表（后端代码文件 → API → 数据表 → REQ 编号）
- 符合项核对清单：
  ✅ 是否符合项目需求
  ✅ 是否依据需求点（列出 REQ-xxx）
  ✅ 是否符合架构设计
  ✅ 是否符合 API 设计
  ✅ 是否符合数据库设计
- 差异与风险

动态内容补充（根据业务需求）：
- 针对所选后端语言（Python/Java/Node.js/Go）的开发规范
- 数据库访问层的具体实现
- 认证鉴权的实现细节
- 性能优化方案
```

## 产出
- `docs/prompts/phase_7B_后端开发_prompt.md`（动态生成的 Prompt 文件）
- `docs/模块开发/*_后端详细设计.md`、`*_后端开发索引.md`、`*_后端可追溯性报告.md`
- `src/backend/` 下的后端代码
- 更新后的 `docs/开发计划/开发进度矩阵.md`
