# Phase 6 — 项目开发计划

## 执行流程
1. **写 Prompt 文件**：根据 API 设计和技术栈，动态生成 Prompt 内容，写入 `docs/prompts/phase_6_开发计划_prompt.md`
2. **读 Prompt 文件**：读取 `docs/prompts/phase_6_开发计划_prompt.md`
3. **执行作业**：根据 Prompt 文件的指令执行

## Prompt 模板（必要条件）

```markdown
任务：生成项目开发计划、开发进度矩阵与可追溯性报告。

必填结构：
1) 输入：
   - docs/需求/需求输入.md
   - docs/需求/需求规格说明书.md
   - docs/架构设计/架构设计文档.md
   - docs/详细需求/模块/*.md
   - docs/数据库设计/数据库设计文档.md
   - docs/API设计/API设计文档.md
2) 输出：
   - docs/开发计划/开发计划文档.md
   - docs/开发计划/开发进度矩阵.md
   - docs/开发计划/开发计划可追溯性报告.md

开发计划文档.md 结构要求：
- 阶段划分与里程碑
- 模块优先级与依赖拓扑
- 前后端并行任务清单（按 Sprint 展示）
- 人员分工建议（RACI）
- 风险清单与缓解措施
- 测试策略
- 验收与发布流程
- 交付物清单

开发进度矩阵.md（强制输出）结构要求：

进度矩阵是开发人员确定当前应该开发哪个模块功能的唯一依据。矩阵以"最小功能单元"为粒度，每个单元对应一个可独立交付的功能点。

**矩阵格式（表格形式）：**

| 模块 | 最小功能单元 | 开发端 | REQ编号 | API接口 | 数据表 | 优先级 | Sprint | 状态 | 负责人 | 开始日期 | 完成日期 | 依赖功能 | 验收标准 |

**字段说明：**
- 模块：所属业务模块名称
- 最小功能单元：不可再拆分的功能点（如"用户登录"、"商品列表查询"）
- 开发端：前端 / 后端 / 全栈
- REQ编号：关联的需求编号
- API接口：关联的 API 路径（如 POST /auth/login）
- 数据表：关联的数据表（如 users, sessions）
- 优先级：P0（核心）、P1（重要）、P2（一般）
- Sprint：分配到的迭代（如 Sprint 1）
- 状态：待开发、开发中、已完成、已审查、已测试、已发布
- 负责人：建议的开发人员
- 开始日期：计划开始日期
- 完成日期：计划完成日期
- 依赖功能：本功能依赖的其他最小功能单元（按单元名称引用）
- 验收标准：完成本功能的验收条件

**矩阵使用规则：**
1. 开发人员应优先开发"待开发"且"依赖功能已完成"的单元
2. 每个功能单元开发完成后，需将状态从"开发中"更新为"已完成"
3. 状态流转：待开发 → 开发中 → 已完成 → 已审查 → 已测试 → 已发布
4. **后端优先原则**：后端功能单元应优先于前端功能单元启动开发

开发计划可追溯性报告.md 必须包含：
- 输入引用清单
- 输出 → 输入映射表（Sprint → 模块 → 开发端 → REQ 编号 → API → 数据表）
- 符合项核对清单：
  ✅ 是否符合项目需求
  ✅ 是否覆盖所有模块
  ✅ 是否符合架构/API/数据库设计
- 差异与风险

动态内容补充（根据业务需求）：
- 针对所选技术栈的开发计划安排
- 前后端协作策略（后端优先，前端在 API 定义完成后并行）
- 技术难点的时间预留
```
