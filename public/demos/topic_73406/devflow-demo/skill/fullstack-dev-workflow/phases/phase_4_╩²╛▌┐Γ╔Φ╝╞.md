# Phase 4 — 数据库设计

## 执行流程
1. **写 Prompt 文件**：根据详细需求和技术栈，动态生成 Prompt 内容，写入 `docs/prompts/phase_4_数据库设计_prompt.md`
2. **读 Prompt 文件**：读取 `docs/prompts/phase_4_数据库设计_prompt.md`
3. **执行作业**：根据 Prompt 文件的指令执行

## Prompt 模板（必要条件）

```markdown
任务：生成数据库设计文档与可追溯性报告。

必填结构：
1) 输入：
   - docs/需求/需求规格说明书.md
   - docs/详细需求/模块/*.md
   - docs/详细需求/模块/*_可追溯性报告.md
2) 输出：
   - docs/数据库设计/数据库设计文档.md
   - docs/数据库设计/数据库可追溯性报告.md

数据库设计文档.md 结构要求：
- 选型与理由（与 需求输入.md 中的数据库选择对齐）
- ER 图（Mermaid）
- 表/集合结构（snake_case 命名，字段含义/类型/约束/默认值/可空）
- 主外键与关系
- 索引与查询优化策略
- 数据一致性与事务策略
- 迁移与版本演进
- 数据安全

数据库可追溯性报告.md 必须包含：
- 输入引用清单
- 输出 → 输入映射表（表/字段 → 模块数据字段 → REQ 编号）
- 符合项核对清单：
  ✅ 是否符合项目需求
  ✅ 是否依据需求点
  ✅ 是否符合详细需求模块
- 差异与风险

动态内容补充（根据业务需求）：
- 针对所选数据库类型的设计要点
- 业务数据的特殊存储需求
- 性能优化的具体策略
```

## 产出
- `docs/prompts/phase_4_数据库设计_prompt.md`（动态生成的 Prompt 文件）
- `docs/数据库设计/数据库设计文档.md`
- `docs/数据库设计/数据库可追溯性报告.md`
