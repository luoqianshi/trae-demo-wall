# Phase 7A — 前端分模块开发（后端 API 定义完成后并行）

> **执行顺序说明**：前端开发应在后端 API 接口定义完成后启动，可与后端开发并行进行（后端继续开发其他模块时，前端可开始对接已完成的 API）。

## 执行流程
1. **写 Prompt 文件**：根据开发计划和前端技术栈，动态生成 Prompt 内容，写入 `docs/prompts/phase_7A_前端开发_prompt.md`
2. **读 Prompt 文件**：读取 `docs/prompts/phase_7A_前端开发_prompt.md`
3. **执行作业**：根据 Prompt 文件的指令执行

## Prompt 模板（必要条件）

```markdown
任务：完成所有模块的前端开发，生成前端详细设计、开发索引、可追溯性报告，并更新开发进度矩阵。

必填结构：
1) 输入：
   - docs/需求/需求输入.md（读取技术栈信息）
   - docs/架构设计/架构设计文档.md
   - docs/详细需求/模块/*.md
   - docs/API设计/API设计文档.md
   - docs/开发计划/开发计划文档.md
   - docs/开发计划/开发进度矩阵.md
2) 输出：
   - docs/模块开发/<模块名>_前端详细设计.md
   - docs/模块开发/<模块名>_前端开发索引.md
   - docs/模块开发/<模块名>_前端可追溯性报告.md
   - src/frontend/ 下的实际代码

开发流程：
1) 读取 开发进度矩阵.md，筛选出"开发端=前端"或"开发端=全栈"且依赖后端模块已完成的最小功能单元；
2) 按照矩阵中的依赖关系和优先级确定开发顺序；
3) 按模块依次生成前端代码和文档；
4) **每个模块开发完成后，必须更新 docs/开发计划/开发进度矩阵.md：**
   - 将该模块下所有"开发中"状态的前端功能单元更新为"已完成"
   - 更新"完成日期"字段为实际完成日期

<模块名>_前端详细设计.md 结构要求：
- 模块概述
- 目录结构（前端特定）
- 关键组件职责
- 页面路由设计
- 状态管理方案
- API 对接点
- 表单与交互设计
- 测试用例清单
- TODO 清单

<模块名>_前端开发索引.md（强制输出）结构要求：
- 代码文件清单（前端）
- 每个文件 ↔ API 接口 ↔ REQ 编号 的映射表
- 依赖的第三方库清单（必须与 架构设计文档.md 保持一致）
- 配置项清单
- 启动 / 构建 / 测试命令
- **开发进度矩阵引用**：列出本模块涉及的所有前端功能单元及其在矩阵中的状态更新情况

<模块名>_前端可追溯性报告.md 必须包含：
- 输入引用清单
- 输出 → 输入映射表（前端代码文件 → API → REQ 编号）
- 符合项核对清单：
  ✅ 是否符合项目需求
  ✅ 是否依据需求点（列出 REQ-xxx）
  ✅ 是否符合架构设计
  ✅ 是否符合 API 设计
- 差异与风险

动态内容补充（根据业务需求）：
- 针对所选前端框架（Vue/React/Angular）的开发规范
- 组件化设计原则
- 样式和交互的具体要求
- 性能优化方案
```

## 产出
- `docs/prompts/phase_7A_前端开发_prompt.md`（动态生成的 Prompt 文件）
- `docs/模块开发/*_前端详细设计.md`、`*_前端开发索引.md`、`*_前端可追溯性报告.md`
- `src/frontend/` 下的前端代码
- 更新后的 `docs/开发计划/开发进度矩阵.md`
