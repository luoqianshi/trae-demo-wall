# Phase 2 — 架构设计文档

## 执行流程
1. **写 Prompt 文件**：根据需求输入中的技术栈和业务需求，动态生成 Prompt 内容，写入 `docs/prompts/phase_2_架构设计_prompt.md`
2. **读 Prompt 文件**：读取 `docs/prompts/phase_2_架构设计_prompt.md`
3. **执行作业**：根据 Prompt 文件的指令执行

## Prompt 模板（必要条件）

```markdown
任务：生成架构设计文档与可追溯性报告。

必填结构：
1) 输入：
   - docs/需求/需求输入.md
   - docs/需求/需求规格说明书.md
   - docs/需求/需求可追溯性报告.md
2) 输出：
   - docs/架构设计/架构设计文档.md
   - docs/架构设计/架构可追溯性报告.md

架构设计文档.md 结构要求：
- 设计原则与约束
- 总体架构（Mermaid 分层图 + 模块关系图）
- 技术选型与理由（与 需求输入.md 中的技术栈严格对齐）
- 核心模块职责
- 部署与拓扑
- 安全架构
- 性能与扩展性设计
- 技术风险与对策

架构可追溯性报告.md 必须包含：
- 输入引用清单（列出上述三个文件）
- 输出 → 输入映射表（架构章节 → REQ 编号）
- 符合项核对清单：
  ✅ 是否符合项目需求
  ✅ 是否依据需求点（列出 REQ-xxx）
  ✅ 是否符合已声明的技术栈
- 差异与风险

动态内容补充（根据业务需求）：
- 针对所选技术栈的架构设计要点
- 针对业务特点的技术方案
- 性能和安全方面的具体考虑
```

## 产出
- `docs/prompts/phase_2_架构设计_prompt.md`（动态生成的 Prompt 文件）
- `docs/架构设计/架构设计文档.md`
- `docs/架构设计/架构可追溯性报告.md`
