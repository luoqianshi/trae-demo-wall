# 文档驱动，而非上下文驱动

## 一句话总结

Fullstack Dev Workflow 的核心设计原则：**所有信息存储在文件中，不在对话上下文里。随时重开会话，读文件即可继续。**

---

## 问题：AI 编码为什么不可靠？

用 AI 辅助开发时，最常见的崩溃场景：

- 对话太长，AI 忘记了前面确定的架构决策
- 上下文窗口溢出，AI 开始编造不存在的接口
- 会话中断后，重新开一个对话，之前的一切全丢了
- AI 说"我记得"，但实际上它在猜

**根本原因**：把项目的"记忆"放在了对话上下文里。上下文是有限的、会丢失的、不可靠的。

---

## 解法：把记忆外化到文件中

Fullstack Dev Workflow 的做法很简单——

```
对话上下文是临时的，文件是永久的。
AI 不应该"记住"项目，而应该"读取"项目。
```

### 具体实现

每个开发阶段做两件事：

1. **生成 Prompt 文件** → `docs/prompts/phase_N_xxx_prompt.md`
2. **读取 Prompt 文件执行** → 产出文档 + 代码 + 追溯报告

```
Phase 1: 生成 prompt → 读 prompt → 产出 需求规格说明书.md
Phase 2: 生成 prompt → 读 prompt → 产出 架构设计文档.md
Phase 3: 生成 prompt → 读 prompt → 产出 详细需求/*.md
  ...
Phase 9: 生成 prompt → 读 prompt → 产出 测试报告.md
```

每个阶段的 Prompt 文件里写明了：
- **输入**：需要读取哪些前序文件（精确到路径）
- **输出**：需要生成哪些文件（精确到路径）
- **约束**：技术栈模板、业务规则、质量标准

AI 不需要"记住"任何东西。打开文件，信息就在那里。

---

## 结果：随时可以重开会话

### 场景 1：会话中断

```
对话到一半，关了电脑。
第二天打开 TRAE，新建会话。
告诉 AI："继续 Phase 5"。
AI 读取 docs/ 下已有的文件，从 Phase 5 继续。
```

不需要把之前的对话内容复制粘贴过来。文件就是全部上下文。

### 场景 2：换一台电脑

```
在公司电脑上做到 Phase 6。
回家换一台电脑，打开 TRAE。
把项目文件夹同步过来，新建会话。
告诉 AI："从 Phase 7 开始"。
```

完全无缝。因为所有状态都在文件里，不在某台机器的某个会话里。

### 场景 3：上下文溢出

```
对话已经很长了，AI 开始"犯迷糊"。
不需要担心。关掉对话，新开一个。
AI 读文件，不读上下文。
```

---

## 为什么这很重要？

| | 上下文驱动 | 文档驱动 |
|---|---|---|
| 信息存储 | 对话历史（会丢失） | 文件系统（永久） |
| 会话中断 | 全部丢失，无法恢复 | 读文件继续，零损失 |
| 上下文溢出 | AI 开始幻觉 | 不受影响，只读文件 |
| 换会话/换设备 | 不可能 | 随时可以 |
| 可复现性 | 无法复现 | 同样的文件 → 同样的产出 |
| 质量保障 | 依赖 AI 的"记忆力" | 依赖文件的准确性 |

---

## 防幻觉的三层机制

### 第一层：Prompt 文件隔离

AI 每次执行前，先读取一个专门生成的 Prompt 文件。这个文件包含了当前阶段需要的所有指令。AI 不会从对话历史中"回忆"信息，而是从文件中"读取"信息。

### 第二层：前序文件依赖

每个阶段的 Prompt 明确列出了需要读取的前序文件。如果前序文件不存在，说明前序阶段没有完成，必须先执行前序阶段。这保证了流程的完整性和一致性。

```
Phase 5 的 Prompt 里写着：
  输入文件：
    - docs/需求/需求规格说明书.md
    - docs/架构设计/架构设计文档.md
    - docs/详细需求/模块/*.md
    - docs/数据库设计/数据库设计文档.md
  
  如果这些文件不存在 → 报错，先执行前序阶段
```

### 第三层：可追溯性报告

每个阶段不仅产出主文档，还产出一份可追溯性报告，回答：
- 是否符合需求？依据是哪个需求点？
- 是否符合架构设计？
- 是否符合 API / 数据库设计？

这是质量门禁，也是进入下一阶段的前提条件。

---

## 总结

> **不要教 AI 记住你的项目，让 AI 去读你的项目。**

Fullstack Dev Workflow 用 9 个阶段、30+ 文档、严格的前序依赖和可追溯性报告，构建了一套**不依赖对话上下文**的开发工作流。

- 不需要维护长对话
- 不需要担心上下文溢出
- 不需要害怕会话中断
- 随时重开，随时继续

**文件就是唯一的真相来源。**
