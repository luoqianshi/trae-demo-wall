用AI设计高并发秒杀系统的完整架构

我要设计一个秒杀系统，预期峰值 QPS 10 万，库存 1 万件。最核心的问题是怎么保证不超卖，同时系统不崩？

这是典型的热点库存高并发场景。核心思路是「分层过滤 + 异步削峰 + 最终一致」：前端按钮置灰挡住无效请求，网关层令牌桶限流，应用层请求进消息队列，异步消费者用 Redis Lua 脚本原子扣减库存...

Redis 扣减库存如果 Redis 挂了怎么办？库存数据丢了就麻烦了。

好问题。建议 Redis Cluster 主从+哨兵，但更关键是兜底策略：开售前预热库存到 Redis，同时 DB 保存一份；Redis 扣减成功后立即发 MQ，消费者异步写 DB...
