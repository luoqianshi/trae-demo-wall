## 1. 架构总览

### 1.1 现有 Demo 架构图

Demo 阶段为**纯前端单页应用（SPA）**，无后端服务，所有业务逻辑、数据存储与状态管理均在浏览器侧完成。

```
┌─────────────────────────────────────────────────────────────┐

│                                                             │

│  │   .html      │    │ (~7200行)    │    │  (~547行)    │    │
│  │  32个screen  │    │  339个函数   │    │  22个函数    │    │
│  │ 12个静态HTML │    │  状态管理    │    │ IIFE封装     │    │

│  │  路线数据(routeData) │ 引导步骤 │ 摄像头模拟           │    │

└─────────────────────────────────────────────────────────────┘
                          │
                          ▼ （无后端调用）
                    ✗ 无服务端通信
```

**关键特征：**

- 单文件 `App.js` 承载全部 339 个函数，通过 `window` 全局作用域暴露，供 `innerHTML` 中 `onclick` 绑定调用。
- 页面路由通过 `showScreen(screenName)` 函数统一管理 32 个 screen 的显隐（位于 `App.js:583`）。
- 数据持久化依赖 `localStorage`（用户、会话、角色）。
- 语音播报使用浏览器原生 `speechSynthesis`（`App.js:520` 的 `speak()` 函数）。
- 地图为 SVG 模拟，摄像头为模拟 AI 识别，无真实算法接入。

### 1.3 架构演进路线

| 阶段 | 目标 | 周期 | 关键交付 |
| --- | --- | --- | --- |
| **阶段 0：Demo（当前）** | 验证产品形态与交互流程 | 已完成 | 单文件 SPA、32 个 screen、模拟数据 |
| **阶段 1：前后端解耦** | 拆分前端框架，引入后端骨架 | 1-2 个月 | React Native 工程化、Node.js API 网关、用户服务 MVP |
| **阶段 2：核心微服务** | 完成导航 + AI 视觉 + 社区 | 2-3 个月 | 接入真实地图 SDK、AI 视觉算法、社区内容流转 |
| **阶段 3：家人守护闭环** | 围栏、位置共享、紧急求助 | 1-2 个月 | 围栏预警、实时位置推送、SOS 求助链路 |
| **阶段 4：生产化加固** | 安全、稳定性、规模化 | 1-2 个月 | 容器化部署、监控告警、灰度发布、隐私合规 |
| **阶段 5：智能化演进** | 端云协同 AI 能力 | 持续 | 端侧轻量模型、云侧大模型、个性化推荐 |

**演进原则：**

1. **渐进式迁移**：保留 Demo 作为参考实现，新架构逐步替换，避免大爆炸式重写。
2. **接口先行**：先定义 API 契约，再实现具体服务，保证前后端并行开发。
3. **数据兼容**：迁移期间保留 localStorage 作为离线兜底，逐步过渡到云端持久化。
4. **可观测优先**：每个阶段交付时同步建设监控与日志能力。

### 3.4 事件机制

Demo 阶段支持三类输入事件，适配视障用户的多种交互方式：

| 事件类型 | 触发方式 | 典型应用 |
| --- | --- | --- |

| 触摸事件 | `click` / `tap` | 按钮点击、列表选择 |
| 鼠标事件 | `mousedown` / `mouseup` | 桌面端调试兼容 |

**事件处理流程：**

1. 用户触发事件 →
2. 事件监听器捕获 →
3. 调用对应业务函数（多数通过 `window.*` 全局调用） →
4. 更新全局状态变量 →
5. 触发 UI 重渲染或 `showScreen` 切换 →
6. 调用 `speak()` 进行语音反馈

**生产阶段演进：** 引入手势识别库（如 `react-native-gesture-handler`），增加长按、双指、边缘滑动等手势，并支持自定义手势映射。

### 3.5 语音播报架构

语音播报是视障用户的核心交互通道，Demo 阶段基于 `Web Speech API` 的 `speechSynthesis` 实现。

#### 3.5.1 当前实现（`App.js:520`）

```javascript
function speak(text) {
  if ('speechSynthesis' in window) {
    window.speechSynthesis.cancel(); // 清空队列
    const utterance = new SpeechSynthesisUtterance(text);
    utterance.lang = 'zh-CN';
    utterance.rate = speechRate; // 全局语速控制
    window.speechSynthesis.speak(utterance);
  }
}
```

**特征：**

- 单一队列，新播报会取消旧播报（`cancel()`）。
- 无优先级区分，导航指令与提示音同等处理。
- `lastSpeech` 记录上次播报内容，用于去重。

#### 3.5.2 目标语音架构

```
┌──────────────────────────────────────────────────┐
│                  语音播报管理器                    │
│                                                  │
│  ┌────────────┐  ┌────────────┐  ┌────────────┐  │
│  │ 高优先级   │  │ 中优先级   │  │ 低优先级   │  │
│  │ 队列       │  │ 队列       │  │ 队列       │  │
│  │            │  │            │  │            │  │
│  │ SOS求助    │  │ 导航转向   │  │ 路况提示   │  │
│  │ 危险告警   │  │ 围栏预警   │  │ 社区通知   │  │
│  │ 紧急消息   │  │ 路线变更   │  │ 状态播报   │  │
│  └─────┬──────┘  └─────┬──────┘  └─────┬──────┘  │
│        │               │               │         │
│        └───────────────┼───────────────┘         │
│                        ▼                         │
│              ┌──────────────────┐                 │
│              │  TTS 引擎调度    │                 │
│              │ (离线优先+在线)  │                 │
│              └──────────────────┘                 │
└──────────────────────────────────────────────────┘
```

**优先级规则：**

- **P0 紧急**：立即打断当前播报，强制播报（SOS、危险告警）。
- **P1 重要**：当前播报完成后立即播报（导航转向、围栏预警）。
- **P2 一般**：进入队列顺序播报（路况、通知）。

**冷却机制：** `DANGER_COOLDOWN = 15000ms` 防止同类危险告警刷屏，生产阶段沿用并扩展到多类型告警独立冷却。

### 3.6 函数暴露机制（window 全局作用域）

#### 3.6.1 当前实现

Demo 阶段由于使用 `innerHTML` 动态生成 DOM，并通过 HTML 内联 `onclick` 属性绑定事件，需要将函数挂载到 `window` 全局作用域。`App.js` 中存在 **275 处** `window.*` 引用。

**典型模式：**

```javascript
// App.js 中
function handleSOS() { /* ... */ }
window.handleSOS = handleSOS;

// 动态生成的 HTML 中
button.innerHTML = '<button onclick="handleSOS()">SOS</button>';
```

#### 3.6.2 存在的问题

| 问题 | 影响 |
| --- | --- |
| 全局命名空间污染 | 函数名冲突风险高 |
| 无法 Tree-shaking | 全部代码打包，体积膨胀 |
| 难以静态分析 | IDE 跳转、重构困难 |
| 安全风险 | 任意脚本可调用内部函数 |

#### 3.6.3 生产阶段演进

- 改用 React 组件 + 事件委托（`addEventListener`），消除 `onclick` 内联绑定。
- 函数按模块组织，通过 ES Module `import/export` 显式依赖。
- 全局状态收敛到 Redux Store，UI 通过 `useSelector` 订阅。
- 仅保留必要的全局错误处理钩子（如全局异常捕获）。

## 4. 后端架构（目标）

后端采用**领域驱动设计（DDD）**，按业务域拆分为 7 个独立微服务，每个服务可独立部署、独立扩展。

### 4.1 微服务划分

#### 4.1.1 用户服务（User Service）

**职责：** 用户账号全生命周期管理。

| 子模块 | 功能 |
| --- | --- |
| 注册 | 手机号注册、验证码、密码强度校验 |
| 登录 | 密码登录、短信验证码登录、第三方 OAuth2 登录（微信、QQ、Apple） |
| 个人信息 | 资料维护、头像、视障等级、偏好设置 |
| 角色管理 | 视障用户 / 家人角色切换、多角色绑定 |
| 账号安全 | 修改密码、注销账号、设备管理 |

**对外接口示例：**

- `POST /api/v1/users/register`
- `POST /api/v1/users/login`
- `POST /api/v1/users/oauth/{provider}`
- `GET /api/v1/users/me`
- `PUT /api/v1/users/profile`

#### 4.1.2 导航服务（Navigation Service）

**职责：** 路线规划与实时导航。

| 子模块 | 功能 |
| --- | --- |
| 目的地检索 | 地点搜索、POI 推荐、历史目的地 |
| 路线规划 | 步行（盲道优先）、公交、地铁、网约车、室内多模式 |
| 实时导航 | 步进指引、转向提示、距离播报、进度更新 |
| 路线重算 | 偏离检测、自动重算、重算次数限制 |
| 最后一公里 | 精细化引导、AI 视觉辅助触发 |
| 导航记录 | 历史路线、收藏路线、行程统计 |

**关键依赖：** 高德/百度地图 SDK、PostGIS 空间计算、AI 视觉服务（联动）。

#### 4.1.3 AI 视觉服务（AI Vision Service）

**职责：** 环境感知与图像理解，为视障用户提供"第二双眼睛"。

| 子模块 | 功能 | 模型 |
| --- | --- | --- |
| 环境识别 | 障碍物、台阶、红绿灯、斑马线、人行道 | YOLO 系列 |
| OCR | 路牌、门牌、菜单、公交站牌文字识别 | PaddleOCR |
| 深度估计 | 前方障碍物距离估计 | MiDaS |
| 场景理解 | 室内/室外、商场/医院/路口场景分类 | CLIP |
| 车牌识别 | 网约车车牌识别（出租车模式） | LPRNet |

**部署形态：** 云侧 GPU 推理服务（Triton）+ 端侧轻量模型（TFLite）混合，低延迟场景走端侧，复杂场景走云侧。

#### 4.1.4 社区服务（Community Service）

**职责：** 视障用户社区内容流转。

| 子模块 | 功能 |
| --- | --- |
| 帖子 | 发布、编辑、删除、列表、详情 |
| 评论 | 多级评论、回复通知 |
| 互动 | 点赞、收藏、分享 |
| 危险标记 | 用户上报危险点（施工、积水、盲道中断），聚合到导航避障 |
| 内容审核 | 文本/图片审核、敏感词过滤、举报处理 |

**数据特征：** 内容结构灵活，适合 MongoDB 文档存储；危险标记需同步到导航服务作为避障因子。

#### 4.1.5 家人守护服务（Guardian Service）

**职责：** 家人对视障用户的位置守护与安全关怀。

| 子模块 | 功能 |
| --- | --- |
| 位置共享 | 实时位置上报、家人查看、历史轨迹 |
| 围栏 | 地理围栏创建（圆形/多边形）、进入/离开预警 |
| 预警 | 长时间静止、电量低、信号丢失、偏离常规路线预警 |
| 关系绑定 | 家人邀请、双向确认、权限管理 |
| 守护日志 | 预警历史、位置快照、处理记录 |

**实时性要求：** 位置上报频率 5-10 秒，围栏检测延迟 < 3 秒，预警推送延迟 < 5 秒。

#### 4.1.6 消息服务（Message Service）

**职责：** 全渠道消息触达。

| 子模块 | 功能 |
| --- | --- |
| 推送 | APNs（iOS）、FCM（Android）、厂商通道（华为/小米/OPPO） |
| 通知 | 应用内通知、通知中心、未读计数 |
| 即时消息 | 家人聊天、语音消息、图片消息 |
| 语音通话 | VoIP 通话（紧急求助场景） |
| 消息模板 | 预警、邀请、验证码等模板管理 |

**关键能力：** 高送达率（多通道兜底）、低延迟（预警秒级触达）、离线推送支持。

#### 4.1.7 语音服务（Speech Service）

**职责：** 语音交互的全链路支撑。

| 子模块 | 功能 |
| --- | --- |
| TTS | 文本转语音，支持音色、语速、情感 |
| STT | 语音转文本，支持中文识别、方言适配 |
| 唤醒词 | "瞳伴瞳伴"离线唤醒，低功耗常驻 |
| 语音指令 | 意图识别、槽位提取、指令路由 |
| 声纹 | 用户声纹注册、识别（可选） |

**部署形态：** 唤醒词端侧实现（避免常驻录音上传），TTS/STT 云侧调用第三方服务（如阿里云、讯飞）+ 本地缓存。

### 4.2 API 网关

API 网关作为所有外部请求的统一入口，承担横切关注点。

```
客户端请求
    │
    ▼
┌──────────────────────────────────────────┐
│              API 网关职责                  │
│                                          │
│  1. TLS 终结                             │
│  2. 认证鉴权（JWT 校验、Token 刷新）      │
│  3. 请求路由（按路径转发到微服务）         │
│  4. 限流熔断（用户级/IP级/接口级）         │
│  5. 请求/响应日志（链路追踪 ID 注入）     │
│  6. 协议转换（REST ↔ gRPC）              │
│  7. 响应聚合（一个请求拆分多服务调用）    │
│  8. 灰度路由（按用户/地域灰度）          │
└──────────────────────────────────────────┘
    │
    ▼
  各微服务
```

**路由示例：**

| 路径前缀 | 转发服务 |
| --- | --- |
| `/api/v1/users/**` | 用户服务 |
| `/api/v1/nav/**` | 导航服务 |
| `/api/v1/vision/**` | AI 视觉服务 |
| `/api/v1/community/**` | 社区服务 |
| `/api/v1/guardian/**` | 家人守护服务 |
| `/api/v1/message/**` | 消息服务 |
| `/api/v1/speech/**` | 语音服务 |
| `/ws/**` | WebSocket 网关（位置、导航、消息） |

### 4.3 数据库

采用**多语言持久化（Polyglot Persistence）**，按数据特征选择合适存储。

| 数据库 | 用途 | 主要表/集合 |
| --- | --- | --- |
| MySQL | 用户、账号、配置 | `users`、`user_credentials`、`user_preferences`、`oauth_accounts` |
| PostgreSQL + PostGIS | 导航、围栏、位置 | `routes`、`navigation_sessions`、`fences`、`user_locations`、`danger_marks` |
| MongoDB | 社区内容 | `posts`、`comments`、`likes`、`reports` |
| Redis | 会话、缓存、消息队列 | session、hot routes、fence alerts stream |
| MinIO（S3 兼容） | 对象存储 | 图片、语音、OCR 结果、用户头像 |
| Elasticsearch | 搜索 | 地点索引、社区全文检索 |

**数据一致性策略：**

- 用户、账号相关：强一致性（MySQL 事务）。
- 社区内容：最终一致性（MongoDB 副本集 + 异步同步到 ES）。
- 位置、围栏：高可用优先（PostgreSQL 主从 + Redis 缓存）。
- 危险标记 → 导航避障：事件驱动（Kafka），允许秒级延迟。

### 5.3 数据流向

#### 5.3.1 导航流程数据流

```
用户输入目的地
    │
    ▼
导航服务接收请求
    │
    ├─▶ 调用地图 SDK 路线规划 ──▶ 多模式路线候选
    │
    ▼
用户选择路线
    │
    ▼
创建 navigation_session（状态：active）
    │
    ├─▶ 推送路线到客户端
    │
    ▼
导航中（每 5 秒）
    │
    ├─▶ 客户端上报位置 ──▶ 更新 user_locations
    │
    ├─▶ 计算与路线偏差
    │       ├─ 偏离 < 阈值：更新进度，下发下一条指令
    │       └─ 偏离 > 阈值：触发重算
    │                ├─▶ reroute_count++
    │                ├─▶ 调用地图 SDK 重新规划
    │                └─▶ 下发新路线（语音播报）
    │
    ├─▶ 进入最后一公里（pct > 80）
    │       └─▶ 触发 AI 视觉服务（摄像头识别）
    │
    ▼
到达目的地
    │
    ├─▶ 更新 navigation_session（状态：completed）
    ├─▶ 记录导航历史
    └─▶ 推送到达通知
```

#### 5.3.2 紧急求助流程数据流

```
用户触发 SOS（按钮 / 语音 / 手势）
    │
    ▼
客户端发起紧急求助
    │
    ▼
消息服务接收求助请求
    │
    ├─▶ 查询用户绑定的家人列表
    │
    ├─▶ 并行通知：
    │       ├─▶ APNs/FCM 推送（家人 App）
    │       ├─▶ 短信通知（无 App 在线）
    │       ├─▶ VoIP 语音通话
    │       └─▶ 紧急联系人电话拨号
    │
    ├─▶ 启动实时位置流（每 3 秒上报）
    │       └─▶ WebSocket 推送到家人端
    │
    ├─▶ 触发家人守护服务预警记录
    │
    ▼
家人响应求助
    │
    ├─▶ 接听 VoIP 通话
    ├─▶ 查看实时位置
    └─▶ 远程协助（导航到用户位置）
```

#### 5.3.3 围栏预警流程数据流

```
用户位置上报（每 5-10 秒）
    │
    ▼
家人守护服务接收位置
    │
    ├─▶ 写入 user_locations
    │
    ├─▶ 查询用户绑定的所有 active 围栏
    │
    ▼
围栏检测（PostGIS ST_Contains / ST_DWithin）
    │
    ├─▶ 状态变化检测：
    │       ├─ 之前在外，现在在内 → enter 事件
    │       └─ 之前在内，现在在外 → leave 事件
    │
    ▼
```

## 6. 安全架构

### 6.1 认证授权

#### 6.1.1 JWT 认证

```
登录成功
    │
    ▼
签发双 Token
    │
    ├─▶ Access Token（短期，2 小时）
    │       ├─ payload: { userId, role, exp, iat }
    │       ├─ 存储：客户端内存 + AsyncStorage
    │       └─ 用途：API 请求鉴权
    │
    └─▶ Refresh Token（长期，30 天）
            ├─ 存储：HttpOnly Cookie + 服务端 Redis
            └─ 用途：刷新 Access Token
```

**鉴权流程：**

1. 客户端请求头携带 `Authorization: Bearer <access_token>`。
2. API 网关校验签名、过期时间、黑名单。
3. 通过后注入 `X-User-Id`、`X-User-Role` 头转发到微服务。
4. 微服务基于角色做细粒度授权。

#### 6.1.2 第三方 OAuth2 认证

```
客户端
    │
    ├─▶ 拉起第三方 App 授权（微信/QQ/Apple）
    │
    ▼
第三方回调 code
    │
    ▼
用户服务用 code 换取 access_token + openid
    │
    ▼
查询 oauth_accounts 表
    │
    ├─ 已绑定：直接签发本系统 JWT
    └─ 未绑定：引导绑定手机号 → 创建用户 → 绑定 → 签发 JWT
```

**支持的第三方：**

- 微信（开放平台 + 小程序）
- QQ（QQ 互联）
- Apple（Sign in with Apple，iOS 必选）

#### 6.1.3 角色权限矩阵

| 操作 | 视障用户 | 家人 | 管理员 |
| --- | --- | --- | --- |
| 发起导航 | ✓ | ✗ | ✗ |
| 触发 SOS | ✓ | ✗ | ✗ |
| 查看自己位置 | ✓ | ✓ | ✓ |
| 查看被守护者位置 | ✗ | ✓（需绑定） | ✓ |
| 创建围栏 | ✗ | ✓（针对被守护者） | ✗ |
| 发布社区帖子 | ✓ | ✓ | ✓ |
| 审核社区内容 | ✗ | ✗ | ✓ |
| 管理用户 | ✗ | ✗ | ✓ |

### 6.2 数据加密

| 层级 | 加密方式 | 说明 |
| --- | --- | --- |
| 传输加密 | TLS 1.3 | 全站 HTTPS，WebSocket over TLS |
| 密码存储 | bcrypt（cost=12） + 随机 salt | 防彩虹表、防暴力破解 |
| 敏感字段加密 | AES-256-GCM | 手机号、身份证、紧急联系人 |
| 数据库加密 | 透明数据加密（TDE） | 静态数据加密 |
| 对象存储 | SSE-S3 / SSE-KMS | 图片、语音文件加密存储 |
| 客户端缓存 | Keychain（iOS）/ Keystore（Android） | Token、敏感信息安全存储 |

### 6.3 隐私保护

#### 6.3.1 手机号脱敏

- **存储：** 加密后存储（AES-256-GCM），密钥由 KMS 管理。
- **展示：** 脱敏显示 `138****1234`。
- **传输：** 仅在注册/登录场景返回完整手机号，其余接口返回脱敏值。
- **日志：** 严禁记录完整手机号，统一脱敏后落盘。

#### 6.3.2 位置数据保护

| 场景 | 保护措施 |
| --- | --- |
| 实时位置上报 | 仅在导航中 / 围栏开启时上报，结束即停止 |
| 位置数据存储 | 7 天滚动清理，仅保留聚合统计（如常去地点） |
| 位置数据共享 | 仅家人可见，且需用户显式开启位置共享 |
| 历史轨迹 | 默认不存储精确轨迹，仅保留起终点 |
| 离线场景 | 位置数据本地加密缓存，网络恢复后上传 |

#### 6.3.3 其他隐私

- 用户声纹、语音指令：端侧处理优先，不上传原始音频。
- 摄像头图像：端侧推理优先，上传时脱敏（去除背景人脸）。
- 社区帖子中的位置：用户可控是否公开精确位置。

### 6.4 紧急求助安全

| 风险 | 防护措施 |
| --- | --- |
| 误触发 | 长按 3 秒 / 双击确认 / 语音"瞳伴求助" |
| 伪造求助 | 求助请求需携带有效 JWT，绑定设备指纹 |
| 求助被拦截 | 多通道并行通知（推送+短信+VoIP），任一通道成功即记录 |
| 家人未响应 | 自动升级：通知第二联系人 → 拨打 110/120 |
| 求助记录篡改 | 求助全链路日志上链 / 只写日志，不可篡改 |
| 位置泄露 | 求助期间位置仅对家人可见，求助结束后 30 分钟自动关闭共享 |

**邀请流程关键点：**

1. **邀请码机制：** 视障用户生成 6 位邀请码，有效期 24 小时，单次使用。
2. **双向确认：** 家人输入邀请码后，视障用户需在 App 内确认绑定关系。
3. **权限分级：** 家人可查看位置、设置围栏、接收预警，但无法代操作视障用户的导航。
4. **解绑机制：** 任一方可主动解绑，解绑后立即停止位置共享与预警推送。
