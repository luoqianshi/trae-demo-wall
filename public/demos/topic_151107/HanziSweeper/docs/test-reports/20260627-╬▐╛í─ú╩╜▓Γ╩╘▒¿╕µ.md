## 发现的问题

### 🟡 中等问题

#### 1. 棋盘尺寸不随波次扩展

**问题描述**:  
无尽模式的棋盘大小始终为 6x6，不随波次递增。

**复现步骤**:
1. 第 1 波次：6x6 棋盘，3 个汉字，6 个部首
2. 第 2 波次：6x6 棋盘，4 个汉字，8 个部首
3. 第 3 波次：6x6 棋盘，5 个汉字，10 个部首

**预期结果**:  
棋盘尺寸应随波次增加（如 6x6 → 7x7 → 8x8）

**实际结果**:  
所有波次都是 6x6 棋盘

**影响**:  
- 随着汉字数量增加，6x6 棋盘可能过于拥挤
- 后期波次缺乏视觉上的难度提升感

**代码位置**:  
`js/game.js` 第 684 行 `startEndlessWave()` 中 `cfg.width` 和 `cfg.height` 固定

---

### 🟢 轻微问题

#### 3. Skill 文档中的技术陷阱

**问题描述**:  
测试过程中发现了多个技术陷阱，已更新到 Skill 文档。

**具体问题**:
1. **`playwright_evaluate` 不能使用 `return` 语句**  
   - 脚本在 `eval` 上下文中执行，不是函数体
   - 使用 `return` 会报 `SyntaxError: Illegal return statement`

2. **格子属性是 `radicalIndex` 而非 `radical`**  
   - 获取部首内容需通过 `game.board.radicalEntries[cell.radicalIndex].component`
   - 直接使用 `cell.radical` 会返回 undefined

3. **无尽模式测试必须用真实点击**  
   - 用 JS 直接赋值 `game.matchedPairs` 会跳过计分逻辑
   - 导致 score 始终为 0，无法验证计分功能

4. **端口可能不是 3000**  
   - `npm start` 指定 `-l 3000`，但如果 3000 被占用，serve 会自动分配其他端口
   - 需要检查终端输出获取实际端口
