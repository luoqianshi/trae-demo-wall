技术架构

身份、权限、审计、熔断四位一体

1. Agent 注册

创建 Agent，分配 scopes，并签发具备时效性的 JWT。

2. 网关实时校验

按请求路径映射所需 scope，校验 token、Agent 状态和权限范围。

3. 放行或拦截

权限满足则执行，不满足则立即拒绝，并把原因清楚地反馈出来。

4. 全量审计

无论允许还是拒绝，都必须留下审计记录，支持追溯与责任归因。

5. 一键熔断

将 Agent 状态切到 revoked，后续所有请求即时失效。

6. 面向工程化扩展

后续可对接真实数据库、API Gateway、MCP、A2A 和企业审计体系。

评委可能追问

提前准备标准回答

和微软 Entra Agent ID、Okta for AI Agents 有什么区别？

这是一个 MVP 级别的核心机制验证，不是和巨头正面比功能全量。价值在于验证这套模型在国产化、政企合规场景下的可行性。

如何防止 Agent 伪造身份？

令牌由服务端签名，Agent 无法自行伪造合法 token。签名私钥或密钥只在服务端持有，逻辑与企业 SSO 中的签名令牌一致。

未来如何支撑更大规模？

把内存存储换成真实数据库，把拦截器能力抽成独立网关服务，并接入企业现有 API Gateway 或统一身份体系。

和 MCP、A2A 的关系是什么？

当前演示先验证核心令牌与权限模型；工程化时可把权限校验做成 MCP、A2A 等协议中的标准中间件。

主题名：AgentPass —— 面向企业的 AI Agent 身份与权限治理平台 创意介绍： AgentPass 是面向企业内部 AI Agent 的身份认证与权限治理平台。当前企业大规模部署 AI Agent 处理业务，但普遍采用共享 API Key 或冒用人类账号的方式授权，导致 Agent 权限不可控、操作无法归因、出问题难以审计。我基于多年 SSO/身份认证系统实战经验，希望为每个 Agent 签发独立数字身份，动态限定其权限范围与访问时效，并完整记录操作轨迹，让企业“敢于”大规模放权给 Agent，而不是靠信任裸奔。 目标用户及痛点： 面向已经或即将大规模部署内部 AI Agent 的中大型企业 IT/安全负责人，尤其是政企、金融等合规要求高的客户。当前用户在 Agent 数量从几个试点扩张后，普遍不清楚有多少 Agent 在运行、能访问什么数据、出问题时无法定位责任，这是制约 Agent 规模化落地的核心卡点。 创意价值与意义： 商业上卡位企业 Agent 治理这一新兴赛道的先发位置，尤其契合国内政企对自主可控身份基础设施的需求；效率上把事后人工排查变成系统级实时管控；长远看，这类基础设施是 AI Agent 被规模化信任使用的前提，具备明确的社会价值。
