# 动画时序

动画的节奏和音乐的节奏一样——它决定了观众感受内容的情绪。快节奏传递紧张和活力，慢节奏传递沉稳和深度。时序不是技术参数，是内容表达的一部分。

## 核心原则：节奏从内容中感受

不要套用固定的时长和缓动。先感受文字的节奏，再设计动画的节奏：

- **急促的信息**（短句、命令、冲击性数据）→ 动画应该干脆利落
- **舒缓的信息**（解释、叙述、情感表达）→ 动画可以有呼吸感
- **递进的信息**（步骤、层次、推理）→ 动画应该有推进的节奏
- **对比的信息**（转折、对立）→ 动画可以用节奏变化制造张力

## API 概览

WebMotion 通过 `utils.interpolate()` 驱动动画。理解 API 的能力，但不要被预设值限制：

- `utils.interpolate(input, inputRange, outputRange, options)` — 核心插值工具
- `utils.ease.*` — 缓动函数集（linear → elastic，从平直到弹性）
- `utils.bezier(x1, y1, x2, y2)` — 自定义贝塞尔曲线
- `utils.spring(frame, fps, config)` — 物理弹簧动画

API 文档列出了所有可用的缓动函数和预设——它们是你的调色板，不是你的模板。**不要总是用 `outCubic`，要根据内容感受选择。**

## 缓动方向的原则

缓动方向传达物理直觉，观众会下意识感受到：

- **入场用 `ease.out` 系列**：元素带着动量进入，减速到位——像物体落地
- **出场用 `ease.in` 系列**：元素开始慢，加速离开——像物体被抛出
- **循环用 `ease.inOut` 系列**：两端平滑，无突兀感

但这只是默认直觉。有时打破直觉才是好的设计——比如一个重要数据用 `ease.in` 入场（慢慢浮现，制造期待），反而比 `ease.out` 更有戏剧性。

## 时序与 mapping 分离

好的动画代码结构是分离"何时动"和"动到什么值"：

```
// 先定义进度（0→1 的归一化时间）
progress = interpolate(t, [startTime, endTime], [0, 1], { easing, clamp })

// 再从进度派生各个属性
opacity = interpolate(progress, [0, 1], [0, 1])
x = interpolate(progress, [0, 1], [startX, endX])
scale = interpolate(progress, [0, 1], [0.8, 1])
```

这种分离让你可以自由调整缓动曲线而不影响数值映射——是创意探索的基础。

## 时长的思考方式

不要查表选时长。用这些维度思考：

- **内容复杂度**：信息量大的内容需要更长停留时间让观众消化
- **文字长度**：长文字需要更多时间阅读，动画也要更慢
- **情感重量**：重要的内容应该慢，让观众感受其分量
- **场景角色**：开场可以慢一些建立氛围，中间场景可以快一些推进节奏

**原则**：如果观众来不及理解内容，动画就太快了。如果观众感到无聊等待，动画就太慢了。

## 交错入场的设计

多个元素依次出现时，延迟不是随意的——它创造了阅读顺序：

- 最重要的元素先出现（或最后出现作为高潮）
- 延迟间隔应该有节奏感，不是均匀的——可以根据内容重要性调整间隔
- 后出现的元素应该让观众感到"期待被满足"，而不是"又一个来了"

实现方式：为每个元素计算 `localT = Math.max(0, t - element.delay)`，然后用 `localT` 驱动该元素的动画。

## Spring 的使用判断

`utils.spring()` 提供物理弹性效果。何时使用：

- 内容本身有"弹性""活力""年轻"的感觉时
- 需要元素有物理重量感和真实感时
- 不要为了"炫"而用 spring——克制的线性/三次缓动往往更专业

预设有 `gentle`、`wobbly`、`stiff`、`slow`、`molasses`、`bouncy`——但你可以自定义 config 参数创造独特的弹性感。
