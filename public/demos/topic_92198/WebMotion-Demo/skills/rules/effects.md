# 视觉效果

效果是画面的调味料——适量提升风味，过量掩盖食材本味。效果的存在是为了强化内容传达，不是炫耀技术。

## 核心原则：效果有理由才存在

每一个视觉效果都应该能回答"为什么它在这里"：

- 光晕存在 → 因为内容需要氛围感或焦点引导
- 粒子存在 → 因为内容需要空间感或动态感
- 几何装饰存在 → 因为内容需要结构感或科技感
- 如果回答是"因为好看"→ 删掉它

**克制的专业感 > 堆砌的炫技感。**

## 预览级特效（工具栏开关）

WebMotion 提供三种预览级 CSS 特效，独立于场景代码：

| 特效 | 效果 | 何时有用 |
|------|------|---------|
| 噪点 | 胶片质感纹理 | 模拟实物材质、增加非数字化感 |
| 辉光 | 整体发光滤镜 | 科技感内容、发光物体场景 |
| 色相旋转 | 动态色彩变化 | 氛围营造、迷幻效果 |

这些特效默认关闭，仅影响预览。不要在场景代码中手动实现这些效果——它们由工具栏控制。

## 代码级效果的设计思维

场景代码中可以实现的效果，每个都应该有内容理由：

### 光晕与渐变
- 何时使用：需要营造空间深度或聚焦视线时
- 设计思考：光晕的位置应该引导观众看向焦点，不是随意放置
- 实现：`ctx.createRadialGradient()` 配合 `utils.color.rgba()` 控制透明度
- 克制原则：光晕透明度通常很低（0.05-0.2），它是背景氛围不是主角

### 粒子系统
- 何时使用：内容需要表现"汇聚""扩散""流动""能量"等概念时
- 设计思考：粒子的运动模式应该匹配内容的物理隐喻——数据汇聚用向心运动，能量扩散用离心运动
- 性能底线：2D 场景不超过 200 个粒子，3D 场景不超过 500 个
- 避免：不要因为"粒子好看"就加——它必须服务于内容

### 几何装饰
- 何时使用：需要结构感、科技感或作为内容的视觉隐喻时
- 设计思考：几何形状的选择应该有含义——圆形暗示完整/循环，三角形暗示方向/稳定，方形暗示秩序/结构
- 克制：装饰元素透明度低（0.05-0.2），不与内容竞争注意力

## 绘制层级

绘制顺序决定视觉层级（后绘制的在上层）：

1. 背景渐变/底色
2. 装饰效果（光晕、粒子、几何图形）
3. 辅助视觉元素（图标、次要形状）
4. 主文字和核心内容

**核心原则**：越重要的内容绘制越晚（在上层），装饰元素在最底层。

## 效果过度使用的信号

如果你发现自己做了以下任何一件事，说明效果过度了：

- 光晕铺满整个画面——光晕应该是局部的
- 粒子数量接近上限——粒子应该是点缀
- 多种装饰效果同时存在——效果之间会互相干扰
- 装饰元素比内容更亮——本末倒置
- 去掉效果后内容无法独立成立——说明效果在掩盖内容弱点

## 效果与内容的匹配

效果的选择应该由内容驱动，不是由"我会做什么效果"驱动：

- 科技内容 → 几何线条、光晕、冷色调粒子
- 自然内容 → 有机形状、柔和渐变、暖色调
- 数据内容 → 精确的网格、线条、计数动画
- 情感内容 → 柔和的光晕、缓慢的粒子、呼吸感渐变
- 但这些是启发——最好的效果往往是意想不到的匹配

## 高级效果 API 能力

以下能力是场景代码可以调用的视觉工具。它们是"能做什么"的边界描述，不是"怎么做"的固定路径——每次使用都应该从内容需求出发，思考哪个能力服务于当前表达，而不是套用现成方案。

### 渐变填充能力
- `registerElement` 支持 `gradient` 属性，可以为任意元素填充线性或径向渐变
- 渐变让平面形状获得体积感和光感，是摆脱"贴片感"的关键手段
- 设计思考：渐变的方向、起止色应该暗示光源位置或空间纵深，不是随意取色
- 能力边界：渐变是为内容服务的材质语言，不是装饰——当形状本身不需要体积感时不必强加

### 滤镜效果能力
- `ctx.filter` 提供模糊、亮度、对比度等 Canvas 2D 滤镜
- `registerElement` 的 `filter` 属性可对单个元素施加滤镜
- 设计思考：模糊创造景深（远处虚、近处实），是建立画面层次感的核心工具
- 能力边界：滤镜用于引导视线和建立空间关系，不是给所有元素统一加一层"美化"

### 混合模式能力
- `ctx.globalCompositeOperation` 控制图层如何叠加
- `registerElement` 的 `blendMode` 属性决定元素与下层的混合方式
- 设计思考：`lighter`（加法混合）让发光元素真正发光，`multiply` 让元素与背景融合产生材质感，`screen` 适合光效叠加
- 能力边界：混合模式的选择应该由"这个元素在物理上应该如何与背景交互"决定，不是为了"看起来高级"

### 粒子系统能力
- `utils.createParticles(count, positions, options)` 创建粒子，`utils.updateParticles` 更新状态，`utils.drawParticles` 绘制
- 粒子的运动模式（向心、离心、流动、漂浮）应该匹配内容的物理隐喻
- 设计思考：粒子表达的是"汇聚""扩散""流动""能量"等概念，它的运动逻辑即是内容的视觉隐喻
- 能力边界：参见前文粒子系统的性能底线与克制原则——粒子是点缀不是主角

### 噪声函数能力
- `utils.noise(x, y)` 返回二维平滑噪声，`utils.fbm(x, y)` 返回分形布朗运动（多倍频叠加噪声）
- 噪声让运动和形变获得有机感——自然漂浮、烟雾扩散、水面波动都依赖它
- 设计思考：噪声驱动的应该是"看起来不该规则"的元素——自然现象、有机形状、随机扰动
- 能力边界：噪声用于打破机械感，不是给所有运动都加抖动——规则运动有规则运动的表达力

### 路径运动能力
- 元素可以沿定义的路径运动，路径可以是直线、曲线或自定义贝塞尔轨迹
- 设计思考：路径运动的方向和速度曲线本身在传递信息——汇聚暗示聚合，扩散暗示释放，环绕暗示循环
- 能力边界：路径应该由内容的运动隐喻决定，不是为了让东西"动起来"而随便画一条线

### VisualFX 特效库能力
- `utils.fx.backgroundAtmosphere(options)` 生成有层次的大气背景，一步解决"背景不是纯色"的需求
- 特效库封装了常用的视觉质感组合（渐变、暗角、粒子、网格），让背景层快速获得空间感
- 设计思考：特效库是起点不是终点——它提供基础氛围，内容的独特表达仍需在内容层和前景层完成
- 能力边界：特效库提供的是氛围基底，不能替代对每个场景独立设计的视觉深度思考
