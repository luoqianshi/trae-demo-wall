# 代码质量

代码质量规则分为两类：**技术底线**（必须遵守，否则代码会崩溃）和**创作原则**（必须遵守，否则动画千篇一律）。

## 无路径依赖原则（最重要的创作原则）

**每次生成动画，必须从当前文案内容出发重新设计。**

- 每个动画必须独一无二，基于这段文字的语义、情感和结构
- 不得复制粘贴其他场景的代码结构
- 不得使用固定的代码模板——变量名、动画结构、布局方式都要根据内容变化
- 配色方案根据文案情感推导，不固定使用某种配色
- 动画节奏根据文字长度和复杂度动态调整
- 如果文案很短，场景数少、每个场景时长适当延长
- 如果文案很长，场景数多、每个场景聚焦单一要点

### 反模式检测

如果生成的代码出现以下模式，说明在套用模板而非创作：

- 所有场景的变量名都以 `title` 开头 → 应根据内容命名
- 所有场景都用同一种颜色 → 应根据情感选择色彩
- 所有文字动画都从下方 30px 滑入 → 应根据内容语义选择方向
- 所有场景都是居中布局 → 应根据内容结构选择构图
- 所有场景时长都是 3 秒 → 应根据内容复杂度调整

## 技术底线

### 代码结构

每个场景的代码是独立的函数体：

- 2D 场景：接收 `(ctx, t, width, height, utils)`，不使用 return
- 3D 场景：接收 `(THREE, scene, camera, width, height, utils)`，必须 `return function animate(t) { ... }`

### 保留变量（绝对不能重新声明）

代码作为函数体执行，以下变量已作为参数传入，重新声明会导致编译错误：

- 2D 模式：`ctx, t, width, height, utils`
- 3D 模式：`THREE, scene, camera, width, height, utils`

### 禁止事项

- 禁止 `eval()`、`new Function()`、`setTimeout()`、`setInterval()`
- 禁止声明全局变量
- 禁止 `debugger` 语句
- 禁止使用 `document.*`、`window.*`
- 禁止在生成代码中使用 `console.log()`
- 禁止 `import` 或 `require`
- 禁止直接用 `ctx.fillText()` 或 `ctx.fillRect()` 绘制文字和形状——必须用 `utils.registerElement().draw(ctx)`
- 禁止在 3D 场景中手动创建 `THREE.WebGLRenderer`

### 变量声明

- 使用 `var` 而非 `let`/`const`——代码可能多次执行，`var` 允许重复声明
- 变量名使用有意义的英文命名，避免单字母（`i`、`t`、`ctx` 除外）

### 鲁棒性检查

- `registerElement` 调用必须包含 `x`、`y` 属性，且值在画布范围内
- 文字元素必须设置非空 `text` 属性
- 颜色值必须是有效十六进制（`#rrggbb`）或 `rgba()` 字符串
- `utils.interpolate()` 的输入范围必须单调递增

## 性能底线

- 粒子数量上限：200 个（2D）、500 个（3D）
- 避免在动画循环中创建新对象——在初始化阶段预分配
- 避免在每帧中做字符串拼接或正则操作
- 3D 场景：几何体和材质在初始化时创建，`animate()` 中只更新变换

## 元素注册（必须）

所有可编辑元素（文字、形状）必须通过 `utils.registerElement()` 注册，然后调用 `.draw(ctx)` 渲染。这是为了让用户可以在可视化编辑器中选中、拖拽、编辑这些元素。

装饰效果（光晕、粒子、渐变背景）可以直接用 `ctx` 绘制，不需要注册。

**单一渲染路径原则**：同一个视觉内容只用一种方式绘制——文字用 `registerElement('text').draw(ctx)`，不要同时用 `ctx.fillText`。

## 代码注释

- 代码顶部添加一行注释，说明场景的设计意图（不是场景类型，是设计思路）
- 注释使用中文，简洁明了
- 只注释关键逻辑，不逐行注释

## 3D 场景结构

3D 场景必须返回 `animate` 函数。结构思路：

- 初始化阶段：创建几何体、材质、光源，添加到 scene
- `animate(t)` 函数：只更新已有对象的位置、旋转、缩放、材质属性
- 不要在 `animate` 中创建新对象或添加新 mesh
