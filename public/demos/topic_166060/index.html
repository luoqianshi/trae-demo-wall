P0 风险 TRAE SOLO

SSE 任务流多 Worker 状态共享失效

📅 2026-07-15 P0-1 🔍 Senior Mentor 审查发现
⚠️ 问题
  • 多 Worker 部署时事件发布和订阅跨进程不共享
  • 用户 SSE 连接落到不同 Worker → 收不到实时进度
  • 进程内内存字典存储 → 重启即丢失
✅ 修复方案
  • 新建 agent_event_bus_redis.py（Redis Stream 后端，315 行）
  • 模块级路由层 + 环境变量切换 + 不可用自动降级
  • Stream 最大长度 500 + TTL 1h + pipeline 原子化

P0 风险 TRAE SOLO

幂等缓存跨进程不共享 → 重复执行扣费

📅 2026-07-15 P0-2 🔍 Senior Mentor 审查发现
⚠️ 问题
  • 幂等缓存存在各 Worker 进程内存中
  • 用户重试落到不同 Worker → 重复执行 + 重复扣费
  • 可能造成资金损失 + 用户投诉
✅ 修复方案
  • 幂等缓存迁移到 PostgreSQL idempotent_cache 表
  • PG 不可用时 fail-open（返回 None 让请求重新执行）
  • 写入失败仅记录警告日志，不影响主流程
✓ 11 个新测试 ✓ 174 个回归测试 ✓ 跨进程并发 📝 schema_registry.py + migrations.py
⚠
HIGH 已修复

_next_seq 内存泄漏 + publish_task_event 非原子

📅 2026-07-15 HIGH-1 / HIGH-2 🔧 AI 自动修复
⚠️ 问题
  • _next_seq 只在首次 INCR 设置 EXPIRE → key 永久残留
  • XADD 和 EXPIRE 独立命令 → 进程崩溃后 stream 永久残留
  • Redis 内存持续增长，无人值守场景必爆
✅ 修复方案
  • 每次 INCR 后都设置 EXPIRE（幂等）
  • XADD + EXPIRE 用 pipeline 打包为原子操作
  • 内存泄漏风险彻底消除
✓ 原子性验证 ✓ 泄漏测试 📝 agent_event_bus_redis.py L74-107
⚠
MEDIUM 已修复

idempotent_cache 表 expire_time 精度不足

📅 2026-07-15 MEDIUM-1 🔧 AI 自动修复
⚠️ 问题
  • 表结构用 REAL（单精度浮点）
  • 当前 Unix 时间戳 ~17.8 亿，量化步长 ULP 约 128 秒
  • time.time() + 600 可能被四舍五入成 time.time() + 728 → 缓存提前 128 秒过期
✅ 修复方案
  • expire_time 和 created_at 改用 DOUBLE PRECISION
  • 添加自动迁移逻辑（migrations.py）
  • 已运行数据库自动升级
✓ 自动迁移验证 ✓ 精度回归测试 📝 schema_registry.py L286-287
