# TRAE AI 创造力大赛 - 报名帖

## 1. 创意名称 + 创意介绍

**创意名称：AI FileManager — 会思考的文件管家**

**赛道：效率工具赛道**

**想解决什么问题：**
电脑用久了，文件越堆越多——重复文件占着空间不敢删，整理文件夹费时费力，删了又怕以后找不到。市面上文件管理器只会「增删改查」，不会「思考判断」。

**为什么会想到做这个：**
自己有好几个硬盘、网盘，文件散落各处，手动整理了几次都放弃了。后来发现很多文件其实重复了，但靠人工根本找不全。于是想着：为什么不让 AI 来管文件？它记性好、不怕累，还能学习我的整理习惯。

**产品是什么：**
一个跨平台桌面端智能文件管理系统。技术栈：**Tauri + Rust 后端 + Yew WASM 前端 + Python AI 服务 + SQLite 数据库**。能自动识别文件指纹（MD5 + SHA256 双重哈希）、AI 智能分类、虚拟目录整理，并对删除行为做全链路追踪。

**核心亮点：**
- 🧠 **双重哈希指纹**：每份文件用 MD5 + SHA256 双重哈希打上唯一标识，碰撞概率极低
- 📁 **虚拟目录**：物理文件不动，零拷贝整理，告别大文件移动等待
- 🔍 **重复文件检测**：自动扫描并按哈希分组，一眼看出哪些文件占着空间
- 🗑️ **删除审计链**：删除记录 → 删除队列 → 物理删除确认，全链路可追溯，删了也能找回
- 🚀 **分批扫描**：大目录扫描时逐批上报进度，支持随时取消，不卡界面
- 🧩 **模块化架构**：Rust 后端按功能拆分为独立模块，高内聚低耦合，易于维护和扩展

## 2. 目标用户及痛点

**面向哪些用户：**
- **普通办公族**：电脑里文档、图片、下载文件堆积如山，整理无从下手
- **开发者/设计师**：项目文件、素材文件散落各个目录，重复文件多
- **多硬盘/多设备用户**：同时管理本地磁盘、移动硬盘、网盘，缺乏统一索引

**在什么场景下使用：**
- 每天日常使用电脑时，后台自动监控文件变化
- 需要整理文件时，一键让 AI 自动分类
- 删除文件时，系统自动提示是否为重复文件，防止误删
- 换电脑或备份时，快速识别哪些文件已经存在

**当前痛点：**
- 重复文件全靠手动排查，工作量大且容易遗漏
- 文件分类只能靠手动建文件夹，文件移动耗时长（尤其大文件）
- 没有删除审计机制，删了就找不回来
- 跨硬盘、跨设备管理文件时，缺乏统一的索引和检索能力

**数据库设计（5 张核心表）：**
- `file_metadata`：文件元数据（路径、哈希、大小、类型、时间戳）
- `virtual_directories`：虚拟目录结构（支持层级嵌套）
- `virtual_dir_files`：虚拟目录-文件映射（多对多关系）
- `deletion_records`：删除记录审计（保留完整哈希和历史）
- `delete_queue`：删除队列管理（待处理 → 已处理状态流转）

## 4. 价值与创新点

**效率提升价值：**
- AI 自动分类 + 虚拟目录：用户无需移动物理文件即可完成整理，节省 **90%** 的整理时间
- 重复文件自动识别：释放磁盘空间，SSD 硬盘空间利用率提升 **20%-40%**
- 删除审计链：从删除记录 → 删除队列 → 物理删除，全链路可追溯，**100%** 杜绝误删
- 分批扫描 + 进度上报：扫描大目录时实时反馈进度，用户体验大幅提升

**技术创新点：**
- 双重哈希指纹（MD5 + SHA256）确保文件唯一性，碰撞概率极低
- 虚拟目录设计实现零拷贝文件组织，物理文件路径不受影响
- 跨平台文件系统事件监控，无缝接管系统文件管理器操作
- 删除队列 + 审计日志，解决「删了又后悔」的痛点
- 基于 Tauri 的跨平台架构，兼顾性能（Rust）与可维护性（模块化）
- 前端使用 Rust WASM（Yew 框架），与后端共享类型定义，减少序列化开销
- 后端模块化架构（scanner/、monitor/、db/ 子目录拆分），代码层次清晰，易于扩展

**商业价值：**
- 可发展为付费订阅制的文件管理增值服务
- 可与云存储服务（百度网盘、阿里云盘等）集成，提供统一跨平台管理方案
- 核心模块（文件指纹、AI 分类）可独立输出为 API 服务
