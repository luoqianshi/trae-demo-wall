## 0. 先和大家打个招呼吧 👋

大家好，我是一名跨境电商质量业务管理者，也是一名正在转向 AI 产品方向的职场学习者。

我不是前端工程师。最开始，我只有一个很具体的困惑：一个人在旧行业做过很多真实项目，为什么换行业时，这些经验常常像“归零”了一样？

我把这个问题一点点讲给 TRAE：先让它理解“岗位真正要什么价值”，再让它判断“旧经历里有什么证据”，最后要求它在证据不足时不要编答案，而是只问一个最值得补充的问题。

我和 TRAE 的配合更像“业务判断 + AI 落地”：我负责指出哪里不像真实产品、哪里解释不清，TRAE Code / TRAE Work 根据任务文档把想法变成可以点击的单文件 HTML。初版曾经出现过信息换行不合理、步骤一次铺满、缺少补证动作等问题；我继续把问题写成清晰的验收条件，它再把流程改成 7 个可点击阶段、3 个匿名案例和勾选式补证。最让我觉得“原来可以这么简单”的，是一个不需要 API、双击就能体验的 Agent Demo，真的可以从一句业务困惑逐步迭代出来。

## 1. Demo 简介

### 它是什么

迁跃 AI 是一个**可交互的单页 AI Agent 工作台**，专门帮助已有经验的职场人完成跨行业经验迁移。

它不是简历润色工具，也不是求职全流程助手。它只聚焦一个关键场景：

> **旧经验为什么能被目标岗位认可？当前判断还缺什么证据？**

### 它面向谁

- 已有工作经验、准备跨行业或跨职能转岗的职场人；
- 想从传统行业进入 AI 等新赛道的运营、质量、项目管理从业者；
- 做过很多事情，却难以说明“这些经验为什么对新岗位有价值”的人。

### 三项核心能力

#### ① JD 价值解码

Agent 不停留在关键词匹配，而是识别 JD 背后的业务目标、成功信号与目标价值。

#### ② 证据审计 + 唯一最高价值追问

Agent 从经历原文中提取事实，判断关系强弱。证据不足时，不抛出问题清单，只问一个最可能改变判断的问题。

#### ③ 三节点迁移桥 + Transfer Asset

系统用以下结构解释经验为什么能够迁移：

`Experience → Transfer Mechanism → Target Value`

用户确认中/强关系后，才会生成包含旧经验、目标价值、迁移理由、证据链、证据充分度、缺口和下一步行动的 Transfer Asset。

## 2. Demo 创作思路

### 灵感来源

我在准备跨行业转岗时发现，真正困难的不是“没有经验”，而是看不懂目标岗位 JD 背后的真实意图，也不知道旧经历中的哪些事实能被新行业认可。

例如，区域运营中的“识别重复问题、判断优先级、推动试点并复制”，与 AI 产品经理需要的“需求洞察、方案验证、迭代推广”之间，其实存在可迁移的价值机制。但普通关键词匹配很难解释这层关系。

### 想解决的问题

用户通常卡在三层判断：

1. 目标岗位究竟想解决什么业务问题；
2. 旧经历里有哪些可以追溯的行动和结果证据；
3. 两者为什么能够迁移，当前证据还缺什么。

### 为什么做这个方向

我主动放弃了职业规划、简历、面试和入职成长等求职全流程，只保留“经验迁移”这一条闭环。

因为这个场景最能体现 AI Agent 的价值：价值解码 → 证据抽取 → 迁移判断 → 主动追问 → 二次分析 → 用户确认 → 资产生成。它不是一次输入直接生成答案，而是根据证据状态继续行动。

## 6. 补充：我做了哪些取舍

为了让评审在 60–90 秒内看懂核心价值，v0.1 暂不做登录、数据库、后台、长期记忆、真实模型和求职全流程。

当前版本使用本地 Mock 流程，未接真实大模型；输入只存在当前页面内存，刷新即清空。林晨、周衡、叶舒均为匿名虚构 Persona，案例指标只用于演示产品机制。“证据充分度”表示材料是否足以支持迁移判断，不代表录用概率。

其他工具参与的素材整理、独立验收、截图和视频后期，不计入 TRAE Session，也不会被描述为 TRAE 开发过程。
