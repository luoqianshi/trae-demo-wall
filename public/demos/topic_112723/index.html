1 Demo 简介
是什么
Vinyl Glow 是一个 Windows Electron 桌面音乐播放器——透明亚克力窗口里，一张银色光盘跟着音乐转，旁边是专辑封面和播放控件，底部一排缩略图用鱼眼效果放大，中间悬浮一个液态玻璃歌词框折射专辑封面。可以搜索网易云上的歌，直接在线播放。
面向谁
我自己。我每天写代码时听音乐，网易云桌面版功能够用但界面太"软件感"了，Spotify 好看但要付费且曲库不全。我想要一个既有精致视觉质感、又能真正搜歌播放在线音乐的桌面播放器。

后来发现身边不少人也有类似需求——设计师朋友想要桌面有个好看的播放器当"桌面摆件"，程序员同事厌倦了来回切网易云和 Spotify。所以核心用户就是对桌面颜值有要求、但不想将就用丑播放器的人。
主要功能
🎵
在线搜索播放
接入网易云 API，搜歌→点歌→播放全链路。本地 HTTP 代理绕防盗链 + 透传 Range 请求，howler.js html5 模式拖进度条不卡。
💧
液态玻璃歌词框
SVG feTurbulence 噪声 + feDisplacementMap 位移折射，专辑封面做背景，切歌时双层交叉淡化。不是 CSS 渐变假装的玻璃，是真的有折射扭曲。
👁️
鱼眼缩略图栏
鼠标移上去波纹式放大，连续锚点插值算法消除抖动。所有图标底部对齐同一水平线，放大不偏移。最多 12 首 + 末尾加号入口。
💿
光盘旋转 + 封面呼吸
播放时光盘 6 秒/圈匀速旋转，封面 1.012 振幅 sine.inOut 呼吸缩放。真实 PNG 银色光盘贴图，还原物理唱片质感。

2 Demo 创作思路
灵感来源——一个真实的具体场景
事情的起点很简单：我每天写代码时听音乐，网易云桌面版功能够用但界面太"软件感"了——标题栏、侧边栏、播放列表、评论区、MV 入口全堆在一起，我只需要一个能搜歌、能播放、好看的界面，其他全是干扰。Spotify 界面好看但曲库在中国不全，还要付费。

我脑子里一直有个画面：透明窗口里一张银色光盘跟着音乐转，旁边浮着专辑封面，底部一排缩略图鼠标划过去会波纹式放大。白底、干净、有质感。但市面上没有这样的产品——要么功能强但界面丑，要么界面好看但只是静态展示没法播真实音乐。

所以我给自己定了一个目标：用 Electron 做一个透明窗口桌面播放器，接上真实的在线音乐源，把脑子里的这个画面变成真能用的东西。
想解决的具体问题
问题 1：网易云桌面版界面"软件感"太重。标题栏、侧边栏、播放列表、评论区、MV 入口……我写代码时只需要一个能搜歌、能播放、好看的界面，其他都是干扰。

问题 2：Spotify 界面好看但曲库在中国不全，而且要付费。网易云曲库全但界面不好看。没有一个是"既好看又有全曲库"的桌面选择。

问题 3：市面上的音乐播放器要么深色 Material Design，要么传统白底列表，没有"透明玻璃 + 唱片物理质感 + 鱼眼动效"这种路线。审美上缺一个"安静、克制、有材质感"的选择。
为什么做这个方向
做之前我列了几个判断：

1. Electron 能做到 Web 做不到的事。透明窗口（Windows 11 acrylic）、frameless 无边框、本地 HTTP 代理服务器——这些都是纯 Web 做不了的。选 Electron 不是因为它"流行"，是因为这个项目必须用到桌面级能力。

2. NeteaseCloudMusicApi 这个 npm 包让在线音乐成为可能。它封装了网易云的搜索、歌曲 URL、歌词、扫码登录等接口。配合本地 HTTP server 代理，可以解决封面防盗链（Referer 绕过）和音频 CORS + Range（拖进度条必需）问题。

3. GSAP 是做复杂动效的唯一选择。鱼眼波纹放大需要逐帧计算 scale + 偏移量，唱片旋转需要 paused/play 控制，液态玻璃需要 scale + autoAlpha 入场——这些用 CSS animation 做不了，必须用 GSAP 的 quickTo + timeline。

4. 市场上没有同类产品。音乐播放器要么是深色 Material Design（Spotify），要么是传统白底列表（网易云），没有一个是"透明玻璃 + 唱片物理质感 + 鱼眼动效"的路线。
我对审美舒适的理解
做这个项目的过程中，我一直在想一个问题："好看"和"舒适"到底是不是一回事？

我觉得不是。"好看"是第一眼的视觉冲击——配色漂亮、动效炫酷、排版精致。但"舒适"是看了一个小时之后还不觉得累的那种感觉。很多播放器第一眼好看，用久了却觉得"吵"——太多颜色、太多信息、太多动效在抢注意力。

所以 Vinyl Glow 的审美选择，核心原则是"让画面安静下来"：

1. 白底不等于裸白。纯白背景是最偷懒的做法，看起来廉价。Apple 的白底是有材质的——亚克力玻璃的半透明、光影的微妙渐变、卡片的极浅投影。Vinyl Glow 用 Windows 11 acrylic 透明窗口，背景不是一块白板，而是有深度的玻璃层。这种"有材质的白"才是舒适的白。

2. 一个画面只允许一个视觉焦点。光盘在转的时候，封面就不该也在动；鱼眼缩略图在放大的时候，歌词框就不该也在跳。同一时刻只有一个元素在"说话"，其他元素安静配合。这不是偷懒，是克制——克制是审美舒适的核心。

3. 动效要有物理依据，不能凭空蹦。唱片旋转是匀速的（物理惯性），封面呼吸是 sine 曲线（自然呼吸节奏），鱼眼放大是余弦衰减（光学透镜规律）。每个动效背后都有一个物理原型，所以看起来"舒服"——大脑能理解这个运动，不会觉得突兀。CSS ease-in-out 这种万能缓动之所以不舒服，就是因为它没有物理含义。

4. 字体是情绪。启动页用 Pinyon Script 手写体，是因为"Vinyl Glow"这个名字本身就有复古、温润的气质——手写体一笔连下来，像黑胶唱片慢慢落下的唱针。主界面用 Manrope 无衬线，干净利落，不抢封面图的视觉。两种字体对应两种情绪：进场时温柔，使用时专注。

5. 留白不是浪费，是呼吸。主界面上方有大量空白，很多人会觉得"空"。但正是这些空白让光盘和封面有了"舞台感"——就像博物馆里一幅画周围全是白墙，你才会认真看那幅画。信息密度越高越焦虑，留白越多越舒适。

6. 颜色要少，但要准。整个项目只有三个颜色角色：ink 蓝（品牌色，只用在强调处）、mint 绿（状态色，只用在播放/激活态）、灰阶（文字层次）。没有渐变彩虹，没有主题色切换。颜色越少，大脑处理负担越低，舒适度越高。

这些理解不是设计理论教科书上抄来的，是做这个项目过程中一次次调整后的体会——每次觉得"哪里不对劲"，最后发现都是因为违反了上面某一条。
架构设计——混合架构
音乐源接入最纠结的是"纯 IPC 还是纯 HTTP server"。最终选了混合架构——业务逻辑走 IPC 直调，封面/音频走本地 HTTP server 代理：
┌─────────────────────────────────────────────┐ │ 渲染进程 (React) │ │ SearchView → 搜索 → 结果列表 → 点歌 │ │ usePlayer → getSongUrl → wrapAudioUrl │ │ CoverArt / Timeline / LyricFrame / Controls │ └──────────────┬──────────────────────────────┬┘ │ IPC (window.music) │ HTTP ┌──────────────▼──────────────┐ ┌─────────────▼──────────────┐ │ 主进程 (Electron Main) │ │ 本地 HTTP Server (:3000) │ │ NeteaseCloudMusicApi │ │ /api/cover (防盗链 Referer) │ │ cloudsearch / song_url_v1 │ │ /api/audio (Range 透传) │ │ lyric / qr_login │ │ CORS 全开 + Cache-Control │ └──────────────────────────────┘ └─────────────────────────────┘
理由：纯 IPC 的封面/音频 Range 处理代码量大；纯 HTTP server 又要把业务逻辑多包一层。混合架构让封面代理和音频代理照搬已验证的逻辑，业务逻辑直接走 IPC 性能更好。

4 TRAE 实践过程
开发概览
项目从零开始，用 TRAE 完成全部开发，历时 10 天（2026-07-02 ~ 07-11），跨了多次对话。以下是按时间顺序的完整开发过程，包括任务怎么拆、用了 TRAE 哪些能力、关键 Prompt、踩了什么坑、怎么解决的。
1
项目初始化：脚手架 + 透明窗口 + 规则文档
07-02

任务拆解：① 用 electron-vite 搭建项目骨架；② 配置 Windows 11 透明窗口（acrylic 玻璃材质 + frameless 无边框）；③ 建立三份规则文档（AGENTS.md / AI_HANDOFF.md / PROJECT_MEMORY.md）作为 AI 交接机制。

关键 Prompt
"搭建一个 electron-vite 项目，React + TypeScript + R3F + drei + Tailwind + howler + GSAP。配置透明窗口：frame:false + backgroundMaterial:acrylic。另外帮我建三份文档：AGENTS.md 写项目规则和红线，AI_HANDOFF.md 写工作日志和交接信息，PROJECT_MEMORY.md 写稳定事实和踩坑记录。"

TRAE 做了什么：一键生成 electron.vite.config.ts、package.json、主进程入口 electron/main/index.ts、preload 脚本、React 渲染入口。三份规则文档也是 TRAE 根据我口述的项目定位生成的，后续每次新对话先读这三份文件恢复上下文。

踩坑：沙箱环境下 Electron 崩溃
npm run dev 启动后 Electron 直接 ACCESS_VIOLATION 崩溃。TRAE 帮我排查后发现：Electron 启动时写 userData 到 C:\Users\13412\AppData\Roaming\vinyl-glow 被沙箱拦截，导致崩溃。另外 npm install 时 electron 二进制缓存放 AppData\Local\electron\Cache 也被拦。
解决方案
在 electron/main/index.ts 里加 app.setPath('userData', join(__dirname, '../../.electron-data')) 把 userData 重定向到项目内可写目录。安装时设 ELECTRON_CACHE 环境变量指向 Temp 目录。永久修复，不删。
2
启动页开发：从 Lottie 到 CSS 的弯路
07-02 ~ 07-03

任务拆解：① 设计启动页动画（Vinyl Glow 文字浮现）；② 用 lottie-react 渲染；③ 灰屏 debug。

最初方案：用 lottie-main skill 生成 splash.json（720x360，90 帧 @60fps，VINYL GLOW 浮现动画），然后 lottie-react 渲染。

踩坑 1：electron-vite renderer 404 灰屏
npm run dev 后 Electron 灰屏静止。TRAE 建议我用 curl 逐个端点排查：http://localhost:5173/ 返回 404，/src/main.tsx 也 404，只有 /@vite/client 200。根因是 electron-vite 默认把 renderer 的 root 指向 src/renderer，但我的 index.html 在项目根、源码在 src/ 下——dev server 从不存在的目录服务，所有文件 404，Electron 加载空页，body 透明露出 acrylic 灰底。
解决
electron.vite.config.ts 的 renderer 段加一行 root: resolve(__dirname)。验证方法：dev 起来后 curl / 和 /src/main.tsx 必须返回 200。
踩坑 2：lottie-web 渲染不出文字
灰屏修好后，启动页白屏 2.4 秒直接切主界面，看不到任何浮现动画。TRAE 帮我诊断：lottie-web 对 ty:5（native text）渲染不可靠——lottie-main skill 的 player-contract 明确写了"不要用 lottie-web 验证"，skill 是围绕 Skottie 设计的。文字层不可见，所以白屏。
解决：放弃 lottie-web，改用 CSS/DOM
Splash.tsx 改用 DOM <h1> + CSS @keyframes 逐参数复刻 splash.json 设计：opacity 0→1 + translateY 14px→0 + scale 0.97→1，settle-soft cubic-bezier(0,.65,.51,.99)，500ms。结论：文字类动效一律走 CSS/DOM，lottie-web 仅用于纯 shape 动效。

字体选择：后来换成了 Pinyon Script（Google Fonts 手写签名字体），字号定稿 84px。关键细节：签名字体有连笔，不能加负字距（会破坏连笔），不能用全大写。

3
主界面接入 + Timeline 鱼眼动效
07-05 ~ 07-06

任务拆解：① 搭建主播放界面（6 个组件：Logo / CoverArt / TrackInfo / PlayerControls / Timeline）；② 底部缩略图栏扩到 13 个 + 鱼眼波纹放大动效；③ 银色光盘替换 CSS 渐变。

关键 Prompt
"底部选择栏扩到 13 个。鼠标悬浮波纹式跳起：鼠标下方图标最大、向周围依次递减。不管图案多大，所有图标底部始终对齐静止图标的底部水平线。"

TRAE 做了什么：实现了余弦衰减 + 挤开算法——每个图标根据到鼠标的距离计算 scale（余弦衰减），再根据相邻图标的 scale 计算水平偏移（挤开）。底部对齐用 y = -BASE * (scale - 1) / 2 精确抵消放大导致的底部下移。

踩坑 1：后 5 个缩略图无动效
缩略图从 8 个扩到 13 个后，HMR 推送但后 5 个没有 magnify 动效。TRAE 帮我分析源码后发现：useGSAP 没加 dependencies，只在 mount 时跑一次。扩容后组件 re-render 重建了 13 个 button ref，但 useGSAP 不重新执行 → setters.current 还是旧的 8 个 quickTo → applyMagnify 里后 5 个是 undefined → if (!s) return 跳过。
解决
双重保险：① useGSAP 加 dependencies: [songs.length]，长度变化时自动 cleanup 旧 quickTo + 重建；② applyMagnify 加防御性兜底，万一时机错过临时补建 setter。教训：动手前先读完所有相关源代码理解机制，别凭直觉改。
踩坑 2：鱼眼动效抖动
快速滑动鼠标时缩略图剧烈抖动。TRAE 帮我分析根因：之前用离散锚点（鼠标下方 dist 最小的 thumb），鼠标越过两 thumb 中点时锚点瞬间切换 → x 偏移跳变 → CSS transition 不断重启 → 抖动。
解决：连续锚点插值
改用连续锚点：找到鼠标 cx 两侧的 thumb l 和 r，用 t = (cx - rcL) / (rcR - rcL) 插值计算 x 偏移。锚点在两 thumb 之间连续移动，无跳变。配合 RAF 节流（每帧最多一次计算）+ translate3d 硬件加速 + transition 从 0.4s 缩短到 0.32s，快速滑动时更丝滑。

银色光盘：最初用 CSS 渐变模拟银色光盘，但效果太"假"。后来改用真实 PNG 银色光盘贴图（486KB, 655px），放到 public/cd-disc.png。真实贴图的光泽和纹理是 CSS 渐变做不到的——高光、金属质感、同心圆纹路都有。

4
网易云音乐源接入（搜索 + 播放）
07-07 ~ 07-09

任务拆解（分 3 步）：

Step 1：主进程骨架
装 NeteaseCloudMusicApi，建 electron/main/music/ 模块（types / cookie / proxy / netease / index）。proxy.ts 起本地 HTTP server，findOpenPort(3000) 随机端口 + 只绑 127.0.0.1。/api/cover 带 Referer: https://music.163.com/ 绕防盗链 + CORS 全开 + Cache-Control 24h。/api/audio 透传 Range（howler html5 拖进度条必需）。
Step 2：网易云搜索
netease.ts 的 searchNetease = cloudsearch + 缺封面用 song_detail 批量回填。渲染端建 SearchBar / SearchResults / SearchView 组件，App.tsx 接 searchView + handleSelectSong。
Step 3：网易云播放
getNeteaseSongUrl 按 ['exhigh','standard','lossless'] 三 level 候选尝试，优先返回完整 URL，退而求其次返回试听片段（freeTrialInfo 兜底）。usePlayer.ts 重写为参数化 list + 按需 getSongUrl + wrapAudioUrl 包装代理 URL。
关键 Prompt
"参照 Mineradio-main 项目的双源方案，接入网易云搜索和播放。业务逻辑走 IPC 直调 NeteaseCloudMusicApi，封面和音频走本地 HTTP server 代理。分 3 步：先骨架，再搜索，最后播放。每步跑完 typecheck + lint 再下一步。"
踩坑 1：npm install peer 冲突
装 NeteaseCloudMusicApi 时 npm install 报 ERESOLVE peer 冲突：@react-three/drei 要 react^18，但项目用 react 19。TRAE 分析后建议用 --legacy-peer-deps（项目本来就有此冲突，drei 在 react 19 下实际能跑）。
踩坑 2：const enum 在 isolatedModules 下报错
TypeScript strict 模式下，const enum SoundQualityType 不接受字符串字面量赋值。TRAE 定位到 tsconfig 的 isolatedModules: true 导致 const enum 行为变化。
解决
用 level: level as never 绕过类型检查。运行时仍是字符串 'exhigh' 等，NCM 函数接受。不改 tsconfig 配置，影响面最小。

底部菜单栏改造：接入在线音乐后，Timeline 从静态 13 首示例曲改为动态 queue 渲染。末尾加号入口参与现有 magnify 动效（同尺寸同算法零改动）。搜索选歌追加到队列末尾并播放，用 queueMicrotask 确保 setQueue 后再 select，避免拿到未更新的 list。

5
液态玻璃歌词框
07-10 ~ 07-11

任务拆解：① 实现液态玻璃质感（不是 CSS 渐变假装的，要真的有折射扭曲）；② 专辑封面做背景填充；③ 切歌时交叉淡化；④ 无歌隐藏 / 有歌自动弹出。

关键 Prompt
"做一个液态玻璃歌词框，参考 archisvaze/liquid-glass 的方案。要真实的折射效果，不是 CSS 渐变假装的。背景用专辑封面图填充。切歌时双层图片交叉淡化。有歌时显示，无歌隐藏。"

TRAE 做了什么：生成了完整的 LyricFrame 组件，核心是 SVG filter 实现液态折射：

<!-- SVG 液态折射 filter -->
<filter id="liquid-glass-distortion">
  <feTurbulence type="fractalNoise"
    baseFrequency="0.008 0.008" numOctaves="2" seed="92" />
  <feGaussianBlur stdDeviation="2" />
  <feDisplacementMap scale="77"
    xChannelSelector="R" yChannelSelector="G" />
</filter>

/* 三层玻璃叠加 */
/* 1. 折射层 */
backdrop-filter: blur(3px) saturate(160%);
filter: url(#liquid-glass-distortion);

/* 2. 表面张力高光层 */
box-shadow:
  inset 0 0 20px -5px rgba(255,255,255,0.55),  /* 表面张力 */
  inset 0 1.5px 1px rgba(255,255,255,0.85),     /* 顶部高光 */
  inset 0 -1px 1px rgba(255,255,255,0.25);     /* 底部高光 */

/* 3. 顶部光反射带 */
background: linear-gradient(180deg, rgba(255,255,255,0.30) 0%, transparent 50%);
踩坑：首张图空白
添加第一首歌时玻璃框淡入，但专辑封面图还没加载完就显示了，导致先看到空白再突然跳出图片。体验很差。
解决
双层 imgA/imgB 的 onLoad 回调：图片加载完成后才调用 revealImage 淡入。opacity 初始为 0，onLoad 触发后 GSAP opacity 0→1。如果 complete && naturalWidth > 0（缓存命中）也直接 reveal。切歌时切换 currentImgLayer，旧层淡出新层淡入。

设计取舍：最初想做"可拖动 + 三位置吸附"的歌词框，后来简化为"固定居中"。因为拖动时液态形变（skewX + scaleX）和动态尺寸计算太复杂，而且固定居中视觉更干净。少即是多。

6 踩坑经历与开发心得
踩坑全记录（按时间顺序）
  1. 沙箱环境 Electron userData 写入被拦 → 崩溃
    现象：npm run dev 后 Electron ACCESS_VIOLATION 崩溃。根因：userData 写 AppData\Roaming 被沙箱拦。解决：app.setPath('userData', 项目内 .electron-data)。这个坑如果没 TRAE 帮忙排查，可能要花半天找原因。
  2. electron-vite renderer root 404 灰屏
    现象：Electron 灰屏静止。用 curl 逐个端点排查发现全 404。根因：electron-vite 默认 root 指向不存在的 src/renderer。解决：一行 root: resolve(__dirname)。TRAE 的诊断思路（curl 验证法）比直接改代码更有价值。
  3. lottie-web 渲染不出 ty:5 native text
    现象：启动页白屏 2.4 秒直接切主界面，看不到动画。根因：lottie-web 对 native text 渲染不可靠。解决：放弃 lottie-web，改用 DOM + CSS @keyframes 复刻设计稿参数。诚实面对工具局限性，不硬扛。
  4. useGSAP 缺 dependencies 导致后 5 个缩略图无动效
    现象：8→13 扩容后后 5 个无 magnify。根因：useGSAP 没加 dependencies，只在 mount 跑一次，setters 还是旧的 8 个。解决：加 dependencies: [songs.length] + 防御性兜底。教训：先读完源码理解机制，别凭直觉改。
  5. 鱼眼动效离散锚点切换抖动
    现象：快速滑动鼠标时缩略图剧烈抖动。根因：离散锚点在中点瞬间切换 → x 偏移跳变 → transition 重启。解决：连续锚点插值，t = (cx - rcL) / (rcR - rcL)。动效问题用数学方案解决，不靠调参数。
  6. const enum 在 isolatedModules 下报错
    现象：TS strict 模式下 const enum 不接受字符串字面量。解决：level: level as never 绕过。运行时仍是字符串，NCM 函数接受。不改 tsconfig，影响面最小。
  7. 液态玻璃首张图未加载完就显示空白
    现象：添加第一首歌时先看到空白再跳出图片。解决：双层 imgA/imgB 的 onLoad 回调，加载完成后才 revealImage 淡入。图片加载时序问题用 onLoad 控制，不靠 setTimeout。
用 TRAE 开发的核心心得

1. 先建规则文档，再写代码。项目第一天就建了三份文档（AGENTS.md / AI_HANDOFF.md / PROJECT_MEMORY.md）。每次新对话先读这三份文件恢复上下文。10 天开发跨了多次对话，但项目方向和代码风格始终统一——这是 TRAE 能持续高效开发的前提。


2. 先诊断根因，再小改修复。遇到灰屏不盲目重写配置，而是 curl 逐个端点排查。遇到动效抖动不调参数，而是分析锚点切换机制。TRAE 的诊断能力让 Bug 修复精准高效——每次都能定位到具体的根因，给出最小改动方案。


3. 把任务拆成小步骤，每步验证。音乐源接入拆成 3 步（骨架→搜索→播放），每步跑完 typecheck + lint 再下一步。这样出问题能快速定位是哪一步引入的，不会一锅炖。


4. TRAE 是开发伙伴，不是代码生成器。它不只是帮我写代码，更帮我分析问题——从 curl 排查 HTTP 端点到分析 GSAP quickTo 时机问题，从诊断 lottie-web 渲染限制到设计连续锚点插值算法。每次都是先理解机制再给方案。
