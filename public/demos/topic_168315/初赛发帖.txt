# NetPulse Pro 智能网络脉搏监控台

## 一、Demo 简介

**是什么：** NetPulse Pro 是一款零安装、零配置的纯前端网络监控网页应用，融合 AI 智能诊断引擎，打开 HTML 文件即可使用，无需任何后端服务或安装步骤。

**面向谁：** 远程办公族、在线教育学生、前端/后端开发者、自媒体创作者、小型团队运维——任何需要快速判断网络连通性和服务可用性的互联网用户。

**主要功能：**

1. **AI 智能诊断引擎** — 实时分析全网状态，自动生成离线/亚健康/高延迟洞察，给出可执行的优化建议（如"检查带宽占用""切换 DNS 为 8.8.8.8"），并针对每个异常节点推测根因（DNS 解析失败/网络拥塞/防火墙阻断等）。

## 二、Demo 创作思路

**灵感来源：** 我此前一直在维护一个 Python 版企业级网络监控工具（Network-Watcher V6），它采用 DDD 领域驱动设计，支持 PyQt6 桌面端 + Streamlit Web 端双模协同，能通过 SSH 远程诊断、三角探测定位根因，还能推送企业微信和飞书告警。

但在实际使用中我发现一个矛盾：专业运维工具越做越强大，普通学习者和办公用户却越来越用不上——要装 Python 环境、配 YAML、部署 Docker，门槛太高了。而普通用户遇到"网页打不开""会议卡顿"时，除了逐个打开网站碰运气，没有任何趁手的工具。

于是我想到：能不能把企业级监控的核心诊断能力，浓缩进一个浏览器打开即用的 HTML 页面，并融入 AI 智能诊断引擎，让普通用户也能获得专业级的网络排障体验？这就是 NetPulse Pro 的由来。

**想解决的问题：** 用户遇到网络问题时，缺乏快速判断"是自家网络问题还是目标服务宕机"的能力。现有方案要么门槛高（ping/traceroute 命令行），要么功能单一（仅测速不监控），无法提供多目标实时对比、趋势可视化、智能根因分析的一体化方案。

**为什么做这个方向：** 我做了三点判断和取舍：

- **纯前端 vs 全栈**：选择纯前端单文件，牺牲了 ICMP 层探测精度（浏览器无法发 ICMP），换来了零安装零配置的极致易用性，这对学习工作场景的普通用户更重要。
- **AI 诊断 vs 纯展示**：不做单纯的监控看板，而是加入规则引擎驱动的 AI 诊断，自动给出"问题是什么 + 可能原因 + 怎么解决"的完整建议链路，这才是普通用户真正需要的。
- **场景预设 vs 通用配置**：预置办公/学习/开发三大场景，降低用户配置成本，一键切换即可覆盖最常见的使用场景。

## 三、Demo 体验地址

**提交形式：** 交互式可体验的 HTML 格式文件（Zip 打包上传到社区）

**体验方式：**
1. 下载并解压 NetPulse-Demo.zip
2. 双击打开 `network-monitor-contest.html`（推荐 Chrome / Edge / Firefox 浏览器）
3. 在欢迎页点击「立即体验」即自动启动演示监控

**推荐体验路径：**
- 打开后自动以演示模式启动，观察 AI 诊断面板实时生成洞察
- 点击顶部「📚 学习场景」「💻 开发场景」切换节点组，体验场景预设
- 观察节点卡片的健康评分环、迷你趋势线、根因分析框
- 点击「切换真实探测」对实际目标发起探测
- 点击「🤖 AI 诊断」手动刷新智能分析
- 在左侧告警规则中调整阈值，体验自定义告警
- 点击「导出诊断报告」生成完整诊断文件

### 5. 开发踩坑与心得

**踩坑一：浏览器跨域限制**
浏览器无法发送 ICMP 包，也无法直接 ping 目标。最初用 fetch 探测时，大部分站点因 CORS 策略返回错误。解决方案是采用 Image 探测（加载 favicon.ico）+ Fetch no-cors 模式的双协议混合方案，并增加演示模式作为兜底，确保任何环境都能体验完整功能。

**踩坑二：Canvas 图表高清模糊**
初版 Canvas 图表在 Retina 屏幕上模糊。解决方案是引入 devicePixelRatio 缩放，手动设置 canvas 物理尺寸和样式尺寸，保证高清渲染。

**心得：** 纯前端方案虽然受浏览器安全限制无法做到系统级网络诊断，但通过"演示模式 + 真实探测"双轨设计，既保证了体验完整性，又保留了真实可用性。AI 诊断引擎虽然是规则驱动，但"问题 + 原因 + 建议"的完整链路确实能让普通用户感受到专业级排障体验，这正是产品的核心价值所在。
