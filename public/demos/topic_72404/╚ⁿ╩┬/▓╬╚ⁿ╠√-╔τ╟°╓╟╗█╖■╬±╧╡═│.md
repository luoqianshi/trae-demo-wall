## 一、Demo 简介

**是什么：**「智服务」是一套**社区智慧服务 Web 系统**，覆盖 PC 与移动端，无需安装，打开浏览器即可使用。

**面向谁：**
- 核心用户：**社区居民**（日常查询周边设施、闲置物品交换、购买商家剩食）
- 次要用户：**物业管理人员**（发布社区公告、管理社区成员）
- 商家用户：**社区周边餐饮/零售商家**（发布剩食/商品、配置收款码）

**社会公益价值：** 系统核心的「商家剩食半价销售」功能直接减少食物浪费，闲置物品免费赠送/低价转让促进资源循环利用，符合联合国可持续发展目标（SDG 12：负责任消费和生产）。

**核心功能：**

### 功能 1：周边设施一键查询
支持选择任意城市/区/街道，一键查询周边 8 类设施（地铁、公交、医院、药店、超市、便利店、学校、公园），覆盖全国 4 个一线城市 + 18 个新一线城市的所有区/街道真实数据。

> 产品截图：首页 - 设施查询入口

### 功能 2：附近资源共享与交易
社区居民可发布闲置物品（免费赠送或低价转让），商家可发布当日剩食半价销售。支持**微信/支付宝双渠道支付**，选择支付方式后直接跳转付款码，模拟完整交易闭环。

> 产品截图：附近资源页 - 商品浏览、购买、支付

### 功能 3：多角色权限管理与社区治理
超级管理员后台统一管理用户、审核物业/商家认证、配置社区邀请码、设置平台支付参数。物业人员可发布社区公告、管理社区成员。商家可管理自己的商品、订单和收款配置。

> 产品截图：管理员后台 - 用户管理、支付配置、认证审核

**完整页面体系（共 9 个页面）：**

| 页面 | 说明 |
|------|------|
| 首页 (index.html) | 产品介绍、功能展示 |

| 设施管理 (facilities.html) | 设施数据增删改查 |

## 二、Demo 创作思路

### 灵感来源

我居住的社区有大量未被充分利用的资源：每天面包店、寿司店有当日未售出的食品只能丢弃；邻居家的闲置物品（儿童自行车、书籍、小家电）无处流转；新搬来的住户不知道周边哪里有医院、药店、地铁站。同时，物业与居民之间的信息传达效率低下，公告贴了也没人看。

**这些痛点触发了「智服务」的诞生**——用技术手段让社区资源流动起来，让信息触手可及。

### 想解决的问题

1. **信息不对称**：居民不了解周边设施分布，尤其是老年人和新住户
2. **资源浪费**：商家剩食被丢弃，闲置物品堆积，缺乏便捷的流转渠道
3. **社区治理低效**：物业公告无人看，认证流程繁琐，缺乏统一管理平台
4. **支付信任缺失**：社区交易缺乏可信的支付通道，买卖双方不放心

### 为什么做这个方向

社区服务赛道天然具备「高频刚需」属性——每个人每天都会和社区打交道。相比于泛化的生活平台，聚焦社区场景可以做到更精准的匹配和更高的信任度。选择 Web 系统而非 App 的考量：降低用户使用门槛，无需下载安装，扫码即用，更适合社区中老年用户群体。

## 四、TRAE 实践过程

### 4.1 开发概览

整个项目**从零到完整系统，全程使用 TRAE 对话式开发**，共经历以下关键阶段：

```
阶段一：静态页面搭建 → 阶段二：真实设施数据补全 → 阶段三：前后端分离架构
→ 阶段四：支付交易闭环 → 阶段五：PHP 部署迁移 → 阶段六：安全加固（数据库）
```

**技术栈：**

| 层级 | 技术选型 |
|------|---------|
| 前端 | 原生 HTML/CSS/JS + 毛玻璃UI设计 |
| 后端（Node.js） | Express + CORS + JSON文件存储 |
| 后端（PHP） | 纯 PHP 路由 + SQLite/JSON 混合存储 |
| 数据 | 20+ 城市真实设施数据（facilities-data.js） |
| 部署 | 适配 Apache/Nginx，支持根目录/子目录部署 |

### 4.2 关键开发步骤（附截图）

**步骤 1：TRAE 对话生成完整项目骨架**

通过与 TRAE 的多轮对话，快速搭建了前端页面体系（9 个 HTML 页面）、CSS 毛玻璃设计系统、以及模块化的 JS 架构（store.js 本地存储 + api-client.js 统一 API 客户端）。

**步骤 2：TRAE 搜索并补全 22 个城市的真实设施数据**

通过 TRAE 的 WebSearch 能力，为北京、上海、广州、深圳 4 个一线城市 + 成都、杭州、武汉等 18 个新一线城市的所有区/街道补全了 8 类设施（地铁站、公交站、医院、药店、超市、便利店、学校、公园）的真实名称和地址，写入 facilities-data.js，总量超过 5000 条真实数据。

**步骤 3：TRAE 构建完整的前后端分离架构**

使用 TRAE 生成了 Node.js Express 后端（server.js），实现了用户注册/登录、社区管理、公告发布、设施管理、商品发布/购买、订单管理、支付模拟等 30+ 个 API 接口。前端通过 api-client.js 实现 API 优先 + 本地 Store 降级的双模式架构。

**步骤 4：TRAE 完成 PHP 迁移与数据库安全加固**

根据部署需求，使用 TRAE 将整个系统从 Node.js 迁移到 PHP + SQLite 架构。TRAE 生成了完整的 PHP 路由系统（api/index.php）、公共函数库（api/lib.php）、.htaccess 重写规则，并将用户、会话、验证码、订单、收款配置等敏感数据从 JSON 迁移到 SQLite 数据库，同时保持 API 接口完全兼容，无需修改前端代码。

## 五、经验总结与开发心得

### 5.1 TRAE 开发体验

**最大的感受：TRAE 让 "想法 → 产品" 的距离大幅缩短。**

- **多轮对话驱动力强**：从最初的一句"帮我做社区智慧服务系统"，到最终一个包含 9 个页面、30+ API、完整支付流程的系统，全程通过自然语言对话驱动
- **问题修复效率高**：遇到支付流程 Bug、CORS 跨域问题、语法错误等，TRAE 能够快速定位问题根源并给出修复方案
- **代码质量有保障**：TRAE 生成的代码结构清晰、注释完整，前后端分离架构合理，易于维护和扩展

### 5.2 技术亮点

1. **双模式架构**：前端 api-client.js 实现 API 优先 + 本地 Store 降级，后端不可用时系统仍可正常运行
2. **混合存储方案**：敏感数据（用户/订单/支付）存 SQLite，非敏感数据（公告/设施/商品）存 JSON，兼顾安全与灵活性
3. **自动迁移**：首次运行自动检测旧 JSON 数据并导入 SQLite，无需手动迁移
4. **自适应部署**：前端自动适配根目录或子目录部署，无需额外配置

### 5.3 可改进方向

- 后续可接入真实支付 API（微信支付/支付宝），替代当前的模拟支付
- 增加消息推送功能，让买卖双方实时沟通
- 引入 AI 智能推荐，根据用户位置和偏好推荐附近资源和设施
