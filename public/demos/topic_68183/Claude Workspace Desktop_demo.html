Claude Workspace Desktop

不用命令行，也能安全配置、启动和管理 Claude Code / AI Agent。

很多用户想用 Claude Code / Codex / AI Agent 写代码，却卡在命令行、Node/npm、Provider、API Key 和环境变量配置上。

Claude Workspace Desktop 用桌面 GUI 串起环境诊断、Provider 配置、Agent 启动前检查、安全分享和基础验收。

普通用户不用命令行，也能更安全、更透明、更可控地把 AI Agent 用起来。

使用 Workspace Desktop 之前

  • 需要打开终端手动检查环境
  • 需要手动查 Node / npm / CLI 版本
  • 需要手动确认 Provider 配置
  • 需要手动检查 .env 是否含敏感信息
  • 分享前缺少验收摘要

使用 Workspace Desktop 之后

  • GUI 查看环境状态，一目了然
  • Provider 状态可见，透明可查
  • API Key 自动 masking
  • 本地路径 display-safe 处理
  • 分享前生成安全检查摘要
Workspace Desktop 不替代 Claude Code、Cursor 或 Claude Desktop 的代码编辑能力。它做的是：在你的 AI 编程工作区中，帮你管理环境、透明查看 Provider、安全分享项目、以及交付前的检查和验收。
● 真实场景

一个真实的 AI 编程项目分享场景

小明用 Claude Code 写完了一个 Web 项目，想分享给同事 review。

🔴 没有 Workspace Desktop

project/
├── src/
│   └── index.ts
├── .env                      ← ⚠️ 含 API Key
├── settings.json           ← ⚠️ 含 token
├── package-lock.json
└── README.md

⚠️ 直接 git push 的风险

  • .env 中的 ANTHROPIC_API_KEY 明文暴露
  • settings.json 中的 claude token 明文暴露
  • 本地完整个人路径残留
  • 同事 clone 后可能误用你的 API Key

🟢 有了 Workspace Desktop

project-safe.zip
├── src/
│   └── index.ts
├── .env                      ← ✅ sk-****
├── settings.json           ← ✅ token_****
├── package-lock.json
├── README.md
├── MANIFEST.json           ← 📋 Share Manifest
├── REDACTION.report      ← 📋 脱敏报告
└── EVIDENCE.md             ← 📋 验收证据

✅ 安全分享包

  • API Key 已掩码，不会明文暴露
  • 本地路径已替换为 /workspace/example-project
  • 附带脱敏报告和验收证据
  • 同事可以安全 clone 和 review
你用 AI Agent 写代码。Workspace Desktop 帮你安全地管理和交付。
