# Chat Platform 第一性原理审查报告

> 完整阅读了全部 25 个源代码文件，从安全性、数据完整性、架构、可靠性、代码质量五个维度逐项审查。

---

## 严重问题（7 个）

| # | 问题 | 说明 |
|---|------|------|
| **1.1** | SECRET_KEY 硬编码暴露 | `.env` 含 `chat-platform-secret-key-...`，任何人拿到代码即可伪造 JWT |
| **1.2** | 头像上传无校验 | 无类型校验、无大小限制、扩展名取自用户输入，可被上传可执行文件或耗尽磁盘 |
| **2.1** | username 无数据库层唯一约束 | 仅有应用层 SELECT 检查，存在 TOCTOU 竞态条件，并发注册/改名可导致昵称重复 |
| **2.2** | 好友请求反向自动接受有竞态 | A→B 和 B→A 同时发请求时两个事务可能冲突，导致数据不一致 |
| **4.1** | WebSocket 异常静默吞噬 | `except Exception: pass` 吞掉所有错误，数据库断开后连接假死 |
| **4.2** | Token 过期后前端无限重连 | 固定使用同一过期 Token 重连，3 秒间隔无限循环，永不恢复 |
| **5.1** | 头像加载逻辑 4 处重复实现 | `main_view`/`profile_view`/`contact_item`/`message_bubble` 各自实现同一逻辑 |

## 中等问题（16 个）

| # | 问题 |
|---|------|
| 1.3 | CORS `allow_origins=["*"]` 与 `credentials=True` 冲突 |
| 1.4 | WebSocket Token 经 URL Query 传递（暴露在日志中） |
| 1.5 | 登录/注册端点无速率限制，可被暴力破解 |
| 2.3 | `User.status` 永远为默认值 "offline"，数据库字段形同虚设 |
| 2.4 | WebSocket 整个生命周期复用同一个 DB 会话，一次错误污染全部 |
| 3.1 | WebSocket 端点 57 行代码内嵌在 `main.py`，应与 REST 路由对等分层 |
| 3.2 | HTTP 路由直接调用 `manager.send_to_user`（WebSocket 通知耦合进 REST 层） |
| 3.3 | 前端 `api`/`ws_client`/`session` 全局单例，无法测试、任意模块可修改状态 |
| 4.3 | 前端大面积 `except: pass` 静默吞异常，用户操作无反馈 |
| 4.4 | 无应用层心跳检测，仅依赖 WebSocket 协议 ping/pong |
| 4.5 | 服务停止无优雅关闭，不通知在线用户、不清理连接 |
| 5.2 | 时间戳解析依赖字符串切片魔术数字，`+08:00`/`Z` 等变体直接崩 |
| 5.3 | 手动 `anext()` 绕过 `async with` 获取数据库会话，违反 Python 异步惯例 |
| 5.4 | 前后端零日志输出，排查问题只能靠异常堆栈 |
| 5.5 | 零测试覆盖，无 pytest 依赖 |

## 建议改进（10 个）

| # | 问题 |
|---|------|
| 1.6 | 密码仅限制 6 字符，无复杂度要求 |
| 1.7 | 无 Refresh Token / 黑名单机制，Token 签发后无法撤销 |
| 1.8 | `passlib` 在 requirements 中声明但从未使用，直接 `import bcrypt` |
| 2.5 | `get_friend_ids` 内调用 `get_friends`（查全字段 JOIN），然后仅取 ID 丢弃 |
| 3.4 | 消息类型 `"private_message"`/`"status_change"` 等裸字符串分布 8+ 处 |
| 3.5 | 缺少 API 版本前缀 `/api/v1/` |
| 4.6 | 连续点击"我"按钮可打开多个 ProfileView 模态窗口 |
| 4.7 | 聊天背景图始终覆盖同一文件名，不同用户共享 |
| 5.8 | `password_hash` 字段 255 字符，未来迁 argon2 接近临界 |
| 5.9 | `icontains` 在 SQLite 对 Unicode 行为不确定 |

## 优先修复顺序（按影响面）

```
1.1 (SECRET_KEY) → 2.1 (username 唯一约束) → 1.2 (文件上传限制)
→ 4.2 (Token 过期重连) → 4.1 (WS 异常吞噬) → 2.2 (好友请求竞态)
→ 2.4 (共享 DB 会话) → 5.1 (头像代码去重)
```
