## 二、Demo 简介

### 2.1 是什么

智能组会助手是一款专门为研究生打造的 **组会全流程 AI 辅助工具**，从工作记录整理、周报生成、汇报大纲准备，到会议实时语音转写、智能应答导师提问，再到会后待办事项跟踪，覆盖组会前、中、后每一个环节。

### 2.2 面向谁

- **硕士/博士研究生**：每周需要参加组会汇报进展的同学
- **青年科研人员**：需要定期汇报研究进展的科研工作者
- **导师**：希望查看学生周报和进展的导师角色（Demo 中包含导师看板功能）

### 2.3 核心功能（六大模块）

🏠 **首页仪表盘**：一目了然查看项目总数、工作记录数、本周进展、最近活动

📁 **项目管理**：创建多个研究项目，设置颜色标签，独立管理各项目数据

📝 **工作记录**：按类别（实验/代码/文献/调研/其他）记录每日科研工作，支持增删改查，点击展开查看详情

📊 **周报生成**：AI 自动整理工作记录，生成结构化周报（已完成工作/遇到的问题/下周计划），支持 Markdown 预览和导出

🎯 **汇报大纲**：基于工作记录和周报，AI 生成逻辑清晰的组会汇报提纲，按「进展→成果→问题→计划」组织

💬 **实时应答**（核心亮点）：
- 三种音频源模式：🎬 演示模式 / 🎤 麦克风 / 🖥️ 系统音频
- 实时语音转写，自动检测问句（？、吗、怎么、为什么等关键词）
- 智能匹配相关项目工作记录，生成专业回答建议
- 一键复制回答直接朗读，支持跨项目关联问题应答
- 预设常见导师问题，点击即可体验回答效果
- 自动演示对话，一键查看完整流程

👨‍🏫 **导师看板**：模拟导师视角，查看学生进度、周报、工作记录汇总

⚙️ **数据管理**：支持数据导出/导入，方便备份和迁移

## 三、Demo 创作思路

### 3.1 灵感来源

作为一名研究生，我深刻体会到每周组会前的焦虑：一周做了很多事，实验、读文献、写代码，但组会前总是难以系统整理；汇报时常常流水账式陈述，重点不突出；面对导师的即兴提问，明明做过相关工作，临场却组织不好语言，显得准备不足。和身边同学交流发现，这是研究生群体的普遍痛点，于是想到用 AI 来帮助解决这个问题。

### 3.2 想解决的真实痛点

| # | 痛点 | 具体表现 |
|---|---|---|
| 1 | **工作整理难** | 实验数据、代码进展、文献笔记散落各处，组会前翻半天笔记凑周报 |
| 2 | **汇报没条理** | 不知道如何组织汇报内容，想到哪说到哪，重点不突出 |
| 3 | **临场应答失措** | 导师的尖锐问题让人措手不及，明明做过却答不好，显得准备不足 |
| 4 | **待办易遗忘** | 组会上导师布置的任务，会后容易遗漏或忘记跟进 |

### 3.3 为什么做这个方向

- **刚需高频**：研究生群体庞大，组会是每周/每两周一次的刚性需求
- **场景垂直**：目前市场上缺乏专门针对研究生组会场景的工具，通用 AI 工具（ChatGPT等）无法结合个人工作记录上下文
- **AI 优势明显**：文本整理、逻辑组织、问答生成正是 AI 擅长的领域
- **演示效果好**：功能完整度高，交互性强，适合比赛演示

## 四、核心功能与创新亮点

### 4.1 组会全流程覆盖（核心创新）

不同于单一功能工具，智能组会助手覆盖了组会前、中、后的完整链路：

- **会前**：工作记录 → 周报生成 → 汇报大纲 → Q&A 准备
- **会中**：实时语音转写 → 问题自动检测 → AI 应答建议 → 待办事项记录
- **会后**：问答历史归档 → 会议摘要生成 → 待办跟踪

### 4.2 基于个人数据的智能应答

实时应答不是通用 AI 聊天，而是 **基于用户自己录入的工作记录** 来生成回答：
- 自动匹配问题相关的项目
- 检索相关的工作记录作为回答依据
- 针对不同问题类型（进展/技术细节/文献对比/后续计划/数据异常）生成专业回答框架
- 跨项目关联问题智能识别（"两个项目之间有什么关联"）

### 4.3 零门槛开箱即用

- 单文件 HTML，无需任何安装部署
- 核心功能完全离线可用
- 内置丰富的演示数据，打开即可完整体验
- 本地存储，数据安全不丢失

### 4.4 三种音频模式适配不同场景

| 模式 | 适用场景 | 特点 |
|---|---|---|
| 🎬 演示模式 | 比赛演示、快速体验 | 自动模拟完整组会对话，无需权限 |
| 🎤 麦克风 | 个人练习应答 | 真实语音识别，自己提问练习回答 |
| 🖥️ 系统音频 | 真实腾讯会议场景 | 捕获会议音频，实时转写应答 |

## 五、Demo 体验指南

### 5.1 快速上手（评委第一体验路径）

1. **第一步**：解压 ZIP 包，得到 `index.html` 文件

3. **第三步**：页面加载后默认进入首页，可看到预置的演示数据
4. **第四步**（推荐）：点击左侧「💬 实时应答」→ 点击「🎬 开启自动演示对话」，观看完整的 AI 应答演示流程

### 5.2 推荐体验路径

1. **📁 项目管理**：查看预置的4个演示项目，或创建自己的项目

### 6.3 开发心得

1. **TRAE 生成完整前端代码效率极高**：一次提示就能生成结构清晰、样式完整的 HTML 文件，包含完整的交互逻辑，大大缩短了开发周期
2. **从零到可演示 Demo 速度快**：从需求讨论到功能完整的 Demo，全程在 TRAE 中完成，效率远超传统开发
3. **迭代调试方便**：遇到 Bug 或需要调整功能时，直接描述问题，TRAE 能快速定位并修复
4. **单文件架构降低门槛**：选择纯前端单文件 + LocalStorage 方案，无需后端部署，评委双击即可体验，这对比赛 Demo 至关重要

### 6.4 踩坑经历

1. **真实 AI API 调用问题**：初期想接入真实大模型 API，但考虑到 Demo 的独立性和评委体验的便捷性（无需配置 API Key、无需联网），最终改为前端智能模板生成，结合用户真实工作记录动态组装回答，既保证了体验完整性又降低了使用门槛
2. **浏览器语音识别限制**：Web Speech API 目前只有 Chrome/Edge 支持，且需要联网。为此增加了「演示模式」，自动模拟完整对话流程，确保所有浏览器都能体验核心功能
3. **系统音频捕获权限**：捕获系统音频需要通过屏幕共享 API，且必须同时请求视频，这是浏览器安全限制。在UI中添加了详细的权限引导说明
4. **多项目数据隔离**：多项目管理的数据结构需要仔细设计，确保各项目的工作记录、周报数据正确隔离，同时跨项目查询又能正确关联

## 七、技术架构

| 层级 | 选型 | 说明 |
|---|---|---|
| 前端核心 | 原生 HTML5 / CSS3 / Vanilla JavaScript | 零依赖、单文件、极致轻量 |
| 语音识别 | Web Speech API (webkitSpeechRecognition) | 浏览器原生语音转文字 |
| 音频捕获 | navigator.mediaDevices.getDisplayMedia | 屏幕/系统音频捕获 |
| 音频可视化 | Web Audio API + AnalyserNode | 实时音量电平显示 |
| 数据存储 | LocalStorage | 本地持久化，无需后端 |
| UI 框架 | 自定义 CSS（渐变配色 + 卡片布局 + CSS 动画） | 无外部UI库依赖 |
| 回答生成 | 关键词匹配 + 模板引擎 + 上下文组装 | 基于用户工作记录动态生成 |
