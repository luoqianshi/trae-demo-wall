# 念安中脑层可行性与实现步骤分析

> 本文档最初是早期工程评审分析，记录了原蓝图的五类硬伤和修订建议。随着项目演进，**五类硬伤已全部修复，分类驱动架构、14条服务链、诈骗检测、物品查找和免费AI栈均已实现并通过验证**。本文档已同步更新为最新状态。

## 结论

"念安中脑层"方向不仅可行，而且已完成实现并验证通过。

**原评审结论**：方向可行，但原蓝图不能照原样开工，存在锚点误标、趋势伪上升、红线机械替换、结构化预填、工程可运行性缺失五类硬伤。

**当前状态**：五类硬伤全部已修复，Demo 完整实现并跑通闭环。核心进展包括：

- **分类驱动架构**：从"单管道 AI 处理"升级为"先分类 → 入库 → 按类别触发工作流"
- **14 条服务链**：覆盖急救、健康、情感、记忆、物品、诈骗等全部场景
- **诈骗检测器**：三维检测模型（冒充 + 紧迫感 + 敏感动作）+ 医疗误导检测
- **物品查找引擎**：名称/别名匹配 + 三级敏感度 + 角色权限控制
- **免费 AI 栈**：智谱 GLM-4.7-Flash + 腾讯云 ASR，零成本可运行
- **21 个文件完整实现**：FastAPI + 7 个核心模块 + SQLite + 前端页面
- **8 个测试用例全部通过**：否定处理、情感分类、红线误报、找物、诈骗检测、趋势分析、SOS、零分类归 other

念安的核心壁垒放在自有数据结构、分类体系、生命锚点、趋势算法、红线规则和工作流编排上，而不是押注某一家大模型。外部模型只作为可替换的理解、分类、抽取能力，随时可以切换供应商。

## 新增内容判断（原始评审）

| 新增内容 | 是否可行 | 是否最优 | 判断 |
|---|---|---|---|
| 自建"中脑层"，外接大模型 | 可行 | 是当前最优 | 大模型负责转写、抽取、摘要；念安自己掌握 schema、规则、趋势和边界，避免被单一模型绑定。 |
| `LifeEvent` 生命上下文 schema | 可行 | 是 | 这是把"录音"升级成"生命记录"的基础，字段方向正确。 |
| 锚点引擎 | 可行 | 是 | 健康锚点、物件字典、人物关系库都可以从手写规则起步，能形成念安自己的数据资产。 |
| 趋势分析纯算法 | 可行 | 是 | 这是"主动根据往日录入迭代分析"的核心，不需要 LLM，比赛阶段更容易解释和验证。 |
| 红线规则层 | 可行 | 必须做 | 医疗、隐私、记忆、人格边界都需要硬规则，尤其比赛答辩时可以降低医疗误导和伦理质疑。 |
| FastAPI + SQLite/JSON Demo | 可行 | 基本最优 | 工程量低、能跑通闭环。比赛不需要一开始上 Postgres、向量库和复杂账户体系。 |

## 原蓝图五类硬伤 — 修复状态

| 硬伤 | 原问题 | 修复方案 | 修复状态 |
|---|---|---|---|
| 锚点误标 | `word in raw_text` 会让"血压"命中"血压高"，也无法识别"不头晕"这类否定 | **Trie 前缀树**实现最长匹配优先（"血压高"优先于"血压"）；否定窗口检测（锚点前 3-5 字符检查否定词）；子串去重（按长度降序排列，已覆盖位置跳过） | 已修复 |
| 趋势伪上升 | `count >= 3` 就标 rising，频次不等于趋势 | **朴素时序趋势**：解析日期 → 按天聚合 → 窗口前半段 vs 后半段比较（后半段 > 前半段 x 1.3 = rising，< 前半段 x 0.7 = declining）→ 最少 3 次门槛才生成趋势 | 已修复 |
| 红线机械替换 | `replace("你得了","建议关注")` 会破坏语义，误伤"我得了奖" | **检测 → 标注 → 降级**：不 replace 原文；通过 `flags` 列表返回标记；`positive_contexts` 正则过滤误报（得了奖、得了冠军不触发医疗红线） | 已修复 |
| 结构化预填 | Demo 阶段直接返回 `samples.json` 预置结构化结果 | **规则+正则+词表槽位填充**：按健康词表扫描、正则提取时间/物品位置、地点优先读 GPS meta、人物从词表+别名匹配、锚点引擎提供健康/情绪锚点 | 已修复 |
| 工程可运行性缺失 | 相对路径、包初始化、CORS、历史和现场输入混在一起 | `pathlib.Path` 定位项目根目录；补齐 `__init__.py`；FastAPI CORS 配置；`history/sample_events.json` + 现场输入通过 `/api/record` 追加；SQLite 数据库运行时生成 | 已修复 |

## 分类驱动架构

### 产品逻辑修正

念安不是把每条语音都走同一条 AI 流程，而是先理解、分类、入库，再根据类别触发不同工作流：急救、健康监护、待办事项、日记记忆、家庭沟通、长期资产等。

**总流程：**

| 步骤 | 做什么 | 说明 |
|---|---|---|
| 1. 采集 | 老人按键说话，或通过 NFC/定位/家属补充带入上下文 | 入口仍然保持简单，复杂性放到系统内部 |
| 2. 多源融合 | 合并语音文本、定位、近场身份、手机端照片/相册、时间、设备状态、历史记录和家属补充 | 同一句话在不同人物、地点、照片或物件上下文下可能属于不同类别 |
| 3. 理解与分类 | 规则 + 模型判断内容属于 14 个类别之一 | 不是每条都深度分析，先判断类别和紧急程度 |
| 4. 结构化入库 | 按统一 `LifeEvent` 和分类字段写入个人数据库 | 每个用户自己的长期数据是念安护城河 |
| 5. 工作流触发 | 不同类别进入不同服务链 | 急救立即触发，待办进入提醒，记忆进入归档，健康进入监护 |
| 6. AI 调用策略 | 根据类别决定是否调用大模型、调用多深 | 控制成本，也减少不必要的模型调用 |
| 7. 长期分析 | 对健康、情绪、用药、睡眠、血压等长期数据做周期性整合分析 | 形成趋势、看诊卡、家属提醒和照护建议 |

### 多源输入融合

| 输入源 | 输入内容 | 对分类的影响 |
|---|---|---|
| 语音(ASR) | 老人主动说的话、转写文本 | 判断主语义、情绪、健康症状、待办、记忆内容 |

## 14 条服务链

### WF_SOS 紧急求助链

| 项目 | 内容 |
|---|---|
| **触发条件** | SOS 按键触发、高危词命中（摔倒、胸痛、喘不过气、站不起来、快来帮我） |
| **子分类** | 跌倒/受伤、胸痛/呼吸困难、意识异常、明确求助、严重出血/烫伤 |
| **风险/优先级** | SOS 按键 = 紧急（立即 4G 发送）；高危词 = 高（1 分钟内推送）；疼痛非急症 = 中（5 分钟内） |
| **步骤流程** | 识别（硬规则/按键，不等分类） → 4G/eSIM 独立发送 SOS → 老人端语音安抚 → 家属端高优先级推送 → 误触处理（连续 > 3 次建议调整） → 留痕 → 后续跟进 |
| **规则与红线** | SOS 不经过分类；4G 独立发送不依赖手机；不做医疗判断（只说"已通知家人，建议尽快就医"）；误触不惩罚 |

### WF_HEALTH_SYMPTOM 健康症状追踪链

| 项目 | 内容 |
|---|---|
| **触发条件** | 分类为 health_symptom |
| **子分类** | 症状、睡眠、饮食、疼痛、复诊/检查 |
| **风险/优先级** | 高（胸闷+头晕同时出现、剧烈疼痛）→ 即时推送；中（单一症状反复、连续睡眠差）→ 当天推送；低（偶发轻微）→ 归档 |
| **步骤流程** | 识别与抽取 → 风险分级 → 即时处理 → 健康卡生成（含辅助参考前缀） → 趋势分析 → 看诊卡汇总 → 红线过滤 |
| **规则与红线** | 不诊断疾病；趋势不是诊断；用药记录不等于医嘱；和既往病史关联但不做诊断结论 |

### WF_HEALTH_DATA 健康数据记录链

| 项目 | 内容 |
|---|---|
| **触发条件** | 分类为 health_data，包含血压/血糖/体温/心率/睡眠时长/体重等数值 |
| **子分类** | 血压、血糖、体温、心率、睡眠时长、体重 |
| **风险/优先级** | 超安全阈值（收缩压 >= 180、体温 >= 38.5）→ 高风险推送；异常值 → 标注"建议关注" |
| **步骤流程** | 正则提取数值和单位 → 识别测量时段 → 阈值检查 → 入指标库 → 趋势图 → 周期总结 |
| **规则与红线** | 阈值不是诊断；数值来源标注（口述 vs 设备测量）；异常值优先推送 |

### WF_MEDICATION 用药管理链

| 项目 | 内容 |
|---|---|
| **触发条件** | 分类为 medication |
| **子分类** | 药快没了、忘吃药、药物不适、药物关联 |
| **风险/优先级** | 中等，归入健康时间线 |
| **步骤流程** | 识别药品 → 关联既往用药记录 → 生成家属待办（补药/确认） → 用药记录入健康时间线 |
| **规则与红线** | 记录老人说了什么药，但不建议增减剂量；不替代医嘱 |

### WF_EMOTIONAL 情感陪伴链

| 项目 | 内容 |
|---|---|
| **触发条件** | 分类为 emotional_support |
| **子分类** | 想念、孤独、担心、开心、低落、感谢/留言 |
| **风险/优先级** | 高（"活着没意思"等消极表达）→ 立即推送；中（连续孤独/低落）→ 推送建议增加探访；低（偶发想念）→ 归档 |
| **步骤流程** | 情绪识别（规则匹配高危词） → 即时处理 → 家属消息（保留原话情感） → 情绪趋势 → 陪伴提醒 |
| **规则与红线** | 不添加老人没说的内容；高风险立即推送不等待 |

### WF_SOCIAL 社交记录链

|---|---|

| **规则与红线** | 近场确认必须明确触发；不做无感社交监控 |

### WF_DAILY 生活需求链

| 项目 | 内容 |
|---|---|
| **触发条件** | 分类为 daily_needs |
| **子分类** | 采购、预约/日程、缴费、家务/维修、回访 |
| **风险/优先级** | 低，生成待办 |
| **步骤流程** | 轻量抽取事项 → 生成待办 → 家属响应（接受/转交/完成） → 提醒 → 闭环 |

### WF_LIFE_RECORD 生活记录链

| 项目 | 内容 |
|---|---|

| **子分类** | 出行、社交、活动、天气/环境、普通感受 |
| **风险/优先级** | 低，低成本归档 |
| **步骤流程** | 规则匹配活动类型和地点 → 写入家庭时间线 → 夜间批量生成一句话摘要 → 周期摘要 |

### WF_SAFETY 安全预警链

| 项目 | 内容 |
|---|---|
| **触发条件** | 分类为 safety_alert，或异常地点/深夜离家 |
| **子分类** | 异常地点、深夜离家、长时间停留、陌生环境 |
| **风险/优先级** | 高（深夜离家 22:00-06:00、陌生地点停留 > 30 分钟） |
| **步骤流程** | GPS 采集 → 地点匹配已知库 → 异常判断 → 上下文关联（医院+健康 → 就医事件） → 家属推送 → 地点时间线 |
| **规则与红线** | 不做连续轨迹监控；默认不展示精确位置；只在主动记录、SOS、授权场景使用定位 |

|---|---|

| **风险/优先级** | 高（涉及转账/密码/验证码/冒充身份）→ 即时推送；中（偏方/保健品/陌生人）→ 当天推送；低（家属计划/社区通知）→ 24 小时内 |

| **规则与红线** | 不替老人下结论（不说"骗局""假的"）；高风险不等待；保留原话；隐私保护（不展示转账金额等） |

| **步骤流程** | 状态采集 → 异常判断 → 通知（老人端语音+家属端推送） → 维护流程 → 日志 |
| **规则与红线** | 纯规则处理，不调用大模型 |

### 混合分类架构

```
输入（语音/文本 + meta）
    |
    v
(1) SOS硬规则 → is_sos=true → 直接返回 sos → 结束
    |
    v 不命中
(2) 紧急词规则 → 命中 EMERGENCY_KEYWORDS → urgency=high + 正常分类
    |
    v
(3) 关键词+模式评分 → 对14个分类分别评分，取最高
    |                    |
    |                    +-- confidence >= 0.6 → 直接按规则分类，触发服务链
    |                    +-- confidence < 0.6  → 降级到第(4)层
    v
(4) 调免费LLM做语义分类（智谱 GLM-4.7-Flash）
    |
    v
(5) 结构化抽取（模型 + 规则槽位填充）
    |
    v
(6) 锚点/趋势/红线（纯规则，零模型）
    |
    v
(7) 工作流路由 → 卡片/提醒/告警
```

**核心原则**：能规则解决的不调模型（省成本、零延迟）；规则不确定的才调模型；模型只做分类和抽取，趋势和红线始终是念安自己的纯规则。

### 评分机制

- **关键词评分**：每个分类的关键词在文本中出现，每个 +0.2，上限 3 个关键词 = 0.6 分
- **模式评分**：正则匹配，每个 +0.2，上限 2 个模式 = 0.4 分
- **总分**：keyword_score + pattern_score，上限 1.0
- **Meta 融合**：近场有人 → social_contact +0.2；NFC + 健康 → health_data/medication +0.15

## 诈骗检测

### 三维检测模型

| 维度 | 检测内容 | 示例 |
|---|---|---|
| 冒充（impression） | 冒充银行/公安/客服/社保局 | "我是公安局的""银行客服说""社保局打电话" |
| 紧迫感（urgency） | 紧急/限时/过期 | "赶紧""马上""限时""过期""今天不转就冻结" |
| 敏感动作（sensitive_action） | 转账/汇款/验证码/密码 | "转账""汇款""验证码""密码""银行卡号" |

### 高危组合检测

同时命中多个维度的组合模式直接判定 high risk：

| 组合 | 风险 | 示例 |
|---|---|---|
| 冒充 + 转账 | high | "公安局的让我转账" |
| 中奖 + 手续费 | high | "中奖了要领奖先交手续费" |
| 验证码 + 提供 | high | "客服让我提供验证码" |
| 公安 + 转账 | high | "说我是公安的让我转账" |
| 社保 + 验证码 | high | "社保局打电话要验证码" |

### 医疗误导检测

检测以下医疗误导关键词：

偏方、根治、停药、不用治、多吃两片、秘方、包治、祖传、神药、替代正规治疗

### 风险分级

| 分数 | 等级 | 说明 |
|------|------|------|
| >= 0.7 或命中高危组合 | high | 高风险，立即推送家属端 + 老人端温和提示 |
| >= 0.4 | medium | 中风险，当天推送家属端 |
| > 0 | low | 低风险，归入确认队列 |
| 0 | pending | 无风险 |

### 留痕记录

每次核实都记录：原话、子分类、风险等级、家属判断、处理结果、时间。形成老人的"核实历史库"。如果同一类型诈骗/误导反复出现，系统可提升后续同类信息的默认风险等级。

### 建议与红线

- 不说"骗局""假的"，改为"建议和家人确认""建议立即和家人确认，不要透露验证码或密码"
- 高风险不等待，立即推送高优先级提醒
- 保留原话，不改写老人说的内容
- 涉及转账金额、银行卡号等敏感信息不在家属端明文展示

## 物品存放与查找

### 存放模式

老人通过语音记录物品位置，系统识别"X 放 Y"/"X 在 Z"模式：

- "医保卡放在床头柜第二层" → 物品：医保卡，位置：床头柜第二层
- "老花镜在电视柜旁边" → 物品：老花镜，位置：电视柜旁边
- "存折在蓝色文件袋里" → 物品：存折，位置：蓝色文件袋

### 找物查询

支持名称 + 别名匹配：
- "医保卡在哪里" → 匹配"医保卡""社保卡""医保本"
- "老花镜在哪儿" → 匹配"老花镜""花镜""眼镜"

### 三级敏感度

| 级别 | 示例 | 权限说明 |
|---|---|---|

| 角色 | normal | health | high |
|---|---|---|---|

## 硬件连接：BLE + 4G/eSIM 双模

SOS 是念安的安全承诺，不能依赖 BLE + 手机方案——老人忘带手机、手机没电、蓝牙被关、手机在另一个房间等场景下 SOS 发不出去。

| 连接 | 负责什么 | 可靠性 | 功耗 |
|---|---|---|---|
| BLE（蓝牙） | 日常数据通道：录音上传、缓存同步、近场识别、家属端实时查看 | 依赖手机在身边且蓝牙开启 | 低 |
| 4G/eSIM | 安全通道：SOS 独立发送、BLE 长时间未连时离线告警、缓存补传、低频定位上报 | 不依赖手机，几乎任何场景可用 | SOS 瞬时高但极短；日常可关闭或极低频心跳 |

**功耗策略**：日常走 BLE 省电；BLE 长时间未连接时激活 4G 低频心跳；SOS 触发时 BLE 和 4G 同时尝试，4G 确保送达。4G 月流量极小（SOS 消息 + 定位上报 + 缓存补传，月均 < 50MB），物联网卡月租 3-10 元可覆盖，成本含在家庭服务订阅里。

## 安全性设计

### 6 级数据分类

| 数据级别 | 包含内容 | 默认可见范围 | 保护策略 |
|---|---|---|---|
| 普通生活数据 | 日记、普通时间线、非敏感家庭活动 | 老人本人、授权家属 | 可分享、可删除、可导出 |
| 家庭记忆数据 | 语音、照片、人物关系、家庭故事 | 老人本人、被授权家属 | 家属分级可见；补充和修改留痕 |
| 健康数据 | 症状、血压、用药、看诊卡、趋势 | 老人本人、主照护人、被授权医疗/护理角色 | 强提示"辅助参考"；导出需授权；访问留痕 |
| 位置数据 | 当前地点、常去地点、异常地点、探访地点 | 默认不展示精确位置；授权后可见 | 不做连续轨迹默认展示；只在主动记录、SOS、授权场景使用 |
| 物品位置数据 | 医保卡、钥匙、病历、存折、证件、药品位置 | 按物品敏感度决定可见范围 | 敏感物品不主动推送；查询需权限 |
| 数字纪念素材 | 声音、长期故事、表达习惯、价值观材料 | 老人明确授权范围内可见 | 生前授权、继承规则、退出和删除机制 |

### 5 种角色

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 老人本人 | 记录、查询、删除自己的数据；授权或撤回家属权限 | - |
| 主照护人 | 查看健康趋势、待办、看诊卡、重要提醒；协助补充信息 | 不能默认查看所有私密记忆和敏感物品位置 |
| 普通家属 | 查看被分享的记忆、日记、部分待办 | 不能默认查看健康详情、精确定位、证件/存折等敏感物品位置 |
| 医生/护理人员 | 查看老人授权导出的看诊卡或健康摘要 | 不能访问家庭记忆、物品位置、完整私密时间线 |
| 紧急联系人 | 在 SOS 或高风险场景下接收必要信息 | 不能因一次紧急授权获得长期全量访问 |

### 核心安全机制

| 机制 | 作用 |
|---|---|
| 最小权限 | 每个家属默认只能看被授权的数据，不默认全家共享 |
| 场景授权 | 看诊、急救、探访、纪念等场景使用不同权限 |
| 敏感物品保护 | 识别身份证、银行卡、存折、钥匙、药品等高敏感内容，自动提高保护级别 |
| 访问留痕 | 谁在什么时候查看了健康、位置、物品位置和记忆材料，都有记录 |
| 设备丢失冻结 | 账号可在家属端冻结；新设备绑定后恢复数据；旧设备本地敏感缓存失效 |
| SOS 临时例外 | 可以临时向紧急联系人展示必要位置和健康摘要，但只限本次事件 |
