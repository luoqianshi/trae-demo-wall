§01 Pain · the friction no one measures context-switching cost

每一次 工具跳转，
你的心流就被切掉一块。

// 现象

现代知识工作者的一天被切成 8-15 个互不连贯的工作台。每次切换都是一次认知重启——重新定位「刚才在哪」「下一步做什么」「这窗口是不是要找的那个」。

// 代价

这种重复劳动累积成一道看不见的摩擦力。它偷走的不只是时间，更是进入深度工作的能力——专注变成稀缺品，心流变成奢侈品。

§02 Mechanism · two primitives, one layer intent_as_ui / semantic_fold

我们不打算再加一个工具。我们要做的是——把你和工具之间多余的步骤折叠掉。两个原始操作支撑这个目标。

// primitive.01 → user.interface

意图 即 界面

你不再打开「某个 App」，你只描述「想做什么」。AI 代理解析意图、选择工具、调度执行——前台是一个干净的输入框，后台是一整支 agent 队伍。

// intent → execution
intent("把上周会议同步到笔记")
  → parse()            // agent.nlu
  → route([calendar, meet, notes])
  → execute_parallel()
  → deliver()
// primitive.02 → data.layer

多模态 语义折叠

不同应用有不同形态：表格、白板、文档、对话、链接。FlowMind 把它们折叠成一个统一的语义层——跨形态查询、引用、重组，仿佛它们原本就是一体的。

// semantic fold
sources = [table, board, doc, thread, link]
fold(sources) → unified_graph
  // 跨形态 query
  graph.query("上周关于 X 的所有讨论")
  → merged_view()

通用 agent（Claude Code、Cursor、MCP 智能体）是 被动 的——你叫它，它才干活。 FlowMind 的另一半是 静默协同：它常驻后台，观察你的工作流节奏，在你即将被打断前主动浮现建议，在你专注时彻底隐身。

场景演示：周会准备，从 40 分钟到 3 分钟。

// scenario · product_review
before 40min → after 3min

这是一个真实场景：产品经理小李，每周一早上要为 10:30 的产品评审会准备议程。 没有 FlowMind 时，他要在 5 个 App 间切换、手动搬运信息、格式化议程，40 分钟过去，心流早已断裂。 有 FlowMind 时，他只说一句话，3 分钟拿到议程草稿——剩下的时间用来思考决策本身。

BEFORE · 没有 FlowMind 40 min
01 打开 Calendar 看会议时间，发现议程未填
02 切到 Notion 翻上周用户访谈纪要，找到 3 条关键反馈
03 切到 Slack 搜 #product 频道，翻出"转化率下降"的讨论
04 切到 Obsidian 找上周的待办，确认哪些已推进
05 切到 Docs 手动整理议程，复制粘贴 4 个来源的内容
06 格式化、标红决策点、发邮件给参会人——心流已断
AFTER · 有 FlowMind 3 min
01 按 ⌘⇧F 唤出 FlowMind 悬浮层
02 说一句："准备下周产品周会议程"
03 FlowMind 自动折叠 Notion + Slack + Calendar + Obsidian
04 生成议程草稿：3 项决策点已标红，2 个待确认问题
05 余光扫一眼，心流未断——继续写刚才的文档
06 会前 5 分钟再唤出，议程已就绪
