# My AI Robot — Tree AI 创造力大赛 初赛提交材料

## 一、Demo 简介

### 是什么
**My AI Robot** 是一个 **C2M 模式的 1:1 实体硅胶 AI 机器人定制平台**。用户通过交互式配置器，从身高体型、肤色五官、发型发色到性格声音，亲手设计一个真正能触碰、有温度、会思考的实体机器人伙伴。

### 面向谁
| 用户群体 | 需求场景 |
|---------|---------|
| 独居青年 | 情感陪伴、日常互动、缓解孤独 |
| 二次元/科技爱好者 | 将虚拟角色实体化、收藏展示 |
| 空巢老人 | 日常照料提醒、对话陪伴 |
| 高端定制用户 | 打造独一无二的专属伙伴 |

### 主要功能（3个核心）

**1. 全维度交互定制器**
6 大步骤、50+ 项定制参数，点击选项即可实时预览机器人头像变化。从关系类型（哥们/女朋友/闺蜜/男伴/玩伴）到身高体型、肤色质感、面部五官、发型发色、性格声音，每一步都有视觉反馈。预览区采用高科技感动画头像——双层旋转光环、扫描线、脉冲核心、HUD 数据线、闪烁数据点，选择眼睛颜色和发色时核心光会实时变色响应。

> 截图：`screenshots/screenshot_builder.png`、`screenshots/screenshot_tech_face.png`

**2. 实体规格展示**
产品不是概念——医用级铂金硅胶三层皮肤结构、88+ 高自由度关节、36.5°C 恒温系统、眼内微摄像头视觉感知、DeepSeek/通义千问大语言模型、Azure TTS 声音克隆。所有技术参数均基于已验证的供应链和技术方案。首屏搭配 AI 生成的梦幻背景图片和 Canvas 双色粒子动画。

> 截图：`screenshots/screenshot_hero.png`、`screenshots/screenshot_dreamy_hero.png`

**3. 商业模型验证**
四档产品线（9,800-98,000 元）+ 五维盈利引擎（硬件销售、AI 订阅、虚拟商城、UGC 生态、品牌联名），附 3 年营收预测图表和竞品定价对比。

> 截图：`screenshots/screenshot_business.png`

## 二、Demo 创作思路

### 灵感来源
看到优必选 Walker、特斯拉 Optimus、Realbotix 等实体人形机器人快速迭代，但市场上所有产品都是"厂家造什么、用户买什么"。我想到：如果每个人都能像定制西装一样，亲手设计一个属于自己的实体 AI 伙伴呢？不是虚拟 avatar，是能触碰、有温度、会思考的 1:1 实体机器人。

### 想解决的问题
- **情感陪伴缺口**：中国独居人口超 1.25 亿，宠物/虚拟陪伴无法替代真人互动
- **个性化缺失**：现有机器人外观固定，无法满足用户对"专属感"的需求
- **隐私焦虑**：云端 AI 伴侣数据泄露风险高，用户需要本地化的私密陪伴

### 为什么做这个方向
1. **市场验证**：2026 年全球 AI 陪伴市场规模达 450 亿美元，年增速 35%+
2. **技术成熟**：硅胶工艺、伺服电机、LLM、TTS 均已达到消费级落地标准
3. **差异化**：从"卖标准品"转向"卖定制服务"，毛利率从 30% 提升到 55%+
4. **硬件交互赛道**：与纯软件项目形成差异化，技术壁垒更高

## 四、TRAE 实践过程

### 开发流程概述

整个 Demo 使用 **TRAE Work** 从零开始生成，历经约 8 个 Sessions，经历了"概念跑偏 → 纠正方向 → 交互打磨 → 商业补充 → 视觉升级 → 初赛打包"的完整迭代。

#### 阶段一：概念定义（Session 1-2）
- 最初误做成"虚拟社交 App"，用户及时纠正：要的是 **1:1 实体硅胶机器人**
- 重新定位：C2M 实体定制平台，不是软件而是硬件+软件融合
- 输出：完整产品规划文档 `my-ai-robot.html`

#### 阶段二：交互设计（Session 3-4）
- 用户要求："要有体验感，选鼻子、眼睛、身高的互动按键"
- 实现：6 步交互式定制器 + 实时头像预览
- 关键设计：每个选项点击后，右侧头像即时变化，提供视觉反馈
- 用户要求扩展选项：性格从 5 种增加到 12 种、声音从 5 种增加到 12 种，新增 12 项"独特怪癖"

#### 阶段三：商业与技术补充（Session 5）
- 用户要求："保留所有内容，加点商业价值"
- 补充：五维盈利模型、3 年营收预测 ECharts 图表、竞品分析、发展路线图

#### 阶段四：初赛 Demo 打包（Session 6）
- 精简 `my-ai-robot.html` 为 `demo.html`：保留核心交互，去除冗余文字
- 添加 Canvas 粒子动画、滚动揭示动画、hover 反馈等视觉增强
- 浏览器测试中发现并修复 2 个关键 Bug：
  - **Bug 1**：颜色 swatch 匹配失败（浏览器将 hex 转为 rgb，导致颜色名映射失效）
  - **Fix**：为所有 swatch 添加 `data-color` 属性，直接读取中文颜色名
  - **Bug 2**：按钮 emoji 前缀导致选项匹配失败
  - **Fix**：用正则 `replace(/^[^\u4e00-\u9fa5a-zA-Z]+\s*/, '')` 清洗文本

#### 阶段五：视觉与交互增强（Session 7）
- 添加步骤导航点（Step Dots）和进度条
- 按钮点击涟漪效果、生成按钮激活逻辑、结果弹窗
- 生成 3 张 AI 梦幻背景图（`dreamy_hero.png`、`dreamy_customize.png`、`dreamy_cta.png`）
- 增强发光文字、浮动动画、HUD 线条效果

#### 阶段六：科技感动画头像（Session 8）
- 用户要求："将机器人伴侣位置的脸替换为带有高级科技感的动画效果"
- 移除原 SVG 人脸，替换为纯 CSS 科技感动画头像
- 实现：双层反向旋转光环 + 网格背景 + 上下扫描线 + 脉冲核心 + HUD 数据线 + 闪烁数据点
- 选择眼睛颜色时核心光变色，选择发色时外环边框变色，切换时触发亮度闪烁反馈

### 踩坑经历与解决方案

**坑 1：方向跑偏**
- 第一次理解成"虚拟社交小程序"，用户纠正后才发现真正需求是实体硬件。
- **教训**：做产品前先确认"形态边界"——是虚拟还是实体？是软件还是硬件？

**坑 2：浏览器本地文件访问限制**
- `demo.html` 直接双击打开时，部分 JS 功能因浏览器安全策略受限。
- **解决**：使用 `python3 -m http.server` 启动本地服务器，通过 `http://localhost` 访问。

**坑 3：颜色匹配 Bug**
- 代码用 `el.getAttribute('style')` 获取 hex 颜色，但浏览器自动转为 `rgb()`，导致颜色名映射全部失效。
- **解决**：所有 swatch 改用 `data-color` 属性存储中文颜色名，绕过浏览器样式转换。

**坑 4：emoji 前缀文本匹配**
- 按钮文本是 "💖 女朋友"，但配置对象 key 是 "女朋友"，直接匹配失败。
- **解决**：正则清洗 emoji 和空格前缀后再匹配。

**坑 5：SVG 替换后 JS 残留引用**
- 将 SVG 人脸替换为 CSS 科技动画头像后，`updateSVG()` 函数仍引用已删除的 SVG 元素 ID，导致点击选项时 JS 报错。
- **解决**：重写 `updateSVG()` 为驱动 CSS 动画反馈函数，移除所有旧 SVG 引用。
