02

问题与动机

青少年情绪困扰常常发生在家庭、学校与公共心理服务难以及时抵达的时间缝隙里。

想解决的问题

许多青少年在焦虑、低落、孤独或压力爆发时，不愿意主动向父母、老师或咨询师开口。尤其在深夜、考试前、冲突后等场景，他们需要一个低门槛、无评判、随时在线的情绪支持入口。

创意来源

灵感来自"在凌晨三点也不缺席的陪伴"。把 AI 多智能体技术应用到青少年心理健康场景中，让孩子在最难开口的时候，仍然可以被看见、被理解、被引导去求助。

03

三位 AI 伙伴

暖暖作为主对话 Agent 面向用户，聪聪和豆豆在后台协同分析，用户只看到一个对话界面。

暖暖 主对话 Agent

EMPATHY · 共情陪伴

面向用户的主对话角色。用温暖、不评判的语言接住情绪，回复中自然融入聪聪的分析和豆豆的建议，让用户感受到一个完整、连贯的陪伴者。

聪聪 后台分析 Agent

COGNITION · 认知分析

在后台运行，识别情绪背后的认知模式，分析"为什么会有这样的感受"，结果融入暖暖的回复中。用户主动要求时也可以独立出现。

豆豆 后台行动 Agent

ACTION · 行动建议

在后台运行，提供可执行的小建议、疗愈练习或求助路径，把理解转化为行动。高危场景下直接触发危机干预流程。

交互设计决策：用户只看到一个对话界面，不会困惑"我在跟谁说话"。暖暖负责全部前端对话，聪聪和豆豆的后台分析结果由 Orchestrator 融合后，以暖暖的口吻呈现。这种"主 Agent 对话 + 后台多 Agent 协同"模式既保留了多智能体的技术深度，又保证了用户体验的流畅。

04

多 Agent 协作流程

三个 Agent 不是轮流值班，而是由中央调度器根据情绪状态自动决策协作模式，像医疗团队联合出诊。

06

核心创新

从"用户找 AI"变成"AI 主动守护用户"，是本方案区别于普通聊天机器人的关键。

01

多 Agent 会诊

三个 Agent 各施其职，中央调度器根据情绪状态自动决策协作模式，而非单 Agent 轮流值班。

02

AI 主动关怀

五种触发机制（早晚问候、情绪危机、缺席关怀、周报推送、场景化关怀），降低求助门槛。内置关怀衰减机制：连续缺席超时后推送频率逐渐降低；用户连续忽略 3 次，AI 改为更轻量的方式（如更新情绪总结），避免产生被监视感。用户可自行设置关怀偏好和免打扰时段。

03

专业内容游戏化

CBT 疗法融入 7 天冒险任务，PHQ-9 / GAD-7 量表转化为"情绪体检"，降低心理防御。

04

危机干预入口

识别到自伤风险时快速推送心理援助热线，把求助路径摆到用户面前。

持续跟进

AI 持续陪伴，引导后续寻求专业帮助

AI 安全边界：在危机场景中，AI 的角色是"识别风险 + 推送求助路径"，而非"提供心理治疗"。所有高风险场景均推送专业热线信息，不尝试自行处理。情绪数据按敏感个人信息标准加密存储，遵循未成年人数据保护规范。产品明确提示用户：AI 不能替代心理咨询师、医生或紧急救援。

技术路径

基于大语言模型 API 构建多 Agent 调度，微信小程序作为前端载体。

采用 LLM-as-Agent 架构，通过意图识别将用户输入路由到对应角色 Agent。中央调度器 Orchestrator 负责情绪状态追踪、协作模式决策与主动关怀触发。前端基于微信小程序原生框架开发，后端使用云函数 + 向量数据库实现情绪历史存储与个性化推荐。
