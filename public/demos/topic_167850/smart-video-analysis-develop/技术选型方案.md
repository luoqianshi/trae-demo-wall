# 多模态视频智能解析与创作辅助系统 — 技术选型方案

## 一、项目概述

基于 AI 的多模态视频智能解析与创作辅助平台，涵盖视频上传解析、多视频融合创作、以图搜视频检索、帧级画面创作、音频创作、在线剪辑等核心功能模块。系统需对接 ComfyUI、TTS/歌声合成等本地 AI 服务，提供完整的视频分析→创作→剪辑一站式能力。

---

| **AI 服务对接** | ComfyUI / GPT-SoVITS / RVC | — | HTTP API 调用 |

## 三、后端架构

### 3.1 框架与语言

- **JDK**: OpenJDK 17 (LTS)
- **构建工具**: Maven 3.9+
- **框架**: Spring Boot 3.2.x
  - spring-boot-starter-web (RESTful API)
  - spring-boot-starter-websocket (实时任务状态推送)
  - spring-boot-starter-validation (参数校验)
  - spring-boot-starter-security (权限控制, JWT 认证)
  - spring-boot-starter-actuator (健康检查)

### 3.2 数据层

| 组件 | 选型 | 用途 |
|------|------|------|
| **ORM** | MyBatis-Plus 3.5.x | 单表 CRUD、分页、逻辑删除 |
| **连接池** | HikariCP (Spring Boot 默认) | 数据库连接管理 |
| **数据库迁移** | Flyway | 版本化 SQL 变更管理 |

**MyBatis-Plus 配置要点：**
- 自动填充: createTime / updateTime
- 逻辑删除: isDeleted 字段
- 分页插件: PaginationInnerInterceptor
- 代码生成器: AutoGenerator (快速产出 Entity/Mapper/Service/Controller)

### 3.3 缓存与消息

| 组件 | 选型 | 用途 |
|------|------|------|
| **缓存** | Redis 7.x (Spring Data Redis) | Token 存储、热点数据缓存、验证码 |
| **任务队列** | Redis Stream / Spring Task | 异步任务管理 (AI 解析/生成任务) |
| **分布式锁** | Redisson | 防止重复提交、资源竞争 |

**Redis 使用场景明细：**

```
- 用户 Session / JWT Token 黑名单          → String, TTL 自动过期
- AI 任务状态实时推送                       → Pub/Sub (WebSocket + Redis)
- 视频解析任务队列                          → Redis Stream (消费者组模式)
- 接口限流                                 → Redis + Lua 脚本 (令牌桶)
- MinIO 预签名 URL 缓存                     → String, 短期 TTL
```

### 3.4 文件存储

**MinIO 作为统一静态资源服务器：**

```
 Bucket 设计:
 ├── video-raw          ← 原始上传视频
 ├── video-processed    ← 处理后视频片段
 ├── audio-output       ← AI 生成的音频文件
 ├── image-frames       ← 关键帧截图
 ├── image-generated    ← AI 生成的画面
 ├── project-exports    ← 导出的成片文件
 └── temp              ← 临时文件 (定期清理)
```

- 通过 MinIO Java SDK 操作
- 预签名 URL 提供给前端直接上传/下载, 减轻服务器带宽压力
- 文件元信息 (路径、大小、类型) 存入 MySQL

### 3.5 AI 服务对接

系统不内置 AI 模型, 通过 HTTP API 对接外部 AI 服务:

| AI 服务 | 通信方式 | 用途 | 部署方式 |
|---------|---------|------|---------|
| **ComfyUI** | HTTP API (WebSocket 事件流) | 帧级画面生成、重绘、插帧 | Docker 容器 |
| **GPT-SoVITS** | HTTP API | TTS 语音合成、人声克隆 | Docker 容器 |
| **RVC** | HTTP API | 歌声音色转换 | Docker 容器 |
| **Whisper** | HTTP API (本地部署) | 语音转文字、音频转写 | Docker 容器 (GPU) |

**对接策略:**
- Spring Boot 中定义统一的 `AiServiceClient` 接口
- 每种 AI 服务一个实现类, 通过 `@ConditionalOnProperty` 按配置开关注册
- 配置项: 服务地址、密钥、超时时间、重试策略
- 健康检查: Actuator 自定义 HealthIndicator, 检测各 AI 服务连接状态

## 五、数据库设计要点

### 5.1 核心表结构 (概要)

```sql
-- 用户表
t_user (id, username, password_hash, avatar, role, status, created_at, updated_at)

-- 项目/工作空间
t_project (id, user_id, name, description, cover_image, status, created_at, updated_at)

-- 视频资源
t_video (id, project_id, filename, storage_path, duration, resolution,
         file_size, status, created_at)

-- 视频解析结果
t_video_analysis (id, video_id, transcript_json,  -- 音频转写 JSON
                  frames_json,                     -- 关键帧分析 JSON
                  prompts_json,                    -- 画面提示词 JSON
                  analysis_status, created_at)

-- 关键帧
t_video_frame (id, video_id, frame_index, timestamp,
               storage_path, scene_tags, prompt_text)

-- 音频资源
t_audio (id, project_id, video_id, filename, storage_path,
         duration, sample_rate, channels, created_at)

-- 融合创作任务
t_fusion_task (id, project_id, video_ids_json, fusion_mode,
               script_outline, shot_suggestions, status, created_at)

-- 帧级创作任务
t_frame_task (id, project_id, video_id, comfyui_workflow_id,
              mode, params_json, result_paths_json, status, created_at)

-- 音频创作任务
t_audio_task (id, project_id, audio_id, mode, voice_id,
              params_json, result_path, status, created_at)

-- 剪辑项目
t_edit_project (id, project_id, timeline_json,          -- 时间轴数据
                assets_json, export_path, status, created_at)
```

### 5.2 JSON 字段策略

对于结构不固定的大文本数据 (转写文案、关键帧信息、时间轴数据), 采用 MySQL JSON 类型存储:
- 避免过度分表 (如逐句文案单独建表)
- 查询时通过 MySQL JSON Functions (`JSON_EXTRACT`, `JSON_CONTAINS`) 按需检索
- 适用于 MVP 阶段, 后续可按需拆分

## 八、关键流程设计

### 8.1 视频上传解析流程

```
前端                              后端                              中间件/存储
 │                                  │                                  │
 │─ POST /api/video/upload ────────>│                                  │
 │   (文件直传 MinIO 预签名)         │── 生成预签名 URL ───────────────>│ MinIO
 │                                  │<── 返回上传 URL ─────────────────│
 │─ PUT 直传到 MinIO ─────────────────────────────────────────────────>│ MinIO
 │                                  │                                  │
 │─ POST /api/video/analyze ──────>│                                  │
 │                                  │── 创建解析任务 (Redis Stream) ──>│ Redis
 │                                  │── 调用 Whisper 转写 ────────────>│ Whisper
 │                                  │── 逐帧分析 (FFmpeg + 本地)       │
 │                                  │── 存储关键帧到 MinIO ────────────>│ MinIO
 │                                  │── 结果写入 MySQL ───────────────>│ MySQL
 │<── WebSocket 进度推送 ──────────│                                  │
```

### 8.2 任务状态机

```
PENDING → RUNNING → SUCCESS
                → FAILED (可重试)
                → CANCELLED

状态存储: MySQL (持久) + Redis (实时查询)
通知方式: WebSocket (前端订阅频道)
```

## 十、技术选型对照与决策依据

| 决策点 | 选项 | 选择 | 理由 |
|--------|------|------|------|
| ORM | MyBatis vs JPA vs MyBatis-Plus | MyBatis-Plus | 团队熟悉、灵活控制 SQL、代码生成效率高 |
| 前端框架 | React vs Vue | Vue 3 | 团队技术栈匹配、Element Plus 生态完善 |
| UI 组件库 | Ant Design vs Element Plus | Element Plus | 中文社区活跃、表格/表单组件丰富 |
| 任务队列 | RabbitMQ vs Redis Stream | Redis Stream | 减少中间件依赖、MVP 阶段够用、可后续升级 |
| 视频处理 | FFmpeg (Java) | FFmpeg CLI + ProcessBuilder | 成熟稳定、格式支持全面 |
| 实时通信 | SSE vs WebSocket | WebSocket | 双向通信、支持任务进度推送 |
| API 文档 | Swagger / Knife4j | Knife4j | Spring Boot 原生集成、中文界面 |
| 数据库迁移 | Flyway vs Liquibase | Flyway | 轻量、SQL 优先、与 Spring Boot 集成好 |

## 十一、后续扩展方向

1. **GPU 加速**: Docker Compose 中挂载 nvidia-docker runtime, 支持 ComfyUI / Whisper GPU 推理
2. **任务队列升级**: 量增大后 Redis Stream → RabbitMQ / RocketMQ
3. **微服务拆分**: AI 服务调用层可独立为 Gateway + 微服务架构
4. **CDN 分发**: MinIO 前置 Nginx 反向代理或接入 CDN, 加速视频资源访问
5. **前端 SSR**: 剪辑工作台等重交互页面可考虑 WebWorker + OffscreenCanvas 提升性能
