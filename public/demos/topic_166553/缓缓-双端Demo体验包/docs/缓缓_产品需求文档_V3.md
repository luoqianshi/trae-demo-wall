| **命名理由** | 「缓缓」兼具「慢下来」与「我缓着你」双重含义：既呼应产品核心——温柔地将用户从手机沉迷中拉回现实生活，又传递「被陪伴、被惦记」的情感温度。叠词形式南北通用、读音柔和，不易与常见人名冲突，品牌延展性强，可覆盖健康、出行、烹饪等全场景，且与模块「闲情·慢时光」气质一致。 |

## 1. 产品概述

### 1.1 产品定位

**缓缓**是一款面向老年人的智能情感陪伴与生活引导应用。它以常驻后台的温和感知为基础，在合适时机主动发声，像一位懂分寸的老友——不催促、不指责，只轻声建议：歇歇眼睛、出去走走、记得吃药。

它不是又一个「让老人多玩手机」的工具，而是帮助老人**更少无效刷屏、更多真实生活**的桥梁。

### 1.2 目标用户

| 用户类型 | 画像 | 核心诉求 |
| :--- | :--- | :--- |
| **核心用户（父母端）** | 60 岁以上，有智能手机，存在孤独感、健康管理需求或无意识刷机习惯 | 被关心、生活有节奏、健康有人提醒 |
| **次要用户（子女端）** | 与父母异地居住，关心父母近况但无法时刻陪伴 | 远程了解父母状态、参与陪伴、异常预警 |

### 1.3 核心价值

- **情感**：从「没人管」到「有人惦记」——用应景、口语化的主动关怀填补孤独感。
- **行为**：从「被动消耗」到「主动生活」——以更有吸引力的现实活动替代无意识刷机。
- **健康**：从「病了才治」到「日常预防」——用药、测量、不适关键词的轻量守护。

### 1.4 成功指标（北极星）

> **每周「放下手机并完成一条生活建议」的次数**（非 App 内停留时长）

| 指标类型 | 具体指标 | 说明 |
| :--- | :--- | :--- |
| 北极星 | 周均生活建议完成数 | 如出门散步、完成用药确认、记录血压等 |
| 情感 | 建议接受率 | 用户点击「好的/去看看」占比 |
| 健康 | 用药按时确认率 | 7 日内按时确认服药的比例 |
| 家庭 | 子女端周互动次数 | 点赞、留言、发起通话等 |
| 克制 | 日均无效打断次数 | 应控制在 ≤ 2 次，避免骚扰感 |

## 2. 用户痛点与解决方案

| 诉求领域 | 用户痛点 | 缓缓 的解法 |
| :--- | :--- | :--- |
| **情感陪伴** | 子女不在身边，孤独、渴望被惦记 | 拟人化主动关怀，称呼「老朋友」，语气用「咱们」 |
| **社交需求** | 社交圈窄，缺出门契机 | 结合天气、位置推荐可执行的出门理由 |
| **健康管理** | 忘吃药、不会记指标、略懂健康知识就焦虑 | 大按钮用药提醒 + 语音记录 + 权威来源科普 |
| **价值实现** | 退休后觉得「没用」 | 烹饪、挑菜、手工等任务赋予「为家人创造价值」的意义 |
| **数字沉迷** | 无意识刷短视频，事后空虚 | 温柔打断 + 提供更有吸引力的现实替代，禁止生硬锁机 |

### 3.1 智能感知与温柔打断引擎 【P0】

#### 功能描述

常驻后台监测指定类别 App（短视频、资讯、小游戏等）的连续使用时长，在合适窗口以全屏卡片 + 人声播报温柔介入。

#### 核心规则

| 规则项 | 默认值 | 可调范围 |
| :--- | :--- | :--- |
| 连续使用阈值 | 45 分钟 | 30–90 分钟 |
| 每日打断上限 | 3 次 | 1–5 次 |
| 静默时段 | 21:00–07:00 | 用户可自定义 |
| 最短间隔 | 两次打断间隔 ≥ 2 小时 | — |

#### AI 时机判断因子

- **时间**：深夜不建议出门，可建议听戏曲/闭目养神。
- **天气**：雨雪、高温时不推荐户外，转为室内活动。
- **历史偏好**：用户多次拒绝「去公园」后，降低同类建议权重。
- **健康标签**：糖尿病用户饭点优先推饮食建议而非甜食相关活动。

#### 打断交互规范

- 全屏半透明遮罩，中央温暖卡片，**两个等大按钮**：「好的」与「不了，谢谢」。
- 语气必须是**建议**而非命令。示例：「老朋友，歇歇眼睛吧。楼下月季开得正好，咱们下楼看看？走路只要 5 分钟~」
- 用户拒绝后，**当日内不再就同一类建议重复打扰**。
- 连续 3 次拒绝同一模块，自动降低该模块推送频率。

#### 退出机制（V3.1 新增）

- 弹窗出现后，底部小字提示「暂时不想被打扰」倒计时（5 秒后出现），点击后当日暂停打断。
- 用户点击「不了，谢谢」后，卡片收起，不做二次确认，无强制停留。
- 用药提醒等**健康类弹窗**不可跳过（无退出机制），仅生活建议类打断可退出。

#### 验收标准

- [ ] 达到阈值后 3 秒内弹出打断卡片并播报语音
- [ ] 静默时段内不触发户外类建议
- [ ] 「不了，谢谢」与「好的」按钮触控区域 ≥ 48dp
- [ ] 用户可在设置中关闭某类 App 的监测
- [ ] 「暂时不想被打扰」入口在弹窗出现 5 秒后可见，点击后当日不再弹出打断
- [ ] 用药提醒弹窗不包含退出入口

#### 行动引导闭环（V3.1 新增）

用户点击「去看看」后，不可简单跳回主页，必须提供**明确的下一步行动引导**，确保从"被打断"到"完成行动"的路径连贯。

| 建议类型 | 行动引导页内容 | 完成确认方式 |
| :--- | :--- | :--- |
| 户外散步（下楼看花/去公园） | 目的地卡片（含公园名、步行时间、天气）+ 一键导航按钮 + 「我到了」确认 | 用户点击「我到了」或 30 分钟后自动标记为"可能已完成" |
| 室内活动（听戏曲/闭目养神） | 沉浸式卡片（大按钮播放 + 定时器 15/30/60 分钟） | 用户主动结束或倒计时结束 |
| 喝水/起身 | 简单确认页「喝一杯温水吧」+ 大按钮「喝好了」 | 用户点击确认 |

**验收标准**：
- [ ] 所有生活建议类型均有对应的行动引导页，不可出现"去看看后无下一步"的情况
- [ ] 户外类引导页包含「一键导航」跳转至系统地图
- [ ] 行动引导页提供明确的「完成」或「放弃」选项
- [ ] 完成的行动记入北极星指标（周均生活建议完成数）

#### 模块一：食光·生活家 【V1.5】

| 功能 | 触发条件 | 内容示例 |
| :--- | :--- | :--- |
| 饭点烹饪建议 | 10:30 / 16:30，结合健康标签 | 推送适合糖尿病人的菜谱短视频，步骤语音播报 |

| 价值感文案 | 嵌入各场景 | 「学会了这个，下次给孙子露一手，他准喜欢！」 |

#### 模块二：四季·逍遥游 【V1.5】

| 功能 | 触发条件 | 内容示例 |
| :--- | :--- | :--- |
| 出行建议 | 14:00–16:00，天气适宜 | 「下午 3 点，25 度不冷不热，最适合散步。」 |

#### 模块三：安康·守护者 【P0】

| 功能 | 交互要点 |
| :--- | :--- |
| **用药提醒** | 药品名 + 服用方式语音播报；「已服用」「等会提醒」两个大按钮 |
| **未确认 escalation** | 5 分钟后再提醒 → 连续 2 次未确认通知子女端 |
| **健康指标记录** | 用户说「记录血糖」，进入语音录入页，实时转写并确认 |
| **趋势图** | 极简折线图，可分享给子女 |
| **关键词关怀** 【V2.0】 | 感知「头晕」「胸闷」等输入，弹窗建议休息并联系家人 |

**用药提醒验收标准：**

- [ ] 提醒准时误差 ≤ 1 分钟
- [ ] 药品名称字号 ≥ 24sp，对比度符合 WCAG AA
- [ ] 语音播报可重复播放，按钮 ≥ 56dp

#### 模块四：闲情·慢时光 【V1.5】

| 功能 | 示例 |
| :--- | :--- |
| 线下活动建议 | 「钩针拿出来钩两针？」「君子兰该浇水了~」 |
| 怀旧电台 | 戏曲、评书、老歌，引导闭目养神 |
| 亲情连接 | 打断后建议「给闺女发个语音，说说今天挑荔枝的窍门」 |

### 3.3 子女端联动 【P0 基础 / V1.5 深化】

#### MVP 能力

- **今日一览**：父母完成了哪些建议（出门、服药确认、健康记录）
- **温情点赞/留言**
- **安全预警**：用药连续未确认、白天 2 小时无任何手机操作

#### V1.5+ 能力

- **远程任务共创**：子女发起「明天教我做红烧排骨」→ 父母端生成特别做菜任务
- **视频通话快捷入口**

#### 子女端设计原则

- 信息呈现**温情而非监控**：用「妈妈今天去公园走了 3000 步」而非「妈妈 14:32 离开家」。
- 所有预警需父母端提前授权并告知。

## 4. 交互与界面设计原则

| 维度 | 规范 |
| :--- | :--- |
| **视觉** | 极简布局；白底 + 深绿主色；最小字号 18sp，正文 20–24sp；图标 ≥ 48dp |
| **听觉** | 核心提醒必须有人声播报；语速偏慢，音量可独立调节；V2.0 支持粤语、四川话 |
| **交互** | 以大按钮点击 + 语音为主；减少滑动和文字输入；所有建议提供明确「做 / 不做」 |
| **情感化** | 称谓用「咱们」「老朋友」；允许子女帮父母设置昵称（如「王阿姨」） |
| **无障碍** | 支持系统大字模式联动；关键操作支持语音确认 |

## 6. 首次使用与权限引导

### 6.1  onboarding 流程（3 步 + JIT 权限）

1. **欢迎页**：「您好，我是缓缓，往后日子缓缓过，我轻轻陪着您。」
2. **昵称设置**：子女可代设，或老人自选。
3. **健康档案（可选）**：慢性病标签、常服药品、测量计划。

> **权限请求改为 Just-in-Time（随用随请求）**：
> - **通知权限**：在首次进入「今日缓缓」主页时请求，配合提示"开启通知，我能准时提醒您吃药"。
> - **使用情况感知权限**：在首次触发打断监测时请求（即首次进入「设置 > 监测 App 管理」时），配合说明"只感知您刷了多久，不会读取聊天和支付内容"。
> - **定位权限（可选）**：在首次触发出行建议场景时请求，配合提示"开启定位，我能推荐附近公园和菜场"。
>
> **理由**：一页内同时请求 3 个权限对老年人认知负荷过高，改为在用户首次需要该功能时自然请求，转化率更高。

### 6.2 子女绑定

- 父母端生成 6 位绑定码，子女端扫码或输入完成关联。
- 绑定需父母端二次确认：「确认让【小明】关注您的生活建议完成情况吗？」

## 7. 技术约束与合规

### 7.1 平台能力边界（务必在开发前评估）

| 能力 | Android | iOS |
| :--- | :--- | :--- |
| 后台 App 使用时长监测 | 可通过 UsageStats（需用户授权）实现 | **受限**，需依赖 Screen Time API 或合理替代方案 |
| 全屏打断其他 App | 悬浮窗/全屏 Intent 可行 | 需用通知 + 快捷入口，无法完全遮罩第三方 App |
| 关键词感知 | 仅限本 App 内输入 | 同左，**不可读取其他 App 输入内容** |

> **V1.0 策略建议**：Android 优先实现完整打断体验；iOS 以「强通知 + 语音播报 + 一键返回缓缓」为替代，并在产品内诚实说明平台差异。

### 7.2 隐私与合规

- 遵循《个人信息保护法》；健康数据单独加密存储。
- 最小化采集：不读取短信、通话记录、其他 App 内容。
- 子女端仅展示**汇总后的生活建议完成情况**，不默认开放实时定位轨迹。
- 提供「一键暂停所有打扰」与「卸载无忧」说明页。

### 7.3 内容安全

- 健康建议标注来源（卫健委、三甲医院科普等），避免诊断性表述。
- 关键词关怀文案统一为「建议休息 + 联系家人」，不做在线诊断。

## 9. 风险与对策

| 风险 | 对策 |
| :--- | :--- |
| 老人反感「被管」 | 语气建议式、拒绝后降频、每日打断有上限 |
| 后台权限被系统杀死 | 引导加入电池白名单；核心用药提醒走系统闹钟级通知 |
| iOS 无法实现遮罩打断 | 分平台体验，文案管理预期 |
| 健康建议引发焦虑 | 科普口吻、避免恐吓式表述 |
| 子女端变「监控」 | 默认汇总态、预警需授权、无实时轨迹 |

## 10. 总结

**缓缓**的目标不是提高老人的屏幕时间，而是提高他们**真实生活的次数**。

它用「日子缓缓，陪伴轻轻」的态度，在柴米油盐、四季更迭与身心安康之间，做那座温柔的桥——当老人又无意识刷了很久手机时，轻轻说一句：「老朋友，歇会儿吧，生活在等你呢。」
