日子缓缓，陪伴轻轻

不是让老人多玩手机，而是温柔地把他们从无意识刷屏里拉回到真实生活。 父母端 缓缓 常驻轻量守护，子女端 缓缓·轻轻 远程了解近况、留言互动与安全预警。

14MB 父母端安装包（Kotlin 原生），适配低配旧手机
双端分离 父母机只跑必要后台，子女机承载完整查看与互动
v1.5 生活场景建议、健康记录、Open-Meteo 天气、位置报备
子女端「轻轻」· 今日一览 v1.5 真机截图

父母端完成用药确认后，子女端实时看到「已服用」；同时展示父母当地天气与位置报备入口。

为什么做两个 App，而不是集成在一起？

这是产品架构的核心取舍：父母手机和子女手机的使用场景、性能预算完全不同。

① 父母手机性能普遍较弱

老人机多为中低端 Android，存储和内存有限。父母端采用 Kotlin 原生精简实现，Debug 包约 14MB，安装快、占用小，可长期后台运行用药闹钟、使用时长监测与位置报备。

② 角色不同，界面理应不同

父母需要「大按钮、少步骤、语音播报」；子女需要「汇总查看、地图、预警卡片、留言互动」。合并到一个 App 会让老人面对复杂导航，也会让子女功能挤占父母端空间。

③ 权限与后台能力按设备分配

UsageStats 使用监测、全屏打断、30 秒位置上报等敏感能力只应在父母自己的手机上运行；子女端只通过 API 查看汇总结果，避免「监控感」。

④ 可独立迭代，互不影响

父母端专注执行闭环（打断→引导→确认），子女端专注情感连接（一览→互动→预警）。双端通过 Go 后端同步，各自升级不拖累对方安装包体积。

Demo 简介与创作思路

对应大赛正文：是什么、面向谁、核心功能、为什么做这个方向。

🌿

温柔打断

监测无意识刷机，全屏轻声建议休息或出门，TTS 播报，支持「今日暂停打扰」。

💊

用药闭环

闹钟 + 5 分钟二次提醒，未确认则子女端收到 missed 预警。

🌦️

生活场景 v1.5

Open-Meteo 驱动买菜/烹饪/出行建议，健康记录，父母天气同步子女端。

💚

远程陪伴

汇总态呈现今日完成、位置报备、留言互动，拒绝实时监控焦虑。

灵感来源：父母独自在家刷短视频，子女异地关心却怕「监控」。

想解决的问题：数字沉迷、孤独感、用药遗忘、信息不对称。

取舍：成功指标是「每周完成生活建议次数」，不是 App 停留时长；父母端极致轻量，子女端承载丰富查看能力。
