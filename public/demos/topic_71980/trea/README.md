# 安诊 · 智能分诊助手

> 老百姓去医院总挂错科？这个网页让用户选身体部位和症状，30 秒推荐该挂的科室、判断紧急程度、给出就医提示。社会服务方向的纯前端 Demo。

## 产品简介

「安诊」是一款面向公众的智能分诊小工具，目标用户是不知道该挂哪个科室的普通就诊者。用户通过人体图选择身体部位、勾选症状、补充年龄/病程/慢病史等基础信息后，系统会基于内置的规则引擎推荐最合适的科室、判断紧急程度（常规/较急/紧急），并给出实用的就医提示。危急症状（如压榨性胸痛、呼吸困难）会触发红色急诊警告并提示拨打 120。

整个应用为单 HTML 文件，零依赖、零网络请求，双击即可离线运行，适合在医院自助机、社区健康站、家庭电脑等任意场景使用。

## 功能清单

### 核心分诊
- **9 大部位**：头部、眼睛、耳鼻喉、胸部、腹部、皮肤、骨骼关节、全身、情绪睡眠
- **44 条症状**：每个部位 4-5 个常见症状，含 1-2 个危急症状（红色标记）
- **15 个科室**：神经内科、眼科、心内科、消化内科、皮肤科、骨科、儿科、急诊科等
- **权重累加算法**：根据症状权重计算得分，推荐匹配度最高的科室
- **危急症状熔断**：勾选危急症状自动触发红色急诊横幅 + 120 拨号按钮

### 智能规则
- **儿童分诊**：14 岁以下非危急症状自动改推「儿科」
- **老年人上调**：60 岁以上伴胸痛/头晕/心悸，紧急程度自动上调一档
- **慢病史加权**：心脏病史 + 胸部症状 → 心内科权重 +3
- **长病程提示**：症状持续超过两周 → 增加"建议全面检查"提示

### 交互亮点
- **SVG 人体轮廓图**：内联手绘人体图，7 个可点击热区，选中时涟漪扩散动画
- **双向联动**：人体图热区与右侧部位列表、底部胶囊按钮三方同步
- **跨部位多选**：可同时选择多个部位，症状按部位分组显示
- **分析动画**：1.5 秒转圈动画 + 三段文案切换（分析症状 → 匹配科室 → 评估紧急程度）
- **圆环进度图**：SVG 圆环带 1 秒生长动画 + 百分比数字滚动增长
- **三格色带**：常规(绿)/较急(黄)/紧急(红)三档，当前档位高亮放大
- **科室小百科**：推荐科室后 ⓘ 图标点击展开，含「看什么病」+「常见检查」
- **语音播报**：结果生成后自动中文朗读"建议挂 XX 科"，🔊 按钮可重播/停止（不支持时自动隐藏）
- **分诊小票**：模态框展示医院取号凭条样式（logo、日期、症状清单、推荐科室大字、紧急度、就医提示、底部条形码）

### 数据与持久化
- **统计条**：顶部"9 大部位 · 44+ 症状 · 15 个科室"数字滚动增长
- **历史记录**：localStorage 保存最近 5 次分诊，刷新页面仍在，支持一键清空
- **复制分诊单**：将结果整理成纯文本复制到剪贴板

### 视觉与体验
- 医疗感青绿色主调（#14b8a6 / #0d9488），白色圆角卡片
- 步骤进度线，完成步骤打勾
- 症状标签选中弹跳动画
- 卡片滚动淡入（IntersectionObserver）
- 移动端自适应（375px 不破版）
- 所有按钮 hover/active 反馈

## 运行方式

### 方式一：双击打开（最简单）
直接双击 `index.html`，系统默认浏览器打开即可使用，无需安装任何环境。

### 方式二：本地服务器（推荐用于开发）
```bash
# Python 3
python -m http.server 8000
# 然后浏览器访问 http://localhost:8000/index.html
```

### 方式三：直接拖入浏览器
将 `index.html` 文件拖入任意现代浏览器窗口即可。

**兼容性**：Chrome / Edge / Safari / Firefox 等现代浏览器，桌面端与移动端均支持。语音播报依赖浏览器 SpeechSynthesis API，不支持时按钮自动隐藏，不影响其他功能。

## 技术说明

### 架构
- **单文件**：所有 HTML / CSS / JS 内联在 `index.html` 中
- **零依赖**：不引入任何外部库、CDN、图片、字体
- **零网络请求**：完全离线运行，不接任何 API
- **图标全部用 emoji**：无 SVG 图标库依赖（人体图与圆环进度除外，均为内联手写 SVG）

### 规则引擎
分诊逻辑采用**本地症状-科室映射 + 权重累加**的规则引擎：

1. 每个症状关联一个目标科室和权重（1-5，5 为危急）
2. 用户勾选症状后，按科室累加权重
3. 取得分最高的科室作为推荐结果
4. 叠加业务规则：儿童改推儿科、老年人紧急度上调、慢病史加权等
5. 匹配度 = 推荐科室得分 / 总得分（保底 68%）

规则全部硬编码在 `KB` 常量中，可读、可改、可审计，无任何外部依赖。

### 数据结构
```javascript
KB = {
  head: {
    name: '头部', emoji: '🧠',
    symptoms: [
      { id: 'h1', name: '持续性头痛', dept: '神经内科',
        weight: 3, reason: '...',
        crit: false  // 是否危急
      },
      ...
    ]
  },
  ...
}
```

### 持久化
- 使用 `localStorage`（key: `anzhen_history_v1`）保存最近 5 次分诊记录
- 不存储任何个人身份信息（PII），仅保存时间、科室、紧急度、症状摘要

### 未来可接大模型 API 的扩展点
当前规则引擎适合演示和离线场景，若需更强的语义理解能力，可平滑升级为：

1. **症状自由描述**：将文本框输入的症状描述发送给大模型，由模型映射到结构化症状
2. **多轮问诊**：大模型根据已选症状追问关键鉴别问题（如"胸痛是否放射到左肩"）
3. **更细粒度推荐**：大模型结合 ICD 编码给出更精确的科室与子专科
4. **风险分层**：大模型基于症状组合给出概率化的紧急程度评估

扩展时只需在后端封装一个 `/triage` 接口，前端 `computeDiagnosis()` 替换为 `fetch('/triage', {...})` 即可，UI 层无需改动。建议保留当前规则引擎作为兜底，当大模型 API 不可用时降级到本地规则。
