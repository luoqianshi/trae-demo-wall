## 一、项目概述

### 1.1 项目简介

本项目是一个面向真实宴席场景（婚宴、升学宴、寿宴、满月宴等）的**局域网轻量级协同管理系统**。系统采用本地部署模式，无需公网服务器，通过一台电脑运行后端服务，现场所有设备通过局域网连接使用。

系统覆盖宴席的全流程管理：从宾客名单导入、座位编排、礼金登记，到现场迎宾、传菜管理、环节控制、照片分享、祝福语互动等，实现宴席的数字化协同。

### 1.2 适用场景

- 婚宴（核心场景）
- 升学宴
- 寿宴
- 满月宴
- 公司年会
- 其他需要统筹安排的宴席活动

### 1.3 部署形态

- **纯局域网运行**：全场设备连接同一个路由器，数据在局域网内流转
- **单节点部署**：一台电脑运行后端服务和数据库
- **GUI控制台**：桌面端图形界面，负责服务器启停、日志查看、数据库备份与恢复
- **多端协同**：不同角色通过不同URL入口访问对应功能页面

## 二、核心价值与设计理念

### 2.1 核心价值

#### 价值一：年轻主家的"亲戚识别作弊小抄"

通过精确到座位的人员分布图，帮助年轻的新郎新娘在敬酒和迎宾时快速识别亲戚身份，消除社交尴尬。每个座位都有备注信息（如"新郎二舅"、"新娘小姨"），点开就能看到。

#### 价值二：人情账数字化闭环

实现礼金的全流程数字化管理：导入名单 → 现场登记 → 实时统计 → 导出报表，告别纸质账本容易丢失、统计麻烦的痛点。

#### 价值三：多角色协同效率提升

主人、主持人、摄影师、迎宾、传菜员等多个角色通过系统协同工作，信息实时同步，避免人工传话的遗漏和错误。

#### 价值四：宴席体验升级

宾客通过手机端可以查看座位信息、菜品进度、现场照片、发送祝福语，提升宴席的互动性和科技感。

### 2.2 设计理念

1. **现场优先**：所有设计以真实宴席现场的使用场景为出发点，不追求花哨功能，只求稳定、好用、应急有兜底。
2. **极简操作**：一线操作人员（迎宾、传菜员）可能不熟悉电子产品，操作流程必须极简，按钮要大，步骤要少。
3. **全量留痕**：任何操作都要有日志记录，出了问题可以回溯。
4. **局域网优先**：不依赖公网，断网也能用，数据不出现场。
5. **容错设计**：重要操作要有确认机制，误操作可以补救（但传菜等不可逆操作除外）。

### 4.2 架构原则

#### 4.2.1 单API端口，路由区分角色

**坚决摒弃"8个物理端口"的设计！** 后端只运行一个FastAPI服务（默认端口8000），通过URL路由区分不同角色端。

| 路由路径 | 对应端 | 说明 |
|----------|--------|------|
| `/host` | 主人端 | 主家管理后台 |
| `/emcee` | 主持人端 | 主持人使用 |
| `/photographer` | 摄影师端 | 摄影师上传照片 |
| `/usher` | 迎宾端 | 迎宾登记使用 |
| `/waiter` | 传菜端 | 传菜员上菜确认 |
| `/staff/{id}` | 身份牌端 | 工作人员身份牌展示 |
| `/table/{id}` | 宴桌端 | 桌上平板展示 |
| `/guest` | 宾客端 | 宾客手机访问 |
| `/api/*` | API接口 | 所有后端API接口 |
| `/static/*` | 静态资源 | 前端静态文件 |

#### 4.2.2 前后端分离

- 后端：FastAPI提供RESTful API
- 前端：HTML + CSS + JavaScript（可选用Vue3或原生JS）
- 静态文件由FastAPI直接托管

#### 4.2.3 GUI与后端进程分离

GUI控制台和后端Web服务是**两个独立的进程**：
- GUI只负责发指令（启动/停止/备份）
- 后端服务通过 `subprocess.Popen` 在后台独立启动
- GUI崩溃或关闭，不影响后端服务运行（只要不主动发停止指令）

#### 4.3.1 局域网部署

```
                    ┌─────────────┐
                    │  现场路由器  │
                    │  192.168.x.1│
                    └──────┬──────┘
                           │
          ┌────────────────┼────────────────┐
          │                │                │
    ┌─────▼─────┐   ┌──────▼──────┐  ┌──────▼──────┐
    │ 服务器电脑 │   │  工作人员   │  │   宾客手机   │
    │ 运行后端   │   │  PDA/手机   │  │  (HTTP访问) │

```

#### 4.3.2 HTTP与HTTPS策略

由于局域网环境下配置HTTPS证书需要在所有设备上安装证书，对宾客极不友好，因此采用**设备分级策略**：

| 设备类型 | 访问协议 | 是否需要摄像头 | 说明 |
|----------|----------|----------------|------|
| 宾客手机 | HTTP | 不需要 | 纯展示和交互，无硬件调用 |
| 宴桌平板 | HTTP | 不需要 | 纯展示，无硬件调用 |
| 迎宾PDA | HTTP | 需要 | 通过Chrome flags白名单允许HTTP调用摄像头 |
| 传菜PDA | HTTP | 需要 | 通过Chrome flags白名单允许HTTP调用摄像头 |
| 摄影师端 | HTTP | 需要 | 通过Chrome flags白名单允许HTTP调用摄像头 |

**Chrome Flags设置方法**：
- 在需要调用摄像头的设备上，打开Chrome/Edge浏览器
- 地址栏输入：`chrome://flags/#unsafely-treat-insecure-origin-as-secure`
- 将该选项设为 Enabled
- 在下方输入框中填写服务器地址，如：`http://192.168.1.100:8000`
- 重启浏览器生效

## 五、数据库设计

### 5.1 数据库选型与配置

- **数据库**：SQLite 3
- **文件位置**：`./data/banquet.db`
- **必须开启**：WAL模式（Write-Ahead Logging）

#### 5.1.1 WAL模式开启

在SQLAlchemy创建engine后，必须执行：

```sql
PRAGMA journal_mode=WAL;
PRAGMA foreign_keys = ON;
```

**WAL模式的作用**：
- 允许读写并发，解决 `database is locked` 问题
- 提高并发写入性能
- 适合现场多人同时操作的场景

- 共6位数字

### 6.3 认证机制

#### 6.3.1 Token认证

- 使用 JWT (JSON Web Token) 进行认证
- 登录成功后返回 access_token
- 前端将 token 存在 localStorage 中
- 每次请求在 Header 中携带：`Authorization: Bearer <token>`

#### 6.3.2 Token过期策略

- 工作人员账号：Token有效期 8 小时（覆盖整个宴席时长）
- 宾客账号：Token有效期 24 小时
- Token过期后需要重新登录

#### 6.3.3 密码策略

- 主人/工作人员账号：密码可修改
- 宾客账号：**密码不可修改**（`password_changeable = false`）
- 宾客默认密码：手机号后6位（导入时自动生成）
- 现场添加的宾客：密码同样为手机号后6位

#### 7.1.2 功能清单

| 功能 | 说明 |
|------|------|
| 启动服务 | 点击后通过 subprocess.Popen 启动 FastAPI 后端进程 |

#### 7.1.3 进程管理设计

- GUI进程和后端进程完全分离
- 使用 `subprocess.Popen` 启动后端进程
- 通过进程PID管理后端服务
- GUI异常退出不影响后端运行
- 启动时检测是否已有后端进程在运行，避免重复启动

- **基础URL**：`/api`

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

```json

  "code": 40001,
  "message": "参数错误",
  "detail": "手机号格式不正确"
```

## 十、前端页面规划

### 10.1 技术选型建议

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| 原生HTML + CSS + JS | 轻量、无依赖、兼容性好 | 开发效率稍低 | ⭐⭐⭐⭐ |
| Vue3 + Vite | 开发效率高、组件化 | 需要构建、老设备兼容性 | ⭐⭐⭐⭐⭐ |
| React + Vite | 生态丰富 | 学习成本高 | ⭐⭐⭐ |

**推荐方案**：Vue3 + Vite + TailwindCSS
- 组件化开发，效率高
- 响应式设计方便
- 打包后可直接由FastAPI托管

### 11.1 SQLite WAL模式

**问题**：SQLite默认并发写入时会报 `database is locked`。

**解决方案**：
```python
# SQLAlchemy 异步配置示例
from sqlalchemy.ext.asyncio import create_async_engine

engine = create_async_engine(
    "sqlite+aiosqlite:///./data/banquet.db",
    echo=False,
    future=True,
)

# 连接创建时执行PRAGMA
@event.listens_for(engine.sync_engine, "connect")
def _set_sqlite_pragma(dbapi_connection, connection_record):
    cursor = dbapi_connection.cursor()
    cursor.execute("PRAGMA journal_mode=WAL;")
    cursor.execute("PRAGMA foreign_keys=ON;")
    cursor.close()
```

### 11.2 环节推进的并发锁

**问题**：主人和主持人同时点击"下一环节"，可能导致跳过环节。

**解决方案**：
1. 前端点击后按钮立即置灰，显示loading
2. 后端使用数据库行锁或乐观锁
3. 校验当前环节状态，只有active才能推进

```python
# 伪代码
async def advance_stage(user_id: int):
    async with db.begin():
        # 悲观锁：SELECT FOR UPDATE（SQLite用事务隔离）
        current_stage = await get_current_stage_with_lock()
        
        if current_stage.status != "active":
            raise BusinessError("当前环节状态不正确")
        
        # 找到下一个环节
        next_stage = await get_next_stage(current_stage.sequence_order)
        if not next_stage:
            raise BusinessError("已是最后一个环节")
        
        # 更新状态
        current_stage.status = "completed"
        current_stage.completed_at = datetime.now()
        current_stage.confirmed_by = user_id
        
        next_stage.status = "active"
        next_stage.started_at = datetime.now()
        next_stage.confirmed_by = user_id
        
        # 记录日志
        await log_operation(...)
```

### 11.3 传菜码输入优化

**优化方案**：

### 11.6 图片上传压缩

**问题**：原图太大，上传慢，占存储空间。

**优化方案**：
1. 前端使用 Canvas 压缩图片后再上传
2. 压缩到 500KB 左右，格式 WebP/JPG
3. 生成多尺寸（缩略图、压缩图、原图）
4. 缩略图用于列表展示，压缩图用于详情查看，原图按需下载

```javascript
// 前端图片压缩示例
function compressImage(file, maxSize = 500 * 1024) {
    return new Promise((resolve) => {
        const reader = new FileReader();
        reader.onload = (e) => {
            const img = new Image();
            img.onload = () => {
                const canvas = document.createElement('canvas');
                const ctx = canvas.getContext('2d');
                // 计算缩放比例
                let width = img.width;
                let height = img.height;
                const maxDim = 1920;
                if (width > maxDim || height > maxDim) {
                    if (width > height) {
                        height = (height / width) * maxDim;
                        width = maxDim;
                    } else {
                        width = (width / height) * maxDim;
                        height = maxDim;
                    }
                }
                canvas.width = width;
                canvas.height = height;
                ctx.drawImage(img, 0, 0, width, height);
                // 压缩
                canvas.toBlob((blob) => {
                    resolve(blob);
                }, 'image/jpeg', 0.8);
            };
            img.src = e.target.result;
        };
        reader.readAsDataURL(file);
    });
}
```

### 11.7 CSV导入校验

**问题**：用户填的CSV格式可能有问题。

**解决方案**：

### 11.8 GUI进程分离

**问题**：GUI和后端跑在一个进程，GUI卡死导致后端断网。

**解决方案**：
```python
# GUI端使用 subprocess 启动后端
import subprocess
import sys

def start_server():
    # 获取Python解释器路径
    python_path = sys.executable
    # 后端启动脚本
    script_path = os.path.join(app_dir, "server", "main.py")
    # 启动子进程
    process = subprocess.Popen(
        [python_path, script_path],
        stdout=subprocess.PIPE,
        stderr=subprocess.STDOUT,
        creationflags=subprocess.CREATE_NO_WINDOW if sys.platform == "win32" else 0,
    )
    return process

def stop_server(process):
    if process and process.poll() is None:
        process.terminate()
        process.wait(timeout=10)
```

### 11.9 数据库备份策略

**问题**：现场数据丢失后果严重。

**解决方案**：

2. 保留数量：保留最近12份（约2小时内的备份）
3. 备份文件命名：`backup_YYYYMMDD_HHMMSS.db`
4. 手动备份：GUI上有"立即备份"按钮
5. 恢复前自动备份当前数据（防止恢复错了）
6. 备份文件存放在 `./data/backups/` 目录

### 11.11 局域网IP获取

**问题**：主家不知道服务器IP，其他设备连不上。

**解决方案**：
```python
import socket

def get_local_ip():
    """获取本机局域网IP"""
    try:
        s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
        s.connect(("8.8.8.8", 80))
        ip = s.getsockname()[0]
        s.close()
        return ip
    except:
        # 获取失败时返回hostname对应的IP
        return socket.gethostbyname(socket.gethostname())
```

GUI控制台大字显示IP和端口，方便现场输入。

### 11.13 密码存储

**问题**：密码不能明文存储。

**解决方案**：
1. 使用 passlib + bcrypt 哈希密码
2. 验证时比对哈希值
3. 宾客密码虽然是默认的，但也要哈希存储

```python
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def hash_password(password: str) -> str:
    return pwd_context.hash(password)

def verify_password(plain_password: str, hashed_password: str) -> bool:
    return pwd_context.verify(plain_password, hashed_password)
```

### 11.14 呼叫服务的超时处理

**问题**：宾客呼叫后忘了取消，一直响着。

**解决方案**：
1. 后端定时任务检查超时的呼叫
2. 超时自动标记为 cancelled
3. 宴桌端按钮恢复正常
4. 超时时间可配置（默认5分钟）
