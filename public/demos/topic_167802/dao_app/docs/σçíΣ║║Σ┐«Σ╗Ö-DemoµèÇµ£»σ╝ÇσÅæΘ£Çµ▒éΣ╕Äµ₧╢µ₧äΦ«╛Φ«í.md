# 《凡人修仙》Web 版 Demo — 技术开发需求与架构设计文档

> 版本：v0.1（待确认）
> 文档类型：Demo 阶段开发需求 + 架构设计
> 目标：交付一个「网页版渲染的 App 效果」的可交互演示 Demo，用于产品展示与报名材料，功能优先，后端用 Mock 数据模拟。
> 来源：基于 `basic_intro.html` 的产品创意提炼而来。

---

## 1. 项目背景与定位

《凡人修仙》是一款面向 18–35 岁年轻人的 AI 小程序，以道教「山、医、命、相、卜」五术为核心结构，用游戏化 + AI 交互的方式承载传统文化内容。

本次交付的是 **Web 版 Demo**：

- 在网页中 **模拟手机 App 的外观与交互**（移动端外壳 / 手机模型容器）。
- 覆盖 **完整 UI 设计与全部交互功能**（不是静态页，而是可点击、可流转的原型）。
- 后端使用 **Mock 数据**（前端本地模拟，无真实服务端 / 无真实第三方算命接口）。
- **功能优先**：先把「能用、能演示、能讲清楚产品逻辑」跑通。

### 1.1 Demo 阶段明确的边界（不做）

- 不接入真实 AI 大模型（用规则 + 预置话术模拟 AI 回复）。
- 不接入真实八字/面相/易经算法引擎（用简化规则 + Mock 结果）。
- 不做真实登录/注册/支付/服务端持久化（用 localStorage 模拟）。
- 不做真实摄像头人脸识别算法（相：用「上传/拍照 → 模拟分析动画 → Mock 结果」流程演示）。
- 不做真实的健康医疗诊断（所有健康、命理内容均标注为「生活方式建议 / 文化体验参考」）。

## 2. 产品功能需求（Demo 范围）

整体信息架构围绕五术 + 成长体系。底部导航建议 5 个主入口：**首页（洞天）**、**修行（山医）**、**玄机（命相卜）**、**问道（AI）**、**我的（修行者）**。

### 2.1 首页 · 洞天（Dashboard）
- 顶部：修行者名号、当前**境界**（如：练气三层）、修为进度条。
- 今日概览卡片：**今日运势**（一句话卦辞 + 宜/忌）、**每日修行任务**（打卡入口）。
- 五术快捷入口（山/医/命/相/卜圆形图标，点击进入对应模块）。
- 「每日一签 / 今日功课」提醒。

### 2.2 山 · 身体修炼（Body）
- 功法列表：八段锦、五禽戏、五行拳等（Mock 3–5 套）。
- 功法详情：图文 + 分节说明 + 「开始跟练」计时器 + 完成打卡。
- 打卡后：修为 +X，进度条增长，可能触发「境界提升」动画。

### 2.3 医 · 养生保健（Health）
- 节气养生卡片（根据当前日期 Mock 当前节气建议）。
- 日常保健小贴士列表（饮食/作息/穴位/呼吸）。
- 冥想/呼吸练习：可视化呼吸引导动画（吸气—屏息—呼气节律）+ 计时。

### 2.4 命 · 八字命理（Destiny）
- 输入：出生日期、时辰、性别。
- 输出：四柱八字排盘（简化 Mock）、五行分布图、AI 白话解读（预置话术）。
- 结果可保存到「我的」并支持分享卡片生成。

### 2.5 相 · 面相观察（Face）
- 流程：上传照片 / 调用摄像头拍照 → 模拟「扫描分析」动画 → Mock 面相解读（三庭五眼、气色、状态建议）。
- 支持「日常状态记录」，形成长期趋势（Mock 折线）。

### 2.6 卜 · 易经占卜（Divination）
- 两种模式：**快速运势卜**（一键摇卦）、**任务卜**（针对某个问题起卦）。
- 交互：摇卦动画（铜钱 / 数字卦）→ 生成卦象 → 卦辞 + AI 启发式建议。
- 记录到「问卜日志」。

### 2.7 问道 · AI 修行助手（Chat）
- 对话式界面（气泡、打字机效果）。
- 基于关键词的规则式回复 + 预置知识卡（把五术内容用白话讲）。
- 支持从各模块「带上下文提问」（如从命盘点「问 AI」）。

### 2.8 我的 · 修行者（Profile）
- 修行档案：境界、累计修为、连续打卡天数、解锁功法。
- 历史记录：问卜日志、命盘、状态记录。
- 设置：名号、主题（可选深色/羊皮纸浅色，呼应现有配色）。

### 2.9 贯穿全局的成长系统（Gamification）
- 修为值 → 境界（练气 / 筑基 / 金丹 …，Demo 可到前 3–4 个境界）。
- 每日修行任务、连续打卡、功法解锁、境界提升动画。
- 数据用 localStorage 持久化，保证 Demo 刷新后仍有进度。

## 4. 技术架构设计

### 4.1 技术选型（推荐方案）

给出两条可选路线，请你确认其一：

**方案 A（推荐）· 原生 HTML + CSS + 原生 JS（多页或单页 Hash 路由）**
- 优点：零构建、零依赖、直接双击 `index.html` 即可运行，和现有 `basic_intro.html` 一致，交付/展示最省事。
- 适合：纯 Demo 展示，快速迭代。

**方案 B · Vue 3 + Vite（或 React + Vite）单页应用**
- 优点：组件化、状态管理清晰，后续更易演进为正式产品。
- 缺点：需要 Node 环境 + 构建，交付稍重。

> Demo 阶段建议 **方案 A**（功能优先、即开即用）。若你计划后续演进为真实小程序（Taro/微信小程序），可选方案 B 以便复用组件思路。

### 4.2 目录结构（以方案 A 为例）

```
dao_app/
├── basic_intro.html          # 已有：创意介绍页
├── index.html                # Demo 入口（手机外壳 + 路由容器）
├── docs/
│   └── 凡人修仙-Demo技术开发需求与架构设计.md
├── assets/
│   ├── css/
│   │   ├── tokens.css        # 设计变量（复用 basic_intro 配色）
│   │   ├── app.css           # 全局与外壳样式
│   │   └── components.css     # 组件样式
│   ├── js/
│   │   ├── router.js         # Hash 路由
│   │   ├── store.js          # 状态 + localStorage 持久化
│   │   ├── mock/             # Mock 数据层
│   │   │   ├── fortune.js    # 运势/卦辞
│   │   │   ├── bazi.js       # 八字排盘规则 + 话术
│   │   │   ├── face.js       # 面相 Mock 结果
│   │   │   ├── gongfa.js     # 功法/养生内容
│   │   │   └── ai.js         # AI 规则式回复
│   │   ├── pages/            # 各页面渲染逻辑（山/医/命/相/卜/AI/我的/首页）
│   │   └── components/       # 复用组件（tabbar、card、progress…）
│   └── fonts/                # 复用 Outfit 字体
```

### 4.3 分层架构

```
┌─────────────────────────────────────────┐
│  视图层 Pages / Components (HTML+CSS)      │  ← 手机外壳内渲染
├─────────────────────────────────────────┤
│  路由层 Router (hash 路由 + 页面切换动画)   │
├─────────────────────────────────────────┤
│  状态层 Store (修为/境界/打卡/历史记录)      │  ← localStorage 持久化
├─────────────────────────────────────────┤
│  Mock 数据/服务层 (模拟 API：Promise+延时)   │  ← 模拟网络请求体验
└─────────────────────────────────────────┘
```

### 4.4 Mock 数据层设计
- 统一封装 `mockApi(endpoint, params)`，返回 `Promise`，带 200–800ms 随机延时以模拟真实网络与「AI 思考中」体验。
- 各模块数据独立成文件，便于替换为真实接口（后续把 `mockApi` 换成 `fetch` 即可）。
- 关键 Mock 接口（示例）：
  - `getDailyFortune()` → 今日运势/宜忌
  - `getGongfaList()` / `getGongfaDetail(id)` → 功法
  - `getHealthTips(solarTerm)` → 养生
  - `calcBazi(birth)` → 八字排盘 + 五行分布 + 解读
  - `analyzeFace(image)` → 面相解读（延时模拟扫描）
  - `castHexagram(question)` → 起卦 + 卦辞 + 建议
  - `chatWithAI(message, context)` → AI 回复

### 4.5 状态与持久化
- `store` 保存：用户名号、修为值、境界、连续打卡、已解锁功法、问卜日志、命盘记录、状态记录、主题。
- 通过 `localStorage` 读写，保证刷新/重开不丢进度。
- 提供「重置 Demo 数据」入口，方便演示复位。
