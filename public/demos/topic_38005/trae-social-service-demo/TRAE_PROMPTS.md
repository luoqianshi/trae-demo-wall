# TRAE 分阶段提示词

把下面 4 段分别发给 TRAE。每段完成后保留对应 Session ID，初赛帖可写入“TRAE 实践过程”。

## Session 1：产品需求与流程梳理

请基于“社会服务赛道”帮我完善一个小程序风格 Demo，项目名为“邻里预审：社区办事材料预审助手”。目标用户是社区居民和基层工作人员，核心价值是提前检查办事材料，减少居民线下窗口反复跑。请输出：

1. 目标用户和痛点。
2. 3 个核心使用场景。
3. 小程序首页、材料预审页、一页式办事清单、社区端概览的用户流程。
4. 初赛 Demo 最小可行功能范围。
5. 需要避免的合规风险。

## Session 2：页面与交互开发

请在现有静态项目基础上开发一个小程序风格网页 Demo。要求：

1. 使用 `index.html`、`style.css`、`app.js`，无需后端。
2. 视觉上像手机里的小程序，包含顶部栏、功能 tab、底部导航。
3. 支持选择办事事项：居住证办理、医保零星报销、老年优待卡、灵活就业社保补贴。
4. 支持勾选已准备材料，动态计算材料完整度。
5. 点击“生成预审建议”后，生成材料缺失项、风险提醒、窗口沟通话术。
6. 页面必须适配移动端，文本不能溢出。

## Session 3：预审逻辑优化

请优化 `app.js` 里的材料预审逻辑，让 Demo 更像真实公共服务工具：

1. 根据用户输入识别“代办、异地、电子材料、不在本地、老人行动不便”等关键词。
2. 对不同办事事项生成更具体的补材料建议。
3. 结果页输出 3 到 5 条一页式办事清单。
4. 社区端概览同步展示待补材料、高优先级事项和今日预审数量。
5. 所有判断都要说明“仅作预审参考，最终以窗口要求为准”。

## Session 4：初赛提交打磨

请帮我检查这个 Demo 是否符合 TRAE AI 创造力大赛初赛要求，并输出：

1. Demo 简介，150 字以内。
2. 创作思路，说明为什么属于社会服务赛道。
3. 主要功能清单，列出 2 到 3 个核心功能。
4. TRAE 实践过程描述，保留可填 Session ID 的位置。
5. 可继续迭代到复赛的产品路线图。
