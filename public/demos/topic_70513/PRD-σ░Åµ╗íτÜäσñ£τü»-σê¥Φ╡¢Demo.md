## 1. 产品概述

### 1.1 一句话
**小满的夜灯**：一个住在全家已有群聊里的育儿机器人——不用下载、不用注册、不用学，会用群聊、会拍照，就会用。

### 1.2 目标用户与痛点
新手爸妈 + 月嫂/爷爷奶奶多人轮流带娃的家庭。四个真实痛点：
1. 半夜喂奶全靠人脑记，记不清上次几点喂的；
2. 月嫂下班，一本纸质日记交接，信息瞬间归零；
3. 多人带娃各记各的，重复记、漏记、各说各话；
4. 遇到状况临时狂搜，越查越慌，还可能搜到伪科学。

### 1.3 两束光（产品主结构）
- **第一束光 · 记录线（照亮当下的慌）**：家人拍下纸质喂养记录发到群里 → 机器人自动识别、**自动判重**（多人各拍各的不会重复记）→ 写进喂养/睡眠/排泄等六张表 → 每天清晨群里自动弹「育儿早报」，知识卡随宝宝**日龄**长大而变；轮班时可开「紧急模式」倒计时提醒喂奶窗口；家人随口提问，机器人给**遵医嘱的检索式安全回答**。
- **第二束光 · 记忆线（收藏过去的暖）**：机器人默默把群里的宝宝照片收进「成长相册」，生成**同款时间轴**（不同月龄的同一场景排成一条成长带）和**月度叙事回顾**（照片+成长数字+里程碑拼成会说话的一页）。

### 1.4 核心创新点（Demo 必须体现）
1. **形态创新**：不是 App，是群聊机器人——零下载零学习成本，这是与所有育儿 App 的根本区别；
2. **多人判重**：全家各记各的，机器人自动对齐成一个频道；
3. **随孩子长大**：早报知识卡随日龄自动升级（今天教认色，半年后提醒加辅食）；
4. **不瞎编的 AI**：医学问题走已校验知识库检索，拿不准就让用户问医生。

## 2. Demo 形态与边界

### 2.1 是什么
- 一个**模拟的手机端家庭群聊界面**：整体套手机外框（竖屏 375–430px 宽），群聊填满手机屏；桌面浏览器打开时手机居中、两侧夜色留白。
- 两屏结构：**主屏 = 家庭群聊**「小满·成长记录群」；**子屏 = 成长相册**（横滑进入，可返回）。
- 评委通过点击底部操作条的 4 个按钮触发交互，像真的在群里使用机器人。

### 2.2 不是什么（边界，不要做）
- ❌ 不调任何真实接口。所有「OCR 识别」「判重」「早报生成」「问答」都是**前端写死数据 + 动画模拟**。
- ❌ 不做真实登录/注册/用户系统。
- ❌ 不做后端、不做数据持久化（刷新即重置是正常的）。
- ❌ 不引用任何外部资源（图片/字体/CDN/JS 库），照片一律 CSS 渐变色块 + emoji 占位。
- ❌ 不做自由文本输入的开放式聊天（问答只有预设按钮触发的写死回答）。

### 2.3 交付物
1. `index.html` 单文件（CSS/JS 全内联，零外部依赖，Zip 打包后本地双击即可完整运行）；
2. 手机顶部状态栏下方常驻小角标：`演示数据 · 宝宝化名「小满」`。

## 4. 功能规格 ★核心

> 每个交互一节：触发 → 流程分步 → 动画时序 → 验收标准。全部文案在 §6 对应小节，此处只写编号引用。

### 4.0 通用交互规则
- 消息气泡出现方式：从下方 8px 淡入上移（200ms），机器人多条连发时逐条间隔 400–600ms（模拟打字节奏）。
- 机器人发言前可显示「夜灯正在输入…」小灰条 600ms（可选加分项）。
- 每个交互按钮**可重复点击重放**（重放时在消息流追加新一轮，不清空历史）。
- 新消息出现后聊天区自动平滑滚动到底部。

### 4.1 交互① 拍照即录入 + 判重合并（记录线·暖黄）★创新点最重
**触发**：点操作条 [📷 拍张月子记录]。
**流程**：
1. 我方（当前用户视角）冒出一条「照片消息」气泡：用纯 CSS 画一张简化的手写月子日记表格（内容见 §6.2.a，白纸底、手写感排布、微微旋转 -1.5deg 增加真实感）。
2. 机器人回复「识别中…」气泡，气泡上有一条**扫描光带**从上往下扫过照片消息（CSS 动画，约 1.2s）。
3. 机器人回一张**结构化回执卡**：§6.2.b 的条目逐条 stagger 淡入（每条间隔 150ms），每条格式如 `喂养 · 母乳 · 14:00 · 15min`。
4. 其中**第 2 条是判重条目**：单独暖橙高亮，先出现两条视觉上重叠/并排的记录，播放「两条并成一条」的合并动画（两条向中间收拢融合为一条，约 600ms），旁挂标签 `🔀 检测到奶奶也记了这顿，已自动合并`。
5. 回执卡底部点亮徽章 `✅ 已写入 6 张表`（微光脉冲一次）。
6. 机器人补一句点题气泡（§6.2.c）。

**验收标准**：
- [ ] 照片消息的手写表格视觉可辨认出 3 条记录内容；
- [ ] 扫描光带动画肉眼可见、不卡顿；
- [ ] 回执条目逐条 stagger 淡入，非一次性出现；
- [ ] 合并动画能看清「两条 → 一条」的过程，且合并条目与普通条目颜色区分明显；
- [ ] 重复点击可完整重放，消息流不错乱。

### 4.2 交互② 育儿早报 + 日龄滑块 + Day N 回声（记录线·暖黄，含「和孩子一起长大」叙事）
**触发**：点操作条 [🌅 看今天的育儿早报]。
**流程**：
1. 机器人推送一张**育儿早报卡片消息**（卡片式气泡，宽度约占聊天区 88%）。
2. 卡片顶部是**日龄滑块**：`Day 1 → Day 365`，默认 Day 60。拖动滑块，卡片内容**实时联动**（无刷新、无闪跳）：
   - 标题行：`小满 · 第 {N} 天（约 {月龄}月龄）`（月龄 = floor(N/30)，N<30 显示「新生儿期」）；
   - **今日知识卡**：按日龄段切换（分段与全文见 §6.3.a），每卡带维度徽章（衣👕/食🍼/住🏠/行🚼/心🧸/亲🤝）+ 可选 `✅循证` / `🔍辟谣` 角标；
   - **喂养/睡眠摘要行**：写死示例数字随段位变（§6.3.b）；
   - **Day N 回声（记忆线彩蛋）**：当 N 恰为 30 的整数倍（30/60/90…360）时，卡片底部浮现一条暖玫小照片条「{N/30} 个月前的今天」（渐变色块占位 + 一句旁白，§6.3.c）；非整月节点不显示（淡出收起）。
3. 机器人补一句点题气泡（§6.3.d）。

**验收标准**：
- [ ] 滑块拖动流畅（60fps 体感），内容实时联动无闪白；
- [ ] 至少 3 个日龄段的知识卡内容不同（Day1–90 / Day120–180 / Day180–365 各至少 2 张卡轮换）；
- [ ] Day 30/60/90 等整月节点出现回声条、非节点消失，切换有淡入淡出过渡；
- [ ] 维度徽章与 循证/辟谣 角标正确显示。

### 4.3 交互③ 紧急模式倒计时（记录线·暖橙）
**触发**：点操作条 [🚨 开启紧急模式]。
**流程**：
1. 机器人发一条**暖橙警示卡**：大字倒计时 `距离下次喂奶窗口还有 02:47:{ss}`，基于「上次喂奶 + 3 小时」的模拟时点，用 `setInterval` **每秒真跳**。
2. 当剩余 < 30 分钟（Demo 里可用「模拟快进」按钮直接跳到 29:59 演示）：卡片进入**脉冲呼吸**状态（box-shadow 呼吸动画），文案切换为 `⏰ 快到喂奶时间啦`。
3. 卡片带说明文字与两个按钮：`模拟：刚喂完，重置`（倒计时回 03:00:00）和 `模拟快进到 30 分钟内`（跳到 00:29:59，方便评委看到状态切换）。文案见 §6.4。

**验收标准**：
- [ ] 倒计时每秒真实跳动，格式 `HH:MM:SS`；
- [ ] < 30 分钟时呼吸脉冲 + 文案切换生效；
- [ ] 重置/快进按钮均可用且可反复操作；
- [ ] 离开子屏再回来倒计时仍在跑（interval 不销毁不重复创建）。

### 4.4 交互④ 检索式安全问答（记录线，体现「实用 + 安全」差异化）
**触发**：点操作条 [❓ 宝宝噎到怎么办]。
**流程**：
1. 我方冒出问题气泡「宝宝噎到怎么办？！」。
2. 机器人先回一条小灰条 `🔍 正在查已校验知识库…`（800ms），再回一张**安全回答卡**（全文见 §6.5.a）：有序处置要点（1 岁以下拍背 5 次 + 压胸 5 次、别抠嘴、严重立即打 120），底部小字免责「以上为通用常识，具体请遵医嘱」。
3. 机器人补一句点题气泡（§6.5.b：「我不瞎编医学建议——查过校验知识库才答，拿不准就让你问医生。」）。

**验收标准**：
- [ ] 回答卡要点有序编号、120 醒目（红/橙强调）；
- [ ] 「遵医嘱」免责小字存在；
- [ ] 「查知识库」的过程感（小灰条延迟）存在——这是与「生成式瞎编」的视觉区隔。

### 4.5 子屏 A · 同款时间轴（记忆线·暖玫）★决赛杀手锏雏形
**入口**：点机器人头像 或 操作条 [📖 小满的成长相册] → 横滑进子屏，时间轴在上半部。
**规格**：
1. 一条**横向可拖动/滑动**的成长带，主题「床上仰躺 · 同款照片」，共 5 格。
2. 每格 = 不同暖色渐变色块占位 + 👶 emoji（字号逐格增大制造长大感：如 28→34→40→46→52px）+ 日龄徽标 + 一句暖玫旁白（全文见 §6.6.a）。
3. 格与格之间有「→」成长箭头；整条支持鼠标拖拽与触摸滑动（overflow-x + drag 惯性可选）。
4. 板块底部点题句（§6.6.b）。

**验收标准**：
- [ ] 横滑顺畅（触摸和鼠标拖拽都可用）；
- [ ] 5 格 emoji 尺寸递增肉眼可辨；
- [ ] 日龄徽标与旁白与 §6.6.a 一致。

### 4.6 子屏 B · 月度叙事回顾（记忆线·暖玫）
**位置**：子屏下半部。
**规格**：
1. 一张「相册书页」卡：暖米黄纸感底（区别于全局夜色，像夹在夜里的一页信纸）+ 暖玫点缀。
2. 上半部：3–4 张照片占位拼贴（渐变色块 + emoji，错落布局）。
3. 下半部：叙事文字栏（全文见 §6.7.a）——本月成长数字用**绝对值 + 可爱比喻**（如「已经有一个小西瓜那么沉啦」）、新达成里程碑、一句趣事。
4. 板块底部旁白（§6.7.b）。

**验收标准**：
- [ ] 纸感书页与全局夜色形成材质对比但不突兀；
- [ ] 叙事文案完整呈现，无截断；
- [ ] 主屏 ↔ 子屏往返切换 ≥5 次无布局错乱。

## 5. 视觉设计系统

### 5.1 氛围定位
深夜里为孩子亮起的一盏暖灯。深蓝夜色底 + 暖黄灯光 + 暖玫点缀。**这是一个聊天界面**——气泡/头像/输入区要有 IM 质感，但配色走暖光夜色，不是白底微信。

### 5.2 色板（CSS 变量，严格照抄）
```css
:root {
  --ink:         #0e1626;  /* 群聊背景·墨蓝夜色 */
  --ink-2:       #13203a;  /* 次级深蓝 */
  --bubble-in:   #1b2742;  /* 别人/机器人气泡底 */
  --bubble-me:   #3a2e1a;  /* 我发的气泡底（暖调） */
  --card:        #1b2742;  /* 卡片消息底（早报卡等） */
  --glow:        #ffd592;  /* 夜灯暖黄·机器人主色/记录线 */
  --glow-strong: #ffb65c;  /* 暖橙·紧急模式/判重高亮 */
  --milk:        #fff6e6;  /* 奶白 */
  --milkgreen:   #bfe3c8;  /* 奶绿·知识卡循证标 */
  --rose:        #f6b9c6;  /* 暖玫·记忆线/相册子屏主色 */
  --rose-deep:   #e88aa0;
  --text:        #f3ede0;  /* 主文字·暖白 */
  --text-dim:    #b9c2d6;  /* 次文字 */
  --r:    22px;            /* 卡片圆角 */
  --r-sm: 14px;
}
```
- 气泡圆角 18px；卡片阴影 `0 18px 50px -20px rgba(0,0,0,.7)`。
- 字体：`-apple-system, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`。

### 5.3 组件规格
| 组件 | 规格 |
|---|---|
| 手机外框 | 竖屏 375–430px 宽，深色边框圆角 ~44px，顶部刘海/状态栏示意；桌面端居中，外围 `--ink` 加深渐晕 |
| 成员头像 | 32–36px 圆形，彩色渐变底 + emoji（妈妈👩 爸爸👨 奶奶👵 月嫂🤱） |
| 夜灯头像 | **不用图片**：CSS `radial-gradient` 画一盏发光小夜灯（中心 `--glow` 到透明的光晕 + 底座），是群里最亮的存在，可加 3s 缓慢呼吸光晕 |
| 普通气泡 | 左侧他人 `--bubble-in`、右侧我方 `--bubble-me`，圆角 18px，最大宽度 78% |
| 卡片消息 | `--card` 底 + `--r` 圆角 + 统一卡片阴影，宽约 88%，左侧不带气泡尖角 |
| 日龄滑块 | 原生 range 重绘：轨道 `--ink-2`，已滑过段 `--glow` 渐变，拇指为小夜灯光点（radial-gradient 圆） |
| 倒计时卡 | `--glow-strong` 描边 + 半透明暖橙底，数字等宽字体感（font-variant-numeric: tabular-nums） |
| 徽章/角标 | 12px 圆角胶囊：循证=奶绿底深绿字，辟谣=暖黄底深棕字，维度徽章=描边胶囊 |
| 两束光区分 | 记录线组件（早报/判重/紧急/问答）点缀 `--glow`/`--glow-strong`；子屏记忆线整体点缀 `--rose`/`--rose-deep` |

### 5.4 动效清单
扫描光带（linear-gradient 位移）、合并收拢（transform + opacity）、stagger 淡入（animation-delay 递增）、呼吸脉冲（box-shadow keyframes）、屏间横滑（translateX 300ms ease）、回声条淡入淡出（opacity + max-height）。全部 CSS 动画/最小 JS，禁用大型动画库。

## 6. 演示数据规格（全量写死文案 · 直接搬）

> 全部为**演示数据**。宝宝化名「小满」，家人只用「妈妈/爸爸/奶奶/月嫂」泛称。禁止出现任何真实姓名/生日/真实喂养数值之外的编造真实感信息。

### 6.1 主屏预填氛围消息（开场即在聊天流里）

## 7. 工程规范

1. **单文件**：所有 CSS/JS 内联在 `index.html`；零外部请求（断网双击打开必须完整可用）。
2. **无报错**：全程 console 零 error/warning；所有按钮无死链。
3. **代码组织**：`<style>` 按「tokens → 布局 → 组件 → 动画」分区注释；`<script>` 按「数据（§6 的 JSON 原样放这里）→ 渲染函数 → 交互绑定」分区。
4. **注释**：每个交互模块头部一行中文注释说明对应 PRD 节号（如 `/* §4.1 拍照判重 */`），方便答辩讲解。
5. **性能**：动画用 transform/opacity（避免 layout 抖动）；`setInterval` 全局唯一并妥善管理。
6. **适配**：375px 最小宽不溢出；430px 不松散；桌面端手机框居中。

## 8. 红线（违反即返工）

1. **隐私**：只允许「小满」和「妈妈/爸爸/奶奶/月嫂」称谓；不得出现任何真实人名、真实出生日期；不得引用任何外部真实照片。
2. **不焦虑**：全部文案禁用「关键期 / 错过 / 来不及 / 落后 / 输在起跑线」等制造焦虑的词。
3. **医学安全**：医学相关内容一律带「遵医嘱」；不下诊断；急救要点必须与 §6.5.a 完全一致，不得自行改写医学内容。
4. **演示数据角标**：`演示数据 · 宝宝化名「小满」` 角标常驻，不得省略。
