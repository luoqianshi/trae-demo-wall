# 交接 prompt · 贴给 TRAE 用（单会话版）

> 用法：开一个 TRAE Session，贴下面【交接 prompt】+ 把 `PRD-小满的夜灯-初赛Demo.md` 全文粘在后面（或作为文件给它），一次性做完。
> **Session ID 门槛（≥3）怎么攒**：不用刻意拆任务——首轮生成 = Session 1；之后验收发现的问题修复、视觉打磨、文案微调各开新 Session 迭代，自然就 ≥3 了。每轮记得截图 + 在 `初赛-session-证据.md` 登记。

---

## 【交接 prompt】（连同 PRD 全文一起贴）

你是一名资深前端工程师 + 交互设计师。我们在做一个参赛作品：**「小满的夜灯」初赛可交互 Demo**——一个单文件 `index.html` 的模拟手机端家庭群聊界面，评委扮演家人，和群里的育儿机器人「夜灯」互动。评分维度：创新性 30% / 实用性 30% / 完成度 20% / 美观度 20%。你的最高优先级是「真实可玩的群聊交互」和「暖光美学」。

下面附上完整 PRD，它是唯一需求来源，请严格照做，**不要自行发挥产品设计和文案**（所有文案在 PRD §6 已给全，直接搬）。

**本次请一次性完成全部范围**（PRD §3–§4）：

1. **群聊骨架 + 暖光视觉**：手机外框、群标题栏（5 成员头像，夜灯头像用纯 CSS radial-gradient 画发光小夜灯并呼吸）、预填氛围消息流（§6.1）、底部操作条、全套 §5 色板 tokens、`演示数据 · 宝宝化名「小满」`常驻角标；
2. **记录线四交互**（§4.1–§4.4）：① 拍照即录入+判重合并（照片消息→扫描光带→回执 stagger 淡入→「两条并一条」合并动画→已写入 6 张表徽章）② 育儿早报卡（日龄滑块 Day1–365 实时联动知识卡/摘要行，整月节点浮现 Day N 回声条）③ 紧急模式倒计时（每秒真跳，<30 分钟呼吸脉冲+文案切换，重置/快进按钮）④ 检索式安全问答（查库延迟感→安全回答卡→遵医嘱小字）；
3. **相册子屏**（§4.5–§4.6）：主屏↔子屏横滑切换（点夜灯头像或相册按钮进入，←返回）、同款时间轴（横向可拖 5 格、emoji 尺寸递增、§6.6 文案）、月度叙事书页（暖米黄纸感底、§6.7 全文）。

硬性约束：

- **单文件**：CSS/JS 全内联，零外部依赖（不引 CDN/字体/图片/库），断网双击可完整运行；
- **红线**（违反即返工）：只允许「小满」和「妈妈/爸爸/奶奶/月嫂」称谓；文案禁「关键期/错过/来不及/落后」等焦虑词；医学内容不得改写 PRD §6.5.a 的急救要点；演示数据角标不得省略；
- **工程**：console 零报错；动画只动 transform/opacity；四个交互按钮可重复重放；每个交互模块头部注释对应 PRD 节号；375–430px 不破版，桌面端手机居中。

做完后：按 PRD §9「最终交付验收」清单逐项自查并报告结果，然后给我完整的 index.html。

（——在此粘贴 PRD 全文——）
