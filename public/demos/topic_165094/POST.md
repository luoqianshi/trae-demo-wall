## 1. Demo 简介

### 是什么

**原页记**（NovelMemo）是一款面向英语原版书读者的**轻量化阅读 + 复盘工具**的交互式产品 Demo，当前为 **v1.0 MVP 版本**（目标：5-7 分钟能演示完核心闭环）。核心主张是"原页不忘，阅读有记 —— Page by page, never forget"——通过基于词汇等级的智能高亮、随点随查的悬浮词典、整页 AI 翻译、自动生成的人物关系图，让"读完一本英文书"从痛苦的"查词马拉松"变成有节奏的"理解 - 标注 - 复盘"循环。

### 产品现状

目前**整个产品框架已经设计完毕，主要功能均能使用**（欢迎引导 / 首页书架 / 书籍上传 / 阅读页 / 词典查词 / 整页翻译 / 章节复盘 / 人物关系图 / 生词本 / 设置 共 10 大模块全部跑通）。**因设备问题暂时无法部署上线**，本次初赛以纯前端 demo 形式提交，全部交互可在本机浏览器完整体验。

### 面向谁

* **英语中级学习者（B1-B2）** —— 想读原版书但被生词劝退的人
* **准备留学 / 考研 / 雅思的学生** —— 需要高效积累学术词汇和长难句
* **英语文学爱好者** —— 想理清人物关系、读懂情节转折的"非母语读者"

### 主要功能

#### 功能一：欢迎引导 + 个性化设置（首启体验）

首次进入是 4 步引导页（"原页记·新手引导"），分 4 屏介绍核心能力（进度条 1/4 → 4/4），底部"开始体验 →" / "跳过，直接进入" 两种入口，**不强制学习成本**。

设置页把所有"可调旋钮"集中管理，5 大模块：

* **外观** —— 主题模式（日间 / 夜间 / 跟随系统）、字体大小（12-24px 滑块）、字体样式（衬线书卷气 vs 无衬线现代）、默认朗读速度（0.8x / 1x / 1.2x / 1.5x）
* **词汇等级** —— 4 档：初级（<1500 词）/ 中级（1500-4500）/ 中高级（4500-7000）/ 高级（>7000 词），带"重新评估"按钮
* **词典释义** —— 中文释义（有道词典）vs 英文释义（Free Dictionary）
* **关于** —— 版本号（v1.0 MVP）、slogan、用户协议 / 隐私政策 / 反馈建议
* 全程顶部导航显示当前"词汇：中级"标识，**设置变更实时生效到阅读页**

![设置页](../原页记展示/6.png)

#### 功能二：首页书架 + 上传书籍

首页顶部导航固定为：首页 / 上传 / 生词本 / 统计 / 设置 5 项。

**首页结构**：

* 顶部品牌区 + slogan（"原页不忘，阅读有记"）
* 主横幅卡片："读英文原著，每页 AI 帮你复盘" + 两个 CTA（"上传书籍开始阅读" / "继续上次阅读 →"）+ 装饰书本插画
* 3 个统计卡：**6 在读书籍 / 5 生词本 / 1 已掌握**
* "最近阅读" 网格：每本书一个卡片，显示书名、作者、当前页/总页 · 格式、阅读进度条；右下角"添加新书"快捷入口

**上传页**：

* 拖拽上传区（虚线边框 + 云图标）
* 三种支持格式卡片：**PDF（<30MB）/ EPUB（<20MB）/ TXT（<2MB）**
* "没有文件？试试示例" 横幅：直接体验《小王子》英文节选 · 3 页 · 已含 AI 复盘 —— 解决"零数据演示尴尬"

#### 功能三：基于词汇等级的智能高亮 + 整页 AI 翻译

阅读页核心布局：

* 顶栏：返回书架 / 书名 + 作者 · 章节 / 字号 0.8x / 1x / 1.2x / 1.5x / "关系" / "复盘" 按钮
* 中部：章节标题（Chapter 1 — 1/3 —）
* **双栏对照** —— 左侧英文原文，右侧 AI 翻译（标注模型来源，如 "xophunyuan/7bmt - fast_translation"）
* 底部："本页生词速览（6）" 标签条，所有本页高亮词横向排列，点击可重新跳到对应位置
* 右下角悬浮按钮："AI 页面复盘"

**高亮规则**（按词汇等级动态调整）：

* **黄色高亮** —— 当前等级的"重点词"（建议掌握），A2 等级每段 6-8 个
* **红色高亮** —— 跨等级的"生僻词"（按需查阅）
* **C1 等级** 每段 2-3 个高亮，几乎不打扰阅读
* 切换等级时**立刻重新计算并渲染**，让用户直观感受自己的进步

#### 功能四：随点随查的悬浮词典 + 生词本

点击任意高亮词（如 `swallow`），浮出词典气泡：

* 单词 + 双语音标（英音 / 美音切换）
* 词性分组（verb / noun） + 多条释义
* 当前词等级标签（重点词：高级动词 · 等级 yellow）
* "收藏到生词本" 主按钮（橙色高亮）

收藏的词**持久化到 `localStorage`**，刷新页面不丢。"生词本"页可统一查看、按等级筛选。

#### 功能五：AI 章节复盘 + 动态人物关系图

![动态人物关系图](../原页记展示/5.png)

每读完一节，点"复盘"弹出分层视图：

* **AI 自动生成的章节摘要** —— 谁出场、发生了什么、关键情节转折
* **动态人物关系图**（独立全屏画布）—— 完整功能包含：
  * **节点**：6 个角色，每个带身份标签（叙述者 the narrator、小王子 the little prince 等），支持"已故"角色虚线/灰化
  * **关系连线**：按类型分类 —— **社会 / 亲友 / 爱恋 / 已故**（彩色图例）
  * **时间轴**（0~N 页）：拖动滑块看关系如何随章节演化
  * **操作提示**：点击节点查看详情与关系、搜索高亮人物或别名、拖动时间轴查看关系演化、切换分类筛选聚焦某一类关系
  * 左下角工具栏：缩放（+/-）、全屏、重置视图

关系数据完全由 AI 基于章节内容自动生成，**首次加载即用**——这也是大模型平台实习背景给我的产品直觉：**每本书沉淀下来的"AI 增强数据"就是壁垒**。

## 2. Demo 创作思路

### 灵感来源

我目前在备考雅思。备考过程中最大的感受是：**英语学习本质上就是词汇、语法、英语逻辑这三件事，而"阅读"恰好是同时训练这三件事最高效的方式**——比单纯背单词书更能建立语境，比单纯学语法书更能体会实际用法，比单纯看美剧更能主动调动思考。

但真正去读英文小说 / 雅思真题语料时，我发现三道坎：

1. **生词密度过高** —— 翻开第一页就被劝退
2. **查词流和阅读流割裂** —— 查一个词要切出去 3 次
3. **读完整本书记不住** —— 人物关系一团乱，前面的情节全忘

市面上的工具要么只解决"查词"（Kindle 生词本），要么只解决"翻译"（微信读书），要么只解决"记录"（Notion 笔记），**没有任何工具把"读 - 标 - 查 - 复盘"这条链路打通**。

### 想解决的问题

1. **生词密度失控** —— 很多阅读 App 把所有超纲词都标红，视觉过载反而劝退用户；应该按用户等级动态调整
2. **查词 - 收藏 - 复习断层** —— 查过一次的词再查一次，体验糟糕；应该把收藏的词整合进阅读流
3. **读完即忘** —— 没有任何工具帮你记住"这章发生了什么、谁和谁是什么关系"；应该自动生成可回看的复盘内容

### 为什么做"分级高亮 + 复盘"这个组合

作为大模型平台的产品实习，我比一般同学更早意识到：**LLM 的长文本理解能力成熟后，"自动生成章节摘要"、"自动抽取人物关系"这种以前需要 NLP 工程师做的事，现在一个 Prompt 就能做**。这让我看到"原页记"的核心壁垒不再是技术，而是**对阅读场景的深度理解 + 数据资产的累积**——每一本书沉淀下来的"AI 增强数据"（分章摘要、人物档案、关系图）就是壁垒。

四个核心功能环环相扣：

* **分级高亮是入口** —— 让用户根据自己水平"看得下去"
* **悬浮词典是工具** —— 解决"看懂了记得住"的问题
* **整页翻译是保险** —— 让用户在卡住时能"不掉队"
* **章节复盘是出口** —— 把"读完"变成"记住"

缺一个都会让另三个的效果打折。

## 3. Demo 体验地址

### 交互式 HTML 文件

Demo 以**单 HTML 文件**形式交付，无后端、无构建步骤，浏览器双击即可体验：

* 文件路径：`demo/novelmemo-demo.html`
* 启动方式：在 `demo/` 目录运行 `python -m http.server 8080`，浏览器打开 `http://127.0.0.1:8080/novelmemo-demo.html`

包含 **4 本示例书**（《小王子》6 页 + 3 本 4 页），覆盖：

* 50+ 词典条目（含音标 / 词性 / 释义）
* 6 个角色 + 6 条人物关系
* 4 档词汇等级动态切换
* 亮 / 暗主题切换
* 生词本 + `localStorage` 持久化

### 视觉设计

* **整体调性**：低饱和、暖色系，**主背景浅黄绿（honeydew）、卡片米白、强调色铜橙（bronze `#B8763E`）**，避免高饱和色对长时间阅读的视觉干扰
* **辅色**：鼠尾草绿（celadon）用于状态提示、焦糖橙（amber）用于分类标签和按钮高亮
* **字体方案**：英文 Source Serif 4（衬线书卷气）/ Inter（无衬线现代），中文 Noto Serif SC，中英文双语自然混排
* **主题切换**：CSS 变量驱动，日间 / 夜间 / 跟随系统三档，**亮暗切换零成本**
* **版本定位**：v1.0 MVP —— 已打通"读 - 标 - 查 - 复盘"核心闭环；未做的部分（用户系统、真实 AI 接口、CloudBase 部署、付费）列入下个迭代

### 技术说明

* **纯前端实现**：HTML + Vanilla JS + Tailwind CDN（无 React / Vue / 构建工具）
* **单文件部署**：所有 mock 数据、样式、脚本内联在一个 HTML 中
* **`localStorage` 持久化**：收藏的词、当前设置均保存在浏览器本地
* **图表**：纯 SVG 绘制人物关系图，无第三方库依赖

## 4. TRAE 实践过程

### 整体开发流程

整个 Demo 从需求到完成经历了 5 个步骤：

```
步骤1：分析现有项目结构 → 梳理核心功能边界
        ↓
步骤2：定义 demo 范围 → 砍掉登录 / 云存储 / 真实 AI
        ↓
步骤3：TRAE 生成单 HTML demo → mock 数据 + Tailwind CDN + 原生 JS
        ↓
步骤4：浏览器测试与修复 → 修复 SVG 模板字符串语法错误
        ↓
步骤5：补充 README 演示流程 → 5-7 分钟演示脚本
```

### 关键步骤详解

#### 步骤1：分析项目，明确核心功能

我让 TRAE 帮我**梳理项目里到底哪些是核心功能、哪些是部署后才需要的**。它快速识别出：

* **核心**（demo 必现）：首页 / 书架、阅读页、词典查词、整页翻译、章节复盘、人物关系图、词汇等级切换、暗主题、生词本
* **非核心**（demo 不做）：用户登录、书籍上传到云端、CloudBase 部署、真实 AI 接口调用、付费功能

这一步帮我砍掉了 70% 的工作量。

#### 步骤2：定义 demo 范围

我提出"**纯前端、无后端、可交互**"的三原则，TRAE 据此设计了 demo 的技术路线：

* 4 本示例书 → 全部内联在 JS 里
* 6 个角色 + 6 条关系 → 内联在 JS 里
* 50+ 词典条目 → 内联在 `DICT` 对象里
* AI 翻译、复盘 → 用 mock 数据 + 友好降级提示
* 收藏功能 → 写到 `localStorage`

#### 步骤3：TRAE 生成单 HTML demo

TRAE 一次性生成了一个**完整的 `novelmemo-demo.html`**，包含：

* HTML 头部（viewport、字体 CDN、Tailwind CDN）
* `<style>` 块：CSS 变量（亮 / 暗主题）、组件样式、动画
* `<body>`：单个 `#app` 根 div
* `<script>` 块：mock 数据 + 状态 + hash 路由 + 渲染函数 + 事件绑定

关键函数设计：

* `extractHighlights(text, level)` —— 按词汇等级提取高亮词
* `renderHighlightedText(text, level)` —— 把高亮词包成 `<span>`
* `LEVEL_CFG` —— 4 个等级的阈值和每段数量
* `renderHome() / renderReader() / renderWordbook()` —— 三页面渲染
* `renderDictBubble()` —— 悬浮词典
* `renderRecap()` —— AI 复盘弹层
* `renderGraph()` —— SVG 关系图
* `loadCollected() / saveCollected()` —— `localStorage` 持久化

#### 步骤4：浏览器测试与修复

首次在浏览器打开时，控制台报 `SyntaxError: Missing } in template expression`。

我用 `node --check` 把 HTML 里的 script 块提取出来验证，定位到 `renderGraph` 第 761 行 SVG 模板字符串：

```js
// 错误：少一个 ) 和 }
fill="${c.status === 'deceased' ? '#8a4a3a' : 'rgb(var(--bronze))'"
stroke="rgb(var(--vanilla))" stroke-width="2"/>

// 修正：
fill="${c.status === 'deceased' ? '#8a4a3a' : 'rgb(var(--bronze))'}"
stroke="rgb(var(--vanilla))" stroke-width="2"/>
```

修完后 `node --check` 退出码 0，浏览器正常渲染。

### 踩坑复盘

1. **MVP 范围定义比技术实现更重要** —— 第一次差点直接做"能上线的 v1.0"，幸好及时收敛到"5-7 分钟能演示完核心闭环的 MVP"，否则一天根本做不完

4. **`node --check` 救我命** —— HTML 里的 JS 报错定位很麻烦，提取到 `.js` 文件用 `node --check` 验证比直接看浏览器控制台快 10 倍
5. **新手引导不能太长** —— 4 屏引导 + "跳过" 按钮是必须的，强制 4 步会劝退评委
