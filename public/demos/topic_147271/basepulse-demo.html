从中国棒球运动,到俱乐部,到教练,到家长,到孩子——BasePulse 串联起整条成长链路。

不只是记分工具,更是棒球运动在中国的土壤

棒球在中国是「小众但增长中」的运动。一项运动要扎根,需要的不仅是职业联赛, 更是基层的数据沉淀、门槛降低、社区连接和文化培育——BasePulse 想做的正是这四件事。

数据沉淀
让棒球在中国有了可追溯的数据资产。每场比赛、每个球员、每次挥棒都被记录,这是运动从「活动」走向「产业」的基础设施。
降低门槛
海外 App 全英文、看不懂;纸笔记录易丢失。BasePulse 用中文界面 + 一键记分,让非专业的教练和家长也能轻松参与,扩大运动人口基数。
社区连接
串联俱乐部、校园、家庭三层网络。孩子在校队打球,家长在 App 看成长,俱乐部沉淀数据——形成棒球社区而非孤立的训练课。
文化培育
让孩子从 U8 到 U15 都有成长档案,培养长期运动习惯。棒球教会孩子的专注、韧性、团队精神,BasePulse 用数据让这些品质「被看见」。

    踩过的坑与解决方案

    坑 1:Metro 启动即崩溃(exit code -1073741819)
    根因是系统环境变量 CI=true 触发 Metro 的 CI 模式,导致部分库行为切换,Node 进程内存访问违规。TRAE 帮我定位到环境变量层面,在启动脚本里清除 CI,而非简单重装依赖。

    坑 2:Expo ESM 项目 dotenv 加载失败
    传统 require('dotenv').config() 在 ESM 下不工作,而且原代码把 Supabase 凭证硬编码在 supabase-client.ts 里。TRAE 帮我改用 import { config } from 'dotenv' 并按 NODE_ENV 加载对应 .env 文件,凭证移到 .env.development / .env.production 分离管理。

    坑 3:中文棒球术语口语化多样,正则覆盖不全
    「8号击出二垒安打」可以解析,但实际教练会说「8号二安」「8号打到二垒」「8号安打上二垒」等口语变体。初版正则只覆盖标准说法,真实场景命中率低。TRAE 帮我扩充匹配规则,覆盖三振/挥空/保送/触身/本垒打等口语,但仍承认无法覆盖所有方言变体——这是中文本土化的真实挑战。

    坑 4:攻防转换逻辑最初只有主队得分
    第一版 Demo 只实现了主队记分,没有区分上下半局。真实棒球规则是「上半局客队攻、下半局主队攻,3 出局换边」。TRAE 帮我梳理出完整的攻防状态机:当前攻方高亮、3 出局自动交换、跑者清空、局次递增、各队独立打序。

    坑 5:阵容管理最初只有单队
    棒球是两队对抗,但第一版阵容页只显示一支队伍。用户反馈后,TRAE 帮我改成攻防两方独立阵容,两队各自 9 人,打序独立计数,当前进攻方的击球员高亮标注「击球中」。

    坑 6:创意提案数据真实性存疑
    初版创意提案写了「30万棒球人口、500家俱乐部、0款本土化App」等数字。TRAE 在核实后发现这些数字没有权威来源,属于编造。最终决定删除所有编造数字,改为定性描述「本土中文棒球记分工具几乎空白」。诚实比好看重要——评审会查数据来源。

    开发心得与体会

    1. TRAE 适合做产品协作伙伴,而非只是代码生成器
    开发 BasePulse 时,TRAE 不仅能写代码,还能读懂项目现有的 DESIGN.md 视觉规范、理解 metro.config.js 的代理逻辑、在出错时主动定位根因(如 CI=true 导致崩溃)而非绕过。把它当协作者而非工具,产出质量更高。

    2. 诚实比完美重要
    初版创意提案编造了棒球人口数字,初版 Demo 只有单队记分。发现后没有掩饰,而是直接修正并如实标注哪些功能可用、哪些待接入。评审看重真实价值,编造的数据反而会扣分。

    3. Demo 要有故事,而非只是功能堆砌
    最初 Demo 打开就是一堆按钮,评审不知道这服务于谁。后来在顶部加了背景叙事区(国内棒球基层痛点、家长期待、GameChanger 对比、对棒球运动的意义),让评审先理解价值再体验功能,代入感强很多。

    4. 用户反馈是最好的产品经理
    攻防转换逻辑、阵容两方独立、创建比赛流程——这些都是用户反馈后才补上的。第一版只想着「能记分就行」,但真实教练使用路径是「创建比赛 → 排阵 → 记分 → 看报告」,缺少前置环节会让评审困惑。
