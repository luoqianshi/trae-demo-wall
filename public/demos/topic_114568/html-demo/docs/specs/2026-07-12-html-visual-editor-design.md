## 1. 产品概述

### 1.1 问题背景

大量非技术用户通过 AI 生成 HTML 做教学课件、活动宣传、演示页面。但 AI 生成的 HTML 质量难以一次过关，用户需要反复与 AI 对话修改，即使很小的改动也要重新沟通。现有 AI 建站工具（v0、Bolt、Lovable）侧重生成，精修体验弱；传统可视化编辑器（Webflow、Framer）门槛高，不适合零基础用户。

核心痛点：**非技术用户不需要和 AI 反复 chat，他们需要像改 PPT 一样直接改页面。**

### 1.2 产品定位

一个零安装、打开即用的网页版 HTML 可视化编辑器。用户粘贴 AI 生成的 HTML 代码即可进入编辑，像改 PPT 一样对每个细节进行修改，改完导出或分享。

**一句话描述**：AI 生成 HTML 后的「可视化精修器」。

### 1.3 目标用户

| 优先级 | 场景 | 典型用户 |
|---|---|---|
| P0 | 教学课件 / 课程介绍页 | 教师、培训机构 |
| P0 | 通用演示 / 幻灯片式页面 | 需要展示观点、流程、数据的人 |
| P1 | 活动宣传 / 海报页 | 企业、社团 |
| P1 | 个人作品集 / 博客文章 | 个人 |

### 1.4 成功标准

- 用户从粘贴 HTML 到完成第一次修改（改文字）< 10 秒
- 能覆盖 90% 常见 AI 生成 HTML 的结构
- 核心编辑操作（改字、换色、调间距、拖排序、增删元素）全部可用
- 导出的 HTML 在浏览器中打开效果与编辑态一致
- 整个流程零注册、零安装

## 2. 架构设计

### 2.1 整体架构

产品分为三层，从上到下：

```
┌──────────────────────────────────────────────────┐
│              UI 交互层 (Interaction)               │
│  顶部工具栏 · 左侧素材面板 · 覆盖层 · 右侧属性面板     │
│       · 面包屑导航 · AI 对话面板（Chat 模式）          │
├──────────────────────────────────────────────────┤
│              编辑引擎层 (Editor Engine)             │
│  选中管理 · 内联编辑 · 流式拖拽 · 增删操作 · 撤销重做   │
│            · AI 辅助层（理解 + 批注 + 交接）           │
├──────────────────────────────────────────────────┤
│           数据与渲染层 (Data & Render)              │
│  iframe 渲染 · DOM 标注 · 事务栈 · 导入导出 · 分享   │
│         · AI 结构理解器（导入时标注增强）              │
└──────────────────────────────────────────────────┘
```

### 2.2 模块职责

#### 数据与渲染层

| 模块 | 职责 |
|---|---|
| iframe 渲染器 | 用 sandbox iframe（`sandbox="allow-same-origin"`，不加 `allow-scripts`）安全渲染用户 HTML，禁用脚本但允许父页面穿透访问 DOM |
| DOM 标注器 | iframe 加载后遍历 DOM，给每个可编辑元素打上 `data-eid` 唯一标识 |
| AI 结构理解器（可选） | 导入时识别页面结构、元素类型、可编辑性，增强标注 |
| 事务栈 | 基于**操作指令**（Transaction）模式，记录每个操作的正向和反向指令，支持精确撤销/重做 |
| 导入器 | 支持粘贴代码、上传 `.html` 文件；导入时自动注入 `<base>` 标签解决相对路径问题 |
| 导出器 | 清理编辑属性后序列化 DOM，输出干净 HTML；支持下载、复制、分享、AI 交接文件 |

#### 编辑引擎层

| 模块 | 职责 |
|---|---|
| 选中管理 | 父页面通过同域穿透直接访问 `iframe.contentDocument.elementFromPoint()` 做命中检测；支持面包屑导航和智能向上寻祖 |
| 内联编辑 | 双击文本元素启用 `contenteditable="plaintext-only"`，强制纯文本输入；粘贴时自动消毒 |
| 流式拖拽 | 拖拽本质是**在 DOM 树中移动节点位置（Reordering）**，而非修改坐标；拖拽时计算插入位置，释放时执行 `parentElement.insertBefore()` |
| 增删操作 | 插入新元素、删除选中元素、复制粘贴 |
| 撤销重做 | 基于事务栈，每个操作记录正向/反向指令，支持无限级撤销 |
| AI 辅助层 | 结构理解、批注、交接文件生成、Chat 模式建议生成 |

#### UI 交互层

| 模块 | 职责 |
|---|---|
| 顶部工具栏 | 撤销/重做、预览切换、导出、分享、响应式断点切换 |
| 左侧素材面板 | 可拖拽插入的元素列表 |
| 覆盖层 | 透明叠加在 iframe 之上，负责选中框、拖拽手柄、插入指示线 |
| 右侧属性面板 | 选中元素后显示可安全修改的属性，包含基础样式和 Layout（Flex/Grid）分组 |
| 面包屑导航 | 显示选中元素的父级链条，支持点击切换选中层级 |
| AI 对话面板 | Chat 模式下用户与 AI 交互的界面 |

### 2.3 关键设计决策

1. **iframe 同域穿透**：使用 `sandbox="allow-same-origin"`（不加 `allow-scripts`），既禁用用户 HTML 中的脚本，又允许父页面直接访问 `iframe.contentDocument`，无需 `postMessage` 通信，性能提升一个数量级。
2. **覆盖层而非直接操作**：不在 iframe 内部放编辑 UI，而是用透明覆盖层捕获鼠标事件，编辑器样式不污染用户内容。
3. **DOM 是数据源**：不维护额外的 JSON 树，DOM 本身就是数据，事务栈只记录操作指令，降低复杂度。
4. **流式拖拽而非坐标拖拽**：拖拽改位置的本质是 DOM 树节点重排（Reordering），不写任何 `px` 坐标，保证布局绝不崩溃。
5. **属性面板按类型过滤 + Layout 分组**：不同元素类型暴露不同的安全属性；同时提供 Flex/Grid 布局可视化调整。
6. **AI 理解 + 确定性落地分工**：AI 负责理解页面结构（可选），确定性转换器负责实际写入，降低不可靠性。
7. **双模式编辑**：Visual 模式（点选直接改）处理细节，Chat 模式（自然语言）处理结构性改动。
8. **纯原生架构规范**：坚持零依赖理念，但通过模块化拆分（每个模块独立职责、通过事件总线通信）避免面条代码。

## 3. 核心编辑流程

### 3.1 选中机制

用户进入编辑模式后：

1. **悬停高亮**：覆盖层通过 `iframe.contentDocument.elementFromPoint(x, y)` 获取鼠标坐标下方的 DOM 元素，绘制蓝色虚线框 + 元素标签
2. **点击选中**：点击后变为实线选中框 + 拖拽手柄 + 浮层工具条
3. **浮层工具条**：跟随选中框出现，智能定位（避免超出视口边缘），包含：删除、复制、上移层级、下移层级、AI 助手
4. **右侧属性面板同步**：选中元素后，右侧面板自动展示该元素类型可安全修改的属性
5. **面包屑导航**：选中元素时，在浮层工具条或底部状态栏显示其父级链条（如 `body > div.hero > h1`），允许用户点击父级标签快速向上切换选中
6. **智能向上寻祖**：如果点击命中了不可编辑的纯文本节点或深层嵌套的内联元素，自动将选中目标提升至其最近的块级祖先或打过 `data-eid` 标记的组件
7. **取消选中**：点击空白区域或按 Esc

技术实现要点：
- **同域穿透**：由于 `srcdoc` 默认与父页面同源，且 sandbox 设为 `allow-same-origin`，父页面可以直接访问 `iframe.contentDocument`，无需 `postMessage`
- 用 `iframe.contentDocument.elementFromPoint(x, y)` 做命中检测
- 选中框位置通过 `getBoundingClientRect()` 获取，需检查 `transform` 属性对坐标的影响
- 滚动监听使用 `requestAnimationFrame` 节流，仅在位置变化时更新覆盖层
- `mousemove` 节流至 50ms，避免高频计算

### 3.2 内联文字编辑

- **触发**：双击文本元素
- **机制**：给元素加 `contenteditable="plaintext-only"`，强制纯文本输入，避免浏览器自动插入 `<p>`、`<div>`、`<br>` 等标签
- **适用元素**：`h1-h6`、`p`、`span`、`a`、`button`、`li`、`label` 等文本类元素
- **粘贴消毒**：监听 `paste` 事件，`preventDefault()` 后只插入 `clipboardData.getData('text/plain')`，防止富文本污染
- **回车拦截**：在文本编辑状态下，阻止 Enter 键的默认行为（直接失焦保存），防止产生多行标签
- **提交**：失焦或按 Esc 时，移除 `contenteditable`，将变更提交到事务栈
- **中文输入法**：需在 Chrome/Safari/Firefox 中测试 compositionstart/compositionend 事件，避免输入中途触发提交
- **撤销**：使用 debounce 合并连续字符输入，避免每个字符都产生一个操作栈项

### 3.3 流式拖拽改位置

**核心原则：拖拽不是修改坐标，而是在 DOM 树中移动节点位置（Reordering）。**

- **触发**：在选中元素中心区域按住鼠标拖动
- **机制**：
  - 拖拽过程中，实时计算鼠标悬停在哪个兄弟节点的前后
  - 在兄弟节点之间显示蓝色插入指示线
  - 释放时执行 `parentElement.insertBefore(draggedElement, targetSibling)` 
  - 不写任何 `px` 坐标、不修改 `margin`、不修改 `transform`
- **跨容器拖拽**：支持拖拽到不同的父容器中，但需检测目标容器的 `display` 类型
- **布局安全检测**：
  - 如果父容器是 `flex` 或 `grid`，拖拽排序天然安全（只需改变 DOM 顺序）
  - 如果父容器是 `block` 流式布局，拖拽排序同样安全
  - 不支持将元素拖入 `position: absolute` 的容器（会提示用户）
- **不依赖对齐参考线**：由于是 DOM 重排而非坐标拖拽，不需要复杂的对齐参考线，开发成本大幅降低

### 3.4 拖拽改大小

- **触发**：拖拽手柄
- **机制**：
  - 四角手柄：同时改 width + height
  - 四边手柄：只改对应方向的 width 或 height
  - 优先修改内联 style 的 `width` / `height`
- **智能单位转换**：
  - 如果元素的父容器有明确宽度，优先使用百分比（如 `width: 50%`）而非固定 `px`
  - 对于全宽元素（如 Hero 区），使用 `vw` 单位
  - 对于需要精确控制的元素（如 Logo），保留 `px` 单位
- **断点感知**：
  - 在桌面断点下修改的样式写入默认位置
  - 在手机断点下修改的样式写入 `@media (max-width: 768px)` 媒体查询（P1 阶段实现）
- **约束**：设置最小尺寸（如 20px），防止缩到看不见
- **transform 检测**：如果元素或其祖先含 `transform: scale()`，坐标计算需修正

### 3.5 添加元素

左侧素材面板提供以下可拖拽插入的元素：

| 分类 | 元素 | 插入后的默认行为 |
|---|---|---|
| 文字 | 标题、段落、标签 | 插入到选中元素后方，自动进入内联编辑 |
| 媒体 | 图片、视频、图标 | 弹出输入框填 URL 或上传文件 |
| 组件 | 按钮、分割线、容器 | 插入到选中元素后方，自动选中 |
| 嵌入 | 地图、表单、链接卡片 | 弹出配置面板 |
| 品牌 | Logo 占位 | 预设正方形 + 圆角，点击替换图片 |

插入流程：
1. 用户从左侧面板拖拽元素到画布
2. 覆盖层高亮即将插入的目标位置（元素之间显示蓝色插入指示线）
3. 释放后创建新 DOM 节点，打上 `data-eid`
4. 事务栈记录「新增」操作（正向：`insertNode(node, parentEid, index)`，反向：`removeNode(eid)`）
5. 自动选中新元素

### 3.6 删除元素

- 选中元素 → 按 Delete 键 或 浮层工具条点删除
- 删除前确认弹窗（仅对大块元素，小元素直接删）
- 删除后事务栈记录「删除」操作（正向：`removeNode(eid)`，反向：`insertNode(node, parentEid, index)`）
- 删除后自动选中相邻元素

### 3.7 撤销/重做

基于**事务栈（Transaction Stack）**实现，采用操作指令模式而非快照模式：

- 每个操作 = `{ type, forward: Function, backward: Function, timestamp }`
- 操作类型：`edit-text`、`reorder`、`resize`、`add`、`delete`、`style-change`
- Ctrl+Z 撤销（执行 `backward`），Ctrl+Shift+Z 或 Ctrl+Y 重做（执行 `forward`）
- `data-eid` 一致性：元素被删除后重新添加（undo），保持原 `data-eid`，确保绑定的属性和状态不失效
- 内联编辑使用 debounce 合并连续字符输入（如 500ms 内的连续输入合并为一个操作）
- 大操作栈内存监控：超过 1000 条操作时，将最早的操作归档为快照

### 3.8 右侧属性面板

选中元素后，右侧面板根据元素类型显示可安全修改的属性，分为基础样式和布局两个分组：

#### 基础样式分组

| 元素类型 | 可修改属性 |
|---|---|
| 文本类（h1-h6, p, span, a, button） | 文字内容、颜色、字号、字重、行高、对齐、字间距 |
| 图片类（img） | src、alt、宽度、高度、圆角、边框、阴影 |
| 容器类（div, section, article） | 背景色、内边距、外边距、圆角、边框、阴影 |
| 按钮类（button, a.btn） | 文字、背景色、文字色、圆角、内边距、悬停色 |
| 列表类（ul, ol, li） | 列表样式、间距、缩进 |
| 媒体类（video, iframe） | src、宽度、高度、圆角 |

#### Layout 分组（Flex/Grid 可视化调整）

| 属性 | 控件形式 |
|---|---|
| Display | 切换按钮（block / flex / grid / inline） |
| Flex Direction | 图标按钮组（横向 / 纵向） |
| Justify Content | 对齐九宫格（左 / 中 / 右 / 分散） |
| Align Items | 对齐九宫格（上 / 中 / 下） |
| Gap | 滑块 + 数字输入 |
| Flex Wrap | 开关 |

设计原则：
- 基础样式分组只暴露安全属性，隐藏可能破坏布局的属性（如 position、z-index、float）
- Layout 分组通过可视化图标（如 Webflow 的对齐九宫格）来控制 Flex/Grid 布局
- 颜色使用取色器 + 预设色板
- 字号、间距使用滑块 + 数字输入
- 对齐使用图标按钮组
- 布局警告：修改 position 或 transform 时，如果元素在 flex/grid 容器内，显示警告提示

### 3.9 AI 结构理解器人工覆盖通道

由于 AI（或规则引擎）对元素类型的判断可能不准确，必须提供人工覆盖机制：

- 右键菜单或属性面板中提供「允许编辑」复选框，用户可手动将 AI 标记为不可编辑的元素改为可编辑
- 提供「组件类型」下拉框，用户可手动修正 AI 的分类（如将「装饰文本」改为「标题」）
- 用户的覆盖操作记录在 `data-user-override` 属性中，后续 AI 重新理解时不覆盖用户手动设置

## 4. 端到端流程

### 4.1 导入阶段

三种导入方式，按优先级排序：

**1. 粘贴 HTML 代码（主要方式）**
- 首页即一个大输入框 + 「开始编辑」按钮
- 用户从 AI 工具复制 HTML 代码，直接粘贴
- 点击「开始编辑」后写入 iframe `srcdoc`，进入编辑模式
- 同时提供一个「加载示例」按钮，内置教学课件、活动宣传两个示例 HTML

**2. 上传 .html 文件**
- 支持拖拽文件到输入框或点击「选择文件」
- 读取文件内容后同粘贴流程
- 支持单文件，后续可扩展 ZIP（含资源目录）

**3. 粘贴 URL（受限）**
- 尝试用 CORS 代理抓取目标页面的 HTML
- 因跨域限制，不一定所有网站都能抓到
- UI 上标注「部分网站可能无法获取」

导入后的统一处理流程：
```
获取 HTML 字符串
    ↓
解析 HTML，检测是否包含相对路径资源
    ↓
如有，在 <head> 中注入 <base href="原始URL或资源根路径">
    ↓
写入 sandbox iframe srcdoc（sandbox="allow-same-origin"）
    ↓
iframe 加载完成（监听 onload 事件）
    ↓
DOM 标注器遍历，打 data-eid
    ↓
性能检查（DOM 节点数 > 5000 时显示警告）
    ↓
（可选）AI 结构理解器增强标注
    ↓
进入 Visual 编辑模式
```

### 4.2 AI 结构理解器（可选）

导入时可选启用 AI 增强标注：

```
基础标注（DOM 标注器）
    → 给每个元素打 data-eid
    ↓
AI 结构理解（可选）
    → 识别页面结构
    - 哪些是幻灯片/区块边界
    - 哪些文字可编辑、哪些是装饰
    - 哪些是媒体块（图片/视频/SVG）
    - 哪些是交互元素（按钮/链接/表单）
    ↓
增强标注
    → 补充 data-editable / data-type / data-role
```

后续编辑时，属性面板根据 `data-type` 智能展示对应的安全属性。用户可通过人工覆盖通道（3.9 节）纠正 AI 的错误分类。

demo 阶段可先用规则代替 AI：
- 标签名匹配（img → 媒体类，button → 按钮类）
- class 名关键词匹配（hero → 区块标题，nav → 导航）
- 文本内容长度判断（短文本 → 标题，长文本 → 段落）

### 4.3 预览阶段

- 顶部工具栏点「预览」按钮
- 隐藏所有编辑 UI：覆盖层、左侧面板、右侧面板、浮层工具条
- iframe sandbox 临时添加 `allow-scripts`，恢复正常交互（按钮可点击、链接可跳转、表单可输入）
- 预览态下支持响应式断点切换（桌面 1280px / 平板 768px / 手机 375px）
- 再点一次「预览」退出，回到编辑态

### 4.4 导出阶段

四种导出方式：

**1. 下载 .html 文件**
- 清理所有 `data-eid`、`data-editable`、`data-type`、`data-user-override` 等编辑属性
- 内联所有必要的 CSS（如果用户 HTML 依赖外部 CSS，尝试保留 link 标签）
- 添加导出元数据注释（编辑器版本、导出时间戳、版本哈希）
- 生成独立可打开的 `.html` 文件并下载
- 文件命名约定：`page-YYYY-MM-DD-{random}.html`

**2. 复制 HTML 代码**
- 同样清理编辑属性
- 输出到剪贴板，方便用户粘贴到自己的网站或 CMS

**3. 生成分享链接**
- 将 HTML 内容编码后存到 `IndexedDB`（支持几百 MB，远超 localStorage 的 5-10MB 限制）
- 生成一个包含内容 ID 的短链接（如 `/#view=<contentId>`）
- 打开该链接时从 IndexedDB 读取内容，自动进入预览模式
- 再点击「在此基础上编辑」可加载编辑器继续修改
- **限制说明**：IndexedDB 数据仅存在于当前浏览器，跨设备分享需导出文件后发送。后续可通过接入免费 KV 存储（如 Cloudflare KV / Vercel KV）实现跨设备分享。
- 这是 HTML 相比 PPT 的核心优势体现

**4. 导出 AI 交接文件**
- 生成 markdown 文件，包含：
  - 当前 HTML 的可编辑结构概览
  - 每个可编辑元素的 `data-eid` 和内容摘要
  - 用户在 Chat 模式下的批注记录
  - 约束要求（如「保持现有布局结构」「不要改动 `.hero` 区域」）
- 用户可发给外部 AI 做更复杂的修改后重新导入

## 6. Chat 模式设计

### 6.1 触发方式

- 选中元素后点浮层工具条的「AI 助手」按钮
- 或快捷键 Ctrl+I

### 6.2 交互流程

```
选中元素
    ↓
点「AI 助手」→ 弹出 Chat 面板
    ↓
用户输入需求（如「把这段改成红色按钮，圆角加大」）
    ↓
AI 生成改动建议
    ↓
Before/After 视觉对比（滑块或双视口预览）
    ↓
用户确认 / 取消
    ↓
确认后应用到 DOM + 提交到事务栈（可撤销）
```

### 6.3 安全设计

- AI 不直接操作 DOM，通过事务栈提交
- **改动展示方式**：不向非技术用户展示 HTML 代码 Diff，而是采用 Before/After 视觉对比：
  - 方案 A（推荐）：滑块对比 — 按住按钮显示修改前，松开显示修改后
  - 方案 B：双视口预览 — 左侧显示修改前，右侧显示修改后
- 所有 AI 改动可撤销
- 改动边界约束：AI 只能修改选中元素及其子元素，不能影响其他区域

### 6.4 demo 阶段处理

demo 阶段 Chat 模式预留 UI 和接口，不接入真实 AI。用户输入需求后可手动在属性面板中调整，或导出交接文件发给外部 AI。

## 8. 技术选型

| 层面 | 选型 | 理由 |
|---|---|---|
| 框架 | 纯原生 HTML + CSS + JS | 零依赖、零构建、打开即用，符合低门槛原则；产品本身就是 HTML，用 HTML 做编辑器最直观 |
| 架构规范 | 模块化 + 事件总线 | 每个模块独立职责，通过事件总线通信，避免面条代码和状态同步地狱 |
| 样式 | CSS 变量 + 原生 CSS | 不用 Tailwind / 框架，避免与用户 HTML 样式冲突 |
| 编辑器核心 | 原生 DOM API + 同域穿透 | `sandbox="allow-same-origin"` 下父页面直接访问 `iframe.contentDocument`，无需 `postMessage`，性能最优 |
| 状态管理 | 事务栈（操作指令模式） | 记录正向/反向指令，精确撤销/重做，比快照模式更可靠 |
| AI 接口 | 可选接入，预留 API Key 输入框 | demo 阶段可先不接 AI，结构理解用规则代替 |
| 分享 | IndexedDB + 短链接 | 无需后端，支持大容量 HTML（几百 MB），跨设备分享需后续接入 KV 存储 |

## 10. demo 阶段边界

- **不接后端**：所有数据在浏览器本地（IndexedDB），不持久化到服务器
- **不接 AI**（可选）：结构理解先用规则代替，Chat 模式预留 UI 和接口
- **不支持协同**：单用户编辑
- **不处理 JS 交互**：编辑态下 iframe sandbox 设为 `allow-same-origin`（不加 `allow-scripts`），用户 HTML 中的 `<script>` 被禁用；预览态临时加 `allow-scripts`；导出时保留原样
- **跨设备分享受限**：IndexedDB 数据仅存于当前浏览器，跨设备分享需导出文件

## 11. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 复杂 CSS 导致编辑异常 | 拖拽、改样式可能破坏布局 | 流式拖拽不写坐标；操作前通过事务栈保存原始状态用于撤销；布局警告提示 |
| iframe sandbox 与脚本冲突 | 编辑态无法执行 JS | `sandbox="allow-same-origin"` 禁用脚本但允许 DOM 穿透；预览态临时加 `allow-scripts` |
| 导入 HTML 相对路径失效 | 图片、CSS 报 404 | 导入时自动注入 `<base href="原始URL">` 标签 |
| contenteditable 浏览器差异 | 不同浏览器行为不一致 | 使用 `plaintext-only` 模式；粘贴消毒；回车拦截 |
| 深层嵌套元素选中困难 | 用户无法选中目标元素 | 面包屑导航 + 智能向上寻祖 |
| 大 HTML 性能问题 | 标注和渲染变慢 | IntersectionObserver 虚拟化标注；mousemove 节流至 50ms；DOM 节点 > 5000 时警告 |
| 用户 HTML 含恶意脚本 | 安全风险 | iframe sandbox 禁用脚本；粘贴消毒防止 XSS |
| 分享链接容量限制 | 大 HTML 超出 URL 长度限制 | 使用 IndexedDB 存储（几百 MB），URL 中只带短 ID |
| 中文输入法兼容性 | contenteditable 光标位置异常 | 测试 compositionstart/compositionend 事件 |

## 14. UI 设计规范

> 参见高保真原型：`d:\html-demo\ui-prototype.html`

### 14.1 美学方向

**「精致工坊」(Refined Workshop)** — 温暖中性色调、克制留白、单一高级强调色。参考 2026 年 UI 趋势中的「新极简主义」「柔和光影杂志质感」「舒缓式界面」，拒绝 AI 生成器常见的紫色渐变白底、Inter 字体、卡片堆砌等泛化美学。

### 14.2 设计系统

#### 配色

| Token | 值 | 用途 |
|---|---|---|
| `--bg-base` | `#1a1816` | 最底层背景，温暖深炭而非纯黑 |
| `--bg-surface` | `#22201d` | 面板背景（左/右栏、顶部栏） |
| `--bg-elevated` | `#2a2724` | 浮层、弹窗、选中态 |
| `--bg-hover` | `#322e2a` | 悬停态 |
| `--border-subtle` | `#34302c` | 极淡分割线 |
| `--text-primary` | `#e8e4df` | 主文字，暖白而非纯白 |
| `--text-secondary` | `#a8a39d` | 次要文字 |
| `--text-tertiary` | `#6b6764` | 标签、占位文字 |
| `--accent` | `#c8956d` | 精炼琥珀色，唯一强调色 |
| `--accent-subtle` | `rgba(200,149,109,0.12)` | 强调色低透明度背景 |

设计原则：
- 全局只有一个强调色（琥珀色），不做多色彩点缀
- 背景使用温暖深炭色系（`#1a` 开头），而非中性灰（`#1e` 或 `#222`）
- 文字色为暖白（`#e8e4df`），而非纯白 `#fff`，降低对比度刺眼感
- 功能色（success/warning/danger）全部低饱和，不做亮色系

#### 字体

| 场景 | 字体 | 理由 |
|---|---|---|
| UI 文字 | Instrument Sans | 有微妙的几何特征，非中性化 |
| 展示标题 | Newsreader | 带衬线优雅气质，用于导入页大标题 |
| 代码/标签 | JetBrains Mono | 等宽，用于元素标签、面包屑、属性值 |

拒绝使用：Inter、Roboto、Arial、system-ui 等过于泛化的字体。

#### 间距

采用 4px 基准网格：
- `--space-xs`: 4px
- `--space-sm`: 8px
- `--space-md`: 12px
- `--space-lg`: 16px
- `--space-xl`: 24px
- `--space-2xl`: 32px

#### 圆角

- `--radius-sm`: 4px（按钮、输入框）
- `--radius-md`: 6px（面板、卡片）
- `--radius-lg`: 8px（大型容器）
- `--radius-xl`: 12px（弹窗、模态框）

#### 阴影

柔和分层，不做硬阴影：
- `--shadow-sm`: `0 1px 2px rgba(0,0,0,0.2)` — 微小元素
- `--shadow-md`: `0 4px 12px rgba(0,0,0,0.25)` — 面板
- `--shadow-lg`: `0 8px 24px rgba(0,0,0,0.3)` — 画布 iframe
- `--shadow-float`: `0 12px 32px rgba(0,0,0,0.35), 0 1px 4px rgba(0,0,0,0.2)` — 浮层工具条

### 14.3 布局规范

#### 三栏布局

```
┌─────────────────────────────────────────────────────┐
│                    顶部工具栏 (44px)                   │
├──────────┬───────────────────────────┬──────────────┤
│ 左侧素材   │                           │  右侧属性面板  │
│ 面板       │       中央画布区            │  (264px)     │
│ (220px)   │                           │              │
│           │                           │              │
└──────────┴───────────────────────────┴──────────────┘
```

- 顶部工具栏高度固定 44px
- 左侧素材面板宽 220px，可折叠至 44px
- 右侧属性面板宽 264px，可折叠
- 中央画布区自适应剩余空间
- 画布居中显示 iframe（最大宽度 960px），背景为微妙径向渐变

#### 导入页

全屏居中布局：
- 大标题使用 Newsreader 衬线字体，「即刻精修」部分用琥珀色斜体
- 大输入框（180px 高），等宽字体占位文字
- 底部操作按钮左对齐（示例、上传），右对齐（开始编辑）
- 整体保持大量留白，营造高级感

#### 画布信息条

高度 32px，位于画布区顶部：
- 左侧：面包屑导航（等宽字体，可点击切换层级）
- 右侧：画布尺寸 + 标注状态

### 14.4 组件规范

#### 工具栏按钮

- 高度 30px，最小宽度 30px
- 默认透明背景，文字色 `--text-secondary`
- 悬停：背景 `--bg-hover`，文字变亮
- 选中：背景 `--accent-subtle`，文字 `--accent`
- 禁用：透明度 0.35
- 图标统一 15×15px，SVG 描边 1.5px

#### 断点切换组

- 容器有 1px 边框 + 2px 内边距
- 按钮高 24px，选中态有内阴影
- 图标 13×13px + 文字标注（如 1280）

#### 素材面板项

- 高度自适应，padding `8px 16px`
- 左侧 2px 透明边框，悬停时变琥珀色
- 图标 16×16px，悬停变琥珀色
- 文字 12px，悬停变亮

#### 属性面板

分组结构：
- 每组有 10px 大写标题，字间距 0.08em
- 属性行：52px label + 自适应 input
- 输入框高 26px，聚焦时琥珀色描边 + 光晕
- 颜色选择器：色块 + 等宽色值输入
- 滑块：4px 轨道 + 14px 琥珀色圆形拇指
- 对齐九宫格：3 列网格，每格 22px 高

#### 选中框与覆盖层

- 选中框：1.5px 琥珀色实线，2px 圆角
- 手柄：8×8px 方块，深色背景 + 琥珀色描边
- 悬停框：1px 琥珀色虚线 + 极淡背景
- 元素标签：跟随悬停框顶部，琥珀色背景 + 深色文字
- 浮层工具条：选中框上方 40px，深色背景 + 阴影

#### 浮层工具条

- 位于选中框上方，居中对齐
- 深色背景 + 1px 边框 + 大阴影
- 按钮组：复制、上移、下移 | AI 助手 | 删除
- AI 助手悬停变琥珀色，删除悬停变红色
- 间距分隔线：1px 宽，16px 高

### 14.5 动效规范

- 全局过渡：`0.15s cubic-bezier(0.4, 0, 0.2, 1)`
- 面板折叠：`0.3s` 宽度过渡
- 浮层工具条出现：`0.15s` fadeIn（向上 4px 位移）
- 属性面板内容切换：`0.2s` fadeIn
- 预览徽章脉冲：2s 无限循环透明度变化
- 原则：动效服务于状态反馈，不做装饰性动画

### 14.6 拒绝清单

明确拒绝以下「AI 味」设计模式：

| 拒绝项 | 原因 |
|---|---|
| 紫色渐变白底 | 泛化 AI 美学，缺乏个性 |
| Inter / Roboto / system-ui | 过于常见，无品牌识别度 |
| 等距卡片网格布局 | 千篇一律，缺乏层次感 |
| 多色彩图标点缀 | 破坏专注感，不符合舒缓式界面趋势 |
| 纯黑 (#000) 背景 | 过于冰冷，缺乏温度 |
| 纯白 (#fff) 文字 | 对比度过高，刺眼 |
| 亮色功能色 | 不符合低饱和高级感 |
| 大面积渐变背景 | 泛化装饰，缺乏意图 |
| 通用 emoji 作为图标 | 不专业 |
| 圆角过大 (16px+) | 过于柔和，缺乏工具感 |
