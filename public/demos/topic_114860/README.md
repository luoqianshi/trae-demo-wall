# TestPilot · AI测试设计体检官

> 不只是生成测试用例，更帮你发现遗漏的测试风险。

## 产品简介

TestPilot 是一款面向软件测试工程师的 AI 测试设计副驾驶工具。从需求分析、测试设计、风险识别到自动化建议，全流程辅助测试工程师完成高质量测试设计。

将需求文档到测试用例的转化时间从 **2~4 小时** 缩短至 **10~15 分钟**。

## 使用方法（3 步）

1. **粘贴需求文档** — 在左侧输入区粘贴需求文档内容（≥50字），或点击「加载示例」快速体验
2. **配置参数** — 选择测试级别、测试方法、测试类型和生成偏好
3. **生成用例** — 点击「生成用例」按钮，AI 自动完成分析、生成、体检

## 核心功能

| 功能 | 说明 |
|------|------|
| 🌳 测试点树 | AI 拆解需求为结构化测试点，标注类型和来源 |
| 📋 结构化用例 | 8 字段完整测试用例 + 自动化适用性标注 |
| 🔍 用例体检 | 覆盖率分析 + AI 补充测试点 + 遗漏提醒 |
| 🐛 需求缺陷 | 反向审查需求文档，发现遗漏/矛盾/模糊/不合理 |
| ⚠️ 风险分析 | 识别高风险测试区域，给出资源分配建议 |
| 🤖 自动化建议 | 自动化占比统计 + 落地优先级建议 |
| 💬 迭代优化 | 支持自然语言补充要求，AI 基于上下文优化用例 |
| 📤 导出 | 复制 Markdown / 下载 Markdown / 下载 Excel |

## 技术栈

| 层面 | 技术 |

### 创作思路

作为一名自动化测试工程师，每天都在将需求文档转化为测试用例和自动化脚本。这个过程高度重复但又不能出错，经常加班到很晚还在逐条梳理需求点。TestPilot 的灵感正是来自这个真实痛点 — 如果 AI 能帮我读懂需求、自动生成用例初稿，我只需要审核和补充，效率至少能提升 5 倍。

### 解决的问题

- 手动拆解需求耗时长（2-4小时/需求）
- 人工设计容易遗漏边界条件和异常路径
- 新人上手慢，缺乏标准化的用例设计思路
- 需求变更频繁，用例维护成本高
