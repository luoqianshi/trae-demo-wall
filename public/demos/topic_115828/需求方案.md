# 眠证 Demo 页面需求方案

> 状态:需求已确认,未开始实现。
> 上游文档:`project/无标题.md`(创意申报)、`project/眠证-创意方案.html`(展示页)、`讨论.md`(九轮产品推演)。
> 本 demo 对应讨论.md 第九轮的「形态一:纯 App/小程序」,以可演示原型的方式呈现,不是真实产品。

## 一、定位与场合(已确认)

- **场合**:比赛评审/路演,演示者自己控制节奏讲解。
- **目标**:2–3 分钟内走完核心闭环,优先叙事冲击力,不追求功能完整度。
- **成功标准**:评委在 demo 结束时能复述出一句话——"这是让失眠老人自己攥着证据、反过来说服家人的产品,不是又一个监控老人的产品"。

## 二、核心叙事弧(demo 的五幕)

演示按固定故事线推进,每一幕对应一个屏幕状态:

| 幕    | 屏幕                  | 内容                                                                                                      | 情绪节拍                                     |
| ---- | ------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 1 开场 | 引导页                 | 一句研究原话("我孩子说,我这个年纪,闭上眼睛就该能睡着了")+ 产品名,点击进入                                                               | 先给痛,再给名                                  |
| 2 记录 | 每日记录页(带场景锚定)        | 界面顶部有场景状态("清晨 7:42 · 醒来后"),演示一次完整的语音记录交互(见四)——使用场景写在界面里,不只靠演示者口头交代                                      | 展示"轻":几十秒完成                              |
| 3 累积 | 7 天记录视图(可自由探索)      | 已有 7 天记录的列表,每条带时间戳,**任意一条都可现场点开看转写原文**——评委答辩追问时随手一点有响应                                                  | 展示"具体+连续"的力量                             |
| 4 生成 | **透明的生成过程(核心功能证明)** | 点「给家人看」→ 不是黑箱动画:7 天原始转写逐条闪现,其中的时间/次数/时长片段被琥珀色高亮提取("三点一刻"→ 03:15 夜醒 ×1),提取结果实时汇入报告骨架的对应位置。全程 4–6 秒,可点击跳过 | 亲眼看到"口语碎片→结构化证据"这个核心能力在工作,不是"点一下出现一张效果图" |
| 5 出示 | **双视角切换(高潮)**       | 屏幕切换为"递到家人手里"的报告视图:大字、叙事化、带原声摘录样式;结尾停在关键句                                                               | "这是我这周的数据,不是我矫情"                         |

第五幕结束后停在报告尾页,页面上有低调的「重新演示」入口(回到第一幕),供多轮评审重复使用。

## 三、示例数据与人设(已确认:照研究原话写)

- **人设**:周阿姨,68 岁,与儿子一家同住。多次夜醒型失眠,曾被儿子说"老了都这样,没办法"。人设细节取材自福州质性访谈(CC-SQ3-fuzhou-mci-family-dismissal-qualitative)与养老院质性研究(CC-SQ2)的第一人称语料风格,但**不声称是真实个案**,demo 中标注"示例数据"。
- **7 天记录文本**:每条 1–3 句,口语化、具体到时间和时长。示意(实现时细化):
  - D1:"三点一刻醒的,躺到四点多才迷糊过去。白天头都是沉的。"
  - D3:"昨晚还行,就醒了一次,很快睡回去了。"(故意混入好天,增强可信度——不是天天惨)
  - D5:"两点醒,四点醒,五点半干脆起来了。今天买菜差点忘了拿钱包。"
  - D7:"跟儿子说了,他说老了都这样。我不想再吵,就是想让他看看这一个礼拜。"
- **报告文案基调**:叙事化而非图表化——"这 7 天里,周阿姨有 5 个夜里醒来 2 次以上,最长一次醒着 1 小时 40 分钟"+ 2–3 条原声摘录。数字只做辅助,原话是主角。

## 四、语音环节(已确认:模拟录音+预置文本)

- 点击麦克风按钮 → 波形/呼吸动画约 2–3 秒 → 预置转写文本逐字浮现(打字机效果,速度可被点击跳过)。
- **不调用真实麦克风**,不申请任何浏览器权限,现场零翻车风险。
- 页面角落以极小字注明"演示版·模拟语音转写",诚实但不抢戏。

## 五、报告出示环节(已确认:双视角切换)

- 第 4→5 幕的切换要有"把手机递过去"的仪式感:设计方向为整个手机框翻转/推移过渡 + 报告视图字号显著放大(模拟递到长辈/家人手里、对方拿远看的状态)。
- 报告视图与记录视图**视觉上明确区分**(记录端=工具感;报告端=文档感/信件感),让评委直观看出"这是给另一个人看的东西"。
- 不做家人回应彩蛋(已确认不选),报告以周阿姨的一句原话收尾,留白。

## 六、形态与技术约束

- **单文件自包含 HTML**(HTML+CSS+JS 全内联),双击 file:// 直接打开,零网络依赖、零字体/JS CDN——吸取 TRAE 版依赖本地 `_shared` 目录的教训,复制到任何电脑/U盘都不散架。
- **桌面投屏优先**:页面中央是手机框(iPhone 比例,约 390×844 逻辑像素),手机框外是深色舞台背景;兼容 1080p 与 MacBook 内屏投影。
- **操作方式双轨**:所有推进既可点击手机框内的真实 UI 元素(看起来像真 App),也可用键盘 →/← 前进后退(演示者暗中控制节奏);两种方式驱动同一状态机。
- **手机框内字号**:正文 ≥18px、报告视图 ≥22px——既是适老化的产品主张本身,也保证投影后排可读。
- 视觉语言沿用 `眠证-创意方案.html` 的体系:夜色深蓝底 + 暖琥珀色点缀,衬线字标,产品 UI 内部用系统黑体。
- 动画服从 `prefers-reduced-motion`;深色为主基调(舞台感),不做双主题——这是一个刻意选择,演示环境可控。

## 七、范围外(明确不做)

- 真实语音识别、真实数据存储、登录注册、设置页、家人端独立界面、任何后端。
- 移动端真机适配(如后续需要真机演示再立单独需求)。
- 报告导出/分享的真实功能(演示到"出示"视觉状态为止)。

## 八、验收清单

- [ ] 双击打开,断网环境下全部正常
- [ ] 完整走完五幕 ≤3 分钟,跳过动画可压到 ≤90 秒
- [ ] 键盘与点击两种驱动方式均可完成全流程
- [ ] 第五幕报告视图在 3 米外投影可读
- [ ] 页面无 emoji 图标、无占位文本、无 lorem
- [ ] "演示版·示例数据"标注存在但不显眼
- [ ] **"功能而非概念"三项**:第四幕能看到提取过程(原文高亮 → 汇入报告);第二幕界面内可见场景锚定;第三幕任意一天可点开、报告页可真实滚动

## 九、遗留开放项(不阻塞开发,实现时顺手确认)

1. 产品名字标是否需要一个极简 logo 字形(目前方案:纯文字"眠证",证字用琥珀色)。
2. 第一幕引导页是否加一行赛道/团队署名(取决于比赛要求)。
3. 7 天记录文本的最终文案(上文为示意,实现时按同一基调写满 7 条)。
