# 眠证 Demo 单文件版 · 优化方案(实施级规格)

> 状态:方案,未实施。基于 2026-07-13 对 `眠证-demo-单文件.html`(1194 行)全文审读 + Playwright 实机截图验证。
> 行号以当前文件为准;实施时**以引用的原文定位为准**,行号仅作辅助(前面的改动会使后面行号偏移)。
> 每项含:位置 / 现状 / 改法(可照抄) / 验证方法。

## 保持不动的部分

单文件零依赖、键盘+点击双轨状态机、`prefers-reduced-motion` 支持、第三幕自由探索、报告纸面感与大字号、录音四阶段状态机(idle/recording/typing/done)——实现质量高,以下所有改动不得破坏这些。

## P0-1 报告页溢出被裁(bug,最高优先)

**现状**:`.screen-body`(约 220 行)为 `position:absolute; inset:0` 无滚动;`.phone-screen`(约 189 行)`overflow:hidden`;报告内容总高超出手机屏。实测:第五幕只能看到标题和 summary 第一段,**三条原声摘录、收尾句、`#replayButton` 全部不可见**。

**改法 1/3 —— 让报告幕可滚动**。在 `<style>` 内 `.report-screen` 规则(现为):

```css
.report-screen {
  color: var(--paper-ink);
  padding: 0;
}
```

改为:

```css
.report-screen {
  color: var(--paper-ink);
  padding: 0;
  overflow-y: auto;
  overscroll-behavior: contain;
  scrollbar-width: none;
}
.report-screen::-webkit-scrollbar { display: none; }
```

**改法 2/3 —— 底部渐隐提示"下面还有"**。在 `.report-card` 规则后新增:

```css
.report-scroll-hint {
  position: sticky;
  bottom: 0;
  margin-top: -46px;
  height: 46px;
  pointer-events: none;
  background: linear-gradient(180deg, rgba(234,215,190,0) 0%, var(--paper-deep) 88%);
  border-radius: 0 0 30px 30px;
}
.report-screen.scrolled-to-end .report-scroll-hint { opacity: 0; }
```

并在 HTML 中 `</article>`(report-card 结束标签,约 868 行)之后、`</section>` 之前插入:

```html
<div class="report-scroll-hint"></div>
```

**改法 3/3 —— 键盘滚动支持**。在 `keydown` 监听器(约 1178 行)内、两个 if 之前加入:

```js
const reportScreenEl = document.querySelector('.report-screen')
if (scenes[state.sceneIndex] === 'report' && (event.key === 'ArrowDown' || event.key === 'ArrowUp')) {
  event.preventDefault()
  reportScreenEl.scrollBy({ top: event.key === 'ArrowDown' ? 160 : -160, behavior: 'smooth' })
  return
}
```

(`reportScreenEl` 的 `const` 声明应移到脚本顶部与其他 DOM 引用并列,此处为示意。)

**验证**:打开 demo 走到第五幕,鼠标滚轮和 ↓ 键均可滚到底,能看到三条摘录、"我不想再吵,就是想让他看看这一个礼拜。"和"重新演示"按钮;滚动条不可见;第 1–4 幕不受影响(不出现滚动)。

## P1-1 第四幕补"透明提取"动画(与需求方案的最大差距)

**现状**:`beginGenerate()`(约 1101 行)只做 1.25 秒 handoff overlay 后直接 `goToScene(4)`。需求方案要求可见的"口语碎片 → 结构化证据"提取过程。

**改法概览**:点击"给家人看"后,顺序播放两段:①提取序列(约 4.5 秒,可跳过)→ ②视角切换卡(2.6 秒,见 P1-4)→ 进入第五幕。

**新增 DOM**(插在 `#handoffOverlay` 整块之前,与其同级):

```html
<div class="extract-overlay" id="extractOverlay" hidden>
  <div class="extract-card">
    <div class="eyeline">正在整理这 7 天</div>
    <div class="extract-feed" id="extractFeed"></div>

    </div>

**新增 CSS**(样式沿用 handoff-overlay 的定位与底色,追加):

```

**逐条提取的数据规格**(每条:原文中要 `<mark>` 高亮的词 → 行尾 `.ex-tag` 标签文案;高亮词必须与 demoRecords 转写原文逐字一致):

| 天  | 高亮词        | 标签                    |
| -- | ---------- | --------------------- |
| D1 | 三点一刻       | → 03:15 夜醒 · 清醒 75 分钟 |
| D2 | 一点多、快四点    | → 夜醒 ×2               |
| D3 | 醒了一次       | → 夜醒 ×1(较好的一天)        |
| D4 | 两点、三点四十、五点 | → 夜醒 ×3 · 最长清醒 100 分钟 |
| D5 | 两点、四点、五点半  | → 夜醒 ×3               |
| D6 | 醒了两回       | → 夜醒 ×2               |
| D7 | 看看这一个礼拜    | → 连续第 7 天             |

**时序规格**:每 600ms 追加一行(加 `.shown`);每行出现的同时更新三个计数器——`#exDays` 每行 +1;`#exNights` 在该条 `wakeCount >= 2` 时 +1(最终为 5);`#exLongest` 取到目前为止的 `max(longestAwakeMinutes)`,格式化 `Math.floor(m/60) + ':' + String(m%60).padStart(2,'0')`(最终 1:40)。第 7 行显示完后停 500ms,进入 handoff overlay。全程点击 overlay 任意位置或按 → 立即完成全部行与计数并跳到 handoff。`reducedMotion` 为真时不播动画,直接展示完成态 800ms 后进入 handoff。

**`beginGenerate()` 改造**:原函数体改为「显示 extractOverlay → 播放上述序列 → 隐藏 extractOverlay → 显示 handoffOverlay 2600ms → goToScene(4)」;`state.generating` 守卫、按钮禁用逻辑保持不变。

**验证**:点击"给家人看"能看到 7 行原文逐条出现、时间词高亮、右下三个数字从 0 涨到 7 / 5 / 1:40;中途点击一次立即跳完;→ 键同效;整个序列不超过 6 秒;reduced-motion 系统设置下无动画直达。

## P1-2 第二幕双按钮收敛(交互)

**现状**:`#micButton` 与 `#recordAdvanceButton` 绑定同一动作但文案两套("开始记录/录音中/已录完/完成" vs "开始录音/结束录音/跳过动画/查看 7 天记录")。

**改法**:`renderRecordScreen()`(约 1005 行)内,四个分支各加一行控制底部主按钮可见性,并统一文案:

| 阶段        | micButton 文案 | recordAdvanceButton | skipTypingButton |
| --------- | ------------ | ------------------- | ---------------- |
| idle      | 开始记录         | `hidden = true`     | hidden           |
| recording | 录音中·点击结束     | `hidden = true`     | hidden           |
| typing    | 已录完          | `hidden = true`     | 显示"跳过动画"         |

即在函数开头统一加:`recordAdvanceButtonEl.hidden = phase !== 'done'`,并把 done 分支的按钮文案固定为"查看 7 天记录",删除其余三个分支对 `recordAdvanceButtonEl.textContent` 的赋值;recording 分支 mic 文案改为"录音中·点击结束"。

**验证**:idle/recording/typing 三阶段底部只有 0 或 1 个按钮;任何阶段页面上不同时出现两个语义重复的按钮;全流程仍可纯键盘走通(→ 在各阶段行为不变)。

## P2-1 投影高度自适应

**现状**:phone 400×860 + stage `min-height: 940px`;1080p 投影去掉浏览器 UI 后可视高度常仅 \~880px,整机被截。

**改法**:脚本顶部加:

```js
function fitStage() {
  const needed = 940
  const scale = Math.min(1, (window.innerHeight - 48) / needed)
  document.documentElement.style.setProperty('--fit', String(scale))
}
window.addEventListener('resize', fitStage)
fitStage()
```

CSS 两处 transform 改为复合(保持 report-mode 效果):

```css
.phone-wrap { transform: scale(var(--fit, 1)); }
.phone-wrap.report-mode { transform: scale(var(--fit, 1)) translateX(34px) rotateY(-16deg) scale(1.07); }
```

并将 `.stage { min-height: 940px }` 改为 `min-height: min(940px, calc(100vh - 48px))`。

**验证**:把浏览器窗口高度压到 760px,手机整机仍完整可见、无页面级滚动;窗口恢复后回到原尺寸。

## P2-2 指标单一数据源

**现状**:第四幕静态 HTML 硬编码 `7 / 5 / 1:40`(约 841–843 行);报告里"5 个夜里"由 `getReportData()` 计算,"1 小时 40 分钟"又是硬编码字符串(约 963 行)。同一组指标三处来源,改示例数据会失同步。

**改法**:

1. 三个静态 `.metric .num` 加 id(`gDays`/`gNights`/`gLongest`),初始留空,`resetDemo()` 时从 `demoRecords` 计算填入:天数 = `demoRecords.length`;夜醒2+ = `filter(r => r.wakeCount >= 2).length`;最长 = `max(longestAwakeMinutes)` 用 P1-1 的同一格式化函数。
2. `getReportData().summary` 中"1 小时 40 分钟"改为由最长分钟数生成:`Math.floor(m/60) + ' 小时 ' + (m%60) + ' 分钟'`。

**验证**:把 D4 的 `longestAwakeMinutes` 临时改成 130,第四幕显示 2:10、报告显示"2 小时 10 分钟",两处自动一致;改回后恢复。

## P2-3 幕切换淡入实际未生效

**现状**:`.screen` 以 `display:none → flex` 与 `opacity 0 → 1` 同帧切换,浏览器跳过过渡,视觉为硬切。

**改法**:`renderScene()` 中对新激活的幕改两步:先 `el.style.display = 'flex'`,`requestAnimationFrame` 下一帧再加 `.active`;移除激活时用 `transitionend` 后再置 `display:none`(或简化为直接置 none,只保证入场有淡入)。

**验证**:幕间切换可见 360ms 淡入上移动画(reduced-motion 下仍为瞬切)。
