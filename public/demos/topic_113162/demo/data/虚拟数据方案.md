# NEXWorkBoard 虚拟数据方案

## 目标

为 TRAE AI 创造力大赛报名截图准备一套完整虚拟数据，要求：
1. 引导新用户：通过任务描述和文档内容，展示看板都有什么功能、能做到哪些
2. 覆盖四个方面：任务（看板）、报纸（晨报）、记忆（五层）、文档（Wiki+Skill）
3. 结合 Skill：数据内容反映真实 Skill 系统的调度、记忆、进化逻辑

## 故事主线

以"参加 TRAE AI 创造力大赛"为故事主线。所有数据围绕这条线展开：
- 看板上的任务就是参赛本身（报名帖、创意产物、Skill进化）
- 晨报在追踪大赛相关动态和参赛倒计时
- 记忆系统在沉淀参赛过程的决策
- 文档中心存着参赛文档和 Skill 架构

评委截图时，故事自洽——你在用 Workboard 参赛，看板本身就是参赛作品。

### 二、报纸（晨报）

虚拟一份 2026-06-27 的晨报，内容围绕大赛相关。
看板报纸模式读取 `晨报/YYYY-MM-DD.md`，需要符合晨报skill的板块结构。

#### 板块结构

1. **核心解读** — 今日最重要的变化
   - TRAE大赛报名倒计时18天（7/15截止）
   - 今日GitHub Trending信号：多Agent并行编码趋势
2. **与我相关** — 3条与参赛直接相关的情报
   - 某参赛作品思路（可对比）
   - 某AI工具更新（与功能相关）
   - 某技术趋势（影响产品方向）
3. **昨日回顾** — 昨天在参赛上推进了什么
4. **GitHub Trending** — 5个与项目方向相关的仓库

### 三、记忆（五层晋升）

完整展示五层记忆管线，每层都有内容：

| 层级 | 文件 | 虚拟内容 |
|------|------|---------|
| raw | `memory/raw/2026-06-27.md` | 今日对话要点：报名帖打磨的3个决策 |
| dreams | `memory/dreams/2026-06-27.md` | 晨报蒸馏：从昨日对话提取"痛点递进逻辑" |
| short-term | `memory/short-term.md` | 近7天活跃：大赛倒计时、参赛三大板块已定型 |
| long-term | `memory/long-term.md` | 跨7天积累：TRAE重度用户习惯、产品架构偏好 |
| wiki | `wiki/工作进度.md`等 | 永久资产：参赛项目进展、决策记录 |

#### raw 格式（对话收尾skill定义）

```
## 事实
- [客观发生的事]

- [做出的判断和选择]
## 待办
- [需要跟进的事项]
## 情绪
- [用户的情绪状态]
```

## 引导设计

每个任务描述写法是"引导式"，不是干巴巴的任务名，而是带功能提示：
- T-001："点击编辑查看报名帖正文，确认三大痛点逻辑是否对齐"
- T-002："创意产物HTML已留好4处截图占位，截图保存到assets/后替换img标签"
- T-003："晨报检测到Token优化赛道爆发，是否更新参赛策略Skill？"
- T-004："测试三步检查：raw已追加→wiki检查→short-term更新，全打勾才结束"
- T-007："验证raw→dreams蒸馏→short-term晋升→long-term关联≥7天→wiki永久资产"

评委截图时，任务描述本身就是功能说明。

## 使用方式

1. 启动 index.html（`http://localhost:8765/tools/NEXWorkBoard/index.html`）
2. 用 File System Access API 授权 `demo-data/` 目录
3. 各面板自动加载虚拟数据
4. 截图后替换创意产物HTML中的占位

## 执行顺序

1. 创建目录结构 ✅
2. 写方案文档（本文件）
3. 写看板数据.md
4. 写晨报 md + sources.json
5. 写记忆五层文件
6. 写Wiki文档（5份）
7. 写Skill文档（3份，精简版）
8. 写健康/睡眠/情绪日志（3份）
