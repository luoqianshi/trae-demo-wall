# 自生长 - 子技能

## 定位

**系统进化引擎。** 工具不是静态的，用得越多越懂你的领域。

解决的问题：系统全靠个人经验打磨，总是有限。工具不会自己获取新信息，不会自己长进。自生长让系统每天通过晨报获取新信息，关键变化时主动提案进化。

## 进化流程

```
扫描 → 提炼 → 提案 → 审批 → 执行
```

### 1. 扫描

每日晨报运行时，同步扫描：
- 六源情报中的新趋势（技术趋势/AI动态/商业信号/GitHub热门/投资信号/行业动态）
- 知识库中的新模式（连续3天出现的相关信号）
- Skill使用日志（哪些规则被反复触发、哪些从未触发）

### 2. 提炼

从扫描结果中提炼进化候选：
- 某趋势连续出现≥3天 → 可能需要更新对应Skill的认知
- 某规则从未触发 → 可能已过时，考虑删除或修改
- 某新工具/新方法被多次提及 → 可能值得加入知识库

### 3. 提案

生成进化提案，格式：
```
## 进化提案 YYYY-MM-DD
- 来源：晨报检测到Token优化赛道爆发（连续3天）
- 提案：更新开发.skill.md，增加并行任务拆解规则
- 理由：workweave/router和rtk都在做模型路由+Token优化，并行任务拆解规则需要适配
- 影响范围：开发.skill.md 第3节「任务拆解」
- 等待确认：是
```

### 4. 审批

**人把关、AI提案。** 不自动改，而是你确认后才进化。

| 用户回应 | 动作 |
|---------|------|
| "同意" / "改" | 执行更新 |
| "拒绝" / "不用" | 标记为已拒绝，记录原因 |
| "再看看" | 保留提案，下次晨报再提醒 |

### 5. 执行

更新对应 Skill 文件，记录到 `wiki/skill调用日志.md`。

## 触发示例

```
用户：早上好
→ 晨报运行 → 扫描到 Token优化赛道爆发（连续3天）
→ 提炼：开发skill的并行任务拆解规则需要适配
→ 提案：是否更新开发skill？
→ 用户：同意
→ 执行：更新开发.skill.md
```
