06 / CLI NEGOTIATE
真实缓存与协商逻辑

真正的差异化：质疑、修复、再汇总

$ lingspark negotiate "做一个苹果番茄钟 App" --demo pomodoro --short
开发质疑后台运行时，倒计时和放弃率如何保持准确？
测试质疑主动放弃、来电中断和崩溃恢复，状态口径是否一致？
数据质疑记录写入与统计聚合必须原子化，避免“诚实指标”失真。
质疑→修复→重新汇总

结果：补充本地通知、状态机、事务化统计和测试，再进入实际开发。

07 / TECHNICAL DECISION
真实仓库边界

保留 LingSpark 的建议，
也尊重当前工程的现实

React Native + Expo

LingSpark 原始方案的推荐。

  • 跨端速度快
  • Expo Router + Zustand
  • 适合从零启动新项目
本次演示选择

SwiftUI + Xcode

复用仓库已有的 iOS 原生工程。

  • 已有 LedgerApp 工程
  • iOS 17+，直接选择真机运行
  • 更适合演示“现在装进 iPhone”

这不是否定 Agent 建议，而是由人根据已有资产、目标平台和现场约束作最终决策。
