## 1. 执行摘要

### 一句话定位

**心伴(HeartPal)是面向12-18岁青少年的非盈利公益AI情绪辅助系统。** 它以三层递进的极光架构，由爱心医院联合开发运营，以公益基金覆盖基础成本，将临床级情绪支持通过AI技术触达每一个需要的人——在3000万情绪困扰青少年与600万留守儿童面前，架起一座基础功能永不收费、医生服务按次可及、贫困人群全部免费的桥梁。

### 核心运营模式：非盈利公益+医院联合运营+基金覆盖成本

心伴不是一个商业项目，而是一个**非盈利公益项目**。它的运营建立在一个不可动摇的法律基础之上：**12-18岁青少年是限制民事行为能力人（《民法典》第19条），本身不具有独立付费能力，需要监护人付费。** 这意味着"永不向青少年收费"（HC-12）不是心伴的道德让利，而是法律合规的刚性要求。**HC-12不是限制，是公益属性的基石。**

基于此，心伴设计了**四方资源聚合的非盈利公益模型**：

| 资源方 | 角色 | 覆盖内容 | 占比 |
|:---:|---|---|:---:|
| **公益基金会** | 成本主体 | 服务器、研发、合规成本 | 40-50% |
| **政府扶持基金** | 稳定压舱石 | 福蕾行动采购、教育信息化专项、中央财政社会组织项目 | 25-30% |
| **AI厂商公益+企业CSR+公众捐赠** | 社会参与+技术向善 | 字节跳动/火山引擎豆包免费额度捐赠+云资源公益支持（Token成本归零）、腾讯99公益日、企业定向捐赠 | 10-15% |
| **医生服务收入** | 专业服务 | 医生按次按时付费（挂号式，50-150元/次） | 10-15% |

**费用设计原则**：
- **基础功能完全免费**：AI对话、情绪天气图、认知游戏、量表自测、家庭互动卡、危机干预——零费用
- **非医生增值服务尽量低收费或免费**：家长基础情绪报告1-9元/月（象征性，可申请免费）
- **医生服务按次按时付费**：类似医院挂号，50-150元/次（按医生职称），**不设几百元包月**
- **贫困人群全部免费**：医生志愿者提供免费服务，与付费用户同等品质
- **危机干预永远免费**：公益基金兜底，安全优先于一切

**关键边界：不需要医生的服务→基金覆盖→完全免费；需要医生的服务→按次付费或志愿者免费；危机干预→公益兜底→永远免费。**

### 运营主体：爱心医院联合开发运营

心伴的运营主体是**爱心医院联合体+公益基金会托管**：

- **爱心医院**：提供医生资源、临床专业背书、医疗合规指导、医生志愿者派驻
- **公益基金会**：托管资金、监督公益属性、对接政府资源、公众筹款
- **技术团队**：负责AI系统开发维护、安全护栏、数据保护
- **学校/社区**：触达用户、贫困认证、场景落地

**这不是一家公司的商业项目，而是一个由医院、基金会、技术团队、学校共同托举的公益生态。**

### 本企划书核心论点

在中国，青少年情绪健康面临"三堵墙"困境：太贵、太难约、太让人害怕。国家明令禁止AI"虚拟恋人"诱导未成年人情感依赖，传统心理咨询又受限于资源稀缺与病耻感。心伴是"第三条路"——不模拟亲密关系，不替代医生，而是以专业级AI情绪辅助，在"没有人在乎"和"走进医院"之间，架起一座可触达的桥梁。

本企划书将论证：
- **技术上已验证**：30,000+行代码、2,861测试用例、103测试套件
- **合规上已设防**：12道安全护栏，HC-12是法律合规与公益属性的基石
- **公益上可持续**：四方资源聚合，基金覆盖成本，医生志愿者兜底贫困
- **政策上有红利**：17部门政策鼓励AI参与，福蕾行动采购，中央财政社会组织项目
- **AI公益有创新**：与字节跳动/火山引擎开创"AI回馈社会"新模式，豆包免费额度捐赠使Token成本归零
- **社会价值不可替代**：10万月活年成本约240万，SROI达1:7-10，600万留守儿童核心受益

## 2. 问题与市场

### 2.1 社会问题：一代人的公共健康议题

中国青少年情绪困扰的规模远超公众认知：

| 指标 | 数据 | 来源说明 |
|---|---|---|
| 青少年情绪困扰检出率 | 24.6% | 全国多省份横断面调查综合估算 |
| 受影响青少年规模 | 约3,000万 | 基于12-18岁在校人口推算 |
| 专业就诊率 | 不足20% | 即超过2,400万有需求青少年未获专业支持 |
| 留守儿童规模 | 约600万 | 民政部统计数据 |
| 学校心理老师配比 | 1:4,000 | 教育部配置标准与实际缺口 |

**24.6%的检出率意味着：** 每四个青少年中，就有一个正在经历不同程度的情绪困扰。

**1:4,000的师生配比意味着：** 每名学生每学期实际获得的专属心理关注时间 ≈ 47秒。47秒，不够说完一句"我最近不太开心"。

### 2.2 传统心理咨询三堵墙

- **第一堵墙——太贵：** 专业心理咨询动辄数百元每小时，对留守儿童家庭则是天文数字
- **第二堵墙——太难约：** 优质心理资源稀缺，公立医院心理科排队数周到数月
- **第三堵墙——太让人害怕：** 走进心理咨询室=承认"我有问题"，病耻感让无数孩子选择沉默

三堵墙的叠加效应是：**真正需要支持的孩子，恰恰是最难走进咨询室的那群人。**

### 2.3 市场规模

| 市场层级 | 规模 | 特征 |
|---|---|---|
| 核心受益群体 | 3,000万情绪困扰青少年 | 24.6%检出率，就诊率不足20% |
| 重点公益群体 | 600万留守儿童 | 父母在外、资源为零、零花钱每天2元 |
| 家长端潜在用户 | 数千万家庭 | 愿意为孩子情绪健康付费的家长 |
| 学校端采购市场 | 全国中小学 | 教育部要求配心理老师，但资源严重不足 |
| 政府/公益基金 | 青少年心理专项 | 卫健委、教育局、公益基金会持续投入 |

### 2.4 AI打破三堵墙

| 壁垒 | 传统方案 | 心伴方案 |

### 3.1 AI能力层（紫 · 公平）— 让"被听见"不再奢侈

- **24小时在线**：深夜11点，心理咨询室早关门了，但心伴亮着灯
- **零费用**：基础功能永不收费。在贵州山区，一个父母都在外打工的12岁男孩，他的零花钱是每天2块钱
- **零门槛**：不需要预约、不需要挂号、不需要勇气
- **全国覆盖**：一部手机，一条网线，从北京海淀到贵州毕节
- **AI情绪伙伴"豆豆"**：不评判、不泄密、不说"你想多了"

### 3.2 专业支撑层（青 · 专业）— 让AI说的每一句话都有据可依

| 支柱 | 内容 | 为什么专业 |
|------|------|------------|
| **三层知识库** | CBT脚本库（200+条医生审核脚本）+ 量表关键词库（SDQ/PHQ-9/GAD-7 + 183个危机关键词）+ 故事案例库（50+个脱敏案例） | 每一次AI回应都基于经过审核的专业知识 |
| **医生体系** | 审核者（知识库守门人）+ 协作者（用户授权后查看L2数据）+ 知识贡献者（持续输入专业知识） | 医生协作让AI具备临床级评估能力 |
| **五维工具体系** | 量表（看见自己）+ 对话（说出自己）+ 游戏（练习自己）+ 家庭（连接家人）+ 医生（专业支持） | 完整的情绪支持系统 |

### 3.3 安全守护层（绿 · 信任）— 让信任被刻进代码

**隐私分层 L0/L1/L2**：基于PostgreSQL RLS（行级安全策略），在数据库引擎层强制实现三层隔离。即使有人拿到超级管理员密码，执行 `SELECT * FROM conversations WHERE data_level = 'L2'`，返回的结果也是空。

| 层级 | 内容类型 | 可见范围 | 技术实现 |
|:----:|---------|---------|---------|
| **L0** | 昵称、头像、成就徽章 | 所有人 | 无特殊限制 |
| **L1** | 情绪趋势、活动参与度（聚合摘要） | 用户本人 + 家长（仅摘要） | RLS策略 |
| **L2** | 原始对话、情绪日记、暴露练习内容 | **仅用户本人。管理员不可见（HC-04）。** | RLS策略 |

**12道安全护栏**：覆盖AI输出边界、危机响应、隐私保护、数据主权、收费红线五大维度，全部以测试用例固化。

**11步管道编排器**：每一条AI回复，都要穿越11道关卡才能到达孩子面前。

### 4.1 四端架构

| 角色 | 可见数据层级 | 核心功能 |
|---|---|---|

### 4.2 11步管道编排器

```
用户输入
  │
  ▼
1.意图识别 → 2.危机关键词检测(183词) → 3.安全模式判断
  → 4.知识库检索(三层知识库) → 5.CBT策略匹配 → 6.对话生成(LLM+知识)
  → 7.输出校验(HC-01) → 8.合规检查(HC-03/HC-05) → 9.情感标注
  → 10.分层存储(L0/L1/L2) → 11.返回用户
```

### 4.3 三层知识库

| 层级 | 内容 | 规模 | 审核机制 |
|:---:|------|:---:|---|

| 第二层 | 量表关键词库（SDQ/PHQ-9/GAD-7 + 危机关键词） | 183个关键词 | 医生审核+版本管理 |
| 第三层 | 故事案例库（脱敏真实案例，按年龄/场景分类） | 50+个 | 医生审核+脱敏处理 |

### 4.4 12HC合规体系

| 编号 | 护栏 | 技术实现 | 为什么 |
|:---:|---|---|---|
| HC-01 | AI不得给出确定性建议 | 管道第7步输出校验 | 保护用户自主决策权 |
| HC-02 | 不追问自伤细节 | 管道第3步安全模式 | 避免诱导自伤行为 |
| HC-03 | 禁用"诊断/治疗/康复"三词 | 管道第8步合规检查 | 不越界进入医疗行为 |

| HC-05 | AI输出标注"专业辅助参考" | 管道第8步合规检查 | 明确AI角色边界 |
| HC-06 | 家庭互动卡孩子先确认 | 前端交互逻辑+后端校验 | 保护孩子隐私权 |
| HC-07 | 数据不上传第三方 | 数据流设计+审计 | 防止数据泄露 |
| HC-08 | 用户可导出删除数据 | 数据主权API | 尊重用户数据权利 |
| HC-09 | 量表以情绪天气图呈现 | 前端可视化组件 | 不以标签定义孩子 |
| HC-10 | 危机关键词自动触发安全提示 | 管道第2步关键词检测 | 危机即时响应 |
| HC-11 | 对话历史保留30天可调整 | 数据生命周期管理 | 平衡隐私与服务连续性 |
| HC-12 | 永不向青少年收费 | 商业模式设计+代码约束 | **法律合规壁垒** |

## 5. 合规与伦理专章

### 5.1 2025年4月中央网信办AI服务规范行动应对

2025年4月，中央网信办在全国范围内部署开展AI服务和应用规范行动，明确禁止AI提供"虚拟恋人"等亲密关系服务，尤其严禁向未成年人开放此类功能。

心伴对此的应对是**主动合规、系统合规、代码级合规**：

| 国家要求 | 心伴落地 |
|---|---|
| 不模拟亲密关系 | AI角色定位为"AI情绪伙伴'豆豆'"，非"虚拟恋人"或"朋友" |
| 不诱导情感依赖 | 不使用暧昧话术，帮助用户理解情绪而非依赖AI |
| 不模糊人机边界 | AI输出标注"专业辅助参考"（HC-05） |
| 保护未成年人隐私 | L0/L1/L2隐私分层 + 12道安全护栏 |
| AI服务备案 | 计划在产品正式上线前完成生成式AI服务备案 |

**这条红线，反而让心伴的定位更加清晰：** 心伴不是"虚拟恋人"，心伴是"专业级AI情绪辅助系统"。

### 5.2 HC-12的法律基础：不只是公益承诺，更是法律合规

**《民法典》第19条**：八周岁以上的未成年人为限制民事行为能力人，实施民事法律行为应当由其法定代理人代理或者经其法定代理人同意、追认。

这意味着：**12-18岁青少年独立实施的付费行为，在法律上存在效力瑕疵。** 任何要求青少年直接付费的产品，都面临民事行为能力挑战。

**HC-12的商业价值**：它将"永不向青少年收费"从道德承诺转化为法律合规壁垒。竞品若试图向青少年收费，将面临民事效力瑕疵风险。**HC-12不是限制，是护城河。**

### 5.3 三词禁用规则

心伴严格禁用"诊断""治疗""康复"三词作为产品功能描述（HC-03）。AI输出以"专业辅助参考"替代（HC-05）。

| 禁用词 | 替代表述 | 为什么 |
|---|---|---|
| 诊断 | 情绪状态参考 | AI不具备医疗诊断资质 |
| 治疗 | 情绪引导/认知练习 | AI不提供医疗服务 |
| 康复 | 情绪成长/积极变化 | 不将用户病理化 |

### 5.4 年龄红线

- **目标用户**：12-18岁青少年
- **14岁以下**：须监护人同意方可使用（《个人信息保护法》第31条）
- **内容适配**：知识库按年龄段分类，不同年龄匹配不同CBT脚本与案例

### 5.5 隐私分层

PostgreSQL RLS（行级安全策略）在数据库引擎层强制执行，即使有人拿到超级管理员密码也无法绕过。这是"信任被刻进代码"的技术实现。

**法律基础**：12-18岁青少年是限制民事行为能力人（《民法典》第19条），本身不具有独立付费能力。HC-12"永不向青少年收费"不是道德让利，而是法律合规的刚性要求。这一法律属性从根本上决定了心伴必须是公益项目——**任何向青少年收费的模式都存在民事效力瑕疵。**

- 年度复核一次
- 学校/社区背书制

- 虚假申报列入黑名单
- 贫困用户标记仅后端可见，前端无任何"贫困"标识，避免病耻感叠加

**安全优先于一切，这是心伴的底线。危机干预永远免费，无论用户是否贫困。**

**L3优化详细计算**：
- 40%命中缓存：成本≈0.0001元（仅缓存检索）

- 20%复杂问题用GLM-4.5（压缩后2,800 token）：0.0028元/次
- 加权平均：0.4×0.0001 + 0.4×0.0004 + 0.2×0.0028 = **0.00076元/次**
- 考虑系统开销，保守取 **0.0015元/次** 作为L3优化基准

## 14. 风险与应对

### 14.1 风险管理框架：合规优先+基金覆盖弹性

心伴作为非盈利公益项目，采用"合规优先三层防火墙+基金覆盖弹性管理"的双层风险框架：

- **上线前6个月**：采用合规优先三层防火墙——完成AI备案、HC合规审查、三层防火墙搭建、基金会托管账户设立
- **上线后运营期**：叠加基金覆盖弹性管理——多元化资金来源、基金覆盖缺口预警、非生成式AI备选版本、医生志愿者池冗余

**核心逻辑**：方案1确保"合规不被关停"，方案2确保"基金覆盖下的可持续运营"。心伴不追求盈亏平衡，追求的是基金覆盖下的可持续运营——只要基金覆盖+医生服务收入+政府补贴总和能覆盖运营成本，项目即可持续。

### 14.6 三大应急预案

#### 应急预案1：AI监管政策熔断（最高优先级）

**触发场景**：网信办/教育部出台新规，禁止向未成年人提供AI对话服务

**应急步骤**：
1. **T+0**：启动政策熔断预案，暂停新用户注册
2. **T+24h**：发布"政策合规调整公告"
3. **T+72h**：切换到"非生成式AI"版本——保留量表评估+知识库科普+人工预约心理咨询+危机热线转介
4. **T+7天**：向监管部门提交合规整改报告
5. **T+30天**：评估是否可恢复AI对话功能或永久转型

#### 应急预案2：基金覆盖不足（基金缺口持续超过6个月）

**触发场景**：基金会资助+政府补贴+医生服务收入+捐赠总和持续低于运营成本，储备金耗尽

**应急步骤**：
1. **预警阶段（基金覆盖缺口>20%持续3个月）**：启动"降本增效"模式——缩减Token成本（切换更便宜模型）、暂停非核心功能开发、缩减团队规模，运营成本缩减20%
2. **应急阶段（基金覆盖缺口>40%持续6个月）**：启动"最小化运营"模式——仅保留免费基础功能+危机干预SOP+医生志愿者服务，暂停所有付费医生服务和非核心功能；全员降薪30%（核心团队不领薪）；紧急向备选基金会申请资助
3. **转型阶段（储备金仅剩3个月）**：启动"公益托管"转型——将心伴捐赠给公益基金会/高校心理学院运营，核心团队转为志愿维护；或寻求被大型公益基金会吸收为专项基金，确保用户服务不中断
4. **退出阶段（资金耗尽）**：提前30天通知所有用户，导出用户数据（用户自主下载），安全销毁L2敏感数据，关闭服务

**关键资源**：至少6个月运营储备金；公益基金会/高校合作备忘录（提前签署意向协议）；用户数据导出工具

#### 应急预案3：重大危机事件（用户自杀/自残身亡）

**应急步骤**：
1. **T+0**：封存该用户全部对话记录和系统日志；通知危机审核主管和法务团队
2. **T+2h**：向公司决策层汇报；启动法律风险评估
3. **T+24h**：配合警方调查；向家属表达哀悼（由律师审核措辞）
4. **T+72h**：完成事故复盘报告；检查SOP执行缺陷
5. **T+7天**：优化危机识别模型和SOP；向全员通报复盘结论
6. **舆情应对**：2小时内发布官方声明；不主动公开用户隐私
