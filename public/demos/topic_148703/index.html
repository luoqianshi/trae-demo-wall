01

立项与铁律

为什么是 Godot × Rurix

GRX = Godot / Rurix 工程集成里程碑:验证一个自研 GPU 语言/编译器栈,能否进入生产级引擎的真实渲染帧。靶场:Godot 4.7-dev · Windows D3D12 · Forward+。

为什么选它当靶场

  • 生产级真实渲染器,不是 toy demo:Forward+ 聚簇光照、TAA、SSAO、体积雾、GPU 粒子——有足够多「值得替换」的 GPU pass。
  • D3D12 后端与 Rurix 的 DXIL 目标同栈:原生 ID3D12Resource* 句柄直接跨 C ABI 传递,无翻译层损耗。
  • 4.7-dev 快照可 patch、可复现构建:源码 ignored 不入库,改动收敛为 41 个 tracked patch——可审计、可重放。

Rurix 要证明什么

  • 自研 GPU 语言与编译器栈(rurixc → DXIL),此前已在 CUDA / D3D12 计算侧落地。
  • 契约目标:经 opt-in 的 rurix_accel 模块加载 rurix_godot.dll,在不删除原生渲染路径的前提下替换高收益 GPU pass。
  • fallback 是稳定性硬边界:缺 DLL、ABI 不符、任一门失败,都必须无损回退原生路径,进程绝不崩。

四步打成「可证据化」地基

前四个子里程碑不写一行加速代码:探明工具链、把模块以 patch 形式立起来、验证加载与回退、搭好基准场景骨架。

GRX-001 · 工具链探针

SCons / MSVC / SDK / DXC / Godot tree 全量探测;缺件输出明确 SKIP 原因;不安装、不改全局工具链——缺 launcher 宁可给 null,也不给一条注定失败的命令。

GRX-002 · 模块脚手架

modules/rurix_accel 以 patch 入栈;规范构建命令固化;本机 MSVC C1001 ICE 用单任务 wrapper 绕过;exe / dll 的 SHA-256 全部归档。

GRX-003 · 加载 / 回退双路冒烟

DLL present 与 missing 两条启动路径都要验证:缺 DLL 时退出码 0 并留下 fallback 日志;此时若反而出现 session-ready 标记,判定失败——回退路径本身也要被证明。

GRX-004+b · 基准骨架真实化

基准生成器 + 7 场景逐场景独立 load evidence(failure_count=0);004b 将负载真实化到 workload v2 / v2.3——门的数学与阈值不变。

// 数学规格;运行时 canonical = DXC 编译的 HLSL 桥,数学须与此等价
kernel fn tonemap_apply_linear_srgb(
    src_color: Texture2D<f32>, dst_color: RWTexture2D<f32>,
    source_width: usize, source_height: usize,
    exposure: f32, white: f32, luminance_multiplier: f32,
    t: ThreadCtx<1>,
) {
    // one thread per RGBA channel lane
    let lane_count = source_width * source_height * 4;
    let lane = t.global_id();
    if lane < lane_count {
        let channel = lane % 4;
        let value = src_color[lane];
        if channel < 3 {
            let scaled = value * luminance_multiplier * exposure;
            let clamped = if scaled < 0.0 { 0.0 } else { scaled };
            let srgb = if clamped < 0.0031308 { 12.92 * clamped }
                else { 1.055 * powf(clamped, 1.0 / 2.4) - 0.055 };
            dst_color[lane] = srgb;               // linear → sRGB
        } else { dst_color[lane] = value; }      // alpha 透传
    }
}

五个 rd_native pass 全部越过 0.95 门槛(0.9906–0.9993)——按设计仍 default disabled,启用是逐项目显式 opt-in。gpu_culling:strict success 且字节级保图,但该 bench 口径下高水位 == 满计数,净 draw 削减为 0——如实记「净零」,不包装成收益。

收官前夜的三场硬仗

gpu_culling 的 device-removal 崩溃墙横跨三代实现,07-13 一夜连破;上游 bug 复现包(2 个 MRP + issue 草稿)已入库,按治理规则待 owner 复核后对外提报。

1上游定罪

  • 三代崩溃统一定罪:D3D12 驱动的 command_clear_buffer 建 RAW UAV 无 16 字节对齐守卫,计数清零偏移 4/24/44 全非对齐。
  • 两个最小复现对照:非对齐 clear 第 1 帧即炸;纯 compute→indirect 300 帧干净——「indirect 双角色」假说被证伪。
  • 修复 R1b:清零改走 buffer_copy(无对齐约束),零 kernel 改动,candidate 腿首次存活。

2高水位计数

  • 字段级复算:frustum 数学全对、逐实例误判 = 0——真凶是结构性局限:InterlockedAdd 计数下 indirect 只画前缀,非前缀可见集被砍。
  • 修复:计数改 InterlockedMax(count, i+1) 高水位,前缀恒覆盖全部可见,永不过度剔除。
  • rb5 终审 13 项检查全绿:max_abs=0 字节级保图,首个 strict success 落档。

3七链同栈全绿

  • R1b 字节变更后,全部七条冒烟链统一重签:gpu_culling + 五 rd_native + fused,全 strict success、全 exit 0。
  • stack identity 对齐同一 patch 栈、同一 exe——GRX 史上首次全 pass 证据基座一致。
  • 这份「同栈同 exe」一致性,是 close-out 材料可信的前提。
