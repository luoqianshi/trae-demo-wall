根本问题
章节2
LLM 推理瓶颈是显存带宽而非算力，投机解码的核心公式与三条提速杠杆
大模型生成慢不是因为 GPU 算力不够，GPU 计算单元大部分时间在摸鱼，真正瓶颈是显存带宽——每生成一个 token 都要把整套模型权重从显存搬到计算单元，90% 时间花在搬数据上。批处理是推理优化的根因（同时解码10个token和1个成本几乎一样）。投机解码用草稿模型一口气拆出候选 token 再送大模型验证。核心公式：单token延迟=（草稿耗时+验证耗时）/接受token数。三条杠杆：拆得更快、猜得更准、验得更快。两条主流路线：①自回归草稿（Ego3/MTP1）准而慢 ②并行草稿（DFlash）快而不准（后缀衰减）。DSpark 基线是已优化的 MTP1，含金量足。
显存带宽瓶颈 90%时间搬数据 拒绝采样机制 MTP1基线
创新1：半自回归架构
章节3
并行骨干打底保速度 + 轻量串行头补准确率，融合两者优势
半自回归分两步：①用 DFlash 当并行骨干，一次前向传播输出所有位置基础 logits（保速度）；②用轻量级串行模块从前往后逐个位置注入前缀依赖偏置，修正概率分布。最终概率=并行骨干基础结果+偏置再归一化。示例：骨干独立预测位置1出"of"、位置2出"problem"，串行头看到位置1采样出"of"后，把位置2概率往"course"上掰、压下"problem"。效果：接受率曲线继承并行方案高起点，后半段几乎无衰减。离线数据：平均接受长度比 Ego3 高 26-31%，比 DFlash 高 16-18%。两层 DSpark 效果就能打过五层 DFlash——加轻量创新依赖比堆并行骨干层数性价比高太多。
并行骨干+串行头 纠错机制 接受长度+26-31% 2层胜5层
创新2：自信度调度
章节4
自信度头打分 + 硬件成本表 + 全局排序，三步实现自适应验证
固定草稿长度的问题：①不同任务差异大（代码猜8个能全中，闲聊猜4个都翻车）②服务器负载会变。DSpark 三步解决：①自信度头给每个草稿位置输出存活概率，训练标签是草稿分布与目标分布的总变分距离，数学上与真实接受率严格对应，静态阈值测试闲聊接受率从45.7%拉到95.7%；②提前测好 GPU 不同 batch 大小下的吞吐曲线做成成本表，调度时把所有请求所有候选 token 按存活概率全局排序，逐个往验证 batch 里加，每加一个算总吞吐量，开始下降就停（调度全在 GPU 内部执行无 CPU 延迟）；③顺序温度缩放后处理校准，从左到右逐位置校准累积存活概率，把原始3-8%校准误差压到1%左右，完全在线动态修正阈值。
自信度头 硬件成本表 GPU内部调度 校准误差3-8%→1%
实验结果
章节5
离线9数据集全面碾压，线上生产环境单用户提速60-85%，高并发吞吐数倍
离线基准测试覆盖数学推理、代码生成、日常聊天三大领域共9个标准数据集，在千问3的4B/8B/14B三个尺寸和JA42B上，DSpark 全面碾压 Ego3 和 DFlash。千问34B上平均接受长度相对 Ego3 提升30%、相对 DFlash 提升18.3%。线上：DSpark 直接部署到 DeepSeek V4 生产引擎，和正式服役的 MTP1 做真实流量对比。帕雷托前沿图显示 DSpark 整条曲线稳稳在基线外侧——同样用户速度能承载更高总吞吐，同样总并发用户感受更快回复。具体：同等吞吐量下单用户生成速度提升60-85%；严格低延迟 SLA 下基线快扛不住时 DSpark 仍稳定，吞吐优势达数倍。负载自适应：低负载放开吃满闲置算力，高负载精准裁剪保吞吐，全程不用人工调参。

根本问题：LLM 推理瓶颈是显存带宽（90% 时间搬权重），非 GPU 算力。
创新1：并行骨干（DFlash）打底保速度 + 轻量串行头注入前缀依赖补准确率，2 层胜 5 层，接受长度比 Ego3 高 26-31%、比 DFlash 高 16-18%。
创新2：自信度头打分（数学对应真实接受率）+ 硬件成本表全局排序 + 顺序温度缩放校准（误差 3-8%→1%），闲聊接受率 45.7%→95.7%，调度全在 GPU 内部无延迟。
实验：9 数据集全面碾压，线上单用户提速 60-85%，严格 SLA 下吞吐优势数倍，负载自适应。
启示：单点技术红利收涨，全链路系统打磨才是体验跃升来源（马斯克风格）。全栈开源支持千问3/JA，DeepSeek 工程优化魔王刻板印象再次印证。
