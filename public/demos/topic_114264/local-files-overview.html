01 · OVERVIEW

为什么需要本地文件管理？

散落的合同、笔记、截图、邮件附件分布在 ~/Downloads、~/Documents、微信文件夹等位置。 KnowledgeForge 自动扫描这些目录，去重、归并、生成结构化笔记，并将原始文件以只读 symlink 替换 —— 既保留原有访问路径，又节省存储空间。

多源目录监听

chokidar 增量监听 + 定时全量扫描兜底。支持本地文件夹、微信、邮件、抖音等多源接入， 统一 RawContent 数据模型。

三层智能去重

SHA-256 精确匹配 → SimHash 模糊匹配 → 语义 embedding 比对。跨源同名文件自动归并到同一版本链 lineageId。

LLM 结构化编译

调用 OpenAI/Anthropic/Ollama 生成 Obsidian 风格 Markdown，五种 PageType（entity/concept/comparison/summary/query）。

Inbox 状态机

追踪每个文件的处理进度

03 · MODULES

功能模块详解

每个模块对应一个 packages/ 下的子包， 严格遵循依赖向下流动：core ← sources/storage/search ← pipeline ← cli/tui。

02

Merge Stage

@knowledge-forge/pipeline

三层合并去重。新文件进入时按顺序尝试精确匹配 → 同名归并 → 模糊匹配，命中即复用 lineageId。

L1
exact-skip · 精确匹配
SHA-256 checksum 相同 → 复用 lineageId，跳过新版本创建（跨源完全相同内容归并）
L2
same-name-new-version · 同名归并
normalizeFilename 一致但 checksum 不同 → 同 lineageId 新版本（合同 v1 与 合同 (1).pdf 归到同一版本链）
L3
fuzzy-merge · 模糊匹配
SimHash 汉明距离 ≤ 阈值 → 归并。基于 cyrb53 64-bit + 中文 3-gram 分词，兼容性保证。
⚠ 知识冲突不静默覆盖：保留双方视图，标记 contested: true，等待人工审核。
03

Extract Stage

@knowledge-forge/pipeline

内容提取与标准化。通过 ContentStandardizer 将 HTML/PDF/DOCX 等格式转为纯文本。

maxFileSize 校验
超限文件跳过并标记不可重试
timeout 超时保护
Promise.race + clearTimeout 防止解析卡死
// 超时保护模式
const result = await this.callWithTimeout(
  () => this.standardizeContent(raw),
  this.extractTimeout,
  raw.sourceId
);

Lint Stage

@knowledge-forge/pipeline

质量校验。构建 IndexEntry / LinkGraph，标记 LintIssue。

  • ✓交叉引用校验：通过 inboundIndex.get(page.title) 准确查找入链
  • ✓标签层级检查：基于 SchemaParser 定义的 tag hierarchy
  • ✓矛盾检测：contradiction strategy 标记冲突页面
  • ✓阈值驱动：每个规则有独立的严重级别与阈值
06

Review Stage

@knowledge-forge/pipeline

人工审核关卡。支持 YOLO 自动确认与手动审核两种模式，敏感文件强制审核。

YOLO 模式
自动确认所有非敏感文件，适合大批量冷启动
手动模式
逐项确认，可编辑 LLM 生成的摘要与标签
敏感文件强制审核
含身份证号、银行卡号、金额、合同号的文件即使在 YOLO 模式下也必须人工确认。正则 不带 g flag 防止 lastIndex 状态导致漏判。

Archive Stage

@knowledge-forge/pipeline

双仓归档。原始文件仓（Git LFS）+ 笔记仓（普通 Git），版本可追溯、可回滚。

by-version 保留最新 N 版本 by-age 保留最近 N 天

Write Stage

04 · SAFETY

安全与一致性保障

本地优先架构下，数据一致性是生命线。以下硬约束在所有路径中严格遵循。

数据主权

  • • 所有数据存储在本地（SQLite + Markdown 文件）
  • • LLM 调用仅发送内容摘要，不持久化到云端
  • • Embedding 本地推理（Xenova/transformers）

冲突处理

  • • 知识冲突不静默覆盖，保留双方视图
  • • 标记 contested: true 等待人工审核
  • • 文件变更通过 mtime + checksum 双判定

原子性与事务

  • • .meta.json 使用 write-temp-rename 原子写
  • • 多步 SQLite 操作包裹 withTransaction
  • • PRAGMA foreign_keys = ON + ON DELETE CASCADE
  • • PRAGMA busy_timeout = 5000 防并发冲突

资源管理

  • • pendingFiles Map 限制 1000 条防内存泄漏
  • • 冷启动 30 分钟超时 + 分批处理（mtime-desc + size-asc 排序）
  • • CLI 优雅关闭：SIGINT/SIGTERM 释放连接
  • • 版本保留上限：maxVersionsPerLineage
