KnowledgeForge

知识熔炉 · 本地优先的多源知识管理系统

本地存储 LLM 编译 Obsidian 兼容 多源接入 版本管理 全文 + 语义搜索 Gitea 同步

1这是什么

把散落在各处的文件（本地、微信、邮件、抖音）汇聚起来，用 LLM 编译成结构化的 Obsidian 笔记，并追踪版本与来源。

📥

多源接入

本地文件、微信聊天记录、邮件 .eml、抖音视频字幕，统一进入收件箱等待处理。

🤖

LLM 编译

调用 OpenAI/Anthropic/Ollama，把原始内容编译成带 frontmatter、交叉引用的结构化 Markdown。

🔑

数据主权

所有数据存在本地 SQLite + 文件系统，不依赖云端。Gitea 同步可选。

🧬

版本与去重

SHA-256 精确去重 + SimHash 模糊指纹，跨源同名归并，保留版本链而非覆盖。

🔍

多维搜索

FTS5 全文 + MiniLM 本地嵌入语义搜索 + 混合检索 + LLM 深度研究。

🔄

Gitea 同步

把 Obsidian Vault 纳入 Git 版本管理，推送到自托管 Gitea，大文件走 LFS。

3五步上手

从零到拥有一个可搜索的知识库，只需五步。

1

安装依赖

需要 Node.js ≥ 22（用内置 node:sqlite）和 pnpm。

# 检查 Node 版本（需 ≥ 22）
node -v

# 安装依赖
pnpm install

# 构建所有包
pnpm build
2

初始化知识库

创建 ~/.knowledge-forge/ 目录、配置文件和数据库。

node packages/cli/dist/cli.js init

# 输出：
✔ 知识库初始化完成
✓ 知识库已创建
  配置文件: ~/.knowledge-forge/config.yaml
  数据库: ~/.knowledge-forge/knowledge.db

编辑 ~/.knowledge-forge/config.yaml 配置数据源路径、LLM、Gitea 等（见第 5 节）。

3

导入文件

把文件送入收件箱。支持本地文件、邮件、微信、抖音四种数据源。

# 导入单个文件
node packages/cli/dist/cli.js ingest -u /path/to/note.md

# 导入邮件目录
node packages/cli/dist/cli.js ingest -s email

# 导入微信聊天记录
node packages/cli/dist/cli.js ingest -s wechat

# 导入抖音视频字幕（需 yt-dlp）
node packages/cli/dist/cli.js ingest -s douyin -u https://douyin.com/xxx

# 查看收件箱
node packages/cli/dist/cli.js inbox --stats
node packages/cli/dist/cli.js inbox --list
4

LLM 编译

调用 LLM 把原始内容编译成结构化 Obsidian 页面（需配置 LLM API Key）。

# 编译所有待处理版本
node packages/cli/dist/cli.js compile

# 全量重建（忽略已编译）
node packages/cli/dist/cli.js compile -r

# 输出：
✔ 找到 3 个待编译版本
✔ 调用 LLM 编译（可能耗时较长）...
✓ 编译完成: 3 成功

编译后会在 Obsidian Vault 生成 .md 文件，并自动建立搜索索引。

5

搜索知识

四种搜索模式：全文、语义、混合、深度研究。

# 全文搜索
node packages/cli/dist/cli.js search "数据治理"

# 语义搜索（首次会下载 MiniLM 模型，约 80MB）
node packages/cli/dist/cli.js search "如何管理组织知识" -s

# 混合搜索（全文 + 语义）
node packages/cli/dist/cli.js search "SimHash 去重" -a

# 深度研究（LLM 多步推理）
node packages/cli/dist/cli.js search "对比各类哈希算法" -r

4CLI 命令参考

二进制名 kf，共 11 个命令。运行 node packages/cli/dist/cli.js --help 查看。

命令 说明 常用参数
init 初始化知识库 —
ingest 从数据源导入文件到收件箱 -u <path> 单文件 · -s <source> 数据源（local/email/wechat/douyin）
compile LLM 编译为结构化页面 -r 全量重建
search <query> 搜索知识库 -l <n> 数量 · -s 语义 · -a 混合 · -r 深度研究
lint 质量审查（断链、孤立、矛盾） —
stats 查看知识库统计 —
config 查看当前配置 —
inbox 收件箱管理 -l 列表 · -s <status> 过滤 · -a <id> 归档 · -r <id> 重试 · --stats 统计
sync Gitea 同步 -p 推送 · -l 拉取 · -s 状态
history [file] 查看提交历史 -l <n> 数量
merge 跨源归并近似重复 -n 预览不写入

5关键配置

配置文件位于 ~/.knowledge-forge/config.yaml，关键部分如下。

Vault 路径

vault:
  path: ~/Documents/Obsidian Vault   # Obsidian 库目录
  schemaPath: SCHEMA.md
  indexPath: index.md

LLM（编译用）

llm:
  provider: openai              # openai | anthropic | local
  model: gpt-4o-mini
  apiKey: env:OPENAI_API_KEY     # 从环境变量读取
  maxTokens: 2000
  temperature: 0.3
  embedding:
    provider: local             # 本地 MiniLM，无需 API
    model: Xenova/all-MiniLM-L6-v2

数据源

sources:
  - type: local
    enabled: true
    config:
      watchPaths: [~/Documents/待整理, ~/Downloads/知识文件]
      ignorePatterns: ["*.tmp", ".DS_Store"]
      maxFileSize: 52428800       # 50MB

  - type: douyin
    enabled: false
    config:
      extractSubtitles: true
      outputFormat: txt

Gitea 同步（可选）

git:
  enabled: false                # 设为 true 启用
  giteaUrl: https://git.example.com
  username: your-username
  token: env:GITEA_TOKEN         # 从环境变量读取
  repo: knowledge-vault
  branch: main
  lfs: true                     # 大文件走 LFS

6典型工作流

日常使用的三个核心场景。

📚

日常积累

把感兴趣的文件丢进 watchPaths，运行 kf ingest + kf compile，LLM 自动整理成结构化笔记。

kf ingest -u note.md
kf compile
kf search "主题" -a
🔀

跨源归并

同一份资料从微信、邮件、本地多处收到，SimHash 自动识别近似重复。

kf merge --dry-run     # 预览
kf merge               # 执行归并
☁️

多端同步

编译完成后推送到自托管 Gitea，其他设备拉取即可。

kf sync -s             # 查看状态
kf sync -p             # 推送
kf history             # 历史

7开发命令

pnpm monorepo，8 个包（core/sources/storage/search/vault-git/pipeline/cli/tui）。

# 全量构建 / 测试 / lint
pnpm build
pnpm test
pnpm lint

# 单包开发（watch 模式）
pnpm --filter @knowledge-forge/pipeline dev

# 运行单个测试
pnpm --filter @knowledge-forge/search test -- v2

# 清理所有 dist
pnpm clean

包依赖方向：core ← sources/storage/search/vault-git ← pipeline ← cli/tui。
新增功能时实现已有接口并从 src/index.ts 导出，不要引入平行抽象。
