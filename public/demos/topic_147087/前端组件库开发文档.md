# 事刻·渊 V0.4 前端组件库开发文档

> 版本：V0.4
> 目标：从零构建可独立开发、独立测试、独立复用的前端组件库
> 核心原则：**Headless 核心 + 样式外部化 + 状态驱动 + 事件通信**

---

## 一、概述

### 1.1 为什么需要组件库

V0.3 的全部叙事视图逻辑集中在单个 HTML 文件内，节点渲染、画布操作、编辑功能、焦点模式、连线绘制全部耦合在一起。导致：

- 改一处样式牵动全局
- 无法单独测试节点交互
- 无法复用组件到新视图
- 亮点功能（焦点模式、一镜到底）被埋藏在大量 DOM 操作代码中
- 开发进入瓶颈，越写越困难

V0.4 采用**从组件库出发、自底向上**的构建策略：先建好可靠的底层基座，再逐层组装视图。

### 1.2 技术约束

| 约束项 | 要求 |
|--------|------|
| 框架 | 纯原生 JavaScript（ES6 Class），不引入 React / Vue / Angular |
| 依赖 | **零外部依赖**。不使用 D3.js，SVG 连线用原生 API |
| 样式 | 纯 CSS 文件 + Design Tokens（CSS 变量）+ BEM 命名 |
| 样式选择器 | 优先使用 `[data-role]` 属性选择器 + `[data-state]` 状态属性 |
| 浏览器 | Chrome 120+ / Edge 120+ / Safari 17+ |
| 响应式 | 桌面端（≥769px）多列，移动端（≤768px）单列 |

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **Headless Core** | 组件只输出语义化 DOM 骨架，不内嵌样式、不写死 class |
| **Theme Adapter（Bridge 模式）** | 样式通过映射层注入：组件输出语义 → ThemeAdapter 生成类名 → CSS 命中 |
| **Observer 驱动** | 状态变化自动广播，视图被动响应，不主动轮询 |
| **语义化数据接口** | DOM 通过 `data-role`（角色）+ `data-state`（状态）+ `data-node-id` 等属性与 CSS / JS 通信 |
| **设计模式落地** | Bridge、Observer、Singleton、Composite、Decorator 组合应用 |
| **单一数据源** | 所有数据读写走 DataStore，不存在多个全局变量各自维护一份数据 |
| **组件自行管理生命周期** | 每个组件提供 `create()` / `destroy()` 方法，负责自己的 DOM 创建和清理 |

### 1.4 架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                      入口页 (app.html)                       │
│              路由：News → Detail → Canvas                    │
├─────────────────────────────────────────────────────────────┤
│                      视图组件层 (Views)                      │
│      NewsView / EventDetailView / OneTakeTransition         │
│             （OneTakeTransition 可降级为 fade 过渡）          │
├─────────────────────────────────────────────────────────────┤
│                      画布组件层 (Canvas)                     │
│   NarrativeCanvas / TimelineColumn / TimeAxis                │
│   ConnectionLayer / FocusMode / EasyConnect                 │
├─────────────────────────────────────────────────────────────┤
│                      节点组件层 (Nodes)                      │
│   EventNodeCard / NodeToolbar / NodeHandle                  │
│   NodeDetail（只读展示） / NodeEditor（编辑表单）           │
├─────────────────────────────────────────────────────────────┤
│                       UI 组件层 (UI)                         │
│    TimelineSelector / TimelineCreator / ModifiedBadge         │
│         RelationManager / ExportImportPanel                  │
├─────────────────────────────────────────────────────────────┤
│                      核心逻辑层 (Core)                       │
│   EventEmitter（通信基座） → DataStore / CanvasState         │
│   RelationIndex / MdAdapter                                 │
├─────────────────────────────────────────────────────────────┤

数据流方向：
```
.md 文件 → [MdAdapter] → DataStore → 组件读取渲染
                         CanvasState → 组件订阅状态
用户交互 → 组件 emit 事件 → CanvasState / DataStore 处理 → 广播 → 其他组件响应
```

## 二、核心逻辑层（Core）

核心层是整个组件库的底座，所有上层组件都依赖它。它只处理数据、状态、通信，**不操作 DOM**。

---

### 2.0 EventEmitter（通信基座）

#### 干嘛的

`EventEmitter` 是所有需要事件通信的组件的**共享基类**。DataStore、CanvasState 和所有视图组件都继承它，提供统一的 `on()` / `off()` / `emit()` 接口。

#### 为什么这么设计

- **统一通信协议**：不再每个组件自己写一套事件机制，全部继承 EventEmitter
- **便于调试**：任何地方的事件触发和订阅遵循同一套接口
- **轻量**：约 30 行代码，无需外部库

#### 接口定义

```js
class EventEmitter {
  on(event, handler)       // 订阅事件，返回解绑函数
  off(event, handler)      // 取消订阅
  emit(event, data)        // 触发事件
}
```

#### 使用方式

```js
class DataStore extends EventEmitter {
  updateNode(nodeId, changes) {
    // ...数据更新逻辑...
    this.emit('node:changed', { nodeId, node });
  }
}

const store = DataStore.getInstance();
store.on('node:changed', ({ nodeId, node }) => {
  console.log('节点已更新:', nodeId);
});
```

```js
window.TT.Events = Object.freeze({

  FOCUS_EXITED: 'focusExited',

  COLUMN_REMOVED: 'columnRemoved',
  ZOOM_CHANGED: 'zoomChanged',
  CONNECT_ENTERED: 'connectEntered',
  CONNECT_EXITED: 'connectExited',
});
```

### 2.1 DataStore（数据仓库）

#### 干嘛的

`DataStore` 是整个应用的**唯一数据源**（Singleton），持有所有节点、事件线数据。上层组件不直接操作原始数据对象，全部通过它读写。

#### 为什么这么设计

- **单一数据源**：避免全局变量分散在各处导致状态不一致
- **数据一致性**：写入操作自动触发订阅回调，所有订阅者同步更新
- **变更追踪**：内置修改标记，导出时只需导出已修改的文件
- **数据保护**：读取接口返回浅冻结副本，防止上层组件绕过 API 直接篡改数据

#### 接口定义

```js
class DataStore extends EventEmitter {
  static getInstance()

  // === 读取（返回浅冻结副本） ===
  getNode(nodeId)              // → Node | null
  getAllNodes()                // → Node[]
  getTimeline(timelineId)      // → Timeline | null
  getAllTimelines()            // → Timeline[]
  getRelationsOf(nodeId)       // → RelationEntry[]

  // === 写入 ===
  updateNode(nodeId, changes)            // → boolean
  createNode(nodeData)                   // → string（新 nodeId）
  deleteNode(nodeId)                     // → boolean

  // === 事件线操作 ===
  addNodeToTimeline(nodeId, timelineId, index)          // → boolean
  removeNodeFromTimeline(nodeId, timelineId)            // → boolean
  reorderNodeInTimeline(timelineId, nodeId, newIndex)   // → boolean
  moveNodeToTimeline(nodeId, fromTlId, toTlId, newIndex)// → boolean

  // === 关联操作（V0.5：全局关系图） ===
  addRelation(relation)                              // → boolean（relation: { fromNodeId, toNodeId, targetTimelineId?, label }）
  removeRelation(fromNodeId, toNodeId)               // → boolean
  updateRelation(fromNodeId, toNodeId, changes)      // → boolean
  getRelationsOf(nodeId)                             // → Relation[]
  loadRelations(relationsArray)                      // → void（初始化时批量注入全局关系）

  // === 变更追踪 ===
  getModifiedNodes()            // → Node[]
  getModifiedTimelines()        // → Timeline[]
  markModifiedNode(nodeId)      // → void（手动标记节点为 dirty，nodomEditor save 时调用）
  markModifiedTimeline(tlId)    // → void（手动标记事件线为 dirty）
  clearModified()               // → void

  // === 批量加载 ===
  loadNodes(nodesMap)           // → void（初始化时批量注入全局事件池）
  loadTimelines(timelinesMap)   // → void（初始化时批量注入事件线视图）
}
```

#### 错误处理约定

- 所有写入方法返回 `boolean`：成功 `true`，失败 `false`
- 失败时通过 `console.warn()` 输出原因，**不抛异常**
- `getNode('不存在的ID')` 返回 `null`
- `updateNode('不存在的ID', {})` 返回 `false`

#### 数据保护约定

`getNode()` / `getAllNodes()` 返回的是**浅冻结副本**（`Object.freeze` 包装）。修改节点必须通过 `updateNode()`。

```js
const node = store.getNode('by-seed');
node.title = '新标题';           // ❌ 静默失败（frozen object）
store.updateNode('by-seed', { title: '新标题' }); // ✅ 正确
```

### 2.2 CanvasState（画布状态机）

#### 干嘛的

`CanvasState` 是叙事视图的**状态总控**（Singleton），管理当前模式、选中节点、焦点链、活跃列、缩放、滚动等所有与「视图状态」相关的数据。

#### 为什么这么设计

- **状态驱动视图**：状态变化自动通知订阅者，不需要手动调用 `renderXxx()`
- **模式互斥**：`view` / `edit` / `focus` 三种模式自动处理交叉清理（如退出编辑模式时自动清理选中节点和连接模式）
- **后续可扩展 Command 模式**：状态快照机制为撤销/重做预留接口

#### 接口定义

```js
class CanvasState extends EventEmitter {
  static getInstance()

  // === 模式 ===
  setMode(mode)           // 'view' | 'edit' | 'focus'
  getMode()               // → string

  // === 节点选择 ===
  selectNode(nodeId, nodeEl)   // → void（仅编辑模式生效）
  deselectNode()               // → void
  getSelectedNode()            // → { nodeId, nodeEl } | null

  // === 事件线列 ===
  addTimelineColumn(timelineId)     // → void
  removeTimelineColumn(timelineId)  // → void
  getActiveTimelineIds()            // → string[]

  // === 焦点模式 ===
  enterFocusMode(nodeId)      // → void
  exitFocusMode()             // → void
  getFocusChain()             // → { nodeIds, relationIds, centerNodeId } | null

  // === 缩放 ===
  setZoom(zoom)               // → void（0.3 ~ 3.0，自动钳制）
  getZoom()                   // → number

  // === 关联连接模式 ===
  enterConnectMode(fromNodeId, fromTimelineId)  // → void
  exitConnectMode()                              // → void
  getConnectMode()                               // → { fromNodeId, fromTimelineId } | null

  // === 订阅（继承自 EventEmitter） ===
  on(event, handler)          // → 解绑函数，按事件名订阅
  off(event, handler)         // → void
  subscribe(callback)         // → 语法糖 = on('*', callback)，监听全部事件
}
```

#### 事件类型

```
modeChanged     → { mode, prevMode }
nodeSelected    → { nodeId, nodeEl }
nodeDeselected  → {}
focusEntered    → { centerNodeId, focusChain }
focusExited     → {}
columnAdded     → { timelineId }
columnRemoved   → { timelineId }
zoomChanged     → { zoom }
connectEntered  → { fromNodeId }
connectExited   → {}
```

#### on() 与 subscribe() 的分工

| 方法 | 适用场景 | 示例 |
|------|----------|------|
| `on(event, handler)` | 只关心**单个事件**的组件 | `canvasState.on(TT.Events.MODE_CHANGED, ({mode}) => {...})` |
| `subscribe(callback)` | 需要统筹**所有事件**的根组件 | 如 NarrativeCanvas 内部，通过 `switch(event.type)` 分发子组件更新 |

`subscribe()` 本质是 `on('*', callback)` 的语法糖，回调参数为 `{ type, ...具体字段 }`。两者的解绑函数用法相同。

### 2.3 MdAdapter（MD 适配器）

#### 干嘛的

`MdAdapter` 封装 `md-store.js`，负责 `.md` 文件与 `DataStore` 内存对象之间的**双向转换**，以及数据的加载、导入、导出。

#### 为什么这么设计

- **隔离解析细节**：上层组件不需要知道 YAML frontmatter 怎么解析
- **统一数据入口**：加载、保存、导入、导出都走这里
- **便于替换存储**：后续如果改用 IndexedDB 或其他存储，只需替换这一个模块

#### 接口定义

```js
class MdAdapter {
  async loadFromFiles(fileList, manifestPath)  // 加载所有 .md 文件并注入 DataStore
  parseNodeMarkdown(mdString)                  // → Node（委托给 md-store.js）
  parseTimelineMarkdown(mdString)              // → Timeline（委托给 md-store.js）
  serializeNode(node)                          // → mdString
  serializeTimeline(timeline)                  // → mdString
  exportModified()                             // → Blob[]
  exportAll()                                  // → Blob[]
  importFiles(files)                           // → Promise<void>
}
```

#### 数据加载方案

由于使用本地文件系统 + `server.ps1` 本地服务器，不需要 `manifest.json` 手动维护文件清单。

**方案**：在 HTML 入口中维护一个**硬编码的文件名列表**。

```js
const NODE_FILES = ['ft-1', 'ft-2', 'ft-3', /* ... */];
const TIMELINE_FILES = ['tl-demo-main', 'tl-demo-side'];

// 逐个 fetch
for (const id of NODE_FILES) {
  const resp = await fetch(`/nodes/${id}.md`);
  const mdStr = await resp.text();
  const node = parseNodeMarkdown(mdStr);
  store.loadNodes({ [node.id]: node });
}
```

演示数据量小（~40 个节点），硬编码维护成本可接受。后续数据量增长后可接入自动目录扫描。

### 2.4 RelationIndex（关联索引）

#### 干嘛的

`RelationIndex` 由所有事件线的 `relations` 字段构建，提供**双向关联查询**。

#### 为什么这么设计

- **关系存在事件线中**：节点文件不存储关联，关联全部在事件线文件里
- **频繁查询**：焦点模式、连线渲染、关联管理都需要查某个节点的所有关联
- **索引加速**：构建 `{ nodeId: [relations] }` 反向索引，避免每次遍历所有事件线
- **双向索引**：A → B 的关系，同时写入 A 和 B 的索引条目，确保从任意端都能查到

#### 接口定义

```js
class RelationIndex {
  static getInstance()
  getRelationsOf(nodeId)         // → RelationEntry[]
  getFocusChain(nodeId)          // → { nodeIds: Set, relationIds: Set }（递归一层）
  rebuild()                      // → void（DataStore 变更后调用）
}
```

## 三、节点组件层（Nodes）

节点层负责「事件」这个最小叙事单元的展示与交互。所有组件遵循 **Bridge 模式**：逻辑与样式分离。组件只输出语义化 DOM。

---

### 3.1 EventNodeCard（节点卡片）

#### 干嘛的

`EventNodeCard` 是最基础的展示单元，负责渲染一个事件节点的全部信息：时间、标题、摘要、重要性边框、关联标记、分支徽章、版本号等。

#### 为什么这么设计

- **最小复用单元**：资讯首页、叙事视图、分支列、焦点模式都复用同一个组件
- **Bridge 解耦**：卡片只输出 `data-role` 和 `data-state` 属性，样式完全由外部 CSS 控制
- **状态通过 props 传入**：不内部维护状态，所有状态（selected、edited、mode、inFocusChain）由父组件传入

#### 输入参数

```ts
interface EventNodeCardOptions {
  nodeId: string;
  timelineId: string;       // 当前所属事件线
  state: {
    selected: boolean;
    edited: boolean;        // 是否被编辑过（未保存标记）
    mode: 'view' | 'edit' | 'focus';
    inFocusChain: boolean;
  };
}
```

#### 语义结构输出

```html
<div data-role="node-card" data-node-id="by-seed" data-timeline-id="tl-bd-main"
     data-importance="breakthrough" data-state="selected edited">
  <div data-role="node-date">2023-02-15</div>
  <div data-role="node-title">Seed 团队成立</div>
  <div data-role="node-summary">字节组建大模型研发团队...</div>
  <div data-role="node-tags">
    <span data-role="node-tag" data-tag-type="person">朱文佳</span>
  </div>
  <span data-role="relation-dot"></span>
  <div data-role="edited-dot"></div>
</div>
```

#### 暴露事件

| 事件名 | 参数 | 触发时机 |
|--------|------|----------|
| `select` | `{ nodeId, el }` | 编辑模式下单击 |
| `detail` | `{ nodeId }` | 查看模式下单击 |
| `focus` | `{ nodeId }` | 双击 |
| `dragstart` | `{ nodeId, el }` | 开始拖拽 |
| `dragend` | `{ nodeId }` | 拖拽结束 |
| `connectStart` | `{ nodeId, timelineId, startPos }` | 从关联手柄按下拖拽 |

#### 使用方式

```js
const card = EventNodeCard.create({
  nodeId: 'by-seed',
  timelineId: 'tl-bd-main',
  state: { selected: false, edited: false, mode: 'view', inFocusChain: false }
});

container.appendChild(card.el);

card.on('select', ({ nodeId, el }) => canvasState.selectNode(nodeId, el));
card.on('detail', ({ nodeId }) => NodeDetail.show(nodeId));
card.on('focus', ({ nodeId }) => canvasState.enterFocusMode(nodeId));
```

### 3.2 NodeToolbar（节点浮动工具栏）

#### 干嘛的

`NodeToolbar` 是节点被选中后浮现的操作面板，提供五个功能按钮：编辑、关联、聚焦、移出、删除。

#### 为什么这么设计

- **编辑模式专属**：仅在编辑模式下出现，通过订阅 `CanvasState` 的 `nodeSelected` / `nodeDeselected` 事件自动显隐
- **浮动定位**：自动计算节点位置，上方优先，空间不足时放下方，左右边界自动避开
- **内置行为 + 可扩展**：聚焦、移出、删除在工具栏内部直接执行，编辑和关联通过事件委托给外部

#### 暴露事件

| 事件名 | 参数 | 说明 |
|--------|------|------|
| `editRequest` | `{ nodeId }` | 点击编辑按钮，外部打开 NodeEditor |
| `connectRequest` | `{ nodeId }` | 点击关联按钮，外部进入连接模式 |

#### 使用方式

```js
const toolbar = NodeToolbar.getInstance();

toolbar.on('editRequest', ({ nodeId }) => NodeEditor.open(nodeId));
toolbar.on('connectRequest', ({ nodeId }) => canvasState.enterConnectMode(nodeId, ...));
```

### 3.3 NodeHandle（关联拖拽手柄）

#### 干嘛的

`NodeHandle` 是节点卡片右边缘的橙色小圆点，用户从此处拖拽临时连线到另一个节点以建立关联。

#### 为什么这么设计

- **显式入口**：关联创建必须有明确的视觉触发点，不能是隐藏手势
- **拖拽三阶段**：`dragstart`（显示预览线起点）→ `dragmove`（更新预览线 + 高亮目标）→ `dragend`（落点判断 + 弹出关联表单）
- **仅编辑模式出现**：`data-role="node-handle"` 元素只在编辑模式渲染

#### 使用方式

```js
const handle = NodeHandle.create(cardEl, {
  nodeId: 'by-seed',
  timelineId: 'tl-bd-main'
});

handle.on('dragstart', (e) => EasyConnect.start(e));
handle.on('dragmove', (e) => EasyConnect.update(e));
handle.on('dragend', (e) => EasyConnect.end(e));
```

### 3.4 NodeDetail（节点详情面板）

#### 干嘛的

`NodeDetail` 是点击节点后弹出的**只读信息面板**，展示事件的完整信息：重要性徽章、标题、时间、摘要、备注、来源、关联列表、所属事件线列表等。

#### 为什么这么设计

- **信息分层**：卡片只展示摘要，详情面板展示全部信息
- **只读展示**：不提供编辑能力。编辑功能由 NodeEditor 独立负责
- **响应式**：桌面端居中浮动卡片（380px），移动端底部抽屉（Sheet）

#### 使用方式

```js
const detail = NodeDetail.getInstance();

detail.show('by-seed');

detail.on('editClick', ({ nodeId }) => {
  detail.hide();
  NodeEditor.open(nodeId);
});
```

### 3.5 NodeEditor（节点编辑器）

#### 干嘛的

`NodeEditor` 是独立的节点编辑面板，提供全量表单字段。与 NodeDetail 是两个独立的组件，通过事件通信。

#### 为什么这么设计

- **独立组件**：编辑器有自己的生命周期、表单验证逻辑、保存/取消按钮，不与详情面板耦合
- **即时预览 + 快照回滚**：字段变更即时写入 DataStore 实现实时预览效果；同时在 `open()` 时深拷贝原始数据到内部 `_snapshot`，用户点 cancel 时用快照覆盖回 DataStore，保证数据可恢复
- **未保存标记**：save 确认后标记该节点为 dirty，顶部徽章自动更新

#### 快照回滚机制

```js
class NodeEditor {
  constructor() {
    this._snapshot = null; // 打开时保存的原始数据快照
  }

  open(nodeId) {
    const node = store.getNode(nodeId);
    this._snapshot = JSON.parse(JSON.stringify(node)); // 深拷贝快照
    this._currentNodeId = nodeId;
    // 渲染表单...
  }

  // fieldChange → 即时写入 DataStore（实时预览）
  _onFieldChange(field, value) {
    store.updateNode(this._currentNodeId, { [field]: value });
  }

  // save → 确认快照，标记 dirty
  _onSave(data) {
    store.updateNode(this._currentNodeId, data);     // 最终写入
    store.markModifiedNode(this._currentNodeId);            // 标记未保存
    this._snapshot = null;
    this.emit('save', { nodeId: this._currentNodeId, data });
  }

  // cancel → 用快照覆盖 DataStore，恢复原始数据
  _onCancel() {
    if (this._snapshot) {
      store.updateNode(this._currentNodeId, this._snapshot);
    }
    this._snapshot = null;
    this.emit('cancel', { nodeId: this._currentNodeId });
  }
}
```

#### 表单字段

```
title（text）      | 标题
startTime（date）  | 开始时间
endTime（date）    | 结束时间（可选）
importance（select）| breakthrough / important / minor
summary（textarea） | 摘要正文
note（textarea）    | 备注
tags（动态键值对）  | 标签
source（text）      | 来源
versionNumber / versionTag / changelog（特定版用）
```

#### 使用方式

```js
const editor = NodeEditor.getInstance();

editor.open('by-seed');

editor.on('save', ({ nodeId, data }) => {
  store.updateNode(nodeId, data);
  canvasState.notify({ type: 'nodeEdited', nodeId });
});

editor.on('cancel', () => {
  // 不保存，丢弃修改
});
```

### 4.4 ConnectionLayer（连线层）

#### 干嘛的

#### 为什么这么设计

- **纯原生 SVG**：不使用 D3.js，用 `document.createElementNS` + 手动计算贝塞尔路径
- **分层渐进显示**：默认隐藏减少视觉干扰 → 悬浮/长按时高亮当前节点关联 → 焦点模式全显关联链

const connLayer = ConnectionLayer.create({

connLayer.renderFocusChain(focusChain);    // 焦点模式渲染
connLayer.clear();                         // 隐藏所有
```

### 4.5 FocusMode（焦点模式）

#### 干嘛的

点击关联标记后，将关联链上的所有节点压缩到一屏内展示，无关节点模糊处理。这是大赛演示的核心亮点功能。

#### 交互流程

1. 点击节点关联标记 → 进入焦点模式
2. **前置检查**：查找关联链上所有节点所在的事件线，对尚未展开的事件线 **自动调用 `canvas.addColumn()`** 展开
3. 关联链节点（当前节点 + 一层关联）**压缩到一屏内**
4. 无关节点 `filter: blur(4px)` + `opacity: 0.2` + `pointer-events: none`
5. 关联连线全部显示，高亮加粗，标注文字可见
6. 时间轴刻度压缩，保留真实时间标注
7. ESC 或点击空白处 → 退出焦点模式，恢复原状

#### 自动展开目标列逻辑

```js
// FocusMode.enter(nodeId) 内部前置步骤：
enter(nodeId) {
  const focusChain = RelationIndex.getInstance().getFocusChain(nodeId);

  // 1. 找出关联链上所有节点所在的事件线
  const store = DataStore.getInstance();
  const allTimelines = store.getAllTimelines();
  const affectedTimelineIds = new Set();
  focusChain.nodeIds.forEach(nid => {
    allTimelines.forEach(tl => {
      if (tl.nodes.some(n => n.nodeId === nid)) affectedTimelineIds.add(tl.id);
    });
  });

  // 2. 对每个尚未展开的事件线，自动添加列
  const state = CanvasState.getInstance();
  affectedTimelineIds.forEach(tlId => {
    if (!state.getActiveTimelineIds().includes(tlId)) {
      state.addTimelineColumn(tlId); // 触发 columnAdded 事件，画布自动渲染新列
    }
  });

  // 3. 等待列渲染完成后再执行压缩布局和高亮连线
  requestAnimationFrame(() => this._compressAndHighlight(focusChain));
}

#### 压缩算法 + 边界处理

```js
// 收集焦点节点原始位置
const focusNodes = getFocusNodePositions();
const span = maxY - minY;
const targetSpan = viewportHeight * 0.55;
const scaleY = targetSpan / span;

// 关键：加下限保护
const clampedScale = Math.max(0.12, Math.min(1, scaleY));
// 若关联链有 20+ 节点导致压缩比过大（<0.12），改为自动平滑滚动方案

allNodes.forEach(node => {
  node.el.style.transform = `translateY(${offset}px) scaleY(${clampedScale})`;
});
```

### 4.6 EasyConnect（关联创建器）

#### 干嘛的

`EasyConnect` 实现从节点 A 拖拽到节点 B 建立关联的完整交互流程。

#### 交互流程

1. 从 NodeHandle 拖出 → SVG 覆盖层绘制贝塞尔预览线（橙色虚线）
2. 拖拽中 → 鼠标划过节点时高亮该节点，表明可落点
3. 释放到目标节点 → 弹出关联建立表单
4. 表单字段：关系名（自由文本）、方向（→/← radio）、目标事件线（必选 select）、关系说明（可选 textarea）
5. 保存 → 关系写入 DataStore，连线以虚线表示「未保存到磁盘」
6. 独立事件例外：目标不在任何事件线时，不显示事件线下拉

### 5.3 OneTakeTransition（一镜到底动画）

#### 干嘛的

`OneTakeTransition` 实现从事件详情页到叙事视图的「一镜到底」动画过渡。

#### 为什么标记为可降级

这是整组件库中技术复杂度最高的模块。如果实现困难，可以退化为简单的 **fade 过渡**（详情页淡出 → 叙事视图淡入），不影响核心功能。

#### 三阶段动画（目标形态）

| 阶段 | 描述 | 时长 | 缓动 |
|------|------|------|------|
| 1 | 详情页卡片缩减至节点位置 | 400ms | ease-spring |
| 2 | 主题色从详情页流到节点 | 500ms | ease-out |
| 3 | 其他事件线列从两侧滑入 | 400ms | ease-out |

#### 降级方案

```js
if (OneTakeTransition.supported()) {
  OneTakeTransition.start({ fromNodeId, targetTimelineId, onComplete });
} else {
  // 降级：简单 fade
  fadeOut(detailView, 300, () => {
    canvas.loadTimeline(targetTimelineId);
    canvas.scrollToNode(fromNodeId);
    fadeIn(canvasView, 300);
  });
}
```

## 九、开发规范

### 9.1 组件编写规范

1. **Headless 原则**：组件代码中禁止出现 `style=`、禁止硬编码 `className`
2. **语义输出**：DOM 通过 `data-role` 标识角色、`data-state` 标识状态
3. **事件通信**：所有组件继承或组合 EventEmitter，统一用 `.on()` / `.emit()` 通信
4. **状态订阅**：组件通过 `CanvasState.on(event, handler)` 或 `CanvasState.subscribe(callback)` 响应状态变化，不主动轮询
5. **销毁清理**：组件提供 `destroy()` 方法，移除事件监听、解绑订阅、移除 DOM
6. **单一数据源**：所有数据读写走 `DataStore`，禁止直接操作原始数据对象

### 9.2 样式编写规范

1. **CSS 变量优先**：颜色、间距、圆角、阴影全部使用 `tokens.css` 变量
2. **属性选择器**：`[data-role="node-card"]` 用于基础结构，`[data-state~="selected"]` 用于状态样式
3. **BEM 命名**：`.tt-node` / `.tt-node--breakthrough` / `.tt-node.is-selected`
4. **禁止 `!important`**：除非覆盖第三方库
5. **响应式**：移动端样式在 `@media (max-width: 768px)` 内

### 9.3 文件命名规范

| 类型 | 命名方式 | 示例 |
|------|----------|------|
| 组件文件（Class） | PascalCase | `EventNodeCard.js` |
| 样式文件 | kebab-case | `nodes.css` |
| 数据文件 | kebab-case + 语义 ID | `by-seed.md` / `tl-demo-main.md` |
| 入口文件 | 小写 | `app.html` |

### 9.4 错误处理约定

| 场景 | 处理方式 |
|------|----------|
| DataStore 写入失败（ID 不存在） | 返回 `false` + `console.warn()` |
| 网络加载 .md 文件失败 | `console.warn()` + 跳过该文件继续加载 |
| 组件接收非法参数 | `console.warn()` + 提前 return |
| 动画执行异常 | 捕获异常 + 降级为直接切换（不走动画） |

**核心原则**：静默降级优于抛异常。永远不要让一个组件的错误导致整个页面崩溃。

### P5 完成的核心能力（超出原始计划）

P5 在原始"时间轴 + 连线层"基础上，额外完成了**多列统一时间映射系统**：

1. **统一 time→Y 映射**（`_getTimeY`）：所有列共享同一份 time→Y 函数，主列节点按时间排序后均匀分布，分支节点按时间落入主列对应区间
2. **动态行高**（`_getLayout`）：检测每个主列区间内的分支节点数，自动拉开该区间行高，无分支区间保持紧凑（64px），有分支区间按 `(N+1)*56px` 扩展
3. **区间内均匀分布**：分支节点在所属区间内按时间排序后均匀分布（非比例插值），避免时间密集导致拥挤
4. **布局缓存**（`_layoutCache`）：列增删时失效缓存并重新定位所有卡片（`_repositionAllCards`），不重建卡片避免闪烁
5. **分支展开机制**：点击带跨列关联的节点自动引出目标事件线，主列节点自动让位
6. **hover 中间展开**：卡片 hover 时高度从 44px 变 160px，以中心对称扩展，不影响中心点 Y 坐标，时间轴刻度不跳动
7. **跨列连线过滤**：同列内连续关系不画线，仅跨列关系连线
8. **260ms 连续重绘**：hover 期间持续重绘连线和时间轴，跟随 transform 放大效果

## 十一、附录：组件间通信协议完整定义

### A.1 EventEmitter 基类实现

```js
class EventEmitter {
  constructor() {
    this._events = {};
  }
  on(event, handler) {
    (this._events[event] = this._events[event] || new Set()).add(handler);
    return () => this.off(event, handler);
  }
  off(event, handler) {
    this._events[event]?.delete(handler);
  }
  emit(event, data) {
    this._events[event]?.forEach(h => h(data));
  }
}
```
