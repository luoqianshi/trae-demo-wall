## 〇、V0.2 → V0.3 变更摘要

| 变更项 | V0.2 | V0.3 |
|--------|------|------|
| **架构层级** | 叙事集 → 叙事线 → 节点（三层容器） | 叙事线 ↔ 节点（扁平对等） |

## 一、产品定义

**事刻（TimeTrace · 渊 Aion）** 是一个以时间线为基台的多维叙事引擎。

核心价值：将"孤立的事件"重组成"可探索的因果网络"——让任何人在三分钟内看懂一件事的来龙去脉，而不是翻十几篇帖子自己拼凑。

**V0.3 入口策略**：以资讯网站的形态降低用户理解门槛。首页呈现最新事件流，用户像读新闻一样自然进入，逐步深入到事件线、关联网络。

## 二、核心术语

| 术语 | 英文 | 定义 |
|------|------|------|
| **事件** | Event | 客观发生的一件事，是叙事的最小单元。全局唯一存在 |
| **节点** | Node | 事件在文件系统中的存储实体。一节点一文件，全局唯一 |
| **事件线** | Timeline | 一条按时间排列的节点引用序列，含节点间关系定义。每条事件线有唯一编码 |
| **关联** | Relation | 两个节点之间的因果/逻辑关系。关联目标必须指明「节点 + 事件线」组合定位 |
| **独立事件** | Standalone Event | 不属于任何事件线的节点。其作为关联目标时直接用节点 ID 定位，不带事件线 |
| **时段标注** | EraMarker | 事件线上标注时间区间的元信息层（V0.3 暂缓实现） |

**废弃术语**：叙事集（NarrativeSet）、容器（Container）、家族（Family）

## 三、产品架构

### 3.1 扁平化架构

```
事件线 A (Timeline)
  │
  ├─ 引用节点1 ── 关联：导致 ← 节点2 @ 事件线A（同线关联）
  ├─ 引用节点2 ── 关联：响应 ← 节点X @ 事件线B（跨线关联）
  ├─ 引用节点3
  │
事件线 B (Timeline)
  │
  ├─ 引用节点X
  ├─ 引用节点Y
  ├─ 引用节点Z
  │
节点 (Nodes，全局唯一)
  ├─ 节点1 (events/xxx.md)
  ├─ 节点2 (events/yyy.md)
  └─ ...
```

### 3.2 实体关系

```
Timeline    N ──── M  Node          (通过节点引用列表引用)
Node         1                                    (全局唯一，文件即实体)
Relation     ────→  目标 = Node + Timeline 组合定位
Standalone   1                                    (不属于任何 Timeline)
```

**设计原则：**
- **节点全局唯一** —— 一个事件有且只有一个节点文件，不存在同一事件两个节点
- **节点依附事件线** —— 节点至少属于一条事件线，独立事件例外
- **关联必带事件线索引** —— 关联的目标节点必须指明在哪条事件线里被引用
- **事件线独立编码** —— 不同用户可贡献类似主题的事件线，每条有唯一 ID

### 3.3 用户贡献机制

- 事件线有 `author` 字段标识创建者
- 事件线有 `visibility` 字段（public/private）
- 事件线有 `rating` 字段，用户可对事件线质量打分
- 不同用户可对同一主题创建多条事件线（各自独立编码）

> V0.3 不涉及跨工作区 fork 机制，仅支持同一工作区内的事件线创建与关联。跨用户协作的细化机制留待后续版本。

## 四、各要素详细说明

### 4.1 事件 / 节点（Node）

- **原则**：节点全局唯一，一节点一文件
- **存在性**：至少属于一条事件线；独立事件例外
- **存储**：`nodes/` 目录下，文件名 = 节点 ID
- **核心字段**：见第六章数据结构
- **治理**：Wiki 式众创 + 平台审核
  - ✅ 提交新节点（申请 → 审核）
  - ✅ 编辑现有节点（申请 → 审核）
  - ✅ 质疑节点（标记争议）
  - ✅ 评分节点
  - ✅ 评论节点
  - ✅ 举报节点

### 4.2 事件线（Timeline）

- **创建权**：平台主导创建；用户可提交创建申请，平台审核后创建
- **本质**：节点的引用列表 + 节点间关系定义
- **展示类型**：仅两大类
  - **标准版（standard）**：通用时间线展示
  - **特定版（special）**：需特殊排版逻辑的场景（如版本迭代）
- **列头显示**：仅显示事件线自身名称，绝不显示任何分类标签
- **展示方向**：纵向延伸（上 = 过去，下 = 未来）
- **独立编码**：每条事件线有唯一 ID
- **作者**：每条事件线有 `author` 字段标识创建者
- **可见性**：public / private
- **评分**：用户可对事件线质量打分，事件线有 `rating` 聚合字段
- **用户贡献**：不同用户可创建类似主题的事件线（各自独立编码）

### 4.3 关联（Relation）

- **定义**：两个节点之间的因果/逻辑关系
- **关联目标**：必须是「节点 + 事件线」组合定位
- **唯一例外**：目标节点是独立事件（不在任何事件线里），则单独引用节点 ID
- **同线关联**：写在事件线文件的节点 relations 字段里，目标仍需带 `@ 本线ID`
- **跨线关联**：同样写在事件线文件里，目标带 `@ 目标事件线ID`
- **特征**：
  - 带箭头，表示影响方向（`→` 出向 / `←` 入向）
  - 关系名为用户自由文本（"导致""催生""响应""对抗"等）
  - 任意节点之间均可建立关联，不限于相邻事件线

### 4.4 时段标注（EraMarker）

> V0.3 暂缓实现，待节点与事件线编辑能力成熟后再做。

- 定义：事件线上的元信息层，标注时间区间/范围
- 作用：提供"上帝视角"的宏观上下文
- 绑定范围：仅绑定在一条事件线上，不跨线
- 样式：band（背景色带）或 bracket（括号/侧边标记）

## 五、核心交互模型

### 5.1 入口：资讯流首页

```
资讯首页（最新事件流，按时间倒序）
  → 用户像读新闻一样浏览
    → 点击某条事件
      → 进入事件详情页
        → 明显的「事件线」按钮
          → 点击 → 一镜到底动画过渡
            → 进入叙事视图（多列并行展示）
```

### 5.2 一镜到底动画（核心体验亮点）

```
状态1：资讯详情页（全屏事件卡片）
    │
    │  点击「事件线」按钮
    ↓
状态2：画面缩减到一个节点（事件变成节点位置）
    │  原画面的主题色 / 标题元素
    │  从原位置动画流到节点位置
    ↓
状态3：叙事视图（多列并行展示）
    主题色已落到节点上，动画结束
```

**设计要点：**
- 动画不间断，整个过程不切换页面
- 主题色（事件线的主色调）从资讯页流到叙事视图的对应节点
- 给用户"从一个事件钻进去，看到整个事件网络"的沉浸感

### 5.3 展开新事件线：两种方式并存

**方式A · 节点触发（精准探索）**

节点卡片上有**关联标记**（小圆点），点击该标记 → 并排展开目标事件线（如尚未展开）→ 进入焦点模式，将关联链压缩到一屏内完整展示，无关节点模糊处理。详见 5.6 关联压缩展示。

**方式B · 事件线选择面板（主动探索）**

叙事视图顶部有横向滚动的标签条，列出所有可用事件线名称。用户可勾选/取消，自由组合要并列查看的事件线。

### 5.4 并行叙事

- 用户在一条事件线上，点击某节点的关联标记 → 旁边并排展开另一条事件线
- 非跳转，是并排显示
- 最多支持 9 条事件线同时显示

### 5.5 跨线连线

不同事件线的节点之间用连线连接。连线的交互为分层渐进：

| 层级 | 默认状态 | 交互后 |
|------|----------|--------|
| **关联标记**（节点上的小圆点） | 始终可见，提示"此节点有关联" | — |
| **连线** | 不可见 | 悬浮/长按某节点时，该节点的所有连线 + 标注文字全显示，连线变色加粗 |
| **连线标注文字** | 不可见 | 连线显示时出现，悬浮于连线中点 |

连线带箭头表示影响方向，线上标注关系名称。

### 5.6 关联压缩展示（焦点模式）

**问题背景**：事件线纵向排版、从上至下延伸，且多事件线共用同一条时间轴。当点击节点的关联标记时，关联节点在目标事件线中可能处于较远的时间位置，导致关联链跨度过大，**一个屏幕展示不下完整的关系链**。

**解决方案**：点击关联标记后进入焦点模式，将关联链压缩到一屏内完整呈现。

**交互流程：**
1. 点击节点 A 的关联标记
2. 视图进入焦点模式：
   - 关联链上的所有节点（A 及其所有关联节点）**压缩到一屏内**完整展示
   - 时间轴随之压缩，不再按真实时间比例排列，改为紧凑排列
   - 其他无关节点**模糊处理**（CSS filter: blur，推荐）或降低透明度
   - 关联连线全部显示，高亮加粗
3. 点击空白处或按 ESC → 退出焦点模式，恢复原状

**视觉对比：**

```
普通模式（真实时间比例）：               焦点模式（压缩展示）：

事件线A    事件线B                      事件线A    事件线B
  │         │                            │         │
 节点1     节点4                        [节点1] ──→ [节点4]
  │         │                            │         │
 节点2     节点5                         (模糊)    (模糊)
  │         │                            │         │
 节点3     节点6                        [节点3] ←─ [节点6]
  │         │                           关联链完整呈现在一屏内
 节点A ───→ 节点X                        其他节点模糊处理
  │         │
 节点7     节点Y                        (跨度过大，一屏展示不下)
  ↓         ↓
```

**设计要点：**
- 关联链节点保持原时间相对顺序，但间距压缩
- 模糊处理优于降低透明度——模糊后用户视觉焦点自然落在关联链上
- 时间轴标注保留真实时间，但刻度压缩
- 焦点模式下仍可点击节点查看详情

### 5.7 纵向延伸

事件线纵向排列，时间从上方（过去）流向下方（未来）：

```
事件线A       事件线B       事件线C
  │             │             │
 节点1 ─导致→ 节点4           │
  │             │             │
 节点2        节点5 ─催生→  节点7
  │             │             │
 节点3        节点6         节点8
  ↓             ↓             ↓
(过去 → 未来)
```

### 5.8 节点详情：桌面弹窗 / 移动端底部抽屉

点击节点卡片本体 → 弹出节点详情：

- 桌面端：居中浮动卡片（380px 宽，弹性动画）
- 移动端：底部抽屉（Sheet），拖拽指示条 + 圆角顶部

详情内容：
```
┌──────────────────────────────────┐
│  [重要性徽章]                     │
│  事件标题                         │
│  时间                             │
│  ────────────────────────────── │
│  摘要正文                         │
│  备注（斜体，左侧色边）             │
│  来源引用                         │
│  ─── 关联 ────────────────────── │
│  出向关联列表  ·  入向关联列表     │
│  ─── 事件线 ──────────────────── │
│  此节点所属的事件线列表             │
│  ────────────────────────────── │
│  ⭐ 评分  💬 评论  ⚠️ 举报  ✏️ 申请编辑 │
└──────────────────────────────────┘
```

### 5.9 移动端适配

| 场景 | 桌面端 (≥769px) | 移动端 (≤768px) |
|------|----------------|-----------------|
| 事件线列 | 多列并排（单列 240px 宽） | 单列全屏 |
| 事件线切换 | 直接看多列 | 底部横向切换条 + 左右滑动手势 |
| 节点详情 | 居中浮动卡片 | 底部抽屉 |
| 连线 | SVG 跨列连线 | 节点右侧显示"→ 关联线"提示 |

多列同步滚动：滚动任意一列，所有列保持时间轴对齐同步。

## 六、数据结构定义

### 6.1 存储架构

```
V0.3/
├── nodes/              ← 节点：一节点一文件（实体内容）
│   ├── by-founding.md
│   ├── by-toutiao.md
│   └── ...
├── timelines/          ← 事件线：一事件线一文件
│   ├── tl-bd-main.md
│   ├── tl-oa-gpt.md
│   └── ...
├── era-markers.md      ← 时段标注（V0.3 暂缓）
└── index.html
```

**设计原则：**
- 节点是实体，全局唯一，一节点一文件
- 事件线是引用列表，不含节点内容
- 关联全部写在事件线文件里，不单独存储
- 一切数据以 Markdown 格式存储，人类可读可改

### 6.2 节点文件格式

**文件位置**：`nodes/{nodeId}.md`
**文件名**：节点 ID（如 `by-founding.md`）

```markdown
---
id: by-founding
type: event
title: 字节跳动公司成立
startTime: 2012-03-09
endTime:
importance: important
tags:
  person: [张一鸣]
  eventType: [创业]
source: 公开资料
aliases: []
versionNumber:
versionTag:
changelog: []
createdAt: 2026-06-24T00:00:00.000Z
updatedAt: 2026-06-24T00:00:00.000Z
createdBy: curator
status: approved
---

张一鸣在北京创立字节跳动，瞄准移动互联网与个性化信息分发。

> AI 基因在此刻种下——从一开始就没有编辑，只有算法。
```

**字段说明：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | ✅ | 节点唯一标识 |
| type | string | ✅ | 节点类型（默认 event，未来可扩展 organization/product 等） |
| title | string | ✅ | 事件标题 |
| startTime | ISODate | ✅ | 发生时间（精准到日） |
| endTime | ISODate? | ❌ | 结束时间（可选，持续事件） |
| importance | enum | ✅ | breakthrough / important / minor |
| tags | object | ❌ | 自由标签组 |
| source | string | ❌ | 来源引用 |
| aliases | string[] | ❌ | 别名 |
| versionNumber | string? | ❌ | 版本号（特定版用） |
| versionTag | string? | ❌ | stable / beta |
| changelog | string[]? | ❌ | 变更日志（特定版用） |
| createdAt | ISODate | ✅ | 创建时间 |
| updatedAt | ISODate | ✅ | 更新时间 |
| createdBy | string | ✅ | 创建者 |
| status | enum | ✅ | approved / pending / disputed / flagged |

**正文规则：**
- 正文 = 事件摘要（summary）
- `>` 引用块 = 备注（note，背景补充）
- 正文部分支持标准 Markdown

### 6.3 事件线文件格式

**文件位置**：`timelines/{timelineId}.md`
**文件名**：事件线 ID（如 `tl-bd-main.md`）

```markdown
---
id: tl-bd-main
title: 字节 AI 发展编年史
description: 从2012年公司成立至今，字节跳动在AI领域的完整进化路线。
author: curator
visibility: public
displayType: standard
sortField: time
sortOrder: asc
icon: 🎯
rating: 4.8
ratingCount: 12
createdAt: 2026-06-24T00:00:00.000Z
updatedAt: 2026-06-24T00:00:00.000Z
status: published
---

## 节点序列

### 2012-03-09 · 字节跳动公司成立
- node: by-founding
- importance: important
- relations:

### 2012-08-15 · 今日头条 1.0 上线
- node: by-toutiao
- importance: breakthrough
- relations:
  - 导致 ← by-founding @ tl-bd-main

### 2016-02-15 · AI Lab 成立
- node: by-ailab
- importance: breakthrough
- relations:
  - 导致 ← by-toutiao-v3 @ tl-bd-main

### 2023-02-15 · Seed 团队成立
- node: by-seed
- importance: breakthrough
- relations:
  - 响应 ← by-chatgpt-shock @ tl-oa-gpt
  - 催生 → by-volc-ark @ tl-bd-main
```

**字段说明：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string | ✅ | 事件线唯一标识 |
| title | string | ✅ | 列头显示的名称 |
| description | string | ❌ | 简介 |
| author | string | ✅ | 创建者 |
| visibility | enum | ✅ | public / private |
| displayType | enum | ✅ | standard / special |
| sortField | enum | ✅ | time / custom / version_number |
| sortOrder | enum | ✅ | asc / desc |
| icon | string | ❌ | emoji |
| rating | number | ❌ | 评分聚合（0-5，保留一位小数） |
| ratingCount | number | ❌ | 评分人数 |
| createdAt | ISODate | ✅ | 创建时间 |
| updatedAt | ISODate | ✅ | 更新时间 |
| status | enum | ✅ | published / draft / pending_review |

**节点序列格式：**
- 每个节点以 `### {时间} · {标题}` 作为标题
- `node`: 引用的节点 ID
- `importance`: 节点在此事件线中的重要性（可覆盖节点自身）
- `relations`: 关联列表，每条格式为：
  - `{关系名} {方向} {目标节点ID} @ {目标事件线ID}`
  - 方向：`→` 出向（本节点影响目标）/ `←` 入向（目标影响本节点）
  - 独立事件例外：`{关系名} {方向} {目标节点ID}`（不带 @）

**关联格式示例：**
```
- 导致 ← by-founding @ tl-bd-main           # 同线关联：目标在本线
- 响应 ← by-chatgpt-shock @ tl-oa-gpt        # 跨线关联：目标在 tl-oa-gpt
- 催生 → by-volc-ark @ tl-bd-main           # 出向关联
- 关联 → standalone-event-001               # 独立事件关联（无 @）
```

## 八、编辑能力（V0.3 核心新增）

### 8.1 编辑模式总览

V0.3 把"展示视图"本身变成"可视化编辑器"。点击顶栏「编辑模式」按钮切换：

```
展示模式（只读）  ──点击「编辑模式」──▶  编辑模式（可拖拽）
                                      │
                                      ├─ 节点卡片：双击 → 弹出编辑表单
                                      ├─ 列内拖拽：节点上下排序
                                      ├─ 跨列拖拽：节点加入/移出事件线
                                      └─ 关联拖拽：两节点拖线 → 输入关系名 + 选事件线
```

### 8.2 阶段一 · 节点内容编辑器（最高优先级）

**目标**：解决"事件描述粗糙"的底层问题。

**交互流程：**
1. 编辑模式下，双击节点卡片
2. 弹出节点编辑表单（与详情弹窗同位置）
3. 可编辑字段：
   - title（标题）
   - startTime / endTime（时间）
   - importance（重要性）
   - summary（摘要，正文）
   - note（备注，引用块）
   - tags（标签）
   - source（来源）
   - versionNumber / versionTag / changelog（版本相关）
4. 保存 → 即时更新内存 + 标记"未保存到磁盘"
5. 顶部显示「未保存修改」徽章，点击导出 .md 文件

**视觉指示：**
- 编辑过的节点卡片左上角显示橙色小圆点
- 顶部「未保存」徽章显示修改数量

### 8.3 阶段二 · 事件线结构编辑

**目标**：解决"事件线编辑能力差"的问题。

**交互流程：**

| 操作 | 效果 |
|------|------|
| 列内拖拽节点 | 上下排序，改变在事件线中的顺序 |
| 跨列拖拽节点 | 节点加入/移出事件线（修改 eventIds 引用列表） |
| 选择面板勾选 | 创建/删除事件线列 |
| 顶栏"+ 新事件线" | 创建新事件线，弹出表单填名称/作者/可见性 |
| 列头"✕" | 关闭该事件线列（不删除事件线本身） |

**拖拽视觉反馈：**
- 拖拽中：节点卡片半透明 + 阴影增强
- 目标位置：插入位置显示橙色横线
- 跨列拖拽：目标列高亮边框

### 8.4 阶段三 · 关联可视化编辑

**目标**：让关联建立变得直观。

**交互流程：**
1. 编辑模式下，节点卡片上的关联标记变为可拖拽
2. 从节点 A 的关联标记拖出连线 → 拖到节点 B
3. 弹出关联建立表单：
   - 关系名（自由文本，如"导致""催生""响应"）
   - 方向（A → B 出向 / A ← B 入向）
   - **目标事件线**（必选下拉框，列出节点 B 所属的所有事件线）
   - 关系说明（可选）
4. 保存 → 连线立即出现（虚线表示未保存）

**独立事件例外：**
- 如果节点 B 是独立事件（不在任何事件线里），则不显示事件线下拉框，直接引用节点 ID

**关联管理：**
- 长按关联标记 → 弹出关联管理面板
- 可查看当前节点的所有关联列表
- 可编辑/删除现有关联
- 可申请新增关联

### 8.5 数据持久化

**策略**：规则 + MD 导出/导入

```
浏览器内存（编辑即时生效）
    │
    │ 点击「导出」
    ↓
下载 .md 文件包（nodes/ + timelines/ 目录结构）
    │
    │ 用户手动覆盖本地文件
    ↓
本地文件系统（V0.3/data/）

    │ 拖入 .md 文件
    ↓
浏览器解析加载（导入）
```

**导出功能：**
- 顶部「导出」按钮 → 下载所有修改过的 .md 文件
- 文件名保持原命名规则
- 可选择"仅导出修改过的"或"全部导出"

**导入功能：**
- 拖入 .md 文件到浏览器 → 解析并加载
- 自动识别节点文件 / 事件线文件
- 加载后即时刷新视图
