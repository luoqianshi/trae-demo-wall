# 旋律进化

一个在浏览器本地运行的符号旋律实验。用户从随机候选中选择母本，决定它是继续进化还是冻结并生长；旋律按 2、4、8、12、16 小节逐段形成，系统不会替用户决定何时进入下一阶段。

主入口是 `music-evolution.html`。

## 从一张候选卡开始

旋律的完整路径是：

```text
2 小节种子 → 4 小节 A → 8 小节 A/A' → 12 小节加入 B → 16 小节 A'' 回归
```

1. 播放牌堆顶部候选。左划表示跳过，右划表示选为母本；页面按钮和键盘左右键执行同一操作。
2. 右划只进入创作决策，不会立即生成下一代。此时再选择“按母本再进化”“冻结并生长”或 16 小节阶段的“完成作品”。
3. 进化或生长时，可以从其他候选中添加最多两个特征参考。每个候选只能参考密度、走向、音区、留白、张力中的一个维度。
4. 生长还必须明确新乐段的作用，以及交界处采用严格冻结还是允许轻调。
5. 到达 16 小节后，选中的候选必须完整播放到结尾，才能确认作品。

候选未完整试听时左划只会前进，不会被当成负面证据。完整试听后左划才形成一次对比；撤销会恢复上一张卡，并撤销刚形成的对比。牌堆看完后可以重新洗牌，洗牌只重排同一批候选，不会生成新旋律。

“查看全部候选”是备用视图。从那里选择候选，与右划进入的是同一个母本决策状态。

## 两种生成动作

**按母本再进化**保持当前小节数不变，只在当前可变区域产生下一轮候选。可以不限轮次地继续，直到用户愿意冻结。

**冻结并生长**保留已经确认的前缀，并扩展到下一个长度。用户必须选择新乐段的作用：

- `continue` / 承接：维持当前节奏骨架与方向。
- `vary` / 变化：保留可辨认的关系，同时增加变化。
- `contrast` / 对比：让新增区域在结构上形成明确差异。
- `return` / 回归：让新增区域重新靠近最初的根动机。

这些选项描述新增乐段在整首作品里的作用。系统会记录请求，也会在生成后保存测得的表达结果；请求本身不等于生成成功。

## 交界契约

冻结生长时，用户必须明确交界策略：

- **严格冻结**：上一阶段最后 1 小节保持逐事件一致。
- **允许轻调**：相对原始交界锚点最多改变 2 个事件，音高移动受音阶级范围约束。

每次同阶段进化都继续对同一个原始锚点检查，不会把上一轮的微调继续累积。界面会列出交界事件的前后变化；原交界与当前交界不同才允许 A/B 试听，而且 A/B 不加入和弦伴奏。

## 特征参考不是好听评分

“参考它的特点”必须由用户显式选择“哪个候选 + 哪个特征”。差异低于该特征阈值时，对应按钮不可选；同一候选不能同时贡献多个特征。

每轮候选大致由以下来源组成：

- 至少 60%：按本轮生长意图生成，或在当前可变区域内继续母本变异。
- 约 25%：尝试朝用户选定的特征参考移动；没有参考时，这部分回到普通母本变异。
- 其余：当前可变区域内的随机注入。

谱系会分别保存参考请求与生成后的测量结果，包括母本值、目标值、结果值、移动进度和结果状态。移动进度只表示结果是否朝目标靠近，不表示旋律质量，也不保证某个特征一定被保留下来；系统可以诚实记录“本轮未明显表达”。

## 随机池与个人偏好

候选池始终由随机进化产生。“随机”和“偏好”只重排同一组候选 ID，不会替换候选，也不会让已跳过的前缀重新出现。

偏好模型只使用明确反馈：

- 执行决策后的母本选择是正向证据。
- 只有完整试听后再左划的候选才是对比证据。
- 未听完、取消选择或从未出现过的候选保持中性。
- 特征参考只更新被用户点选的那个特征维度。

模型表达的是“更接近你的历史选择”，不是客观审美判断。完整说明见 [`AI_MODEL.md`](./AI_MODEL.md)。

## 分支、存档与旧版恢复

- 每个分支保存自己的牌堆、决策、谱系、试听记录、交界契约和阶段快照。
- 复制分支后，两条旋律可以独立进化；回滚会恢复当时的牌堆和决策状态。
- v3 会话自动保存到浏览器 `localStorage`。
- 可安全恢复的 v2 会话会重建每一阶段的交界锚点，不丢失原候选与分支。
- 无法验证交界契约的 v2 分支会原样保留为只读，仍可播放；系统同时打开一个新的可创作分支，不进行破坏性迁移。

## 当前能力

- 固定 16 小节轨道，显示已冻结、交界、当前生长和未来区域。
- 划卡候选、撤销、牌堆耗尽后洗牌，以及全部候选备用视图。
- 同阶段不限轮次进化，只有用户确认冻结才增加旋律长度。
- 最多两个显式单特征参考，并显示相对差异和生成结果。
- 四种新乐段作用与严格/轻调交界契约。
- 随机顺序与个人偏好顺序使用同一候选集合。
- 独立分支、阶段回滚和 v2 只读恢复。
- Web Audio 候选试听、完整主轨播放、可选共享和弦伴奏、纯旋律交界 A/B。
- 16 小节完整试听完成后才可确认作品。

## 本地运行

项目是静态前端，不需要安装依赖。可以直接打开 `music-evolution.html`，也可以在项目目录启动静态服务器：

```bash
python -m http.server 8765 --bind 127.0.0.1
```

访问 `http://127.0.0.1:8765/music-evolution.html`。

## 测试

```bash
node --check music-evolution-core.js
node --check music-evolution.js
node --test tests/music-evolution-core.test.cjs tests/music-evolution.test.cjs
```

测试覆盖阶段生长、冻结前缀、交界锚点、四种生长意图、显式特征参考、随机注入、划卡与撤销、分支隔离、v2/v3 持久化、偏好证据语义、播放范围和 16 小节确认约束。

## 文件结构

- `music-evolution-core.js`：纯旋律数据、突变、生长意图、特征算子和阶段契约。
- `music-evolution.js`：牌堆与决策状态、偏好排序、谱系、迁移、持久化和 Web Audio。
- `music-evolution.html`：工作台结构。
- `music-evolution.css`：轨道、牌堆、决策面板、谱系和响应式状态。
- `tests/`：核心与浏览器侧契约测试。

## 当前边界

这是符号旋律原型，不是训练于商业音乐库的音频生成模型。随机候选不保证符合某种普遍审美；系统也不会自动完成配器、混音或完整曲式编排。它验证的是用户如何通过可审计的选择，让一条旋律逐段生长成 16 小节作品。
