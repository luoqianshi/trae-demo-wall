## 1. 背景与目标

### 1.1 问题
高中阶段（尤其冲刺高考）校外培训费用高昂，一节 1 对 1 家教数百元；学生遇到不会的题常因没人讲而卡壳，时间和信心双双流失。即使在上海中学这类头部学校，学生仍有大量自学场景缺乏即时答疑支持。

### 1.2 产品目标
做一个**学生自学时即时答疑**的小程序：拍题 → AI 分层讲解 → 错题沉淀，把单次答疑成本从家教级别的几十到几百元压到接近零。

### 1.3 成功标准（可衡量）
- **学习有效**：评测集准确率达标（详见 §10.2）
- **省钱可感知**：单题成本 ≤ ¥0.10；订阅价 ≤ 一节家教的 1/10
- **商业成立**：D1 留存 ≥ 40%，7 日留存 ≥ 25%，付费转化 ≥ 3%
- **合规**：定位为自学工具，不踩双减 K12 学科校外培训红线

## 2. 范围

### 2.1 In Scope（MVP）
- 微信小程序原生前端
- 高中数学单学科
- 拍照 OCR + 手动修正输入
- AI 分层提示讲解（hint1 → hint2 → 完整解析）
- 错题本（自动归集、复习卡）
- 用户配额与微信支付订阅
- AI 答错防控 6 层（详见 §8）
- 内容安全合规（敏感词过滤）

### 2.2 Out of Scope（V2+）
- 其他学科（物理、英语等）
- 题库内置与版权内容
- 家长端独立入口（家长目前通过学生账号看）
- 系统性课程（替代辅导班的章节式讲解）— **双减合规风险高，明确不做**
- 课堂教师辅助 / B2B
- 自部署开源模型降本（V2 规模化后考虑）
- AI Agent 多步编排（V2 提质考虑）

## 3. 关键产品决策（brainstorming 锁定）

| 维度 | 决策 | 理由 |
|---|---|---|
| MVP 子系统 | AI 答疑与讲解引擎 | 最高杠杆替代昂贵家教，闭环最短 |
| 使用场景 | 学生自学卡壳时即时答疑 | 高频、合规风险低、工具属性清晰 |
| 学科范围 | 仅高中数学 | 推理清晰、家教单价最高、AI 易出彩 |
| 讲解风格 | 分层提示 + 逐步展开（hint1 / hint2 / full） | 既不沦为抄答案工具，也不让学生因纯启发式烦躁 |
| 平台 | 微信小程序原生 | 学生手机触达、家长微信支付顺、免下载、冷启动快 |
| 输入方式 | 拍照 OCR + 手动修正 | 最贴近真实使用；OCR 公式识别是难点但可降级 |
| 商业模式 | 免费增值：每日 N 次免费，超出订阅 | 与"省钱"诉求一致，家长决策门槛低 |
| AI 模型 | 国产备案模型（智谱 GLM-4-Plus / DeepSeek-V3） | 中国合规硬约束（生成式 AI 服务管理办法） |

## 4. 架构

### 4.1 分层架构

```
┌─────────────────────────────────────────────────┐
│  微信小程序前端 (WXML + WXSS + JS)               │
│  拍照页 · 修正页 · 答疑页 · 错题本 · 我的        │
└────────────────┬────────────────────────────────┘
                 │ wx.cloud.callFunction (HTTPS)
                 ▼
┌─────────────────────────────────────────────────┐
│  微信云开发 (Serverless)                         │
│  云函数: ocr · solve · usage · payment          │
│  云数据库: users · questions · mistakes · log   │
│  云存储: 题目图片 (7 天生命周期)                 │
└─────────┬───────────────────┬───────────────────┘
          │                   │
          ▼                   ▼
   腾讯云公式 OCR       智谱 GLM-4-Plus / DeepSeek-V3
   (题面+公式识别)      (推理 + 讲解生成)
                              │
                              ▼
                      网信办内容安全 API
                      (敏感词 / 违规内容)
                                          ▼
                                  微信支付
                                  (订阅)
```

### 4.2 关键架构决策

1. **微信云开发作为后端**：免运维、免登录拿 openid、按调用计费、与小程序生态深度集成。MVP 阶段最适合。
2. **OCR 与 AI 解耦**：学生修正 OCR 结果后才送入 AI，保证输入干净。
3. **题目缓存**：相同题目（sha1 hash 命中）直接复用 AI 输出，不重复调用。预期缓存命中率 30-50%，是省钱核心。
4. **分层提示后端组装**：`fn-solve` 一次性生成完整三层结构，前端逐步展示，避免每层调用一次 AI。
5. **LLM 适配层抽象**：在 `fn-solve` 内抽象出 `LLMProvider` 接口，可切换 GLM / DeepSeek / 通义，避免锁定。

## 6. 数据模型

### 6.1 `users`
```js
{
  _id, openid,
  plan: "free" | "pro",
  planExpiresAt: Date | null,
  dailyUsed: number,         // 今日已用次数
  dailyResetAt: "YYYY-MM-DD", // 北京时间日期串，跨日重置
  createdAt, updatedAt
}
```

### 6.2 `questions`
```js
{
  _id,
  hash: "sha1(cleaned_text)",  // 题目指纹，缓存命中键
  rawText,                     // OCR 原始识别
  cleanedText,                 // 学生修正后版本
  latexText,                   // 公式 LaTeX 化版本
  imageUrl,                    // 云存储 path（7 天生命周期）
  topic: "二次方程",            // 章节标签（fn-solve 调 LLM 时生成）
  difficulty: "易" | "中" | "难",  // 同上，LLM 自评
  solution: {
    restatement, conditions, goal,
    hint1, hint2,
    solution_steps: [{step, content, basis}],
    final_answer,              // 含 \boxed{}
    answer_type, confidence
  },
  createdAt
}
```

### 6.3 `mistakes`
```js
{
  _id, openid, questionId,
  status: "new" | "reviewing" | "mastered",
  lastReviewedAt, reviewCount,
  note: "学生自加备注",
  addedAt
}
```

### 6.4 `usage_log`
```js
{ _id, openid, questionId, ts, tokensUsed, costYuan, cacheHit: bool }
```

### 6.5 `feedback`
```js
{
  _id, openid, questionId,
  reportedWrong: bool,
  correctAnswer: "学生填的正确答案（可选）",
  wrongStep: "学生指出的错步（可选）",
  ts
}
```

## 8. AI 答错防控体系（深度防御 6 层）

AI 答错一次，信任崩塌、留存归零。必须有体系化防御。

### 8.1 AI 答错的 5 种根因

| # | 类型 | 例子 |
|---|---|---|
| 1 | 数值计算错 | $17 \times 23$ 算成 393（LLM 不做真正算术） |
| 2 | 推理链断裂 | 第 2 步符号错，后续全错 |
| 3 | 误读题意 | OCR "≥" 识别成 "="，没看到"非空集合" |
| 4 | 幻觉公式 | 编造定理，把韦达定理用在三次方程 |
| 5 | 答案格式异常 | 多解只给一个、忽略定义域 |

### 8.2 多层防御

```
Layer 1 输入清洁 ── OCR 置信度门控 + 学生强制过目修正
Layer 2 模型/Prompt 工程 ── 数学强模型 + 结构化 JSON 输出
Layer 3 答案独立验证 ── sympy 计算数值答案对比
Layer 4 多采样一致性 ── 难题并行调用 N 次看答案是否一致
Layer 5 UI 透明化 + 反馈 ── "AI 生成"标识 + 一键报错
Layer 6 数据回流 ── 错答进评测集，每周回归
```

#### Layer 2: Prompt 工程

让 LLM 严格输出 JSON：
```json
{
  "restatement": "用自己话复述题意（catch 误读）",
  "conditions": ["条件1", "条件2"],
  "goal": "要求解/求证的目标",
  "hint1": "≤50字方向性提示，不点破方法",
  "hint2": "指出可用定理/方法，不写推导",
  "solution_steps": [
    {"step": 1, "content": "...", "basis": "依据：韦达定理"}
  ],
  "final_answer": "\\boxed{...}",
  "answer_type": "numeric | symbolic | proof | multi",
  "confidence": 1-5,
  "uncertain_part": "若 confidence<4 必填"
}
```

约束：必须复述题意、每步注明依据、强制 `\boxed{}`、自评置信度。

#### Layer 3: sympy 独立验证（数值题杀手锏）

后端集成 sympy：
- 提取 AI 输出的 `\boxed{}` 内容
- sympy 独立计算关键中间值与最终答案
- 不一致 → 重采样 1 次；仍不一致 → 标低置信，提示"请核对"
- 能 catch：算术错、代数化简错、方程解错

#### Layer 4: 多采样一致性

- 难度"中"以上题目并行调 2 次
- 两次 `\boxed{}` 一致 → 高置信
- 不一致 → 第 3 次决胜；仍不一致 → 标"建议问老师"，不收费
- 成本影响：难题占比 ~20%，整体成本升 ~30%，可接受

#### Layer 5: UI 透明化

每个解答页底部固定：
```
🤖 AI 生成 · 最后核对：你
答案对吗？ [👍] [👎] [🤔 哪步错了]
```
点 👎 → 弹框填正确答案 + 哪步错 → 写 `feedback`。

#### Layer 6: 数据回流（V2 优先，MVP 留接口）

- 学生反馈的错答自动入评测集
- 每周自动跑回归，输出准确率报告
- 准确率低于阈值的题型 → 标"暂不支持"

### 8.3 MVP 落地优先级

| 层 | MVP | V2 |
|---|---|---|
| Layer 1 输入清洁 | ✅ | |
| Layer 2 Prompt 工程 | ✅ | |
| Layer 3 sympy 验证 | ✅（数值题） | 扩展到证明题 |
| Layer 4 多采样 | ✅（难题 2 次） | |
| Layer 5 反馈 UI | ✅ | |
| Layer 6 评测回归 | 留接口 | 自动化 |

## 9. 错误处理矩阵

| 场景 | 检测 | 处理 |
|---|---|---|
| OCR 置信度低（<0.7） | fn-ocr 返回 confidence | 前端高亮低置信段落，强制学生过目后才能提交 |
| OCR 完全失败 | API 5xx / 超时 | 提示"识别失败，请手打或重拍"，不扣配额 |
| AI 超时 / 限流 | 30s 超时 / 429 | 自动重试 1 次；仍失败 → 退还配额 + 友好提示 |
| AI 输出格式异常 | JSON 解析失败 | 降级：展示 raw 文本 + 标记待人工审核 |
| AI 答案与 sympy 不符 | Layer 3 检测 | 重采样；仍不符 → 标低置信 |
| 配额超限 | fn-usage 检查 | 跳转订阅页，不打断答题流 |
| 支付回调失败 | 微信回调验签失败 / 超时 | 定时任务对账（每小时扫未完成订单） |
| 网络断开 | wx.request 失败 | 本地缓存请求，恢复后重试；离线展示已生成内容 |
| 内容安全命中 | 网信办接口返回违规 | 拒绝处理 + 记录；连续命中触发账号风控 |
| 重复刷量 | 同 openid 1 分钟 >5 次 | 限流 + 验证码 |

## 10. 测试策略

### 10.1 测试金字塔

| 层 | 范围 | 工具 | 目标 |
|---|---|---|---|
| 单元 | prompt 组装、sympy 校验、配额扣减、hash 缓存 | Jest | 关键路径 ≥ 80% 覆盖 |
| 集成 | OCR→solve→usage 全链路 | Jest + 云开发本地模拟 | 主流程 + 5 个错误分支 |
| E2E 真题 | 100 题标准集跑 fn-solve | 自建 Node 脚本 | 准确率门控 |

**门控规则**：评测准确率低于阈值禁止部署。

| 函数与导数 | 15 | 3/8/4 |
| 三角函数 | 12 | 3/6/3 |
| 数列 | 12 | 3/6/3 |
| 立体几何 | 14 | 3/7/4 |
| 解析几何 | 15 | 3/8/4 |
| 概率统计 | 14 | 4/7/3 |
| 不等式 / 杂 | 18 | 4/10/4 |

来源：近 5 年高考真题 + 上海各区一模二模 + 人教版教材例题，**人工标注**标答与解析。

### 10.3 准确率门控（公测门槛）

| 题型 | MVP 目标 |
|---|---|
| 选择题 | ≥ 90% |
| 填空题 | ≥ 85% |
| 解答题（最终答案） | ≥ 80% |
| 解答题（关键步骤） | ≥ 70% |

低于阈值就不上线对应题型。**宁可拒答也不能答错**。

## 12. 成本与商业化

### 12.1 单题成本估算
- 腾讯云公式 OCR：¥0.05
- GLM-4 输入 ~1k token：¥0.002
- GLM-4 输出 ~1.5k token：¥0.003
- **合计 ~¥0.055/题**（首次调用）
- 缓存命中后边际成本接近零

### 12.2 定价（初始参考，公测前根据用户调研调整）
- 免费：每日 3 次
- 月订阅：¥19/月（无限答疑）
- 年订阅：¥168/年（折合 ¥14/月）

### 12.3 单题成本预警阈值
- 单题成本 > ¥0.10 → 报警
- 缓存命中率 < 20% → 报警
- 日亏损 > ¥500 → 报警

## 13. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 双减合规突变 | 定位为"自学工具"非"培训"；不主动推学科课程；保留合规备案材料 |
